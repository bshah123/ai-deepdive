# 2.1 — What Is a Variable in Python?

## Opening Motivation & Context

Variables are fundamental building blocks in programming. They allow us to store and manipulate data in our programs. Understanding variables is crucial for writing efficient, maintainable, and bug-free code. In Python, variables are more than just containers for data; they are objects with identities, types, and values. This lesson will explore the nature of variables in Python, their role in memory management, and best practices for using them effectively.

## Core Concepts Breakdown

### [!KEY-INSIGHT]
In Python, variables are names that refer to objects. An object has an identity, a type, and a value. The identity of an object never changes once it has been created; you may think of it as the object's address in memory. The value of some objects can change. Objects that have a type that can be changed are called mutable; objects that have a type that cannot be changed are called immutable.

### [!BEST-PRACTICE]
Use descriptive variable names that convey the purpose of the variable. This makes your code more readable and easier to maintain. Follow the naming conventions recommended by the Python community, such as using lowercase letters with words separated by underscores for variable names.

### [!WARNING]
Be cautious when using mutable objects as default arguments in functions. Since default arguments are evaluated only once when the function is defined, using a mutable object as a default argument can lead to unexpected behavior. Instead, use `None` as the default argument and initialize the mutable object inside the function.

## Code Demonstration & Runtime Output

```python
def demonstrate_variables():
    # Creating variables and assigning values
    x: int = 10
    y: float = 3.14
    name: str = "Alice"
    is_active: bool = True
    my_list: list[int] = [1, 2, 3]

    # Printing variable values
    print(f"x: {x}, type: {type(x)}")
    print(f"y: {y}, type: {type(y)}")
    print(f"name: {name}, type: {type(name)}")
    print(f"is_active: {is_active}, type: {type(is_active)}")
    print(f"my_list: {my_list}, type: {type(my_list)}")

    # Modifying variable values
    x = 20
    my_list.append(4)

    # Printing modified values
    print(f"Modified x: {x}")
    print(f"Modified my_list: {my_list}")

    # Demonstrating variable references
    a: int = 5
    b: int = a
    print(f"a: {a}, b: {b}")

    a = 10
    print(f"Modified a: {a}, b: {b}")

    # Demonstrating mutable default argument pitfall
    def append_to_list(value: int, my_list: list[int] = []):
        my_list.append(value)
        return my_list

    print(append_to_list(1))
    print(append_to_list(2))
    print(append_to_list(3, []))

if __name__ == "__main__":
    demonstrate_variables()
```

### [!ADVANCED]
In Python, variables are implemented as references to objects in memory. When you assign a value to a variable, you are creating a reference to an object. The object itself is stored in memory, and the variable holds the memory address of the object. This allows multiple variables to refer to the same object. When you modify a mutable object, all variables referring to that object will see the changes. Immutable objects, on the other hand, cannot be changed after creation, so modifying an immutable object creates a new object and updates the variable's reference to point to the new object.

### [!QA]
**Q: When should I prefer using immutable objects over mutable objects?**
A: Immutable objects are safer to use in multi-threaded environments because they cannot be modified after creation. They are also easier to reason about and can help prevent bugs. However, mutable objects can be more efficient in certain scenarios, such as when you need to frequently modify a large data structure. It's important to choose the right tool for the job based on the specific requirements of your program.

## Summary & Key Takeaways

- Variables in Python are names that refer to objects.
- Objects have an identity, a type, and a value.
- Mutable objects can be changed after creation, while immutable objects cannot.
- Use descriptive variable names to make your code more readable.
- Be cautious when using mutable objects as default arguments in functions.
- Variables can refer to the same object, and modifying a mutable object will affect all variables referring to it.

### Question #3: Find and fix the bug

```python
def append_to_list(value: int, my_list: list[int] = []):
    my_list.append(value)
    return my_list

print(append_to_list(1))
print(append_to_list(2))
print(append_to_list(3, []))
```

<details><summary>Show Solution</summary>

The bug in the code is the use of a mutable object as a default argument. Since default arguments are evaluated only once when the function is defined, the same list object is used for all calls to the function without an explicit `my_list` argument. This leads to unexpected behavior where the list grows with each call.

To fix the bug, use `None` as the default argument and initialize the mutable object inside the function:

```python
def append_to_list(value: int, my_list: list[int] | None = None):
    if my_list is None:
        my_list = []
    my_list.append(value)
    return my_list

print(append_to_list(1))
print(append_to_list(2))
print(append_to_list(3, []))
```

The fixed code outputs:

```text
[1]
[2]
[3]
```

</details>
