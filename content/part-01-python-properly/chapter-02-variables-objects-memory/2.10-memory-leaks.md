# 2.10 — Detecting & Preventing Memory Leaks

## Opening Motivation & Context

Memory leaks are a critical issue in computing and AI, where resources are not properly released after use. This can lead to excessive memory consumption, system slowdowns, and even crashes. In Python, memory leaks can occur due to circular references, improper use of global variables, or external resources not being closed. Detecting and preventing memory leaks is essential for writing efficient and reliable code.

## Core Concepts Breakdown

### What is a Memory Leak?

A memory leak occurs when a program fails to release memory that is no longer needed. This can happen in Python due to circular references, where objects reference each other, preventing the garbage collector from reclaiming their memory.

> [!KEY-INSIGHT]
> Memory leaks can significantly impact the performance and stability of your applications. Regularly monitoring memory usage and understanding the garbage collection process can help you detect and prevent leaks.

### Garbage Collection in Python

Python uses a garbage collector to automatically manage memory. The garbage collector identifies and removes objects that are no longer in use. However, it may not always be able to reclaim memory due to circular references.

> [!BEST-PRACTICE]
> Use the `gc` module to manually trigger garbage collection and monitor memory usage. Additionally, ensure that you properly close external resources like files and network connections.

> [!WARNING]
> Circular references can lead to memory leaks. Be cautious when creating objects that reference each other, and consider using weak references to break these cycles.

## Code Demonstration & Runtime Output

```python
import gc
import weakref

class Node:
    def __init__(self, value: int):
        self.value = value
        self.next = None

def create_circular_reference():
    node1 = Node(1)
    node2 = Node(2)
    node1.next = node2
    node2.next = node1
    return node1, node2

def monitor_memory_usage():
    print(f"Garbage collector: {gc.isenabled()}")
    print(f"Garbage collector thresholds: {gc.get_threshold()}")
    print(f"Garbage collector count: {gc.get_count()}")

def main():
    monitor_memory_usage()
    node1, node2 = create_circular_reference()
    monitor_memory_usage()

    # Using weakref to break the circular reference
    weakref_node1 = weakref.ref(node1)
    weakref_node2 = weakref.ref(node2)

    # Explicitly delete the nodes
    del node1, node2

    # Force garbage collection
    gc.collect()
    monitor_memory_usage()

if __name__ == "__main__":
    main()
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: The `gc` module is imported to interact with the garbage collector, and `weakref` is imported to create weak references.
2. **Node Class**: The `Node` class is defined to represent nodes in a linked list.
3. **create_circular_reference Function**: This function creates two nodes and sets up a circular reference between them.
4. **monitor_memory_usage Function**: This function prints the status of the garbage collector, including whether it is enabled, its thresholds, and the current count of objects in the generation 0, 1, and 2.
5. **main Function**:
   - `monitor_memory_usage()` is called to print the initial state of the garbage collector.
   - `create_circular_reference()` is called to create nodes with a circular reference.
   - `monitor_memory_usage()` is called again to print the state after creating the circular reference.
   - Weak references to the nodes are created using `weakref.ref`.
   - The nodes are explicitly deleted using `del`.
   - `gc.collect()` is called to force garbage collection.
   - `monitor_memory_usage()` is called again to print the final state of the garbage collector.

> [!ADVANCED]
> The garbage collector in Python uses a generational approach to manage memory. Objects are initially placed in the youngest generation (generation 0). If they survive a garbage collection cycle, they are moved to the next generation. The thresholds for each generation determine when a garbage collection cycle is triggered. Weak references allow you to reference an object without preventing it from being garbage collected.

> [!QA]
> Q: When should I prefer weak references over strong references?
> A: Weak references should be used when you need to reference an object without preventing it from being garbage collected. This is useful in scenarios where you want to keep a reference to an object but do not want to prevent its deletion, such as in caching or observer patterns.

## Summary & Key Takeaways

- Memory leaks can occur due to circular references and improper resource management.
- Python's garbage collector automatically manages memory but may not always reclaim memory due to circular references.
- Use the `gc` module to monitor and control garbage collection.
- Use weak references to break circular references and prevent memory leaks.
- Ensure that external resources like files and network connections are properly closed.
