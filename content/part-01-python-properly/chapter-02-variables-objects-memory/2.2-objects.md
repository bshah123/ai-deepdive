# 2.2 — PyObject & Python's Object System

## Opening Motivation & Context

In Python, everything is an object. This means that even fundamental data types like integers, strings, and lists are objects. Understanding how Python's object system works is crucial for writing efficient, maintainable code, especially when working with large-scale applications or performance-critical sections.

The `PyObject` is the base structure that all Python objects inherit from. It contains essential information about the object, such as its type and reference count. Understanding `PyObject` and Python's object system will help you grasp how Python manages memory, handles object creation and destruction, and implements various object behaviors.

## Core Concepts Breakdown

### [!KEY-INSIGHT]
Python's object system is built around the `PyObject` structure, which is the foundation for all objects in Python. This structure contains essential information about the object, such as its type and reference count, and provides a way to access the object's methods and attributes.

### [!BEST-PRACTICE]
When working with Python objects, always remember that everything is an object. This includes fundamental data types, functions, and even modules. Understanding this concept will help you write more idiomatic Python code and better understand how Python works under the hood.

### [!WARNING]
Be cautious when dealing with object references and memory management. Python uses reference counting to manage memory, and understanding how it works can help you avoid common pitfalls, such as circular references and memory leaks.

## Code Demonstration & Runtime Output

```python
import sys

class MyClass:
    def __init__(self, value: int) -> None:
        self.value = value

    def __del__(self) -> None:
        print(f"Object with value {self.value} is being destroyed")

def demonstrate_object_system() -> None:
    # Create an instance of MyClass
    obj = MyClass(42)

    # Get the reference count of the object
    ref_count = sys.getrefcount(obj)
    print(f"Reference count of obj: {ref_count}")

    # Get the type of the object
    obj_type = type(obj)
    print(f"Type of obj: {obj_type}")

    # Get the size of the object in bytes
    obj_size = sys.getsizeof(obj)
    print(f"Size of obj in bytes: {obj_size}")

    # Create a new reference to the object
    obj_ref = obj
    ref_count = sys.getrefcount(obj)
    print(f"Reference count of obj after creating a new reference: {ref_count}")

    # Delete the new reference
    del obj_ref
    ref_count = sys.getrefcount(obj)
    print(f"Reference count of obj after deleting the new reference: {ref_count}")

    # Create a list containing the object
    obj_list = [obj]
    ref_count = sys.getrefcount(obj)
    print(f"Reference count of obj after adding it to a list: {ref_count}")

    # Remove the object from the list
    obj_list.remove(obj)
    ref_count = sys.getrefcount(obj)
    print(f"Reference count of obj after removing it from the list: {ref_count}")

if __name__ == "__main__":
    demonstrate_object_system()
```

### [!ADVANCED]
Python's object system is implemented in C using the `PyObject` structure. This structure contains essential information about the object, such as its type and reference count, and provides a way to access the object's methods and attributes. The `PyObject` structure is defined in the `Include/object.h` header file in the Python source code.

When you create a new object in Python, the interpreter allocates memory for the object and initializes its `PyObject` structure. The `ob_refcnt` field of the `PyObject` structure is initialized to 1, indicating that there is one reference to the object. The `ob_type` field is set to the type of the object, which is a pointer to a `PyTypeObject` structure that contains information about the object's type, such as its name, size, and methods.

When you create a new reference to an object, the interpreter increments the `ob_refcnt` field of the object's `PyObject` structure. When you delete a reference to an object, the interpreter decrements the `ob_refcnt` field. When the `ob_refcnt` field reaches zero, the interpreter calls the object's destructor method, which is responsible for freeing the object's memory and performing any necessary cleanup.

### [!QA]
Q: When should I prefer using a list over a tuple in Python?

A: You should prefer using a list over a tuple when you need to modify the collection of items. Tuples are immutable, which means that you cannot add, remove, or change items in a tuple after it has been created. Lists, on the other hand, are mutable, which means that you can add, remove, and change items in a list after it has been created. However, tuples are more memory-efficient than lists, so you should prefer using a tuple over a list when you do not need to modify the collection of items.
