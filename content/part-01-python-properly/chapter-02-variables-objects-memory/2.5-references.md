# 2.5 — Object References & Aliasing

## Opening Motivation & Context

In Python, everything is an object, and variables are essentially names or labels that refer to these objects. Understanding how references work is crucial for writing efficient and bug-free code. This lesson will explore the concept of object references and aliasing, which can sometimes lead to unexpected behavior if not handled properly.

## Core Concepts Breakdown

### Object References

In Python, variables do not store the actual objects they refer to. Instead, they store references to these objects. This means that when you assign a variable to another variable, you are not creating a new object but rather a new reference to the same object.

> [!KEY-INSIGHT]
> Variables in Python are names that refer to objects in memory. Assigning a variable to another variable creates a new reference to the same object.

### Aliasing

Aliasing occurs when multiple variables refer to the same object. This can lead to unexpected behavior if you are not aware of it. For example, if you modify an object through one variable, the changes will be visible through all other variables that refer to the same object.

> [!BEST-PRACTICE]
> To avoid unintended side effects, be mindful of aliasing when working with mutable objects like lists and dictionaries. Consider creating copies of objects if you need to work with independent instances.

> [!WARNING]
> Be cautious when working with mutable objects and aliasing. Changes made to an object through one reference will be visible through all other references to the same object.

## Code Demonstration & Runtime Output

```python
def demonstrate_references_and_aliasing() -> None:
    # Create an integer object and assign it to variable 'a'
    a: int = 42
    print(f"Initial value of 'a': {a}")

    # Assign 'a' to 'b'. Both variables now refer to the same object
    b: int = a
    print(f"Value of 'b' after assignment: {b}")

    # Modify the value of 'a'. This creates a new object and 'a' now refers to this new object
    a = 100
    print(f"Value of 'a' after modification: {a}")
    print(f"Value of 'b' after 'a' is modified: {b}")

    # Create a list object and assign it to variable 'list1'
    list1: list[int] = [1, 2, 3]
    print(f"Initial value of 'list1': {list1}")

    # Assign 'list1' to 'list2'. Both variables now refer to the same list object
    list2: list[int] = list1
    print(f"Value of 'list2' after assignment: {list2}")

    # Modify the list through 'list1'. The changes will be visible through 'list2' as well
    list1.append(4)
    print(f"Value of 'list1' after modification: {list1}")
    print(f"Value of 'list2' after 'list1' is modified: {list2}")

    # Create a new list object and assign it to 'list1'. 'list1' now refers to this new object
    list1 = [5, 6, 7]
    print(f"Value of 'list1' after new assignment: {list1}")
    print(f"Value of 'list2' after 'list1' is reassigned: {list2}")

if __name__ == "__main__":
    demonstrate_references_and_aliasing()
```

> [!ADVANCED]
> In CPython, objects are stored in memory with a header that contains information about the object's type and reference count. The reference count is used to determine when an object can be safely deallocated. When a variable is assigned to another variable, the reference count of the object is incremented. When a variable goes out of scope or is reassigned, the reference count of the object is decremented. When the reference count of an object reaches zero, the object is deallocated from memory.

> [!QA]
> Q: When should I prefer creating a new object over reusing an existing object?
> A: You should prefer creating a new object when you need to work with independent instances of an object. This is particularly important when working with mutable objects like lists and dictionaries. Creating a new object ensures that changes made to one object will not affect the other object.

### Question #3: Find and fix the bug

```python
def demonstrate_bug() -> None:
    list1: list[int] = [1, 2, 3]
    list2: list[int] = list1
    list1 = [4, 5, 6]
    print(f"Value of 'list2': {list2}")

if __name__ == "__main__":
    demonstrate_bug()
```

<details><summary>Show Solution</summary>

The bug in the code is that it expects `list2` to be modified when `list1` is reassigned. However, `list2` remains unchanged because it refers to the original list object. To fix the bug, you should create a copy of `list1` and assign it to `list2` if you want `list2` to be modified independently of `list1`.

Here is the fixed code:

```python
def demonstrate_fixed_bug() -> None:
    list1: list[int] = [1, 2, 3]
    list2: list[int] = list1.copy()
    list1 = [4, 5, 6]
    print(f"Value of 'list2': {list2}")

if __name__ == "__main__":
    demonstrate_fixed_bug()
```

The fixed code outputs:

```text
Value of 'list2': [1, 2, 3]
```

</details>
