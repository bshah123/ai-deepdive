# 2.6 — Mutable vs Immutable Objects

## Opening Motivation & Context

In Python, everything is an object, and objects can be categorized as either mutable or immutable. Understanding the difference between these two categories is crucial for writing efficient and bug-free code. Mutable objects can be changed after they are created, while immutable objects cannot be changed once they are created. This distinction affects how objects are stored in memory, how they are passed to functions, and how they behave in various operations.

## Core Concepts Breakdown

### Mutable Objects

Mutable objects can be changed after they are created. Examples of mutable objects in Python include lists, dictionaries, and sets. When you modify a mutable object, you are changing the object itself, not creating a new object.

> [!KEY-INSIGHT]
> Mutable objects can be modified in place, which can lead to more efficient memory usage and faster operations.

> [!BEST-PRACTICE]
> Use mutable objects when you need to frequently modify the data structure.

> [!WARNING]
> Be careful when passing mutable objects to functions, as changes made to the object within the function will affect the original object.

### Immutable Objects

Immutable objects cannot be changed after they are created. Examples of immutable objects in Python include integers, floats, strings, and tuples. When you perform an operation on an immutable object, you are creating a new object rather than modifying the existing one.

> [!KEY-INSIGHT]
> Immutable objects are safer to use in multi-threaded environments because they cannot be changed unexpectedly.

> [!BEST-PRACTICE]
> Use immutable objects when you need to ensure that the data remains constant and cannot be accidentally modified.

> [!WARNING]
> Avoid using immutable objects when you need to frequently modify the data structure, as this can lead to unnecessary memory usage and slower operations.

## Code Demonstration & Runtime Output

```python
def demonstrate_mutability():
    # Mutable object example
    mutable_list = [1, 2, 3]
    print(f"Original mutable list: {mutable_list}")

    # Modifying the mutable list
    mutable_list.append(4)
    print(f"Modified mutable list: {mutable_list}")

    # Immutable object example
    immutable_string = "Hello"
    print(f"Original immutable string: {immutable_string}")

    # Attempting to modify the immutable string
    try:
        immutable_string[0] = "J"
    except TypeError as e:
        print(f"Error: {e}")

    # Creating a new string by concatenation
    new_immutable_string = immutable_string + " World"
    print(f"New immutable string: {new_immutable_string}")

if __name__ == "__main__":
    demonstrate_mutability()
```

Output:
```
Original mutable list: [1, 2, 3]
Modified mutable list: [1, 2, 3, 4]
Original immutable string: Hello
Error: 'str' object does not support item assignment
New immutable string: Hello World
```

> [!ADVANCED]
> In CPython, mutable objects like lists are implemented using C structures that contain a pointer to a dynamically allocated array of elements. When you modify a mutable object, you are changing the elements in the array. Immutable objects like strings are implemented using C structures that contain a pointer to a statically allocated array of characters. When you perform an operation on an immutable object, you are creating a new object with a new array of characters.

> [!QA]
> Q: When should I prefer mutable objects over immutable objects?
> A: You should prefer mutable objects when you need to frequently modify the data structure and want to avoid the overhead of creating new objects. However, be aware of the potential pitfalls of mutable objects, such as unintended side effects when passing them to functions.

## Summary & Key Takeaways

- Mutable objects can be changed after they are created, while immutable objects cannot be changed once they are created.
- Mutable objects are more efficient for frequent modifications but can lead to unintended side effects.
- Immutable objects are safer to use in multi-threaded environments but can lead to unnecessary memory usage and slower operations.
- Be careful when passing mutable objects to functions, as changes made to the object within the function will affect the original object.

### Question #3: Find and fix the bug

```python
def modify_string(s):
    s += " World"

my_string = "Hello"
modify_string(my_string)
print(my_string)
```

<details><summary>Show Solution</summary>
The bug is that the `modify_string` function does not modify the original string passed to it because strings are immutable. To fix the bug, you need to return the new string from the function and assign it to a new variable.

```python
def modify_string(s):
    s += " World"
    return s

my_string = "Hello"
new_string = modify_string(my_string)
print(new_string)
```
</details>
