# 2.7 — Reference Counting & sys.getrefcount()

## Opening Motivation & Context

Reference counting is a fundamental concept in memory management, particularly in languages like Python. It's a mechanism that helps Python automatically manage memory by keeping track of how many references an object has. When an object's reference count drops to zero, it means the object is no longer needed, and Python can safely deallocate the memory it occupies.

Understanding reference counting is crucial for writing efficient and bug-free Python code. It helps you understand how Python manages memory, which in turn helps you write code that doesn't leak memory or cause other memory-related issues.

## Core Concepts Breakdown

### Reference Counting

Reference counting is a technique used by Python to manage memory. Every object in Python has a reference count, which is the number of references to that object. When an object's reference count drops to zero, it means the object is no longer needed, and Python can safely deallocate the memory it occupies.

> [!KEY-INSIGHT]
> Reference counting is a fundamental mechanism in Python's memory management. It helps Python automatically manage memory by keeping track of how many references an object has.

> [!BEST-PRACTICE]
> Always be mindful of object references in your code. Unnecessary references can prevent objects from being garbage collected, leading to memory leaks.

> [!WARNING]
> Circular references can cause memory leaks because objects with circular references will never have a reference count of zero. This is why Python also uses a garbage collector to handle such cases.

## Code Demonstration & Runtime Output

```python
import sys

def get_ref_count(obj: object) -> int:
    """Return the reference count of an object."""
    return sys.getrefcount(obj)

def demonstrate_reference_counting() -> None:
    """Demonstrate reference counting in Python."""
    # Create a new object
    x = [1, 2, 3]

    # Get the reference count of the object
    print(f"Reference count of x: {get_ref_count(x)}")

    # Create a new reference to the same object
    y = x

    # Get the reference count of the object
    print(f"Reference count of x after assigning to y: {get_ref_count(x)}")

    # Delete one reference
    del y

    # Get the reference count of the object
    print(f"Reference count of x after deleting y: {get_ref_count(x)}")

    # Create a new reference to the same object
    z = x

    # Get the reference count of the object
    print(f"Reference count of x after assigning to z: {get_ref_count(x)}")

    # Delete all references
    del x
    del z

    # Try to get the reference count of the object
    try:
        print(f"Reference count of x after deleting all references: {get_ref_count(x)}")
    except UnboundLocalError:
        print("x is no longer defined")

if __name__ == "__main__":
    demonstrate_reference_counting()
```

```text
Reference count of x after assigning to y: 3
Reference count of x after deleting y: 2
Reference count of x after assigning to z: 3
x is no longer defined
```

> [!ADVANCED]
> In CPython, the reference count is stored in the object's header. The header is a structure that contains information about the object, such as its type and its reference count. When an object's reference count drops to zero, CPython calls the object's destructor to deallocate the memory it occupies.

> [!QA]
> Q: When should I prefer using reference counting over garbage collection?
> A: Reference counting is generally faster than garbage collection, but it can't handle circular references. If your code doesn't create circular references, you might prefer using reference counting. However, if your code does create circular references, you should use garbage collection to avoid memory leaks.

### Question #3: Find and fix the bug

```python
import sys

def get_ref_count(obj: object) -> int:
    """Return the reference count of an object."""
    return sys.getrefcount(obj)

x = [1, 2, 3]
y = x
del x
print(get_ref_count(y))
```

<details><summary>Show Solution</summary>

The bug in the code is that it tries to get the reference count of `y` after deleting `x`. However, `y` is still a reference to the same object, so the code should work as expected. The fixed code is:

```python
import sys

def get_ref_count(obj: object) -> int:
    """Return the reference count of an object."""
    return sys.getrefcount(obj)

x = [1, 2, 3]
y = x
del x
print(get_ref_count(y))
```

The code outputs `2`. The reference count of `y` is 2 because there are two references to the same object: `y` and the argument to `get_ref_count`.

</details>
