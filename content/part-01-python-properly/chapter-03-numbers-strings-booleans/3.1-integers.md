Python's `int` never overflows: `2**1000` just works. In this lesson you will read an integer's digits straight out of memory, predict `sys.getsizeof` for any integer, rebuild digit-by-digit addition and multiplication, and spot where fixed-width integers sneak back in (NumPy and PyTorch).

**You need:** Lesson 2.2 (every Python value is an object with a type and a reference count) and place-value notation (4,711 means 4·1000 + 7·100 + 1·10 + 1).

## The problem: fixed-width integers overflow

A processor adds two 64-bit integers in one instruction, so languages like C store an integer in a fixed number of bits. The price is a hard ceiling: the largest signed 64-bit integer is $2^{63}-1 = 9{,}223{,}372{,}036{,}854{,}775{,}807$, and one more wraps around to $-2^{63}$. No error is raised; the number is just wrong. NumPy arrays and PyTorch tensors use these fixed-width types, and the NumPy manual warns that they "may confuse users expecting NumPy integers to behave similar to Python's `int`".

Python removed the ceiling. PEP 237 (Python Enhancement Proposal, the design document) unified the old fixed-size `int` and the unlimited `long`, so integer operations that would overflow return a longer integer instead. The language reference says an `int` has "an unlimited range, subject to available (virtual) memory only". The price moves from correctness to memory and speed, and this lesson shows exactly how much.

## Intuition: a number written in base 2^30

In decimal, 4,711 means 1·10⁰ + 1·10¹ + 7·10² + 4·10³. CPython (the reference implementation of Python) writes every integer the same way, but in base $2^{30} = 1{,}073{,}741{,}824$. A "digit" is a whole number from 0 to $2^{30}-1$, stored in one 4-byte slot, **least significant digit first**. Next to the digits sits a tag word that records the digit count and the sign:

![Two ints drawn as memory: refcount, type pointer, lv_tag, then 30-bit digits; 10**12 has digits 346361856 and 931 in 32 bytes, 2**100 has digits 0, 0, 0, 1024 in 40 bytes](diagrams/3.1-layout.svg "The memory of two Python ints on a 64-bit CPython 3.12 build. Digit i is worth d_i · 2^(30·i).")

The value is $\sum_i d_i \cdot 2^{30 i}$ (the `longintrepr.h` header states this formula for the absolute value). `sys.int_info` reports the choice: `bits_per_digit=30`, `sizeof_digit=4`. Why 30 bits in a 32-bit slot? The header requires that a digit can hold $2\cdot\text{BASE}-1$, so adding two digits plus a carry never overflows the slot. Two spare bits give that room (my reading of that requirement). The header also allows a 15-bit-digit build; `sys.int_info` tells you which one you have.

## Worked example, by hand

Take $10^{12}$. It exceeds $2^{30} \approx 1.07 \times 10^9$, so it needs two digits. Divide by $2^{30}$: $10^{12} = 931 \times 1{,}073{,}741{,}824 + 346{,}361{,}856$, because $931 \times 1{,}073{,}741{,}824 = 999{,}653{,}638{,}144$ and $10^{12} - 999{,}653{,}638{,}144 = 346{,}361{,}856$. The digits are $[346361856,\ 931]$, lowest first. For $2^{100}$, note $100 = 3 \cdot 30 + 10$: three zero digits, then $2^{10} = 1024$, giving $[0, 0, 0, 1024]$.

The code does the same divisions, then reads the real digits from memory with `ctypes` (the standard library's C-interop module):

```python
import ctypes

def digits_base_2_30(n):
    """Digits of abs(n) in base 2**30, least significant digit first."""
    n, out = abs(n), []
    while n:
        n, d = divmod(n, 2**30)
        out.append(d)
    return out

def peek(n):
    """Read lv_tag and the digit array of a CPython 3.12+ int straight from memory."""
    w = ctypes.sizeof(ctypes.c_void_p)                  # pointer size: 8 on 64-bit builds
    tag = ctypes.c_size_t.from_address(id(n) + 2 * w).value   # after refcount and type pointer
    count = tag >> 3                                    # high bits: number of digits
    digits = (ctypes.c_uint32 * count).from_address(id(n) + 3 * w)
    return tag, list(digits)

print(f"{'n':>34}  {'by hand':<26} {'from memory':<30}")
for n in [0, 1, -1, 2**30, 10**12, 2**100]:
    tag, mem = peek(n)
    print(f"{n:>34}  {str(digits_base_2_30(n)):<26} tag={tag:<3} {mem}")
print("sign bits of the tag:", {n: peek(n)[0] & 3 for n in (5, 0, -5)})
```

```output
                                 n  by hand                    from memory                   
                                 0  []                         tag=1   []
                                 1  [1]                        tag=8   [1]
                                -1  [1]                        tag=10  [1]
                        1073741824  [0, 1]                     tag=16  [0, 1]
                     1000000000000  [346361856, 931]           tag=16  [346361856, 931]
   1267650600228229401496703205376  [0, 0, 0, 1024]            tag=32  [0, 0, 0, 1024]
sign bits of the tag: {5: 0, 0: 1, -5: 2}
```

The hand calculation and the memory agree. The tag is `digits × 8 + sign code`: the header defines the masks `_PyLong_SIGN_MASK 3` and `_PyLong_NON_SIZE_BITS 3`, and the sign codes (0 positive, 1 zero, 2 negative) follow from `_PyLong_CompactValue`, which computes `sign = 1 - (lv_tag & 3)`. The dump confirms them. Note that **the sign is not stored in a digit**: `-1` has the same digit list as `1`. Zero has no digits at all.

> [!WARNING]
> This layout is specific to CPython 3.12 and later (I checked 3.12.13, 3.13.14, 3.14.6 and 3.15.0b4: the tag of `2**100` is 32 in all four). CPython 3.11 stored a signed size field instead, so `peek` would read garbage there. Reading memory is harmless; never write to it.

## What it costs: memory

An int object is a 24-byte header (reference count, type pointer, tag: 8 bytes each on 64-bit) plus 4 bytes per digit. The header comment in `longintrepr.h` says CPython "always allocate[s] memory for at least one digit", so even `0` takes 28 bytes, against 8 for a C `int64_t`.

```python
import sys

header = sys.getsizeof(0) - sys.int_info.sizeof_digit    # bytes before the digit array
print("bits_per_digit:", sys.int_info.bits_per_digit, " sizeof_digit:", sys.int_info.sizeof_digit)
print(f"{'bit length':>10} {'digits':>6} {'getsizeof':>9}  getsizeof == header + 4*digits?")
for bits in [0, 1, 30, 31, 60, 61, 90, 91, 300, 1000]:
    n = 2**bits - 1                                      # the largest number with that many bits
    digits = max(1, -(-bits // 30))                      # ceiling of bits/30, at least one slot
    size = sys.getsizeof(n)
    print(f"{bits:>10} {digits:>6} {size:>9}  {size == header + 4 * digits}")
```

```output
bits_per_digit: 30 bits_per_digit: 4
```

![Staircase: a Python int is 28 bytes up to 30 bits, 32 bytes up to 60 bits, 36 up to 90, 40 up to 120 and 44 beyond; a C int64 stays at 8 bytes but wraps after 63 bits](diagrams/3.1-size-steps.svg "Size jumps by 4 bytes at every 30 bits. The red line is a fixed-width C integer.")

The absolute sizes assume a 64-bit build. The in-browser Python on this page is a 32-bit WebAssembly build with 4-byte pointers, so it prints sizes 12 bytes smaller (a 12-byte header); the last column still reads `True`. `sys.getsizeof` counts only the object itself (Python docs), which is the whole story for an int because it holds no references to other objects.

## Arithmetic, digit by digit

Addition is the school method: add digit pairs from the lowest, and when a sum reaches $2^{30}$, keep the low 30 bits and carry 1. It costs one pass over the digits. Multiplication is the school method too: every digit of $a$ times every digit of $b$, so $n \times m$ digit products.

![A 3 by 3 grid where cell (i, j) is a_i times b_j with weight 2 to the power 30(i+j); same-weight cells share a colour; counts 9, 36 and 900 products](diagrams/3.1-schoolbook.svg "Schoolbook multiplication. Doubling the digits quadruples the products.")

CPython's `k_mul` uses this method until both operands have more than `KARATSUBA_CUTOFF = 70` digits (a squaring uses a cutoff of 140). Above that it uses Karatsuba's divide-and-conquer trick, with fewer than $n^2$ products; the source comment cites Knuth, volume 2, section 4.3.3. A 70-digit number is at least $2^{2100}$, a 633-digit decimal number, so every number in this lesson multiplies the school way. Here are both operations rebuilt on digit lists, checked against Python's own `+` and `*`:

```python
import random

BASE = 2**30
MASK = BASE - 1

def to_digits(n):
    out = []
    while n:
        n, d = divmod(n, BASE)
        out.append(d)
    return out

def from_digits(ds):
    return sum(d << (30 * i) for i, d in enumerate(ds))

def add(a, b):
    """Schoolbook addition: one pass over the digits, carrying 0 or 1."""
    out, carry = [], 0
    for i in range(max(len(a), len(b))):
        s = (a[i] if i < len(a) else 0) + (b[i] if i < len(b) else 0) + carry
        out.append(s & MASK)         # low 30 bits stay in this slot
        carry = s >> 30              # the rest moves to the next slot
    if carry:
        out.append(carry)
    return out

def mul(a, b):
    """Schoolbook multiplication: every digit of a times every digit of b."""
    out, products = [0] * (len(a) + len(b)), 0
    for i, x in enumerate(a):
        carry = 0
        for j, y in enumerate(b):
            t = out[i + j] + x * y + carry          # never exceeds BASE**2 - 1
            out[i + j] = t & MASK
            carry = t >> 30
            products += 1
        out[i + len(b)] += carry
    while out and out[-1] == 0:
        out.pop()
    return out, products

random.seed(7)
ok_add = ok_mul = True
for _ in range(1000):
    x, y = random.getrandbits(random.randint(1, 400)), random.getrandbits(random.randint(1, 400))
    ok_add &= from_digits(add(to_digits(x), to_digits(y))) == x + y
    ok_mul &= from_digits(mul(to_digits(x), to_digits(y))[0]) == x * y
print("1000 random pairs, add matches:", ok_add, " mul matches:", ok_mul)

for bits in [90, 180, 900]:
    a = to_digits(2**(bits - 1))
    print(f"{bits:>4}-bit numbers: {len(a):>2} digits each -> {mul(a, a)[1]:>4} digit products")
print("worst case t:", (MASK) + MASK * MASK + MASK, "= BASE**2 - 1 =", BASE**2 - 1)
```

```output
1000 random pairs, add matches: True  mul matches: True
  90-bit numbers:  3 digits each -> 9 digit products
 180-bit numbers:  6 digits each -> 36 digit products
 900-bit numbers: 30 digits each -> 900 digit products
worst case t: 1152921504606846975 = BASE**2 - 1 = 1152921504606846975
```

The last line is the **carry bound**. Inner-loop sums `out[i+j] + x*y + carry` have three terms, each at most $B-1$, $(B-1)^2$ and $B-1$ with $B = 2^{30}$. Their total is at most $(B-1) + (B-1)^2 + (B-1) = B^2 - 1 < 2^{60}$, so it always fits in a 64-bit machine word, which CPython calls `twodigits`. That is what the header asks for: a `twodigits` type that holds every value up to $B^2 - 1$.

(`mul(a, a)` here counts the full $n^2$ products even for equal inputs; CPython's real squaring routine is smarter about it. In `mul(a, a)` above, `a` is the same list for both arguments, which is fine because we only read it.)

## Where fixed width comes back

Everything above is the Python `int`. NumPy and PyTorch use fixed-width types for speed (one machine instruction per element), so the wraparound is back. Factorials show it: $20!$ is the largest that fits in 64 bits.

```python
import math
import numpy as np

print(" n   Python n!                  NumPy int64 n!")
for n in [20, 21, 25]:
    exact = math.factorial(n)
    wrapped = np.prod(np.arange(1, n + 1, dtype=np.int64))
    print(f"{n:>2}   {exact:<26} {wrapped}")
print("largest int64:", np.iinfo(np.int64).max, "=", 2**63 - 1)
a = np.array([2**62, 2**62, 2**62], dtype=np.int64)
print("sum as int64 :", a.sum())
print("sum as int   :", sum(int(v) for v in a))
```

```output
 n   Python n!                  NumPy int64 n!
20   2432902008176640000        2432902008176640000
21   51090942171709440000       -4249290049419214848
25   15511210043330985984000000 7034535277573963776
largest int64: 9223372036854775807 = 9223372036854775807
sum as int64 : -4611686018427387904
sum as int   : 13835058055282163712
```

The array sum raised no warning at all. (NumPy 2.5.4 gives the same numbers for scalars, with a `RuntimeWarning` only for scalar arithmetic like `np.int64(2**63 - 1) + np.int64(1)`; PyTorch 2.15 also wraps: `torch.tensor([2**62]*3).sum()` returns `-4611686018427387904`. I checked both by running them.) To stay exact, convert to Python `int` before summing, use `dtype=object` (slow), or choose a wider type after checking bounds with `np.iinfo`. Switching to floating point loses exactness above $2^{53}$ (Lesson 3.2).

> [!KEY-INSIGHT]
> A Python `int` is a *variable-length array of digits with a header*, not a machine word. That one design choice gives unlimited range, the 28-byte minimum size, and the $O(n^2)$ cost of multiplying big numbers.

## Common traps

> [!TRAP]
> **Floor division rounds toward minus infinity.** `-7 // 2` is `-4`, not `-3`, and `%` takes the sign of the divisor: the language reference guarantees `x == (x//y)*y + (x%y)`. `int(-7 / 2)` truncates toward zero and gives `-3`.

```python
import sys

print(-7 // 2, -7 % 2, divmod(-7, 2), int(-7 / 2))
print("identity x == (x//y)*y + x%y:", -7 == (-7 // 2) * 2 + (-7 % 2))
try:
    str(10**5000)
except ValueError as e:
    print("ValueError:", e)
print("limit:", sys.get_int_max_str_digits(), "| hex works:", len(hex(10**5000)), "characters")
```

```output
-4 1 (-4, 1) -3
identity x == (x//y)*y + x%y: True
ValueError: Exceeds the limit (4300 digits) for integer string conversion; use sys.set_int_max_str_digits() to increase the limit
limit: 4300 | hex works: 4155 characters
```

> [!TRAP]
> **Huge ints refuse to become decimal strings.** The `str(10**5000)` line above shows the second trap: since Python 3.11 (and in later security releases of older versions), converting an int with more than 4300 digits to or from a decimal `str` raises `ValueError`. The limit protects against CVE 2020-10735 (a denial-of-service weakness: those conversions are slow for huge numbers). Hexadecimal, octal and binary conversions are exempt. `sys.set_int_max_str_digits` changes the limit.

> [!TRAP]
> **Do not compare ints with `is`.** Two equal ints may or may not be the same object; Lesson 3.5 shows when, and why you must use `==`.

## Summary

- A Python `int` is a header plus an array of 30-bit digits, least significant first; the sign and digit count live in a tag word. There is no overflow, only memory.
- Size is 24 + 4 × digits bytes on a 64-bit CPython 3.12 build, with at least one digit, so `0` already takes 28 bytes.
- Addition costs one pass over the digits; multiplication costs $n \times m$ digit products below 70 digits, then Karatsuba.
- NumPy and PyTorch integers are fixed-width and wrap silently. Python's `//` floors, and decimal conversion of huge ints is capped at 4300 digits by default.

### Question 1: Size by hand

How many digits does `2**200` have in CPython's representation, and what does `sys.getsizeof(2**200)` return on a 64-bit build?

<details><summary>Show Solution</summary>

`(2**200).bit_length()` is 201, and $\lceil 201/30 \rceil = 7$ digits. The size is $24 + 4 \times 7 = 52$ bytes. Check: `sys.getsizeof(2**200)` returns 52.

### Question 2: Predict the tag

What are `lv_tag` and the digit list of `-2**30`?

<details><summary>Show Solution</summary>

$2^{30}$ is the smallest number that needs two digits: $[0, 1]$, because $2^{30} = 0 + 1 \cdot 2^{30}$. The sign is stored in the tag, not in a digit, so the digits are the same as for $+2^{30}$. The tag is $2 \times 8 + 2 = 18$ (two digits, sign code 2 for negative). The run above shows tag 16 for $+2^{30}$ and the sign rule; I also checked `peek(-2**30)`, which returns `(18, [0, 1])`.

</details>

### Question 3: Spot the bug

A student counts the orderings of 30 distinct tokens and gets a negative number. Find the line to change.

```python
import numpy as np
orderings = np.prod(np.arange(1, 31, dtype=np.int64))   # 30!
```

<details><summary>Show Solution</summary>

$30! \approx 2.65 \times 10^{32}$ is far above $2^{63}-1 \approx 9.2 \times 10^{18}$, so `int64` wraps around. Use Python integers: `orderings = math.factorial(30)` (or `math.prod(range(1, 31))`), which returns the exact 265252859812191058636308480000000.

### Question 4: Count the work

CPython multiplies two different 1000-bit integers. How many 30-bit digit products does the schoolbook method need, and does Karatsuba apply?

<details><summary>Show Solution</summary>

Each number has $\lceil 1000/30 \rceil = 34$ digits, so $34 \times 34 = 1156$ digit products. Karatsuba applies only above 70 digits (about 2100 bits), so it does not.

## Exercise: subtraction with borrow

Write `sub(a, b)` for digit lists (least significant first) when $a \ge b$, borrowing 1 from the next digit when a digit difference is negative. Test it on 1000 random pairs.

<details><summary>Show Solution</summary>

A borrow is the mirror image of a carry: if `a[i] - b[i] - borrow` is negative, add $2^{30}$ to it and borrow 1 from the next digit.

```python
import random

BASE = 2**30

def to_digits(n):
    out = []
    while n:
        n, d = divmod(n, BASE)
        out.append(d)
    return out

def from_digits(ds):
    return sum(d << (30 * i) for i, d in enumerate(ds))

def sub(a, b):
    out, borrow = [], 0
    for i in range(len(a)):
        d = a[i] - (b[i] if i < len(b) else 0) - borrow
        borrow = 1 if d < 0 else 0
        out.append(d + BASE if d < 0 else d)
    while out and out[-1] == 0:          # drop leading zero digits (normalise)
        out.pop()
    return out

random.seed(3)
ok = True
for _ in range(1000):
    x = random.getrandbits(random.randint(1, 400))
    y = random.getrandbits(random.randint(1, 400))
    big, small = max(x, y), min(x, y)
    ok &= from_digits(sub(to_digits(big), to_digits(small))) == big - small
print("1000 random subtractions match:", ok)
```

```output
1000 random subtractions match: True
```

</details>
