By the end of this lesson you will be able to predict whether any built-in value counts as true in an `if`, explain why `True + True` equals `2`, and avoid the two traps that catch most beginners: writing `== True`, and expecting `or` to return a Boolean.

**You need:** `if` statements and function calls. Integers from Lesson 3.1 help with the `True == 1` part.

## The problem a condition solves

Every `if` needs a decision: run this block or not. Suppose a user leaves a name field blank and you want a default. You could write `len(name) > 0`, but Python also accepts the string itself:

```python
name = ""
if name:
    print("Hello,", name)
else:
    print("Hello, guest")
```

```output
Hello, guest
```

The condition `name` is not a Boolean. Python converts any object to a yes or no answer, and this lesson explains how. The same `if` works for strings, lists, numbers and `None`, so you can ask "is there anything here?" without writing a type-specific check. The cost is that you must know the rule. Two questions follow: what a Boolean is, and which values count as true.

## Booleans are integers

A Boolean (`bool`) has exactly two values, `True` and `False`. The type is not separate from numbers: `bool` is a subclass of `int`, a class that inherits from another class. The Python documentation says so directly, and PEP 285 (Python Enhancement Proposal 285, the proposal that added `bool`) made the same decision. Diagram 1 shows the chain, and the code confirms it.

![Class chain object, int, bool, with two calls bool(7) and bool(0) that return the shared objects True and False](diagrams/3.4-bool-is-int.svg "bool is a subclass of int. Every call that returns a Boolean returns one of two shared objects.")

```python
print(issubclass(bool, int))
print([c.__name__ for c in bool.__mro__])
print(True == 1, False == 0)
print(True + True, True * 3, sum([True, False, True]))
print(type(True).__name__, isinstance(True, int))
try:
    class MyBool(bool):
        pass
except TypeError as error:
    print("TypeError:", error)
```

```output
True
['bool', 'int', 'object']
True True
2 3 2
bool True
TypeError: type 'bool' is not an acceptable base type
```

The `__mro__` attribute lists the method resolution order (MRO), the sequence of classes Python searches for methods. Arithmetic works because `True` is an `int` with value 1. The last line shows that you cannot subclass `bool`; this output is from CPython (the standard Python implementation) 3.12.13.

There is only one `True` and one `False`. Every call that returns a Boolean returns one of these two objects:

```python
print(bool(5) is True, bool([]) is False)
print(bool(7) is bool(9))
print(id(True) == id(bool(3)))
```

```output
True True
True
True
```

`id()` returns an object's identity. Because the two Booleans are shared, `x is True` means exactly "x is the Boolean True". It is never true for the int `1`, and the section on `==` shows why that matters.

Because `bool` is an `int`, a list of flags can be counted with `sum`, and a Boolean can index a sequence. Both idioms work, but they are harder to read than the explicit forms, so use them only in short expressions:

```python
flags = [True, False, True, True]
print(sum(flags), flags.count(True))
print(["no", "yes"][True], "ab"[False])
```

```output
3 3
yes a
```

## The truth rule

When you write `if x:`, Python calls `bool(x)`. The Python Language Reference (the data model section, method `object.__bool__`) describes the rule. Python calls `__bool__()` if the class defines it, and that method should return `False` or `True`. If `__bool__` is not defined, Python calls `__len__()` and treats the object as true when the result is nonzero. If a class defines neither, every instance is true. Diagram 2 follows that order.

![Flowchart for bool(x): if x defines __bool__, return its result; otherwise if x defines __len__, return len(x) != 0; otherwise return True](diagrams/3.4-bool-protocol.svg "The order Python uses to decide truth. The first method found wins.")

```python
class Plain:
    pass

class LenZero:
    def __len__(self):
        return 0

class LenFive:
    def __len__(self):
        return 5

class BoolFalseLenFive:
    def __bool__(self):
        return False
    def __len__(self):
        return 5

class BoolReturnsInt:
    def __bool__(self):
        return 0

print("Plain:", bool(Plain()))
print("LenZero:", bool(LenZero()), "| LenFive:", bool(LenFive()))
print("BoolFalseLenFive:", bool(BoolFalseLenFive()))
try:
    bool(BoolReturnsInt())
except TypeError as error:
    print("TypeError:", error)
```

```output
Plain: True
LenZero: False | LenFive: True
BoolFalseLenFive: False
TypeError: __bool__ should return bool, returned int
```

`BoolFalseLenFive` shows that `__bool__` takes precedence over `__len__`. `BoolReturnsInt` shows that the "should return a Boolean" rule is enforced: returning `0` raises `TypeError`. The rule is evaluated each time the condition runs, so a class whose `__len__` changes at runtime changes its truth value at runtime.

## Which values are false

The Python documentation lists the built-in false values. They are `None`, `False`, the zero of every numeric type (`0`, `0.0`, `0j`, `Decimal(0)`, `Fraction(0, 1)`), and the empty sequences and collections (`''`, `()`, `[]`, `{}`, `set()`, `range(0)`). Almost everything else is true, including some values that look empty or zero to a reader, as diagram 3 shows.

![Fifteen blue boxes list the false built-in values; seven rose boxes list truthy values that look empty or zero, such as nan, the strings '0', a space and 'False', and a one-item list that holds 0](diagrams/3.4-truth-table.svg "Left: the false built-in values. Right: values that are true even though they look empty or zero.")

```python
from decimal import Decimal
from fractions import Fraction

falsy = [0, 0.0, -0.0, 0j, "", [], (), {}, set(), range(0), None, False,
         Decimal(0), Fraction(0), b""]
truthy = [float("nan"), "0", " ", "False", [0], [None], range(1)]

print(f"{sum(1 for v in falsy if not bool(v))} of {len(falsy)} built-in values are false")
print([bool(v) for v in truthy])
try:
    len(None)
except TypeError as error:
    print("TypeError:", error)
```

```output
15 of 15 built-in values are false
[True, True, True, True, True, True, True]
TypeError: object of type 'NoneType' has no len()
```

This is why idiomatic Python writes `if items:` rather than `if len(items) > 0:`. The two forms agree for lists, but only the first works for `None`, which has no length, as the last line of the block shows. Empty containers and zeros are false because they carry no content; the truthy values follow the same idea.

The truthy values share one rule: they are non-empty, or non-zero. `float("nan")` (not-a-number, the result of an undefined float operation) is non-zero, so it is true. `"0"` and `"False"` are non-empty strings. `[0]` and `[None]` are lists with one item.

Your own classes choose their truth value. Define `__bool__` for a domain rule, such as a money amount that is false when it is zero. Define `__len__` when the object is a collection. If both are defined, `__bool__` wins, as the `BoolFalseLenFive` example showed, so keep them consistent.

## and, or and not return operands

Trace `'' or 'guest'` by hand. The `or` operator evaluates its left side first, `''`. The empty string is false, so `or` cannot be decided by the left side and evaluates the right side, `'guest'`, and returns it. The result is a string, not `True`. Diagram 4 traces four expressions the same way.

![Four rows: '' or 'guest' gives 'guest'; 'Ada' or 'guest' gives 'Ada'; 0 and 'x' gives 0; not applied to an empty list gives True](diagrams/3.4-and-or.svg "and and or return one of their operands. not always returns a Boolean.")

```python
print(repr('' or 'guest'))
print(repr('Ada' or 'guest'))
print(repr(0 and 'x'))
print(repr([] or None))
print(repr(1 and 2 and 3))
print(repr(not []))
print(repr(not 'x'))
```

```output
'guest'
'Ada'
0
None
3
True
False
```

When you need a stored flag rather than a branch, use `not`: `is_empty = not items` gives `True` for `[]` and a real Boolean for any input. The idiom `value = user_input or 'guest'` relies on the operand rule. It is concise, but it treats every false value as missing, including a valid `0` or empty list. The traps section returns to that.

The Language Reference states the rule: `x or y` returns `x` if `x` is true, otherwise `y`; `x and y` returns `x` if `x` is false, otherwise `y`. The `not` operator always returns a Boolean. Because the right side is evaluated only when needed, the operators short-circuit. Here is a test that counts calls:

```python
calls = 0

def side_effect():
    global calls
    calls += 1
    return True

False and side_effect()
print("after False and f():", calls)
True or side_effect()
print("after True or f():", calls)
True and side_effect()
print("after True and f():", calls)
```

```output
after False and f(): 0
after True or f(): 0
after True and f(): 1
```

`side_effect` ran only in the third line, because the left side of `and` was true and the left side of `or` was true. The first two lines never reached the right side.

## == True is not a truth test

`x == True` asks whether `x` equals the number 1. A truth test asks whether `bool(x)` is true. These are different questions. Diagram 5 shows five values where they disagree.

![Table with rows 0, 1, 2, -1, 0.5, 'a' and a one-item list that holds 1; columns bool(x), x == True and x is True; five rows where x == True is False although bool(x) is True are highlighted](diagrams/3.4-eq-vs-truth.svg "x == True and bool(x) disagree for five of these seven values. Rose cells mark the disagreements.")

```python
probe = [0, 1, 2, -1, 0.5, "a", [1]]
for x in probe:
    print(x, "bool:", bool(x), "x == True:", x == True, "x is True:", x is True)
```

```output
0 bool: False x == True: False x is True: False
1 bool: True x == True: True x is True: False
2 bool: True x == True: False x is True: False
-1 bool: True x == True: False x is True: False
0.5 bool: True x == True: False x is True: False
a bool: True x == True: False x is True: False
[1] bool: True x == True: False x is True: False
```

When you read code, treat `if x == True:` as a suspect line unless `x` is known to be a Boolean. The value `1` equals `True` because `True` is the integer 1. But `2` is true and does not equal `True`. Use `if x:` for a truth test, and `if x is None:` when you mean "no value". `None` is a single object, so `is None` tests identity; `== None` can be overridden by a class that defines `__eq__`, the method behind `==`.

<details><summary>Run locally: needs pip install numpy</summary>

NumPy arrays do not use a single truth value when they hold more than one element. This is checked with NumPy 2.5.5.

```python
import numpy as np

print(bool(np.array([0])), bool(np.array([3])))
try:
    bool(np.array([1, 2]))
except ValueError:
    print("ValueError: two-element array")
try:
    bool(np.array([]))
except ValueError:
    print("ValueError: empty array")
```

```output
False True
ValueError: two-element array
ValueError: empty array
```

## Common traps

> [!TRAP]
> `if x == True:` rejects `2`, `-1` and `"a"`, even though `if x:` accepts them. Write `if x:`.

> [!TRAP]
> `count = count or 10` replaces a valid `count` of `0` with `10`. Test for `None` when zero is a real value: `count = 10 if count is None else count`.

> [!TRAP]
> `bool("False")` and `bool("0")` are both `True`. Parse text to a number or a Boolean explicitly; truth testing does not do it.

> [!TRAP]
> `float("nan")` is true. If `if value:` is the only check, a NaN passes. Test with `math.isnan(value)` where NaN can occur.

> [!TRAP]
> A NumPy array with more than one element raises `ValueError` in `if arr:`. Use `arr.any()` or `arr.all()`.

## Summary

- `bool` is a subclass of `int`: `True` is 1, `False` is 0, and `True + True` is 2. There is one shared `True` and one shared `False`.
- `if x:` calls `bool(x)`: it uses `__bool__` if defined, otherwise `__len__`, otherwise the object is true. `__bool__` must return a Boolean.
- Fifteen built-in values are false: the zeros, the empty containers, `None` and `False`. Almost everything else is true.
- `and` and `or` return one of their operands and short-circuit; `not` always returns a Boolean.
- `x == True` and truth testing disagree for values such as `2`. Use `if x:`.

## Quiz time

### Question 1: Predict the output

```python
print(repr(0 or "" or [] or "end"))
print(repr(0 and "end"))
```

<details><summary>Show Solution</summary>

The output is `'end'` and then `0`. Each `or` skips the false operands until it reaches `"end"`. The `and` stops at the first false operand, `0`, and returns it.

</details>

### Question 2: Find the bug

```python
def has_items(items):
    if items == True:
        return "yes"
    return "no"

print(has_items([1]), has_items(3))
```

<details><summary>Show Solution</summary>

The output is `no no`. `[1] == True` and `3 == True` are both `False`, so the function never returns `"yes"`. The fix is a truth test: `if items:`. An empty list then gives `"no"`, and a non-empty list gives `"yes"`.

</details>

### Question 3: Calculate

What do `bool(float("nan"))`, `bool("0.0")`, `bool(range(0))` and `bool(-0.0)` return?

<details><summary>Show Solution</summary>

They return `True`, `True`, `False` and `False`. NaN is non-zero, and `"0.0"` is a non-empty string. `range(0)` is an empty sequence, and `-0.0` is a zero of a numeric type.

</details>

### Question 4: Explain

Why is `1 is True` false, even though `1 == True` is true?

<details><summary>Show Solution</summary>

`is` tests identity, meaning whether two names refer to the same object. The literal `1` is an `int` object, and `True` is the single shared `bool` object. They are equal in value but are different objects.

</details>
