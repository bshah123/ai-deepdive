# 4.5 — collections.deque vs List for FIFO Queues

## Opening Motivation & Context

In the realm of data structures, the First-In-First-Out (FIFO) queue is a fundamental concept. It's used in a variety of applications, from task scheduling to breadth-first search algorithms. Python provides two primary ways to implement FIFO queues: using the built-in `list` and the `collections.deque` class. Understanding the differences between these two implementations is crucial for writing efficient and scalable code, especially in performance-critical applications.

## Core Concepts Breakdown

### FIFO Queues

A FIFO queue is a data structure that follows the principle of the first element added being the first one to be removed. This is in contrast to a Last-In-First-Out (LIFO) stack, where the last element added is the first one to be removed.

### Lists as FIFO Queues

Python's built-in `list` can be used to implement a FIFO queue. Elements are added to the end of the list using the `append()` method, and elements are removed from the beginning of the list using the `pop(0)` method. However, this approach has a time complexity of O(n) for the `pop(0)` operation because all the remaining elements in the list need to be shifted one position to the left.

> [!WARNING]
> Using a list as a FIFO queue can lead to performance issues, especially when dealing with large datasets, due to the O(n) time complexity of the `pop(0)` operation.

### collections.deque as FIFO Queues

The `collections.deque` class is a double-ended queue that provides O(1) time complexity for append and pop operations from both ends. This makes it an ideal choice for implementing FIFO queues. The `deque` class provides the `append()` method to add elements to the end of the queue and the `popleft()` method to remove elements from the beginning of the queue.

> [!KEY-INSIGHT]
> The `collections.deque` class is optimized for fast appends and pops from both ends, making it the preferred choice for implementing FIFO queues in Python.

> [!BEST-PRACTICE]
> Use `collections.deque` for implementing FIFO queues in Python to ensure optimal performance, especially when dealing with large datasets.

## Code Demonstration & Runtime Output

```python
from collections import deque
import time

def list_fifo_queue(n: int) -> float:
    """Implement a FIFO queue using a list and measure the time taken."""
    queue = []
    start_time = time.time()
    for i in range(n):
        queue.append(i)
    while queue:
        queue.pop(0)
    end_time = time.time()
    return end_time - start_time

def deque_fifo_queue(n: int) -> float:
    """Implement a FIFO queue using a deque and measure the time taken."""
    queue = deque()
    start_time = time.time()
    for i in range(n):
        queue.append(i)
    while queue:
        queue.popleft()
    end_time = time.time()
    return end_time - start_time

if __name__ == "__main__":
    n = 100000
    list_time = list_fifo_queue(n)
    deque_time = deque_fifo_queue(n)
    print(f"Time taken by list FIFO queue: {list_time:.6f} seconds")
    print(f"Time taken by deque FIFO queue: {deque_time:.6f} seconds")
```


### Question #3: Find and fix the bug in the following code:

```python
from collections import deque

queue = deque([1, 2, 3])
queue.append(4)
queue.pop()
print(queue)
```

<details><summary>Show Solution</summary>

The bug in the code is that it uses the `pop()` method to remove the last element from the deque, which is not the intended behavior for a FIFO queue. The `pop()` method should be replaced with the `popleft()` method to remove the first element from the deque.

Here is the fixed code:

```python
from collections import deque

queue = deque([1, 2, 3])
queue.append(4)
queue.popleft()
print(queue)
```

The fixed code outputs `deque([2, 3, 4])`. The `append(4)` operation adds the element `4` to the end of the deque, and the `popleft()` operation removes the first element `1` from the deque.

</details>
