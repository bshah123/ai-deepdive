By the end of this lesson you will be able to pack several values into one tuple, split a tuple back into names, use a starred name to catch the leftovers, and read a `match` statement that matches tuples by shape. Every output below comes from running the code.

**You need:** Lesson 5.1 (what a tuple is) and the idea that a name is a label that points at an object.

## The problem: a function returns one object

A Python function returns exactly one object. If it needs to give back a quotient and a remainder, it has to put both in one container. A tuple is that container, and the step of putting values in is called **packing**. The reverse step, giving each value its own name, is **unpacking**.

Python does both with commas. There is no special syntax for packing: the comma builds the tuple.

## Packing: the comma makes the tuple

![Two values 10 and 20 are packed into one tuple object, which the name t refers to; unpacking x, y = t gives x 10 and y 20](diagrams/5.2-pack-unpack.svg "Packing collects values into one object. Unpacking spreads the object back out.")

Parentheses are optional. The parentheses around `(5)` are only grouping, so `(5)` is an integer. Add a comma and it becomes a tuple.

```python
t = 10, 20
print(t, type(t).__name__)
print(type((5)).__name__, type((5,)).__name__)
print(divmod(17, 5))
```

```output
(10, 20) tuple
int tuple
(3, 2)
```

`divmod(17, 5)` is the built-in that returns the quotient and remainder of a division. The result is a tuple, because 17 = 3 × 5 + 2.

## Unpacking: one object, many names

Unpacking assigns each element of an iterable to a name, from left to right. An **iterable** is anything Python can loop over, such as a list, a string or a dictionary. The count on the left must match the number of elements on the right.

```python
t = 10, 20
x, y = t
print(x, y)

a, b = "hi"
print(a, b)

k1, k2 = {"alpha": 1, "beta": 2}
print(k1, k2)

try:
    p, q = (1, 2, 3)
except ValueError as e:
    print("ValueError:", e)
```

```output
10 20
h i
alpha beta
ValueError: too many values to unpack (expected 2)
```

Two details follow from this. A string unpacks one character at a time. A dictionary unpacks to its keys, not its values, because looping over a dictionary yields keys.

Unpacking also works inside a `for` loop header and can be nested. This is the most common place to see it, for example when `enumerate` gives you an index and a tuple at once:

```python
pairs = [("ada", 91), ("alan", 78)]
for i, (name, score) in enumerate(pairs):
    print(i, name, score)

(a, b), c = (1, 2), 3
print(a, b, c)
```

```output
0 ada 91
1 alan 78
1 2 3
```

The parentheses around `name, score` are optional; they only make the nesting visible. Each nested level still has to match the length of the data it unpacks, and a mismatch raises the same `ValueError` as before.

## Swapping two names

The assignment `a, b = b, a` swaps two values without a third variable. The right side is evaluated first, giving the two current values; then each value is stored into its name. The compiler does not build a tuple for this statement.

On CPython 3.12, the reference implementation of Python, the disassembler shows that the swap does not build a tuple. Each instruction is one step of the bytecode, the low-level form that the interpreter runs. A temporary-variable swap takes six instructions; the tuple swap takes four.

![Bytecode of a temp-variable swap (six instructions, three loads and three stores) and a tuple swap (four instructions, no tuple built)](diagrams/5.2-swap-bytecode.svg "Instruction counts for the two swap styles on CPython 3.12. The tuple swap is shorter because the compiler stores the values directly.")

<details><summary>Run locally: CPython 3.12 disassembly (needs no install; the opcode names change between Python versions)</summary>

```python
import dis

def temp_swap(a, b):
    tmp = a
    a = b
    b = tmp

def tuple_swap(a, b):
    a, b = b, a

def unpack_stmt(t):
    x, y = t

for f in (temp_swap, tuple_swap, unpack_stmt):
    ops = [i.opname for i in dis.get_instructions(f) if i.opname not in ("RESUME", "RETURN_CONST", "LOAD_CONST")]
    print(f.__name__, len(ops), ops)
```

```output
temp_swap 6 ['LOAD_FAST', 'STORE_FAST', 'LOAD_FAST', 'STORE_FAST', 'LOAD_FAST', 'STORE_FAST']
tuple_swap 4 ['LOAD_FAST', 'LOAD_FAST', 'STORE_FAST', 'STORE_FAST']
unpack_stmt 4 ['LOAD_FAST', 'UNPACK_SEQUENCE', 'STORE_FAST', 'STORE_FAST']
```

</details>

The third line shows where unpacking happens in the bytecode: one `UNPACK_SEQUENCE` instruction splits the tuple. The swap has no such instruction; its two stores are emitted directly.

## Star unpacking: catch the leftovers

Putting one name before a comma-separated target with a star (`*middle`) collects all the elements the other names do not take. This is defined in PEP 3132, Extended Iterable Unpacking, which was added in Python 3.0 (the PEP, Python Enhancement Proposal, is the design document for a language change).

Work through `first, *middle, last = range(6)` by hand. The values are 0 to 5. `first` takes the element at index 0. `last` takes the last element, 5. The starred name takes what is left in the middle, which is 1, 2, 3 and 4.

![first, *middle, last = range(6): first is 0, middle is the list [1, 2, 3, 4], last is 5](diagrams/5.2-star-split.svg "The starred name always receives a list, never a tuple.")

```python
first, *middle, last = range(6)
print(first, middle, last, type(middle).__name__)

head, *rest = [7]
print(head, rest)

a, b = 1, 2
a, b = b, a
print(a, b)
```

```output
0 [1, 2, 3, 4] 5 list
7 []
2 1
```

The starred name gets a list even when there is only one element left, and it gets an empty list when nothing is left. If you need a tuple, convert it with `tuple(middle)`.

## Pattern matching: match by shape

Python 3.10 added the `match` statement (PEP 634, Structural Pattern Matching). A `case` line gives a pattern. A **sequence pattern** such as `(x, 0)` matches any sequence (except a string) whose length is 2 and whose second element is 0. A bare name such as `x` in a pattern is a **capture**: it always matches and binds the value to that name.

The cases are tried from top to bottom. The first one that matches runs, and the rest are skipped.

```python
def describe(p):
    match p:
        case (0, 0):
            return "origin"
        case (x, 0):
            return f"x-axis at {x}"
        case (0, y):
            return f"y-axis at {y}"
        case (x, y):
            return f"point ({x}, {y})"
        case _:
            return "not a point"

for p in [(0, 0), (5, 0), (0, 5), (10, 20), [3, 0], "ab", (1, 2, 3), 7]:
    print(repr(p), "->", describe(p))
```

```output
(0, 0) -> origin
(5, 0) -> x-axis at 5
(0, 5) -> y-axis at 5
(10, 20) -> point (10, 20)
[3, 0] -> x-axis at 3
'ab' -> not a point
(1, 2, 3) -> not a point
7 -> not a point
```

Three things to notice. A list matches a sequence pattern just as a tuple does. The string `"ab"` does not match, because the language reference excludes `str`, `bytes` and `bytearray` from sequence patterns. The final `case _` is a wildcard that matches anything and binds nothing.

![Two case orders for the same input. With the literal (0, 0) first, input (5, 0) reaches the x-axis case. With the sequence (x, y) first, input (0, 0) stops at (x, y), so the origin case is never reached.](diagrams/5.2-match-order.svg "Order decides which case runs. Put the most specific patterns first.")

A `case` can also have a guard, an `if` condition that runs only after the pattern matches:

```python
def sign(p):
    match p:
        case (x, y) if x == y:
            return "diagonal"
        case (x, y):
            return "off-diagonal"

print(sign((3, 3)), sign((3, 4)))
```

```output
diagonal off-diagonal
```

## Common traps

> [!TRAP]
> A single value in parentheses is not a tuple. `(5)` is an integer and `(5,)` is a one-element tuple. Forgetting the comma is an easy packing bug to make.

> [!TRAP]
> Unpacking count must match exactly, unless you use a star. `p, q = (1, 2, 3)` raises `ValueError: too many values to unpack (expected 2)`. With a star, the rule becomes "at least": `p, *q, r = [1]` raises `not enough values to unpack (expected at least 2, got 1)`.

> [!TRAP]
> A bare name in a `case` is a capture, not a comparison. To compare against a constant, use a dotted name such as `Color.RED`. In the example below, `Color.RED` matches the value 1, and the bare name `name` captures everything else.

```python
class Color:
    RED = 1

def trap(p):
    match p:
        case Color.RED:
            return "dotted value matched"
        case name:
            return f"capture bound {name!r}"

print(trap(1), "|", trap(5))
```

```output
dotted value matched | capture bound 5
```

> [!TRAP]
> A capture makes later cases unreachable, and Python checks for this only in some cases. A bare name followed by another case is a `SyntaxError`, a compile-time error. A sequence pattern followed by a literal is not an error, so the literal case silently never runs.

```python
def order(p):
    match p:
        case (x, y):
            return "generic"
        case (0, 0):
            return "origin"

print(order((0, 0)))
```

```output
generic
```

The `origin` case is dead code, and the compiler reports nothing. Put the literal `(0, 0)` first, as in the earlier `describe` example.

> [!TRAP]
> The starred name is always a list, never a tuple. After `first, *rest = (1, 2, 3)`, `type(rest).__name__` is `list`. Convert it with `tuple(rest)` if your code needs a tuple.

## Summary

- The comma builds a tuple; parentheses are only grouping, except for the empty tuple `()`.
- Unpacking takes any iterable and assigns elements left to right; the count must match.
- A starred name collects the leftover elements as a list, and it may be empty.
- `match` tries `case` blocks top to bottom and runs the first one that matches.
- A bare name in a `case` captures; use a dotted name to compare against a constant.

What does this print?

```python
print(type((7)).__name__, type((7,)).__name__)
```

It prints `int tuple`. The parentheses around `7` are grouping only. The trailing comma in `(7,)` is what makes it a one-element tuple.

### Question 2: Find the bug

```python
pair = (1, 2)
a, b, c = pair
```

<details><summary>Show Solution</summary>

The tuple has two elements and the left side has three names. Python raises `ValueError: not enough values to unpack (expected 3, got 2)`. Fix it by naming two targets, or by adding a third element to the tuple.

</details>

### Question 3: Explain the result

Why does `head, *rest = (1, 2, 3)` give `rest` a list, and how would you get a tuple?

<details><summary>Show Solution</summary>

The language reference says the starred target always receives a list of the remaining items, possibly empty (PEP 3132 gives the same rule). To get a tuple, write `rest = tuple(rest)` after unpacking.

</details>

### Question 4: Predict the case

```python
def f(p):
    match p:
        case (x, y):
            return "pair"
        case (0, 0):
            return "origin"

print(f((0, 0)))
```

<details><summary>Show Solution</summary>

It prints `pair`. The sequence pattern `(x, y)` matches `(0, 0)` first, and the first match wins. The `origin` case never runs. Swap the two cases to fix it.

</details>

## References

- PEP 3132, Extended Iterable Unpacking. https://peps.python.org/pep-3132/ Opened. Confirms the starred target always receives a list. Target version: Python 3.0.
- PEP 634, Structural Pattern Matching: Specification. https://peps.python.org/pep-0634/ Opened. Confirms the match semantics, that capture patterns are irrefutable (always succeed), and that `str`, `bytes` and `bytearray` do not match sequence patterns. Target version: Python 3.10.
- Python Language Reference, Assignment statements. https://docs.python.org/3/reference/simple_stmts.html#assignment-statements Opened. Gives the rule for iterable unpacking and the starred target. It does not name the exception; the `ValueError` messages in this lesson were observed by running CPython 3.12.
- Python Language Reference, The match statement. https://docs.python.org/3/reference/compound_stmts.html#the-match-statement Opened. Describes top-to-bottom case selection, guards, and dotted names for value patterns.
