# 5.3 — namedtuple vs typing.NamedTuple vs dataclass

## Opening Motivation & Context

In Python, there are several ways to create lightweight, immutable data structures. Understanding the differences between `namedtuple`, `typing.NamedTuple`, and `dataclass` is crucial for writing efficient and maintainable code. Each of these constructs serves a specific purpose and has its own strengths and weaknesses.

- `namedtuple` is part of the `collections` module and provides a simple way to create tuple subclasses with named fields.
- `typing.NamedTuple` is a more modern and type-annotated version of `namedtuple`, introduced in Python 3.6.
- `dataclass` is a decorator introduced in Python 3.7 that automatically generates special methods like `__init__`, `__repr__`, and `__eq__` for classes.

Understanding these differences will help you choose the right tool for the job, whether you need a simple immutable data structure or a more complex one with additional functionality.

## Core Concepts Breakdown

### namedtuple

`namedtuple` is a factory function for creating tuple subclasses with named fields. It is part of the `collections` module and is a simple way to create lightweight, immutable data structures.

> [!KEY-INSIGHT]
> `namedtuple` is immutable, meaning once created, its fields cannot be modified. This makes it a good choice for representing data that should not change.

> [!BEST-PRACTICE]
> Use `namedtuple` when you need a simple, immutable data structure with named fields. It is particularly useful for representing records or data points.

> [!WARNING]
> `namedtuple` does not support type hints. If you need type hints, consider using `typing.NamedTuple` instead.

### typing.NamedTuple

`typing.NamedTuple` is a more modern and type-annotated version of `namedtuple`. It was introduced in Python 3.6 and provides type hints for the fields of the named tuple.

> [!KEY-INSIGHT]
> `typing.NamedTuple` is immutable, just like `namedtuple`. It also provides type hints, which can help catch type-related bugs at compile time.

> [!BEST-PRACTICE]
> Use `typing.NamedTuple` when you need a simple, immutable data structure with named fields and type hints. It is a good choice for representing records or data points with type safety.

> [!WARNING]
> `typing.NamedTuple` is more verbose than `namedtuple` and requires type hints. If you do not need type hints, consider using `namedtuple` instead.

### dataclass

`dataclass` is a decorator introduced in Python 3.7 that automatically generates special methods like `__init__`, `__repr__`, and `__eq__` for classes. It is a more flexible and powerful alternative to `namedtuple` and `typing.NamedTuple`.

> [!KEY-INSIGHT]
> `dataclass` is mutable by default, but you can make it immutable by setting `frozen=True`. It provides a lot of flexibility in terms of customization and can be used to create complex data structures.

> [!BEST-PRACTICE]
> Use `dataclass` when you need a more flexible and powerful data structure with customizable behavior. It is a good choice for representing complex data structures with additional functionality.

> [!WARNING]
> `dataclass` is more verbose than `namedtuple` and `typing.NamedTuple`. If you need a simple, immutable data structure, consider using `namedtuple` or `typing.NamedTuple` instead.

## Code Demonstration & Runtime Output

```python
from collections import namedtuple
from typing import NamedTuple
from dataclasses import dataclass

# Using namedtuple
Point = namedtuple('Point', ['x', 'y'])
p1 = Point(1, 2)
print(f"namedtuple: {p1}, x={p1.x}, y={p1.y}")

# Using typing.NamedTuple
class PointNT(NamedTuple):
    x: int
    y: int

p2 = PointNT(3, 4)
print(f"typing.NamedTuple: {p2}, x={p2.x}, y={p2.y}")

# Using dataclass
@dataclass
class PointDC:
    x: int
    y: int

p3 = PointDC(5, 6)
print(f"dataclass: {p3}, x={p3.x}, y={p3.y}")

# Using frozen dataclass
@dataclass(frozen=True)
class PointFrozenDC:
    x: int
    y: int

p4 = PointFrozenDC(7, 8)
print(f"frozen dataclass: {p4}, x={p4.x}, y={p4.y}")

if __name__ == "__main__":
    # Demonstrate immutability
    try:
        p1.x = 10
    except AttributeError as e:
        print(f"namedtuple is immutable: {e}")

    try:
        p2.x = 10
    except AttributeError as e:
        print(f"typing.NamedTuple is immutable: {e}")

    try:
        p3.x = 10
    except AttributeError as e:
        print(f"dataclass is mutable by default: {e}")

    try:
        p4.x = 10
    except AttributeError as e:
        print(f"frozen dataclass is immutable: {e}")
```

1. **Imports**: We import `namedtuple` from the `collections` module, `NamedTuple` from the `typing` module, and `dataclass` from the `dataclasses` module.
2. **namedtuple**: We create a `Point` namedtuple with fields `x` and `y`. We then create an instance `p1` of `Point` with values `1` and `2`.
3. **typing.NamedTuple**: We define a `PointNT` class using `typing.NamedTuple` with fields `x` and `y` and type hints. We then create an instance `p2` of `PointNT` with values `3` and `4`.
4. **dataclass**: We define a `PointDC` class using the `dataclass` decorator with fields `x` and `y` and type hints. We then create an instance `p3` of `PointDC` with values `5` and `6`.
5. **frozen dataclass**: We define a `PointFrozenDC` class using the `dataclass` decorator with `frozen=True` to make it immutable. We then create an instance `p4` of `PointFrozenDC` with values `7` and `8`.
6. **Immutability Demonstration**: We attempt to modify the fields of each instance and catch the resulting `AttributeError` to demonstrate immutability.

> [!ADVANCED]
> Under the hood, `namedtuple` and `typing.NamedTuple` are implemented using tuples, which are immutable sequences in Python. The `dataclass` decorator generates special methods for the class, including `__init__`, `__repr__`, and `__eq__`, which are used to create instances and compare them. The `frozen` parameter in the `dataclass` decorator ensures that the generated class is immutable by raising an `AttributeError` when an attempt is made to modify an instance.

## Summary & Key Takeaways

- `namedtuple` is a simple way to create lightweight, immutable data structures with named fields.
- `typing.NamedTuple` is a more modern and type-annotated version of `namedtuple` that provides type hints.
- `dataclass` is a more flexible and powerful alternative to `namedtuple` and `typing.NamedTuple` that can be used to create complex data structures with additional functionality.
- `namedtuple` and `typing.NamedTuple` are immutable, while `dataclass` is mutable by default but can be made immutable using the `frozen` parameter.

### Question #3: Find and fix the bug

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Point:
    x: int
    y: int

p = Point(1, 2)
p.x = 10
```

<details><summary>Show Solution</summary>

The bug in the code is that it attempts to modify the `x` field of the `Point` instance `p`, which is frozen and therefore immutable. To fix the bug, you should create a new instance of `Point` with the desired values instead of attempting to modify the existing instance.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Point:
    x: int
    y: int

p = Point(1, 2)
p = Point(10, p.y)
```

</details>
