# 6.1 — Hash Table Foundations & __hash__

## Opening Motivation & Context

Hash tables are fundamental data structures in computer science, providing average-case O(1) time complexity for insertions, deletions, and lookups. They are the backbone of dictionaries in Python and are widely used in databases, caches, and other applications where fast data retrieval is crucial. Understanding hash tables and the `__hash__` method is essential for writing efficient and correct Python code, especially in performance-critical applications.

## Core Concepts Breakdown

### Hash Tables

A hash table is a data structure that implements an associative array, a structure that can map keys to values. It uses a hash function to compute an index into an array of buckets or slots, from which the desired value can be found.

> [!KEY-INSIGHT]
> The efficiency of a hash table depends on the quality of the hash function and the handling of collisions. A good hash function distributes keys uniformly across the hash table, minimizing collisions.

> [!BEST-PRACTICE]
> Always use immutable types as dictionary keys. Mutable types like lists or dictionaries cannot be used as keys because their hash values can change, leading to inconsistencies.

> [!WARNING]
> Avoid using mutable objects as dictionary keys. This can lead to unexpected behavior and bugs.

### The `__hash__` Method

In Python, the `__hash__` method is used to compute the hash value of an object. This method is called by the built-in `hash()` function and is used by dictionaries and sets to store and retrieve values efficiently.

> [!KEY-INSIGHT]
> The `__hash__` method should return an integer that is the same for objects that compare equal. This means that if `a == b` is `True`, then `hash(a) == hash(b)` should also be `True`.

> [!BEST-PRACTICE]
> When implementing a custom class, ensure that the `__hash__` method is consistent with the `__eq__` method. If two objects are considered equal, they should have the same hash value.

> [!WARNING]
> If you override the `__eq__` method in a custom class, you should also override the `__hash__` method to maintain consistency.

## Code Demonstration & Runtime Output

```python
class Person:
    def __init__(self, name: str, age: int) -> None:
        self.name = name
        self.age = age

    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Person):
            return NotImplemented
        return self.name == other.name and self.age == other.age

    def __hash__(self) -> int:
        return hash((self.name, self.age))

    def __repr__(self) -> str:
        return f"Person(name={self.name!r}, age={self.age})"

if __name__ == "__main__":
    # Create some Person objects
    alice = Person("Alice", 30)
    bob = Person("Bob", 25)
    alice_twin = Person("Alice", 30)

    # Create a dictionary with Person objects as keys
    people = {
        alice: "Engineer",
        bob: "Doctor",
    }

    # Add a new entry
    people[alice_twin] = "Architect"

    # Print the dictionary
    print("People dictionary:")
    for person, profession in people.items():
        print(f"{person}: {profession}")

    # Check if Alice is in the dictionary
    print("\nIs Alice in the dictionary?", alice in people)
    print("Is Alice's twin in the dictionary?", alice_twin in people)

    # Check hash values
    print("\nHash values:")
    print(f"Alice: {hash(alice)}")
    print(f"Bob: {hash(bob)}")
    print(f"Alice's twin: {hash(alice_twin)}")
```

Output:
```

Person(name='Bob', age=25): Doctor

Is Alice in the dictionary? True
Is Alice's twin in the dictionary? True

Hash values:

```

### How this works (Line-by-Line Breakdown)

1. **Class Definition**: The `Person` class is defined with `name` and `age` attributes.
2. **`__eq__` Method**: The `__eq__` method is overridden to compare `Person` objects based on their `name` and `age` attributes.
3. **`__hash__` Method**: The `__hash__` method is overridden to compute the hash value of a `Person` object based on its `name` and `age` attributes. This ensures that objects that compare equal have the same hash value.
4. **`__repr__` Method**: The `__repr__` method is overridden to provide a string representation of the `Person` object.
5. **Main Block**: The `if __name__ == "__main__":` block ensures that the code is executed only when the script is run directly.
6. **Object Creation**: `Person` objects `alice`, `bob`, and `alice_twin` are created.
7. **Dictionary Creation**: A dictionary `people` is created with `Person` objects as keys and their professions as values.
8. **Dictionary Update**: The dictionary is updated with a new entry for `alice_twin`.
9. **Dictionary Printing**: The dictionary is printed to show the entries.
10. **Membership Check**: The `in` operator is used to check if `alice` and `alice_twin` are in the dictionary.
11. **Hash Value Check**: The hash values of `alice`, `bob`, and `alice_twin` are printed to show that equal objects have the same hash value.

> [!ADVANCED]
> In CPython, the hash value of an object is computed using the `PyObject_Hash` function, which calls the `__hash__` method of the object. The hash value is stored in the object's `ob_hash` field, which is used by the dictionary and set implementations to store and retrieve values efficiently.

> [!QA]
> Q: When should I prefer a dictionary over a list?
> A: You should prefer a dictionary over a list when you need to store and retrieve values based on a key, especially when the keys are not integers or when the order of elements is not important. Dictionaries provide average-case O(1) time complexity for insertions, deletions, and lookups, making them more efficient than lists for these operations.

## Summary & Key Takeaways

- Hash tables are data structures that provide average-case O(1) time complexity for insertions, deletions, and lookups.
- The `__hash__` method is used to compute the hash value of an object, which is used by dictionaries and sets to store and retrieve values efficiently.
- When implementing a custom class, ensure that the `__hash__` method is consistent with the `__eq__` method.
- Avoid using mutable objects as dictionary keys.
- Use dictionaries when you need to store and retrieve values based on a key.
