In this lesson you will predict which object each parameter of a function refers to, for any mix of positional, keyword and unpacked arguments. You will also see what `*args` and `**kwargs` build at the moment of the call, and why a mutable default value leaks between calls.

**You need:** the idea of a variable as a name bound to an object (Lesson 2.1, What Is a Variable in Python?) and the `def` syntax.

## The problem: one call, several binding rules

A function with a fixed list of parameters is easy to call. Real helpers are less tidy: a logging function takes any number of values plus optional settings, and a wrapper forwards whatever its caller passed. Python has one set of rules that decides where each value in a call goes. When you misread those rules, they fail in one of two ways: loudly, with a `TypeError` raised before your code runs, or silently, with a list that keeps growing between calls.

The greeting function below accepts anything. The call has two positional values and two keyword values, but the function does not name them in advance, so Python must collect them somewhere.

```python
def greet(*args, **kwargs):
    """Greet with any number of positional and keyword arguments."""
    if args:
        print(f"Hello, {' '.join(args)}!")
    else:
        print("Hello, stranger!")
    if kwargs:
        print("Additional information:")
        for key, value in kwargs.items():
            print(f"{key}: {value}")

greet("John", "Doe", age=30, occupation="Software Engineer")
greet()
greet("Alice", city="New York")
```

```output
Hello, John Doe!
Additional information:
age: 30
occupation: Software Engineer
Hello, stranger!
Hello, Alice!
Additional information:
city: New York
```

## Intuition: a parameter is a name for the caller's object

Python does not copy arguments. When you call `f(a)`, the parameter inside `f` is bound to the same object that `a` names. The Python Programming FAQ describes this as arguments being "passed by assignment": assignment creates references to objects, so there is no alias between the caller's variable and the callee's parameter (Python FAQ, see References). Two consequences follow. Rebinding a parameter to a new object does not affect the caller. Mutating the object the parameter refers to does affect the caller, because both names point at one object.

![Three panels: names a and x both point to one list holding 1; after x is rebound to a new list holding 99, a still points to the old list; after x.append(99), both names see the one list, now holding 1 and 99](diagrams/7.2-reference-binding.svg "Rebinding a parameter versus mutating the object it refers to.")

```python
a = [1]

def rebind(x):
    x = [99]          # rebinds the local name x only

def mutate(x):
    x.append(99)      # changes the one object that both x and a name

rebind(a)
print("after rebind:", a)
mutate(a)
print("after mutate:", a)

def bump(n):
    n += 1            # ints are immutable, so this makes a new int
    return n

m = 5
print("bump inside:", bump(m), "outside:", m)
```

```output
after rebind: [1]
after mutate: [1, 99]
bump inside: 6 outside: 5
```

Integers are immutable: `n += 1` creates a new integer and rebinds the local name, so the caller's `m` is unchanged. A list has `append`, which changes the object in place. This difference between rebinding and mutation is the root of the default-argument trap later in the lesson.

## Binding a call to a signature

The signature is the list of parameters in the `def` line. CPython (the reference implementation of Python, written in C) binds each call to the signature in a fixed sequence, which the Python Language Reference (section 6.3.4, Calls) describes:

1. Positional values fill the positional parameters from left to right.
2. Leftover positional values go into a `*args` parameter, as a tuple. The tuple is empty if nothing is left over.
3. Each keyword argument fills the parameter with the same name. If no parameter has that name, it goes into a `**kwargs` parameter as a dict key. If there is no `**kwargs`, the call raises `TypeError`.
4. A parameter that is still empty takes its default. If it has no default, the call raises `TypeError`.

Parameters that appear after `*args` are keyword-only: they can be filled only by name, never by position. This is why the extra positional values go to `args` and not to `c`.

Trace the call `f(1, 2, 3, 4, c=5, z=9)` against `def f(a, b, *args, c, d=4, **kwargs)`. The values 1 and 2 fill `a` and `b`. The values 3 and 4 are left over, so `args` becomes `(3, 4)`. The keyword `c=5` fills `c`. The keyword `z=9` matches no parameter, so `kwargs` becomes `{'z': 9}`. Parameter `d` received nothing and takes its default, 4.

![Six call-site arguments aligned with six parameters: 1 to a, 2 to b, 3 and 4 to args, c=5 to c, nothing to d (default 4), z=9 to kwargs](diagrams/7.2-binding.svg "Each argument lands in exactly one parameter.")

```python
import inspect

def f(a, b, *args, c, d=4, **kwargs):
    return {"a": a, "b": b, "args": args, "c": c, "d": d, "kwargs": kwargs}

print(inspect.signature(f))
print(f(1, 2, 3, 4, c=5, z=9))

for call in [lambda: f(1, 2), lambda: f(1, 2, a=0)]:
    try:
        call()
    except TypeError as e:
        print("TypeError:", e)
```

```output
(a, b, *args, c, d=4, **kwargs)
{'a': 1, 'b': 2, 'args': (3, 4), 'c': 5, 'd': 4, 'kwargs': {'z': 9}}
TypeError: f() missing 1 required keyword-only argument: 'c'
TypeError: f() got multiple values for argument 'a'
```

The two errors are the two failure modes of the rules. In the first, the keyword-only `c` is required and nothing filled it. In the second, `a` was filled twice: once by position and once by name.

## `*args` and `**kwargs` are new containers on every call

`args` is always a tuple and `kwargs` is always a dict, even when empty (Language Reference, section 6.3.4). Keyword arguments keep the order the caller wrote them in; PEP 468 made this guarantee from Python 3.6 onward.

```python
def collect(*args, **kwargs):
    return args, kwargs

print(collect())
kw = {"x": 1}
inner = [1]
args, kwargs = collect(*[inner], **kw)
print("kwargs is kw:", kwargs is kw)
print("args[0] is inner:", args[0] is inner)
print("kwarg order:", list(collect(z=1, a=2, m=3)[1]))
```

```output
((), {})
kwargs is kw: False
args[0] is inner: True
kwarg order: ['z', 'a', 'm']
```

The dict is new: changing `kwargs` inside the function does not change the caller's `kw`. The copy is shallow, though. `args[0] is inner` is True, so the containers are new but the elements they hold are the same objects.

## Unpacking at the call site

A `*` or `**` in a call expands an iterable or a mapping into arguments. CPython 3.12 compiles a call without unpacking to one `CALL` instruction, and a call with unpacking to a different instruction, `CALL_FUNCTION_EX`. The `dis` module (the bytecode disassembler) lets you check this:

```python
import dis

def call_ops(src):
    code = compile(src, "<call>", "exec")
    return [i.opname for i in dis.get_instructions(code) if i.opname.startswith("CALL")]

print("g(1, 2, c=3):", call_ops("g(1, 2, c=3)"))
print("g(*t):", call_ops("g(*t)"))
print("g(**d):", call_ops("g(**d)"))
```

```output
g(1, 2, c=3): ['CALL']
g(*t): ['CALL_FUNCTION_EX']
g(**d): ['CALL_FUNCTION_EX']
```

The opcode names are a snapshot of CPython 3.12; later versions may change them. The stable point is that unpacking takes a more general path. The `*` argument must be an iterable, and the `**` argument must be a mapping whose keys are strings (Language Reference, section 6.3.4).

## Positional-only and keyword-only parameters

Two markers in a signature restrict how values may be passed. A `/` makes every parameter to its left positional-only: a caller cannot pass it by name. This lets an author rename the parameter later without breaking callers who use the name. PEP 570 added the syntax in Python 3.8. A bare `*` makes every parameter to its right keyword-only, as with `c` and `d` above. The kinds must appear in the fixed order shown below.

![Seven signature tokens in a row: a (positional-only), / (separator), b (positional or keyword), *args (rest as tuple), c (keyword-only), d=4 (keyword-only), **kwargs (rest as dict)](diagrams/7.2-parameter-order.svg "Parameter kinds must appear in one fixed order.")

```python
def p(a, /, b, *, c):
    return (a, b, c)

print(p(1, b=2, c=3))
for call in [lambda: p(a=1, b=2, c=3), lambda: p(1, 2, 3, c=0)]:
    try:
        call()
    except TypeError as e:
        print("TypeError:", e)
```

```output
(1, 2, 3)
TypeError: p() got some positional-only arguments passed as keyword arguments: 'a'
TypeError: p() takes 2 positional arguments but 3 positional arguments (and 1 keyword-only argument) were given
```

The exception type is `TypeError`. The wording shown is CPython 3.12's.

## The trap: mutable default arguments

A default value is evaluated once, when the `def` statement runs, not on each call. The Python Tutorial (section 4.7.1) gives this as an "important warning": when the default is a mutable object, every call that omits the argument shares the same object. The tutorial's own example accumulates values across calls, and so does ours.

![Left: one shared list holding 1, 2 and 3 is the default, and three calls each return it. Right: a default of None creates a new list per call, one holding only 1, one only 2 and one only 3](diagrams/7.2-mutable-default.svg "A mutable default is one object for every call; a None default creates a new one.")

```python
def append_bad(item, bucket=[]):
    bucket.append(item)
    return bucket

for i in (1, 2, 3):
    print("bad:", append_bad(i))
print("default now holds:", append_bad.__defaults__[0])

def append_ok(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket

for i in (1, 2, 3):
    print("fixed:", append_ok(i))
```

```output
bad: [1]
bad: [1, 2]
bad: [1, 2, 3]
default now holds: [1, 2, 3]
fixed: [1]
fixed: [2]
fixed: [3]
```

The shared list lives on the function object, in `append_bad.__defaults__`, so you can inspect it. The fix from the tutorial uses `None` as a marker and creates the list inside the function. Each call then gets a new list.

## Common traps

> [!TRAP]
> Rebinding is not mutation. `x = [99]` inside a function leaves the caller's list alone, while `x.append(99)` changes it for everyone who holds the object.

> [!TRAP]
> Mutable defaults are shared. `def f(x, bucket=[])` keeps one list for every call that omits `bucket`. Use `None` as the default and create the object inside the function.

> [!TRAP]
> Iterating a dict yields keys. `for key, value in kwargs:` unpacks each key string, not each pair, and fails on the first key. Use `kwargs.items()`.

> [!TRAP]
> A name can be filled only once. `f(1, 2, a=0)` fails because `a` was already filled by position. Keyword unpacking follows the same rule.

> [!TRAP]
> `**` keys must be strings, as the Language Reference states. Build the mapping you unpack with string keys.

## Summary

- Arguments are passed by assignment: a parameter names the caller's object. Rebinding the name leaves the caller unchanged; mutating the object does not.
- A call binds in a fixed order: positional values fill parameters left to right, extra positional values go to `*args` as a tuple, keyword values match by name or go to `**kwargs` as a dict.
- Each call builds new `args` and `kwargs` containers, but their elements are shared with the caller.
- Keyword-only parameters after `*`, and positional-only parameters before `/`, restrict how values can be passed.
- A mutable default is created once, when the `def` runs, and shared by every call that omits the argument.

## Quiz time

### Question 1: Calculation

Given `def h(x, y=10, *rest, flag=False, **opts):`, what does `h(1, 2, 3, flag=True, color="red")` bind to each name?

<details><summary>Show Solution</summary>

`x = 1` and `y = 2`, the first two positional values. The leftover `3` goes into `rest`, so `rest = (3,)`. `flag=True` fills the keyword-only `flag`. `color="red"` matches no parameter, so `opts = {'color': 'red'}`.

</details>

### Question 2: Prediction

What does this print?

```python
def add_item(item, box=[]):
    box.append(item)
    return len(box)

print(add_item("a"), add_item("b"))
```

<details><summary>Show Solution</summary>

It prints `1 2`. Both calls use the same default list. The first call appends `"a"` and returns length 1. The second appends `"b"` to the same list and returns length 2. Arguments to `print` are evaluated left to right.

```output
1 2
```

</details>

### Question 3: Bug-spotting

Why does this raise an error, and how do you fix it?

```python
def print_kwargs(**kwargs):
    for key, value in kwargs:
        print(f"{key}: {value}")

print_kwargs(name="John", age=30, occupation="Software Engineer")
```

<details><summary>Show Solution</summary>

Iterating a dict yields its keys, not its (key, value) pairs. The first key, `"name"`, is a four-character string, so unpacking it into two names fails. The run gives `ValueError: too many values to unpack (expected 2)`. Use `kwargs.items()`:

```python
def print_kwargs(**kwargs):
    for key, value in kwargs.items():
        print(f"{key}: {value}")

print_kwargs(name="John", age=30, occupation="Software Engineer")
```

```output
name: John
age: 30
occupation: Software Engineer
```

</details>

### Question 4: Explanation

After `f(**d)` is called, the function sets `kwargs["x"] = 5`. Does the caller's dict `d` change? Why?

<details><summary>Show Solution</summary>

No. The call `f(**d)` builds a new dict for `kwargs`, as the experiment above showed with `kwargs is kw` being False. The function changes only its own dict. Only mutation of the same object would change `d`, and the call passes a fresh one.

</details>
