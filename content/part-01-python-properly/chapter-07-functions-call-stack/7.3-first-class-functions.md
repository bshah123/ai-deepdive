# 7.3 — First-Class Functions, Lambdas & Higher-Order Functions

## Opening Motivation & Context

First-class functions, lambdas, and higher-order functions are fundamental concepts in Python that enable powerful functional programming paradigms. These features allow functions to be treated as any other object, passed as arguments, returned from other functions, and assigned to variables. This capability is crucial for writing concise, expressive, and reusable code, especially in domains like data processing, AI, and scientific computing.

## Core Concepts Breakdown

### First-Class Functions

First-class functions are functions that can be treated like any other object. This means they can be assigned to variables, passed as arguments to other functions, and returned from functions.

> [!KEY-INSIGHT]
> Functions in Python are first-class objects, meaning they can be manipulated like any other object.

> [!BEST-PRACTICE]
> Use first-class functions to create higher-order functions, which can abstract and reuse common patterns in your code.

> [!WARNING]
> Be cautious when using first-class functions, as they can lead to complex and hard-to-debug code if overused.

### Lambdas

Lambdas are anonymous functions defined using the `lambda` keyword. They are typically used for short, simple operations where a full function definition would be overkill.

> [!KEY-INSIGHT]
> Lambdas are a concise way to create small, anonymous functions.

> [!BEST-PRACTICE]
> Use lambdas for simple operations, such as sorting or filtering, to keep your code concise and readable.

> [!WARNING]
> Avoid using lambdas for complex operations, as they can make your code harder to read and maintain.

### Higher-Order Functions

Higher-order functions are functions that take other functions as arguments or return functions as their result. They are a powerful tool for abstracting and reusing common patterns in your code.

> [!KEY-INSIGHT]
> Higher-order functions enable functional programming paradigms in Python.

> [!BEST-PRACTICE]
> Use higher-order functions to create reusable abstractions and simplify your code.

> [!WARNING]
> Be cautious when using higher-order functions, as they can lead to complex and hard-to-debug code if overused.

## Code Demonstration & Runtime Output

```python
from typing import Callable, List

def apply_operation(x: int, y: int, operation: Callable[[int, int], int]) -> int:
    """Apply a given operation to two integers."""
    return operation(x, y)

def add(a: int, b: int) -> int:
    """Add two integers."""
    return a + b

def subtract(a: int, b: int) -> int:
    """Subtract two integers."""
    return a - b

def multiply(a: int, b: int) -> int:
    """Multiply two integers."""
    return a * b

def divide(a: int, b: int) -> int:
    """Divide two integers."""
    if b == 0:
        raise ValueError("Cannot divide by zero")
    return a // b

def create_multiplier(multiplier: int) -> Callable[[int], int]:
    """Create a multiplier function."""
    def multiplier_function(x: int) -> int:
        return x * multiplier
    return multiplier_function

def main() -> None:
    # First-class functions
    operations = [add, subtract, multiply, divide]
    for operation in operations:
        print(f"Result of {operation.__name__}: {apply_operation(5, 3, operation)}")

    # Lambdas
    square = lambda x: x * x
    print(f"Square of 5: {square(5)}")

    # Higher-order functions
    double = create_multiplier(2)
    triple = create_multiplier(3)
    print(f"Double of 5: {double(5)}")
    print(f"Triple of 5: {triple(5)}")

    # Using lambdas with higher-order functions
    numbers = [1, 2, 3, 4, 5]
    squared_numbers = list(map(lambda x: x * x, numbers))
    print(f"Squared numbers: {squared_numbers}")

    even_numbers = list(filter(lambda x: x % 2 == 0, numbers))
    print(f"Even numbers: {even_numbers}")

if __name__ == "__main__":
    main()
```


### How this works (Line-by-Line Breakdown)

1. **Imports**: We import the `Callable` and `List` types from the `typing` module to provide type hints for our functions.
2. **`apply_operation` function**: This function takes two integers and a function as arguments. It applies the given operation to the two integers and returns the result.
3. **`add`, `subtract`, `multiply`, and `divide` functions**: These are simple arithmetic functions that take two integers and return the result of the corresponding operation.
4. **`create_multiplier` function**: This function takes an integer as an argument and returns a new function that multiplies its argument by the given integer.
5. **`main` function**: This function demonstrates the use of first-class functions, lambdas, and higher-order functions.
   - **First-class functions**: We create a list of operations and apply each operation to the integers 5 and 3 using the `apply_operation` function.
   - **Lambdas**: We define a lambda function to square a number and apply it to the integer 5.
   - **Higher-order functions**: We create two multiplier functions using the `create_multiplier` function and apply them to the integer 5.
   - **Using lambdas with higher-order functions**: We use the `map` and `filter` functions with lambda functions to square and filter even numbers from a list of integers.

> [!ADVANCED]
> First-class functions in Python are implemented using function objects, which are instances of the `function` type. These objects contain the function's code, global namespace, default arguments, and other attributes. When a function is called, Python creates a new frame on the call stack to hold the function's local variables and other information. The frame is then pushed onto the call stack, and the function's code is executed. When the function returns, its frame is popped from the call stack, and control returns to the caller.

> [!QA]
> Q: When should I prefer lambdas over named functions?
> A: Lambdas are best suited for simple, one-off operations where a full function definition would be overkill. For more complex operations or functions that need to be reused, it's better to define a named function.

### Question #3: Find and fix the bug

```python
from typing import Callable

def apply_operation(x: int, y: int, operation: Callable[[int, int], int]) -> int:
    return operation(x, y)

def divide(a: int, b: int) -> int:
    return a / b

def main() -> None:
    result = apply_operation(5, 0, divide)
    print(f"Result: {result}")

if __name__ == "__main__":
    main()
```

<details><summary>Show Solution</summary>

The bug in the code is that it attempts to divide by zero, which raises a `ZeroDivisionError`. To fix this, we should add a check to ensure that the divisor is not zero.

```python
from typing import Callable

def apply_operation(x: int, y: int, operation: Callable[[int, int], int]) -> int:
    return operation(x, y)

def divide(a: int, b: int) -> int:
    if b == 0:
        raise ValueError("Cannot divide by zero")
    return a / b

def main() -> None:
    try:
        result = apply_operation(5, 0, divide)
        print(f"Result: {result}")
    except ValueError as e:
        print(f"Error: {e}")

if __name__ == "__main__":
    main()
```

</details>
