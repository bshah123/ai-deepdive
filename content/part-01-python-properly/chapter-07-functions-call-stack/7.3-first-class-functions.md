In Python a function is a value: you can store it in a variable, pass it to another function, return it, or create one inline with `lambda`. In this lesson you will use those moves, check each claim against counts measured on CPython 3.12, and avoid the late-binding trap that makes a loop of lambdas return the same value.

**You need:** function definitions and calls (Lessons 7.1 and 7.2), and the idea that a name is a label that points to an object.

## The problem this solves

Suppose a list of records must be sorted by price on one run and by name on another. Without first-class functions you write one sorting routine per rule. With them, you write one `sorted` and hand it the rule as a value: `sorted(records, key=rule)`.

## A function is an object

A `def` statement creates an object of type `function`. The name `square` is only a label on that object, so a second label can point to the same object.

![Two names, square and alias, point to one function object whose __name__ is square; a lambda creates another function object whose __name__ is <lambda>](diagrams/7.3-function-object.svg "A function is an object. Names are labels; a lambda is an object without a name.")

Measured on CPython 3.12.13: `type(square).__name__` is `function`, `square.__name__` is `square`, `alias = square` makes `alias is square` equal to `True`, and `square(5)` returns 25. Calling a function value uses the same call mechanism as calling a named function. Lesson 7.1 covers the frame that the call creates.

## Lambdas are single expressions

`lambda x: x * x` builds a function object whose body is one expression, and whose value is returned. The Python Language Reference says a lambda "yields a function object" and that such functions "cannot contain statements" (see References). A body with an `if` statement is rejected by the parser: `lambda x: if x > 0: 1` raises `SyntaxError: invalid syntax`.

Lambdas have no name in the source, so Python reports them as `<lambda>`. The measured `__name__` is `<lambda>`, and a traceback shows the same. Under the hood, a `def` and a `lambda` with the same body compile to identical bytecode on this version: the five instructions are `RESUME`, `LOAD_FAST`, `LOAD_FAST`, `BINARY_OP` and `RETURN_VALUE`. That identity is a CPython detail we measured, not a language guarantee. The documented rule is the single-expression body.

Use a lambda for one expression that is passed once, such as a `key=` argument. Use `def` when the rule needs a name in logs, several lines, or a docstring.

## Higher-order functions

A higher-order function takes a function as an argument or returns one. Python's built-ins are mostly of this kind: `map`, `filter`, `sorted(key=...)` and `functools.reduce`. The main program at the end of this lesson uses `map` and `sorted`.

The `key` argument of `sorted` is called once per element. The Python Sorting HOWTO says the key function "is called exactly once for each input record". Sorting `[5, 2, 9, 1, 7, 3, 8, 6]` called the key 8 times and made 15 comparisons with `<`. The comparison count belongs to this input and this CPython version; the key count is set by the element count, not by the input order.

![Two bars: 8 key function calls against 15 comparisons while sorting 8 values](diagrams/7.3-sort-key-calls.svg "The key runs once per element. Comparisons are a separate cost.")

## Closures: a returned function keeps its variable

A closure is an inner function that uses a variable from an enclosing scope. When the enclosing function returns, Python keeps that variable alive in a cell object, referenced from the inner function's `__closure__` attribute.

Take `make_multiplier(2)`. The returned function reads `multiplier`, which is a free variable. Measured: `double.__code__.co_freevars` is `('multiplier',)`, the cell holds `2`, and `double(5)` returns 10. The factory's frame has been popped, but the cell survives.

![A function object named multiplier_function points to a cell that holds multiplier = 2; the label double points to the function object](diagrams/7.3-closure.svg "A closure carries its captured variable in a cell.")

## map and filter are lazy iterators

`map(function, iterable)` "returns an iterator that applies function to every item of iterable" (Built-in Functions, see References). Nothing runs until you consume it. `filter` is documented as equivalent to a generator expression, so it is also single-pass.

Measured: right after `map` is created, the function has been called 0 times. Consuming the iterator once with `list` calls it 5 times and returns `[1, 4, 9, 16, 25]`. A second `list` over the same iterator returns `[]` and makes no further calls. A list comprehension, `[x * x for x in data]`, returns the same values with 0 function calls and creates a reusable list. If you need the results twice, wrap the `map` in `list(...)` once and keep the list.

![A list of five numbers feeds a map object; pass 1 returns the squares and 5 calls; pass 2 returns an empty list with still 5 calls](diagrams/7.3-map-once.svg "map returns an iterator. Consume it once.")

## Late binding: the loop trap

A lambda reads its free variables when it is called, not when it is defined. Build three lambdas in a loop and every one reads the same `i`, which is 2 when the loop ends. Measured: `[f() for f in [lambda: i for i in range(3)]]` gives `[2, 2, 2]`.

The body reads whatever object the name is bound to when it runs, which is the same rule as for any function. Two fixes give `[0, 1, 2]`. A default argument, `lambda i=i: i`, is evaluated when the lambda is created, so each one keeps its own copy. A factory function, `(lambda i: (lambda: i))(i)`, creates a new scope per iteration. The Python FAQ gives the same default-argument fix (see References).

![Left: three lambdas share one cell i = 2 and output [2, 2, 2]. Right: each lambda has its own default i and outputs [0, 1, 2]](diagrams/7.3-late-binding.svg "Late binding: the lambda reads the variable when it runs, not when it was defined.")

## Worked example, then the full program

Trace `apply_operation(5, 3, add)` by hand. Inside, `operation` is the object `add`, so `operation(x, y)` is `add(5, 3)`, which is 8. The same code works for `subtract` and `multiply` with no change. Only the object passed in differs.

The last line of the program applies `sorted` with `key=lambda r: r[1]`. The key of each record is its price: 3, 1 and 2. `sorted` orders the records by those keys, giving `fig` (1), `apple` (2) and `pear` (3). The records themselves are not changed; `sorted` returns a new list.

The program below runs alone in the browser (standard library only) and combines all the ideas above. Its output is the real output on CPython 3.12.

```python
from typing import Callable

def apply_operation(x: int, y: int, operation: Callable[[int, int], int]) -> int:
    return operation(x, y)

def add(a: int, b: int) -> int:
    return a + b

def subtract(a: int, b: int) -> int:
    return a - b

def multiply(a: int, b: int) -> int:
    return a * b

def make_multiplier(factor: int) -> Callable[[int], int]:
    def multiply_by(x: int) -> int:
        return x * factor
    return multiply_by

def main() -> None:
    ops = {"+": add, "-": subtract, "*": multiply}
    for symbol, op in ops.items():
        print(f"5 {symbol} 3 = {apply_operation(5, 3, op)}")

    print("add.__name__ =", add.__name__)
    print("lambda name  =", (lambda x: x).__name__)

    double = make_multiplier(2)
    print("double(5) =", double(5))
    print("cell holds:", double.__closure__[0].cell_contents)

    squares = map(lambda x: x * x, [1, 2, 3, 4, 5])
    print("pass 1:", list(squares))
    print("pass 2:", list(squares))

    records = [("pear", 3), ("fig", 1), ("apple", 2)]
    print("by price:", sorted(records, key=lambda r: r[1]))

if __name__ == "__main__":
    main()
```

```output
5 + 3 = 8
5 - 3 = 2
5 * 3 = 15
add.__name__ = add
lambda name  = <lambda>
double(5) = 10
cell holds: 2
pass 1: [1, 4, 9, 16, 25]
pass 2: []
by price: [('fig', 1), ('apple', 2), ('pear', 3)]
```

> [!KEY-INSIGHT]
> Passing a function and passing data are the same operation to Python. The parameter `operation` is a name bound to an object, and the call `operation(x, y)` does not care which object it is.

## Common traps

> [!TRAP]
> **Late binding in loops.** `[lambda: i for i in range(3)]` returns three lambdas that all read the final `i`. Use a default argument (`lambda i=i: i`) or a factory function.

> [!TRAP]
> **map and filter run once.** Reusing a `map` or `filter` object gives an empty result the second time. Wrap it in `list(...)` if you need it twice.

> [!TRAP]
> **Passing a call instead of a function.** `sorted(xs, key=length(x))` calls `length` immediately and passes its result to `sorted`. Pass the function itself, `key=length`, or a lambda that wraps the call.

> [!TRAP]
> **Lambdas are anonymous and single-expression.** A traceback shows `<lambda>`, and a lambda cannot contain statements or assignments. If you need a name in logs or more than one line, write a `def`.

## Summary

- A function is an object of type `function`. Names are labels, so two names can point to one object.
- A lambda is a function with one expression as its body. Its `__name__` is `<lambda>`.
- Higher-order functions take or return functions. `sorted` calls its key once per element; comparisons are counted separately.
- A closure keeps its captured variable in a cell, so `double(5)` still works after `make_multiplier` returns.
- `map` and `filter` return single-pass iterators. Late binding makes a loop of lambdas share one variable.

## Quiz time

### Question 1: Prediction (late binding)

What does this print?

```python
fs = [lambda: i for i in range(3)]
print([f() for f in fs])
```

<details><summary>Show Solution</summary>

It prints `[2, 2, 2]`. Each lambda reads `i` when it is called, and by then the loop has finished with `i = 2`. Use `[lambda i=i: i for i in range(3)]` to get `[0, 1, 2]`.

</details>

### Question 2: Bug-spotting (iterator exhaustion)

What does this print, and what is the bug?

```python
names = ["ada", "bo", "cy"]
upper = map(str.upper, names)
print(list(upper), list(upper))
```

<details><summary>Show Solution</summary>

It prints `['ADA', 'BO', 'CY'] []`. The first `list` consumes the map object, so the second sees nothing. The fix is `upper = list(map(str.upper, names))`, which stores the results once.

</details>

### Question 3: Calculation (key calls)

A call `sorted(values, key=f)` is made on a list of 8 values. How many times is `f` called? How many times is `<` used? Which of the two numbers depends on the order of the input?

<details><summary>Show Solution</summary>

`f` is called 8 times, once per element. For the list `[5, 2, 9, 1, 7, 3, 8, 6]` the sort made 15 comparisons. The comparison count depends on the input order and the Python version, while the key count does not.

</details>

### Question 4: Calculation (reduce)

What does this print?

```python
from functools import reduce
print(reduce(lambda a, b: a * b, range(1, 5)))
```

<details><summary>Show Solution</summary>

It prints `24`. `reduce` combines the items pairwise from the left: `((1 * 2) * 3) * 4 = 24`. The initial value is the first item, because no third argument is given.

</details>

### Question 5: Explanation (closure)

Why does `double = make_multiplier(2)` still give `double(5) == 10` after `make_multiplier` has returned?

<details><summary>Show Solution</summary>

`multiplier` is a free variable of the inner function. Python stores it in a cell object, and the inner function keeps a reference to that cell through `__closure__`. The cell lives as long as the inner function does, so the value 2 is still available after the factory's frame is gone.

</details>
