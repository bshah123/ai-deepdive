# 8.1 — LEGB Scope & PyCellObject Internals

## Opening Motivation & Context

Understanding scope and closures is fundamental to writing maintainable and efficient Python code. The LEGB rule (Local, Enclosing, Global, Built-in) defines the order in which Python searches for variable names. Closures, on the other hand, allow functions to remember the values of variables from their enclosing scope even after the enclosing function has finished executing. This lesson will delve into the internals of these concepts, including the `PyCellObject` structure in CPython, which is crucial for understanding how closures work under the hood.

## Core Concepts Breakdown

### LEGB Scope

The LEGB rule defines the order in which Python searches for variable names:

1. **Local (L)**: Variables defined within the current function.
2. **Enclosing (E)**: Variables defined in the enclosing function's scope (for nested functions).
3. **Global (G)**: Variables defined at the module level.
4. **Built-in (B)**: Variables built into Python (e.g., `print`, `len`).

> [!KEY-INSIGHT]
> Understanding the LEGB rule helps in predicting where Python will look for a variable, which is essential for debugging and writing efficient code.

> [!BEST-PRACTICE]
> Use descriptive variable names and avoid shadowing built-in names to prevent confusion and bugs.

### Closures

A closure is a function object that remembers values in the enclosing scope even if they are not present in memory. Closures are created when a nested function references a value from its enclosing scope.

> [!KEY-INSIGHT]
> Closures are a powerful feature that allows for data encapsulation and function factories.

> [!WARNING]
> Be cautious with closures in loops, as they can lead to unexpected behavior if not handled properly.

### PyCellObject Internals

In CPython, closures are implemented using the `PyCellObject` structure. This structure holds a reference to a variable in the enclosing scope, allowing the nested function to access it even after the enclosing function has finished executing.

> [!ADVANCED]
> The `PyCellObject` structure is defined in the CPython source code as follows:
> ```c
> typedef struct {
>     PyObject_HEAD
>     PyObject *ob_ref;  /* The object contained in the cell */
> } PyCellObject;
> ```
> The `ob_ref` field holds a reference to the variable in the enclosing scope.

## Code Demonstration & Runtime Output

```python
def outer_function(text: str) -> callable:
    def inner_function() -> None:
        print(text)
    return inner_function

closure = outer_function("Hello, World!")
closure()

def make_multiplier(factor: int) -> callable:
    def multiplier(x: int) -> int:
        return x * factor
    return multiplier

double = make_multiplier(2)
print(double(5))

def create_counter() -> callable:
    count = 0
    def counter() -> int:
        nonlocal count
        count += 1
        return count
    return counter

counter = create_counter()
print(counter())
print(counter())

def outer() -> None:
    x = "local"
    def inner() -> None:
        nonlocal x
        x = "nonlocal"
        print("inner:", x)
    inner()
    print("outer:", x)

outer()
```

Output:
```
Hello, World!
10
1
2
inner: nonlocal
outer: nonlocal
```

## How this works (Line-by-Line Breakdown)

1. **Line 1-3**: The `outer_function` defines a nested function `inner_function` that prints the `text` variable from its enclosing scope.
2. **Line 4**: The `outer_function` returns the `inner_function`, creating a closure.
3. **Line 6**: The `closure` variable holds the `inner_function` returned by `outer_function`.
4. **Line 7**: Calling `closure()` prints "Hello, World!", demonstrating that the `inner_function` remembers the `text` variable from its enclosing scope.
5. **Line 9-11**: The `make_multiplier` function creates a closure that multiplies its input by a `factor`.
6. **Line 13**: The `double` variable holds the closure returned by `make_multiplier(2)`.
7. **Line 14**: Calling `double(5)` returns 10, demonstrating that the closure remembers the `factor` variable.
8. **Line 16-19**: The `create_counter` function creates a closure that increments and returns a `count` variable.
9. **Line 21-22**: The `counter` variable holds the closure returned by `create_counter`.
10. **Line 23-24**: Calling `counter()` twice prints 1 and 2, demonstrating that the closure maintains the state of the `count` variable.
11. **Line 26-33**: The `outer` function demonstrates the use of the `nonlocal` keyword to modify a variable in the enclosing scope.
12. **Line 35**: Calling `outer()` prints "inner: nonlocal" and "outer: nonlocal", demonstrating that the `nonlocal` keyword allows modifying variables in the enclosing scope.

## Summary & Key Takeaways

- The LEGB rule defines the order in which Python searches for variable names.
- Closures allow functions to remember values from their enclosing scope.
- The `PyCellObject` structure in CPython implements closures by holding references to variables in the enclosing scope.
- Use descriptive variable names and avoid shadowing built-in names to prevent confusion and bugs.
- Be cautious with closures in loops, as they can lead to unexpected behavior if not handled properly.

## Quiz time

### Question #1: Conceptual question

What is the output of the following code?

```python
def outer():
    x = "local"
    def inner():
        x = "inner"
        print("inner:", x)
    inner()
    print("outer:", x)

outer()
```

<details><summary>Show Solution</summary>

The output of the code is:
```
inner: inner
outer: local
```

Explanation: The `inner` function creates a new local variable `x` and does not modify the `x` variable in the enclosing scope. The `outer` function prints the value of `x` from its local scope, which remains unchanged.
</details>

### Question #2: What does this code output?

```python
def make_adder(addend: int) -> callable:
    def adder(x: int) -> int:
        return x + addend
    return adder

add_five = make_adder(5)
print(add_five(10))
```

<details><summary>Show Solution</summary>

The output of the code is:
```
15
```

Explanation: The `make_adder` function creates a closure that adds its input to the `addend` variable. The `add_five` variable holds the closure returned by `make_adder(5)`. Calling `add_five(10)` returns 15, demonstrating that the closure remembers the `addend` variable.
</details>

### Question #3: Find and fix the bug

```python
def create_counter() -> callable:
    count = 0
    def counter() -> int:
        count += 1
        return count
    return counter

counter = create_counter()
print(counter())
print(counter())
```

<details><summary>Show Solution</summary>

The bug in the code is that the `counter` function tries to modify the `count` variable without declaring it as `nonlocal`. To fix the bug, you need to add the `nonlocal` keyword before the `count` variable in the `counter` function.

Here is the fixed code:

```python
def create_counter() -> callable:
    count = 0
    def counter() -> int:
        nonlocal count
        count += 1
        return count
    return counter

counter = create_counter()
print(counter())
print(counter())
```

The output of the fixed code is:
```
1
2
```

Explanation: The `nonlocal` keyword allows the `counter` function to modify the `count` variable in the enclosing scope. Without the `nonlocal` keyword, the `counter` function would create a new local variable `count` and raise an `UnboundLocalError`.
</details>
