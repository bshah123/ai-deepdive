# 9.2 — Generators & The yield Keyword Internals

## Opening Motivation & Context

Generators are a powerful feature in Python that allow you to create iterators in a more memory-efficient and elegant way. They are particularly useful when dealing with large datasets or when you need to generate a sequence of values on-the-fly. The `yield` keyword is the key to creating generators, as it allows a function to produce a sequence of values over time, rather than computing them all at once and returning them in a list.

Understanding how generators work internally is crucial for writing efficient and effective Python code. It helps you leverage the full potential of Python's iterator protocol and makes you a more proficient programmer.

## Core Concepts Breakdown

Generators are a special kind of iterator, which means they implement the iterator protocol. The iterator protocol consists of two methods: `__iter__()` and `__next__()`. Generators automatically implement these methods, so you don't need to write them explicitly.

The `yield` keyword is used in a function to create a generator. When a function contains a `yield` statement, it becomes a generator function. When you call a generator function, it returns a generator object, which is an iterator.

> [!KEY-INSIGHT]
> Generators are lazy evaluators. They generate values on-the-fly and yield them one at a time, rather than storing all the values in memory at once. This makes them memory-efficient, especially when dealing with large datasets.

> [!BEST-PRACTICE]
> Use generators when you need to generate a sequence of values on-the-fly, especially when the sequence is large or infinite. Generators are also useful when you need to process data in a pipeline, as they allow you to chain multiple generators together.

> [!WARNING]
> Generators are single-use iterators. Once you have iterated over a generator, it is exhausted and cannot be reused. If you need to iterate over the same sequence multiple times, you should create a new generator each time.

## Code Demonstration & Runtime Output

```python
def count_up_to(max: int) -> int:
    """Generator function that yields numbers from 0 to max-1."""
    count = 0
    while count < max:
        yield count
        count += 1

if __name__ == "__main__":
    # Create a generator object
    counter = count_up_to(5)

    # Iterate over the generator
    for num in counter:
        print(num)

    # Try to iterate again (will not work)
    for num in counter:
        print(num)
```

Output:
```
0
1
2
3
4
```

### How this works (Line-by-Line Breakdown)

1. `def count_up_to(max: int) -> int:`: This line defines a generator function named `count_up_to` that takes an integer `max` as an argument and returns an integer.
2. `"""Generator function that yields numbers from 0 to max-1."""`: This is a docstring that describes what the function does.
3. `count = 0`: This line initializes a variable `count` to 0.
4. `while count < max:`: This line starts a while loop that continues as long as `count` is less than `max`.
5. `yield count`: This line yields the current value of `count` and pauses the function's execution. The next time the generator is iterated over, the function will resume execution from this point.
6. `count += 1`: This line increments the value of `count` by 1.
7. `if __name__ == "__main__":`: This line checks if the script is being run directly (as opposed to being imported as a module).
8. `counter = count_up_to(5)`: This line calls the `count_up_to` function with an argument of 5 and assigns the resulting generator object to the variable `counter`.
9. `for num in counter:`: This line starts a for loop that iterates over the generator object `counter`.
10. `print(num)`: This line prints the current value of `num`.
11. `for num in counter:`: This line starts another for loop that iterates over the generator object `counter`.
12. `print(num)`: This line prints the current value of `num`.

> [!ADVANCED]
> When a generator function is called, it returns a generator object. The generator object is an iterator that implements the iterator protocol. The `__iter__` method of the generator object returns the generator object itself, and the `__next__` method of the generator object calls the generator function until it encounters a `yield` statement. The value yielded by the generator function is then returned by the `__next__` method. If the generator function raises a `StopIteration` exception, the `__next__` method raises a `StopIteration` exception.

> [!QA]
> Q: When should I prefer generators over lists?
> A: You should prefer generators over lists when you need to generate a sequence of values on-the-fly, especially when the sequence is large or infinite. Generators are memory-efficient because they generate values on-the-fly and yield them one at a time, rather than storing all the values in memory at once. Lists, on the other hand, store all the values in memory, which can be inefficient for large sequences.

### Question #3: Find and fix the bug

```python
def count_up_to(max: int) -> int:
    """Generator function that yields numbers from 0 to max-1."""
    count = 0
    while count <= max:
        yield count
        count += 1

if __name__ == "__main__":
    counter = count_up_to(5)
    for num in counter:
        print(num)
```

<details><summary>Show Solution</summary>

The bug in the code is in the while loop condition. The condition `while count <= max:` will cause the loop to continue even when `count` is equal to `max`, which will result in an infinite loop. To fix the bug, change the condition to `while count < max:`.

Here is the corrected code:

```python
def count_up_to(max: int) -> int:
    """Generator function that yields numbers from 0 to max-1."""
    count = 0
    while count < max:
        yield count
        count += 1

if __name__ == "__main__":
    counter = count_up_to(5)
    for num in counter:
        print(num)
```

</details>
