# 11.2 — Context Managers & The with Statement (__enter__/__exit__)

## Opening Motivation & Context

Context managers are a powerful feature in Python that allow you to allocate and release resources precisely when you want to. The most widely used example of context managers is the handling of file operations. By using the `with` statement, you can ensure that files are properly closed after their suite of code has executed, even if exceptions occur.

Context managers are not limited to file operations. They can be used to manage any resource that requires explicit setup and teardown, such as database connections, network sockets, or hardware devices. This makes context managers a fundamental tool for writing robust and maintainable code.

## Core Concepts Breakdown

### The `with` Statement

The `with` statement is used to wrap the execution of a block of code with methods defined by a context manager. This allows resources to be properly managed before and after the block of code is executed.

> [!KEY-INSIGHT]
> The `with` statement ensures that resources are properly managed, even if exceptions occur within the block of code.

> [!BEST-PRACTICE]
> Always use the `with` statement when working with resources that require explicit setup and teardown, such as files, database connections, and network sockets.

> [!WARNING]
> Forgetting to use the `with` statement when working with resources that require explicit setup and teardown can lead to resource leaks and other issues.

## Code Demonstration & Runtime Output

```python
from contextlib import contextmanager
import time

class Timer:
    def __enter__(self):
        self.start = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.end = time.time()
        self.interval = self.end - self.start
        print(f"Elapsed time: {self.interval:.2f} seconds")

@contextmanager
def timer():
    start = time.time()
    yield
    end = time.time()
    interval = end - start
    print(f"Elapsed time: {interval:.2f} seconds")

def main():
    # Using the Timer class as a context manager
    with Timer():
        time.sleep(2)

    # Using the timer function as a context manager
    with timer():
        time.sleep(2)

if __name__ == "__main__":
    main()
```

```text
Output:
Elapsed time: 2.00 seconds
Elapsed time: 2.00 seconds
```

## How this works (Line-by-Line Breakdown)

1. **Imports**: We import the `contextmanager` decorator from the `contextlib` module and the `time` module for timing operations.
2. **Timer Class**: We define a `Timer` class with `__enter__` and `__exit__` methods to measure the elapsed time of a block of code.
   - `__enter__`: This method is called when the `with` statement is executed. It records the start time and returns the `Timer` instance.
   - `__exit__`: This method is called when the block of code inside the `with` statement is exited. It records the end time, calculates the elapsed time, and prints it.
3. **Timer Function**: We define a `timer` function decorated with `@contextmanager` to achieve the same functionality as the `Timer` class but using a generator function.
   - The `yield` statement marks the point where the block of code inside the `with` statement is executed.
   - After the block of code is executed, the remaining code in the function is executed, which calculates and prints the elapsed time.
4. **Main Function**: We define a `main` function to demonstrate the usage of both the `Timer` class and the `timer` function as context managers.
   - We use the `with` statement to wrap a block of code with the `Timer` class and the `timer` function.
   - The `time.sleep(2)` function is used to simulate a time-consuming operation.
5. **Main Block**: We call the `main` function when the script is executed directly.

> [!ADVANCED]
> The `with` statement is implemented using the context management protocol, which involves the `__enter__` and `__exit__` methods. When the `with` statement is executed, the `__enter__` method of the context manager is called, and the return value is bound to the target specified in the `as` clause. The block of code inside the `with` statement is then executed. Finally, the `__exit__` method of the context manager is called, even if an exception occurs within the block of code. The `__exit__` method can handle the exception or let it propagate by returning a false value.

## > [!QA]

### Q: When should I prefer using a class as a context manager over using a function with the `@contextmanager` decorator?

A: The choice between using a class as a context manager and using a function with the `@contextmanager` decorator depends on the complexity of the resource management and the need for additional functionality. Classes are more suitable when you need to maintain state or provide additional methods. Functions with the `@contextmanager` decorator are more concise and suitable for simple resource management tasks.

## Summary & Key Takeaways

- Context managers are used to manage resources that require explicit setup and teardown.
- The `with` statement ensures that resources are properly managed, even if exceptions occur within the block of code.
- Context managers can be implemented using classes with `__enter__` and `__exit__` methods or using functions with the `@contextmanager` decorator.
- Always use the `with` statement when working with resources that require explicit setup and teardown.

### Question #3: Find and fix the bug

```python
class FileManager:
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    def __enter__(self):
        self.file = open(self.filename, self.mode)
        return self.file

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.file.close()

def main():
    with FileManager("example.txt", "w") as file:
        file.write("Hello, World!")
        raise Exception("An error occurred!")

if __name__ == "__main__":
    main()
```

<details><summary>Show Solution</summary>

The bug in the code is that the `FileManager` class does not handle exceptions properly. The `__exit__` method should return `True` to suppress the exception, or it should handle the exception and return `False` to propagate it. Here is the fixed code:

```python
class FileManager:
    def __init__(self, filename, mode):
        self.filename = filename
        self.mode = mode

    def __enter__(self):
        self.file = open(self.filename, self.mode)
        return self.file

    def __exit__(self, exc_type, exc_val, exc_tb):
        self.file.close()
        if exc_type is not None:
            print(f"An exception occurred: {exc_val}")
            return True

def main():
    with FileManager("example.txt", "w") as file:
        file.write("Hello, World!")
        raise Exception("An error occurred!")

if __name__ == "__main__":
    main()
```

The fixed code outputs:

```text
An exception occurred: An error occurred!
```

</details>
