# 11.3 — Custom Container Emulation & Sequence Protocols

## Opening Motivation & Context

In Python, the data model is the foundation that allows for dynamic and flexible programming. One of the most powerful aspects of the data model is the ability to create custom containers that emulate built-in sequence types like lists, tuples, and strings. This capability is crucial for creating domain-specific data structures that can be used seamlessly with Python's built-in functions and libraries.

Understanding how to emulate sequence protocols is essential for writing efficient, reusable, and maintainable code. It allows you to create objects that behave like sequences, which can be iterated over, indexed, sliced, and concatenated, among other operations. This lesson will guide you through the process of creating custom containers that emulate sequence protocols.

## Core Concepts Breakdown

### Sequence Protocol

The sequence protocol in Python defines a set of methods that allow objects to be treated as sequences. The primary methods include `__len__`, `__getitem__`, `__setitem__`, `__delitem__`, and `__contains__`. By implementing these methods, you can create objects that behave like sequences.

> [!KEY-INSIGHT]
> The sequence protocol is a fundamental part of Python's data model. By implementing the necessary methods, you can create custom containers that behave like built-in sequences.

> [!BEST-PRACTICE]
> Always implement the `__len__` and `__getitem__` methods when creating a custom sequence. These methods are essential for basic sequence operations.

> [!WARNING]
> Implementing the sequence protocol incorrectly can lead to unexpected behavior. Ensure that your methods adhere to the expected behavior of sequences.

## Code Demonstration & Runtime Output

```python
from typing import Any, Optional, Union

class CustomSequence:
    def __init__(self, data: list) -> None:
        self._data = data

    def __len__(self) -> int:
        return len(self._data)

    def __getitem__(self, index: Union[int, slice]) -> Any:
        return self._data[index]

    def __setitem__(self, index: int, value: Any) -> None:
        self._data[index] = value

    def __delitem__(self, index: int) -> None:
        del self._data[index]

    def __contains__(self, value: Any) -> bool:
        return value in self._data

    def __repr__(self) -> str:
        return f"CustomSequence({self._data})"

if __name__ == "__main__":
    seq = CustomSequence([1, 2, 3, 4, 5])
    print(f"Length of sequence: {len(seq)}")
    print(f"Element at index 2: {seq[2]}")
    seq[2] = 10
    print(f"Sequence after setting index 2 to 10: {seq}")
    del seq[3]
    print(f"Sequence after deleting index 3: {seq}")
    print(f"Is 10 in the sequence? {10 in seq}")
```

Output:
```

Element at index 2: 3
Sequence after setting index 2 to 10: CustomSequence([1, 2, 10, 4, 5])
Sequence after deleting index 3: CustomSequence([1, 2, 10, 5])
Is 10 in the sequence? True
```

> [!ADVANCED]

> [!QA]
> Q: When should I prefer a custom sequence over a built-in sequence?
> A: You should prefer a custom sequence when you need to create a domain-specific data structure that behaves like a sequence but has additional functionality or constraints. For example, you might create a custom sequence to represent a mathematical vector or a DNA sequence.
