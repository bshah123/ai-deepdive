# 12.1 — Exception Hierarchy & Stack Unwinding

## Opening Motivation & Context

Exceptions are a fundamental aspect of robust programming, allowing developers to handle errors gracefully and maintain the flow of control in their applications. Understanding the exception hierarchy and stack unwinding is crucial for writing maintainable and reliable code. This lesson will explore these concepts in depth, providing you with the knowledge to handle exceptions effectively and debug your code when things go wrong.

## Core Concepts Breakdown

### Exception Hierarchy

In Python, exceptions are organized in a hierarchy, with the base class being `BaseException`. Most exceptions you'll encounter inherit from the `Exception` class, which itself inherits from `BaseException`. This hierarchy allows for more specific exception handling and provides a clear structure for organizing error types.

> [!KEY-INSIGHT]
> The exception hierarchy allows for more granular exception handling, enabling you to catch specific exceptions while allowing others to propagate up the call stack.

> [!BEST-PRACTICE]
> Always catch the most specific exception first and more general exceptions later. This ensures that the appropriate handler is invoked for each exception type.

### Stack Unwinding

Stack unwinding is the process by which the Python interpreter searches the call stack for an exception handler when an exception is raised. If no handler is found, the program terminates. Understanding stack unwinding helps you design your code to handle exceptions effectively and ensures that resources are properly released.

> [!WARNING]
> Improper exception handling can lead to resource leaks and make debugging more difficult. Always ensure that resources are properly released in exception handlers.

## Code Demonstration & Runtime Output

```python
def divide(a: float, b: float) -> float:
    try:
        result = a / b
    except ZeroDivisionError as e:
        print(f"Error: {e}")
        raise
    else:
        print(f"Division successful: {a} / {b} = {result}")
        return result
    finally:
        print("Division operation completed.")

def nested_function():
    try:
        divide(10, 0)
    except Exception as e:
        print(f"Caught exception in nested_function: {e}")
        raise

if __name__ == "__main__":
    try:
        nested_function()
    except Exception as e:
        print(f"Caught exception in main: {e}")
```

Output:
```
Error: division by zero
Division operation completed.
Caught exception in nested_function: division by zero
Caught exception in main: division by zero
```

## How this works (Line-by-Line Breakdown)

1. **Function `divide` definition**: This function takes two float arguments and attempts to divide the first by the second.
2. **Try block**: The division operation is performed within a try block to catch any exceptions that may occur.
3. **Except block**: If a `ZeroDivisionError` occurs, it is caught, and an error message is printed. The exception is then re-raised using the `raise` keyword.
4. **Else block**: If no exceptions occur, the result of the division is printed, and the result is returned.
5. **Finally block**: The finally block is executed regardless of whether an exception occurred or not. It prints a message indicating that the division operation is completed.
6. **Function `nested_function` definition**: This function calls the `divide` function with arguments 10 and 0, which will raise a `ZeroDivisionError`.
7. **Except block in `nested_function`**: The exception is caught, and an error message is printed. The exception is then re-raised.
8. **Main block**: The `nested_function` is called within a try block in the main block. The exception is caught, and an error message is printed.

> [!ADVANCED]
> When an exception is raised, Python searches the call stack for an exception handler. If no handler is found, the program terminates. The finally block is executed before the exception is propagated up the call stack, ensuring that resources are properly released.

## > [!QA]

Q: When should I prefer catching a specific exception over catching a general exception like `Exception` or `BaseException`?

A: You should prefer catching specific exceptions over general ones when you can handle the exception in a more targeted manner. Catching specific exceptions allows you to provide more meaningful error messages and perform more precise recovery actions. Additionally, catching general exceptions can mask programming errors and make debugging more difficult. Always catch the most specific exception first and more general exceptions later.

## Summary & Key Takeaways

- Exceptions are organized in a hierarchy, with the base class being `BaseException`.
- Most exceptions inherit from the `Exception` class, which itself inherits from `BaseException`.
- Stack unwinding is the process by which the Python interpreter searches the call stack for an exception handler.
- Always catch the most specific exception first and more general exceptions later.
- Ensure that resources are properly released in exception handlers.
- Use the finally block to execute cleanup code regardless of whether an exception occurred or not.

### Question #3: Find and fix the bug

```python
def divide(a: float, b: float) -> float:
    try:
        result = a / b
    except ZeroDivisionError as e:
        print(f"Error: {e}")
    else:
        print(f"Division successful: {a} / {b} = {result}")
        return result
    finally:
        print("Division operation completed.")

if __name__ == "__main__":
    divide(10, 2)
    divide(10, 0)
```

<details><summary>Show Solution</summary>

The bug in the code is that the `ZeroDivisionError` is caught but not re-raised, which can lead to unexpected behavior. To fix the bug, you should re-raise the exception after catching it.

```python
def divide(a: float, b: float) -> float:

        print(f"Error: {e}")
```
