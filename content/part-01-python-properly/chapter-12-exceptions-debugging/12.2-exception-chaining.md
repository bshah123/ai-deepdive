# 12.2 — Exception Chaining: raise ... from ...

## Opening Motivation & Context

Exception chaining is a powerful feature in Python that allows you to explicitly indicate that one exception was caused by another. This is particularly useful when you want to provide more context about an exception or when you're handling an exception and want to raise a new one that maintains the original exception's information.

In the context of computing and AI, exception chaining helps in debugging by providing a clear chain of events that led to an exception. This is especially important in complex systems where multiple layers of code can contribute to an error.

## Core Concepts Breakdown

### Exception Chaining

Exception chaining allows you to explicitly indicate that one exception was caused by another. This is done using the `raise ... from ...` syntax.

> [!KEY-INSIGHT]
> Exception chaining provides a clear and explicit way to indicate the cause of an exception, making debugging and error handling more straightforward.

> [!BEST-PRACTICE]
> Use exception chaining when you want to provide more context about an exception or when you're handling an exception and want to raise a new one that maintains the original exception's information.

> [!WARNING]
> Overusing exception chaining can make your code harder to read and understand. Only use it when it provides meaningful context about the exception.

## Code Demonstration & Runtime Output

```python
def divide(a: float, b: float) -> float:
    try:
        return a / b
    except ZeroDivisionError as e:
        raise ValueError("Cannot divide by zero") from e

def calculate(a: float, b: float) -> float:
    try:
        return divide(a, b)
    except ValueError as e:
        print(f"An error occurred: {e}")
        print(f"Original exception: {e.__cause__}")
        raise

if __name__ == "__main__":
    try:
        result = calculate(10, 0)
    except Exception as e:
        print(f"Final exception: {e}")
        print(f"Exception chain: {e.__context__}")
```

Output:
```
An error occurred: Cannot divide by zero
Original exception: division by zero
Final exception: Cannot divide by zero
Exception chain: Cannot divide by zero
```

### How this works (Line-by-Line Breakdown)

1. **Line 1-3**: The `divide` function takes two float arguments and attempts to divide the first by the second.
2. **Line 4-6**: If a `ZeroDivisionError` occurs, it raises a new `ValueError` with a custom message and chains it to the original exception using `raise ... from ...`.
3. **Line 8-10**: The `calculate` function calls the `divide` function and handles any `ValueError` that might be raised.
4. **Line 11-13**: If a `ValueError` is caught, it prints the error message and the original exception using `e.__cause__`.
5. **Line 14**: The `calculate` function then re-raises the exception.
6. **Line 16-18**: The `if __name__ == "__main__":` block is the entry point of the script. It calls the `calculate` function and handles any exceptions that might be raised.
7. **Line 19-21**: If an exception is caught, it prints the final exception and the exception chain using `e.__context__`.

> [!ADVANCED]
> Exception chaining in Python is implemented using the `__cause__` and `__context__` attributes of the exception object. The `__cause__` attribute is set when an exception is explicitly chained using `raise ... from ...`, while the `__context__` attribute is set when an exception is implicitly chained by another exception being raised in the same context.

> [!QA]
> Q: When should I prefer `raise ... from ...` over `raise ...`?
> A: You should prefer `raise ... from ...` when you want to explicitly indicate that one exception was caused by another. This is particularly useful when you want to provide more context about an exception or when you're handling an exception and want to raise a new one that maintains the original exception's information.
