# 13.3 — Virtual Environments, Site-Packages & Package Resolution

## Opening Motivation & Context

In the world of Python development, managing dependencies and isolating project environments is crucial. Virtual environments allow developers to create isolated Python environments, ensuring that each project has its own set of dependencies without interfering with each other. This is particularly important in the context of AI and machine learning, where different projects may require different versions of the same libraries.

Understanding how virtual environments work, how they interact with the `site-packages` directory, and how Python resolves package imports is essential for efficient and error-free development. This lesson will delve into these concepts, providing you with the knowledge and tools to manage your Python environments effectively.

## Core Concepts Breakdown

### Virtual Environments

Virtual environments are isolated Python environments that allow you to install packages without affecting the system-wide Python installation. This is particularly useful when working on multiple projects that require different versions of the same package.

> [!KEY-INSIGHT]
> Virtual environments provide a clean slate for each project, ensuring that dependencies are isolated and conflicts are minimized.

> [!BEST-PRACTICE]
> Always use a virtual environment for your Python projects to avoid dependency conflicts and ensure reproducibility.

### Site-Packages

The `site-packages` directory is where Python installs third-party packages. When you create a virtual environment, it creates its own `site-packages` directory, allowing you to install packages specific to that environment.

> [!WARNING]
> Modifying the system-wide `site-packages` directory can lead to dependency conflicts and system instability. Always use virtual environments for package installation.

### Package Resolution

Python uses a specific order to resolve package imports. It first looks in the current directory, then in the `site-packages` directory, and finally in the Python standard library. Understanding this order is crucial for troubleshooting import errors.

> [!KEY-INSIGHT]
> Python's package resolution order is: current directory, `site-packages`, and finally the standard library.

## Code Demonstration & Runtime Output

Let's create a virtual environment, install a package, and demonstrate how Python resolves package imports.

```python
import os
import subprocess
import sys

def create_virtualenv(env_name: str) -> None:
    """Create a virtual environment."""
    subprocess.run([sys.executable, "-m", "venv", env_name], check=True)

def install_package(env_name: str, package_name: str) -> None:
    """Install a package in the virtual environment."""
    pip_path = os.path.join(env_name, "bin", "pip") if os.name != "nt" else os.path.join(env_name, "Scripts", "pip.exe")
    subprocess.run([pip_path, "install", package_name], check=True)

def list_packages(env_name: str) -> None:
    """List installed packages in the virtual environment."""
    pip_path = os.path.join(env_name, "bin", "pip") if os.name != "nt" else os.path.join(env_name, "Scripts", "pip.exe")
    subprocess.run([pip_path, "list"], check=True)

def main() -> None:
    env_name = "myenv"
    package_name = "requests"

    print(f"Creating virtual environment: {env_name}")
    create_virtualenv(env_name)

    print(f"\nInstalling package: {package_name}")
    install_package(env_name, package_name)

    print("\nListing installed packages:")
    list_packages(env_name)

if __name__ == "__main__":
    main()
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import the necessary modules, `os`, `subprocess`, and `sys`.
2. **create_virtualenv**: This function creates a virtual environment using the `venv` module.
3. **install_package**: This function installs a package in the virtual environment using the `pip` command.
4. **list_packages**: This function lists the installed packages in the virtual environment using the `pip list` command.
5. **main**: The main function orchestrates the creation of the virtual environment, installation of the package, and listing of the installed packages.
6. **if __name__ == "__main__"**: This block ensures that the `main` function is called only when the script is executed directly.

> [!ADVANCED]
> When you create a virtual environment, Python creates a new `site-packages` directory within the environment. This directory is added to the `sys.path` list, allowing Python to find packages installed in the virtual environment. The `venv` module uses the `ensurepip` module to install `pip` in the virtual environment, which is then used to install packages.

## Summary & Key Takeaways

- Virtual environments provide isolated Python environments for each project.
- The `site-packages` directory is where Python installs third-party packages.
- Python's package resolution order is: current directory, `site-packages`, and finally the standard library.
- Always use virtual environments for your Python projects to avoid dependency conflicts.
- Modifying the system-wide `site-packages` directory can lead to dependency conflicts and system instability.

### Question #3: Find and fix the bug

```python
import os
import subprocess

def create_virtualenv(env_name: str) -> None:
    """Create a virtual environment."""
    subprocess.run(["python", "-m", "venv", env_name], check=True)

def main() -> None:
    env_name = "myenv"
    create_virtualenv(env_name)

if __name__ == "__main__":
    main()
```

<details><summary>Show Solution</summary>

The bug in the code is that it uses `"python"` as the command to create the virtual environment. This can lead to issues if the system's default Python version is different from the one you want to use. To fix this, you should use `sys.executable` to get the path to the current Python interpreter.

```python
import os
import subprocess
import sys

def create_virtualenv(env_name: str) -> None:
    """Create a virtual environment."""
    subprocess.run([sys.executable, "-m", "venv", env_name], check=True)

def main() -> None:
    env_name = "myenv"
    create_virtualenv(env_name)

if __name__ == "__main__":
    main()
```

</details>
