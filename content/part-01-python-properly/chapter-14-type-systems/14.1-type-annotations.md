# 14.1 — Python Type Annotations & Mypy Static Checking

## Opening Motivation & Context

In the rapidly evolving landscape of computing and AI, type systems play a crucial role in ensuring code reliability, maintainability, and performance. Python, as a dynamically typed language, has traditionally lacked static type checking. However, with the introduction of type annotations and tools like Mypy, Python developers can now leverage static type checking to catch errors early and improve code quality.

Type annotations allow developers to specify the expected types of variables, function parameters, and return values. Mypy, a popular static type checker for Python, uses these annotations to perform type checking at compile-time, helping to identify potential type-related bugs before runtime.

In this lesson, we will explore Python type annotations and how to use Mypy for static type checking. We will cover the basics of type annotations, how to use Mypy, and best practices for incorporating type checking into your Python projects.

## Core Concepts Breakdown

### Type Annotations

Type annotations in Python allow you to specify the expected types of variables, function parameters, and return values. This information is used by static type checkers like Mypy to perform type checking at compile-time.

> [!KEY-INSIGHT]
> Type annotations provide a way to make your code more explicit about the types it expects, which can help catch errors early and improve code readability.

> [!BEST-PRACTICE]
> Use type annotations consistently throughout your codebase to ensure that your static type checker can provide accurate feedback.

### Mypy Static Type Checking

Mypy is a popular static type checker for Python that uses type annotations to perform type checking at compile-time. Mypy can help catch potential type-related bugs before runtime, improving the overall reliability of your code.

> [!KEY-INSIGHT]
> Static type checking can help catch potential type-related bugs before runtime, improving the overall reliability of your code.

> [!WARNING]
> Mypy may not catch all type-related bugs, so it's still important to perform runtime testing to ensure the correctness of your code.

## Code Demonstration & Runtime Output

Let's start by looking at a simple example of type annotations in Python. We'll define a function that takes two integers and returns their sum, with type annotations for the parameters and return value.

```python
def add_numbers(a: int, b: int) -> int:
    return a + b

if __name__ == "__main__":
    result = add_numbers(5, 7)
    print(f"The sum of 5 and 7 is {result}")
```

Output:
```
The sum of 5 and 7 is 12
```

### How this works (Line-by-Line Breakdown)

1. `def add_numbers(a: int, b: int) -> int:`: This line defines a function called `add_numbers` that takes two parameters, `a` and `b`, both of which are annotated as integers. The `-> int` annotation indicates that the function returns an integer.
2. `return a + b`: This line returns the sum of `a` and `b`.
3. `if __name__ == "__main__":`: This line checks if the script is being run as the main program.
4. `result = add_numbers(5, 7)`: This line calls the `add_numbers` function with the arguments `5` and `7` and stores the result in the variable `result`.
5. `print(f"The sum of 5 and 7 is {result}")`: This line prints the result of the `add_numbers` function.

Now, let's look at an example of using Mypy for static type checking. We'll use the same `add_numbers` function and run Mypy on it to check for type-related errors.

```python
def add_numbers(a: int, b: int) -> int:
    return a + b

if __name__ == "__main__":
    result = add_numbers(5, "7")
    print(f"The sum of 5 and 7 is {result}")
```

Output:
```
mypy type_checking.py
type_checking.py:7: error: Argument 2 to "add_numbers" has incompatible type "str"; expected "int"
Found 1 error in 1 file (checked 1 source file)
```

### How this works (Line-by-Line Breakdown)

1. `def add_numbers(a: int, b: int) -> int:`: This line defines a function called `add_numbers` that takes two parameters, `a` and `b`, both of which are annotated as integers. The `-> int` annotation indicates that the function returns an integer.
2. `return a + b`: This line returns the sum of `a` and `b`.
3. `if __name__ == "__main__":`: This line checks if the script is being run as the main program.
4. `result = add_numbers(5, "7")`: This line calls the `add_numbers` function with the arguments `5` and `"7"` and stores the result in the variable `result`.
5. `print(f"The sum of 5 and 7 is {result}")`: This line prints the result of the `add_numbers` function.
6. `mypy type_checking.py`: This command runs Mypy on the `type_checking.py` file to check for type-related errors.
7. `type_checking.py:7: error: Argument 2 to "add_numbers" has incompatible type "str"; expected "int"`: This line indicates that Mypy has found a type-related error in the `type_checking.py` file. Specifically, it shows that the second argument to the `add_numbers` function has an incompatible type of `str` when it was expected to be an `int`.
8. `Found 1 error in 1 file (checked 1 source file)`: This line summarizes the number of errors found by Mypy.

> [!ADVANCED]
> Mypy uses the Python Abstract Syntax Tree (AST) to parse and analyze the type annotations in your code. It then uses this information to perform type checking at compile-time, helping to catch potential type-related bugs before runtime.

> [!QA]
> Q: When should I prefer using type annotations over runtime type checking?
> A: Type annotations are generally preferred over runtime type checking because they allow you to catch potential type-related bugs at compile-time, improving the overall reliability of your code. Additionally, type annotations can make your code more explicit about the types it expects, improving code readability and maintainability.

### Question #3: Find and fix the bug

```python
def divide_numbers(a: int, b: int) -> float:
    return a / b

if __name__ == "__main__":
    result = divide_numbers(5, 0)
    print(f"The result of dividing 5 by 0 is {result}")
```

<details><summary>Show Solution</summary>

The bug in the code is that it attempts to divide by zero, which is not allowed in mathematics. To fix this bug, you should add a check to ensure that the denominator is not zero before performing the division.

```python
def divide_numbers(a: int, b: int) -> float:
    if b == 0:
        raise ValueError("Cannot divide by zero")
    return a / b

if __name__ == "__main__":
    try:
        result = divide_numbers(5, 0)
        print(f"The result of dividing 5 by 0 is {result}")
    except ValueError as e:
        print(e)
```

</details>
