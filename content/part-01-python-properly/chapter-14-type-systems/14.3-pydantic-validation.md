# 14.3 — Data Validation with Pydantic V2 & Rust Backend

## Opening Motivation & Context

Data validation is a critical aspect of software development, ensuring that the data your application receives, processes, and sends out is accurate, consistent, and secure. In the context of modern web applications, this is especially important as they often interact with various sources of data, including user inputs, APIs, and databases.

Pydantic V2 is a powerful data validation and settings management library for Python. It leverages Python type hints to provide runtime data validation and parsing, making it easier to ensure that your data adheres to the expected structure and types. When combined with a Rust backend, you can create a robust and efficient system that handles data validation both in Python and Rust, ensuring data integrity across your entire application stack.

## Core Concepts Breakdown

### Data Validation

Data validation is the process of ensuring that data meets certain criteria before it is processed or stored. This can include checking for required fields, validating data types, ensuring data falls within a specific range, and more. Proper data validation helps prevent bugs, security vulnerabilities, and data corruption.

> [!KEY-INSIGHT]
> Data validation is not just about checking for errors; it's about ensuring that your data is in the correct format and structure before it is used, which helps maintain the integrity and reliability of your application.

> [!BEST-PRACTICE]
> Always validate data at the point of entry, as well as at the point of use. This helps catch errors early and ensures that your application is more robust and secure.

> [!WARNING]
> Never rely solely on client-side validation. Always validate data on the server side as well, as client-side validation can be bypassed by malicious users.

### Pydantic V2

Pydantic V2 is a data validation and settings management library for Python. It uses Python type hints to provide runtime data validation and parsing, making it easier to ensure that your data adheres to the expected structure and types. Pydantic V2 is built on top of Pydantic V1 and includes several new features and improvements, such as better performance, improved error messages, and support for more complex data structures.

### Rust Backend

Rust is a systems programming language that is known for its performance, safety, and concurrency. It is often used for building high-performance backends, especially in applications that require low-level control over hardware resources. By combining Pydantic V2 with a Rust backend, you can create a robust and efficient system that handles data validation both in Python and Rust, ensuring data integrity across your entire application stack.

## Code Demonstration & Runtime Output

Let's look at an example of how to use Pydantic V2 to validate data in a Python application, and then send that data to a Rust backend for further processing.

```python
from pydantic import BaseModel, ValidationError, field_validator
from typing import Optional
import requests

class User(BaseModel):
    id: int
    name: str
    email: str
    age: Optional[int] = None

    @field_validator('email')
    def email_must_contain_at_symbol(cls, v):
        if '@' not in v:
            raise ValueError('Email must contain an @ symbol')
        return v

def validate_user_data(user_data: dict) -> User:
    try:
        user = User(**user_data)
        return user
    except ValidationError as e:
        print(f"Validation error: {e}")
        raise

def send_data_to_rust_backend(user: User) -> dict:
    response = requests.post('http://localhost:8000/validate', json=user.model_dump())
    response.raise_for_status()
    return response.json()

if __name__ == "__main__":
    user_data = {
        "id": 1,
        "name": "John Doe",
        "email": "john.doe@example.com",
        "age": 30
    }

    try:
        validated_user = validate_user_data(user_data)
        print(f"Validated user: {validated_user}")

        response = send_data_to_rust_backend(validated_user)
        print(f"Response from Rust backend: {response}")
    except Exception as e:
        print(f"An error occurred: {e}")
```

Output:
```
Validated user: id=1 name='John Doe' email='john.doe@example.com' age=30
Response from Rust backend: {'status': 'success', 'message': 'Data validated and processed successfully'}
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import the necessary modules and classes from Pydantic and the standard library.
2. **User Class**: We define a `User` class that inherits from `BaseModel`. This class represents the structure of the data we want to validate.
3. **Field Validators**: We define a field validator for the `email` field to ensure that it contains an `@` symbol.
4. **validate_user_data Function**: This function takes a dictionary of user data, attempts to create a `User` instance from it, and handles any validation errors that may occur.
5. **send_data_to_rust_backend Function**: This function sends the validated user data to a Rust backend for further processing.
6. **Main Block**: In the `if __name__ == "__main__":` block, we define some sample user data, validate it using the `validate_user_data` function, and then send it to the Rust backend using the `send_data_to_rust_backend` function.

> [!ADVANCED]
> When you create a Pydantic model, it generates a set of methods and attributes that are used for data validation and parsing. These include methods like `model_validate`, `model_dump`, and `model_dump_json`, as well as attributes like `model_fields` and `model_config`. These methods and attributes are implemented in Cython for better performance, and they use Python's type hints to determine the expected structure and types of the data.

> [!QA]
> Q: When should I prefer Pydantic V2 over other data validation libraries like Marshmallow or Cerberus?
> A: Pydantic V2 is a good choice if you are already using Python type hints in your codebase, as it integrates seamlessly with them. It also offers better performance and improved error messages compared to some of the older data validation libraries. However, if you need more flexibility or have specific requirements that are not met by Pydantic V2, you may want to consider other libraries.

### Question #3: Find and fix the bug

```python
        print(f"Validated book: {validated_book}")
    except Exception as e:
        print(f"An error occurred: {e}")
```

<details><summary>Show Solution</summary>

The bug in the code is that the `year` field is defined as an integer, but the value provided in the `book_data` dictionary is a string. To fix this, you need to convert the string value to an integer before creating the `Book` instance. Here's the corrected code:

```python
from pydantic import BaseModel, ValidationError

class Book(BaseModel):
    id: int
    title: str
    author: str
    year: int

def validate_book_data(book_data: dict) -> Book:
    try:
        book_data["year"] = int(book_data["year"])
        book = Book(**book_data)
        return book
    except ValidationError as e:
        print(f"Validation error: {e}")
        raise

if __name__ == "__main__":
    book_data = {
        "id": 1,
        "title": "The Great Gatsby",
        "author": "F. Scott Fitzgerald",
        "year": "1925"
    }

    try:
        validated_book = validate_book_data(book_data)
        print(f"Validated book: {validated_book}")
    except Exception as e:
        print(f"An error occurred: {e}")
```

</details>
