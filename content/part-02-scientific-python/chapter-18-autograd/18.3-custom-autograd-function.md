# 18.3 — Custom PyTorch autograd.Function & Gradient Hooks

## Opening Motivation & Context

In the world of deep learning, understanding how gradients are computed and propagated is crucial. PyTorch provides a powerful autograd system that automatically computes gradients for us, but sometimes we need more control. This is where custom `autograd.Function` and gradient hooks come into play. They allow us to define our own operations and customize how gradients are computed, giving us the flexibility to implement complex operations or optimize performance.

## Core Concepts Breakdown

### Custom autograd.Function

PyTorch's `autograd.Function` allows us to define custom operations that are not natively supported by PyTorch. This is useful when you need to implement a custom operation that doesn't have a gradient defined in PyTorch or when you want to optimize performance by implementing a custom operation in a lower-level language like C++.

> [!KEY-INSIGHT]
> Custom `autograd.Function` allows you to define forward and backward passes for operations that are not natively supported by PyTorch.

> [!BEST-PRACTICE]
> Use custom `autograd.Function` when you need to implement a custom operation that doesn't have a gradient defined in PyTorch or when you want to optimize performance by implementing a custom operation in a lower-level language.

> [!WARNING]
> Custom `autograd.Function` can be complex and error-prone. Make sure to thoroughly test your implementation and understand the mathematical operations involved.

### Gradient Hooks

Gradient hooks allow you to inspect or modify gradients during the backward pass. This is useful for debugging, logging, or implementing custom gradient transformations.

> [!KEY-INSIGHT]
> Gradient hooks allow you to inspect or modify gradients during the backward pass, providing flexibility in how gradients are computed.

> [!BEST-PRACTICE]
> Use gradient hooks for debugging, logging, or implementing custom gradient transformations. However, be cautious when modifying gradients, as this can affect the training process.

> [!WARNING]
> Modifying gradients in a gradient hook can have unintended consequences. Make sure to understand the impact of your modifications on the training process.

## Code Demonstration & Runtime Output

```python
import torch
from torch.autograd import Function

class CustomFunction(Function):
    @staticmethod
    def forward(ctx, input):
        # Save input for backward pass
        ctx.save_for_backward(input)
        # Perform custom operation
        output = input * 2
        return output

    @staticmethod
    def backward(ctx, grad_output):
        # Retrieve saved input
        input, = ctx.saved_tensors
        # Compute gradient
        grad_input = grad_output * 2
        return grad_input

# Create a tensor with requires_grad=True
x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)

# Apply custom function
y = CustomFunction.apply(x)

# Compute gradient
y.sum().backward()

# Print results
print("Input:", x)
print("Output:", y)
print("Gradient:", x.grad)

# Gradient hook example
def gradient_hook(grad):
    print("Gradient before hook:", grad)
    return grad * 0.5

# Register gradient hook
x.register_hook(gradient_hook)

# Compute gradient again
y.sum().backward()

# Print results
print("Gradient after hook:", x.grad)
```

Output:
```
Input: tensor([1., 2., 3.], requires_grad=True)
Output: tensor([2., 4., 6.], grad_fn=<CustomFunctionBackward>)
Gradient: tensor([2., 2., 2.])
Gradient before hook: tensor([2., 2., 2.])
Gradient after hook: tensor([1., 1., 1.])
```

### How this works (Line-by-Line Breakdown)

1. `import torch`: Imports the PyTorch library.
2. `from torch.autograd import Function`: Imports the `Function` class from PyTorch's autograd module.
3. `class CustomFunction(Function):`: Defines a custom function that inherits from `Function`.
4. `@staticmethod`: Decorator to define static methods.
5. `def forward(ctx, input):`: Defines the forward pass of the custom function.
6. `ctx.save_for_backward(input)`: Saves the input tensor for the backward pass.
7. `output = input * 2`: Performs a custom operation (doubling the input).
8. `return output`: Returns the output tensor.
9. `def backward(ctx, grad_output):`: Defines the backward pass of the custom function.
10. `input, = ctx.saved_tensors`: Retrieves the saved input tensor.
11. `grad_input = grad_output * 2`: Computes the gradient for the input.
12. `return grad_input`: Returns the gradient tensor.
13. `x = torch.tensor([1.0, 2.0, 3.0], requires_grad=True)`: Creates a tensor with `requires_grad=True`.
14. `y = CustomFunction.apply(x)`: Applies the custom function to the input tensor.
15. `y.sum().backward()`: Computes the gradient of the output with respect to the input.
16. `print("Input:", x)`: Prints the input tensor.
17. `print("Output:", y)`: Prints the output tensor.
18. `print("Gradient:", x.grad)`: Prints the gradient tensor.
19. `def gradient_hook(grad):`: Defines a gradient hook function.
20. `print("Gradient before hook:", grad)`: Prints the gradient before the hook.
21. `return grad * 0.5`: Modifies the gradient by halving it.
22. `x.register_hook(gradient_hook)`: Registers the gradient hook with the input tensor.
23. `y.sum().backward()`: Computes the gradient again, triggering the gradient hook.
24. `print("Gradient after hook:", x.grad)`: Prints the gradient after the hook.

> [!ADVANCED]
> Custom `autograd.Function` allows you to define operations that are not natively supported by PyTorch. The forward pass defines the operation, while the backward pass defines how gradients are computed. Gradient hooks provide a way to inspect or modify gradients during the backward pass, giving you more control over the gradient computation process.

<details><summary>Show Solution</summary>

The bug is that the gradient hook is registered after the first backward pass, so it doesn't affect the first gradient computation. To fix this, register the gradient hook before the first backward pass:

```python

```
