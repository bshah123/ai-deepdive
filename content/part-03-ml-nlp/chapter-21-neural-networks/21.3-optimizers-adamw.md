Training a neural network repeats one step: move every weight against its gradient. Optimizers differ in what they remember between steps and how they scale each weight's step. By the end you will compute one step of each of the four rules by hand, check a NumPy version against `torch.optim`, and read a learning-rate sweep.

**You need:** gradient descent and the chain rule (Lesson 21.1), and the idea of a learning rate.

## The problem: one step size, many directions

Plain gradient descent moves each weight by $-\eta\, g$, where $\eta$ is the learning rate (called `lr` in code) and $g$ is the gradient of the loss. Two things go wrong. The same $\eta$ applies to every weight, but a loss surface is often steep in one direction and flat in another. An $\eta$ that is safe for the steep direction is then painfully slow in the flat one. Second, with minibatch training (each step uses a small random subset of the data), $g$ is a noisy estimate of the true gradient, so the steps jitter.

## Four rules, one gradient

![Four boxes, one per optimizer: each shows what the optimizer keeps between steps and the update it applies, written in code-like notation](diagrams/21.3-update-rules.svg "The four update rules. Only the memory and the scaling differ.")

SGD (stochastic gradient descent) uses only the current gradient. Momentum keeps a velocity $v$ that accumulates past gradients, decayed by $\mu$ each step. RMSprop (root mean square propagation) keeps $s$, an exponential moving average (EMA) of $g^2$, and divides each step by $\sqrt{s}$, so every weight gets its own effective step size. AdamW keeps two EMAs, $m$ of $g$ and $v$ of $g^2$, bias-corrects them (the hat marks, defined below), and also shrinks the weights directly before the step. That shrinkage is weight decay, with strength $\lambda$.

## Worked example by hand

Take $f(w) = w^2$, start at $w_0 = 2$, and use $\eta = 0.1$. The gradient is $g = 2w = 4$. Step 1 for each rule:

- **SGD:** $w_1 = 2 - 0.1 \cdot 4 = 1.6$.
- **Momentum** ($\mu = 0.9$): the velocity starts at zero, so $v_1 = 4$ and $w_1 = 1.6$. On step 2, $g_2 = 3.2$, $v_2 = 0.9 \cdot 4 + 3.2 = 6.8$ and $w_2 = 1.6 - 0.1 \cdot 6.8 = 0.92$.
- **RMSprop** ($\alpha = 0.99$): $s_1 = 0.01 \cdot 16 = 0.16$, so the step is $0.1 \cdot 4 / \sqrt{0.16} = 1.0$ and $w_1 = 1.0$.
- **AdamW** ($\lambda = 0.01$): the decay gives $2 \cdot (1 - 0.1 \cdot 0.01) = 1.998$. Then $m_1 = 0.1 \cdot 4 = 0.4$, $v_1 = 0.001 \cdot 16 = 0.016$, $\hat m_1 = 0.4 / 0.1 = 4$, $\hat v_1 = 0.016 / 0.001 = 16$, and the step is $0.1 \cdot 4 / \sqrt{16} = 0.1$, so $w_1 = 1.898$.

On step 1, SGD and Momentum both move 0.4, RMSprop moves 1.0, and AdamW moves 0.102 (0.002 of decay plus 0.100 of step). Momentum ties SGD on step 1 and then pulls ahead as its velocity builds.

![Horizontal bars showing how far each optimizer moves w on the first step, from w = 2 with lr 0.1: SGD 0.4, Momentum 0.4, RMSprop 1.0, AdamW 0.102](diagrams/21.3-first-step.svg "Distance moved on step 1. RMSprop's step does not depend on the gradient's size.")

Check the numbers in NumPy. Each class is one update rule, written to match `torch.optim`.

```python
import numpy as np

class SGD:
    def __init__(self, lr, momentum=0.0):
        self.lr, self.mu, self.v = lr, momentum, None
    def step(self, w, g):
        if self.mu == 0.0:
            return w - self.lr * g
        self.v = g.copy() if self.v is None else self.mu * self.v + g   # v = mu*v + g
        return w - self.lr * self.v

class RMSprop:
    def __init__(self, lr, alpha=0.99, eps=1e-8):
        self.lr, self.alpha, self.eps, self.s = lr, alpha, eps, None
    def step(self, w, g):
        self.s = (1 - self.alpha) * g * g if self.s is None else self.alpha * self.s + (1 - self.alpha) * g * g
        return w - self.lr * g / (np.sqrt(self.s) + self.eps)

class AdamW:
    def __init__(self, lr, wd=1e-2, b1=0.9, b2=0.999, eps=1e-8):
        self.lr, self.wd, self.b1, self.b2, self.eps = lr, wd, b1, b2, eps
        self.m, self.v, self.t = None, None, 0
    def step(self, w, g):
        self.t += 1                                   # t starts at 1, so the bias correction never divides by 0
        w = (1 - self.lr * self.wd) * w               # decoupled decay: shrink w directly
        self.m = (1 - self.b1) * g if self.m is None else self.b1 * self.m + (1 - self.b1) * g
        self.v = (1 - self.b2) * g * g if self.v is None else self.b2 * self.v + (1 - self.b2) * g * g
        m_hat = self.m / (1 - self.b1 ** self.t)      # bias correction
        v_hat = self.v / (1 - self.b2 ** self.t)
        return w - self.lr * m_hat / (np.sqrt(v_hat) + self.eps)

# f(w) = w^2, so the gradient is 2w. Start at w = 2 with lr = 0.1.
optimizers = {
    "SGD":      SGD(0.1),
    "Momentum": SGD(0.1, momentum=0.9),
    "RMSprop":  RMSprop(0.1),
    "AdamW":    AdamW(0.1, wd=0.01),
}
for name, opt in optimizers.items():
    w = np.array([2.0])
    trace = []
    for _ in range(3):
        w = opt.step(w, 2.0 * w)                      # g = 2w
        trace.append(f"{w[0]:.3f}")
    print(f"{name:9s} w after steps 1-3: {', '.join(trace)}")
```

```output
SGD       w after steps 1-3: 1.600, 1.280, 1.024
Momentum  w after steps 1-3: 1.600, 0.920, 0.124
RMSprop   w after steps 1-3: 1.000, 0.551, 0.310
AdamW     w after steps 1-3: 1.898, 1.796, 1.695
```

The hand values match the code. Against `torch.optim` (torch 2.15.0, float64), the same rules agree to at most $4.4 \times 10^{-16}$ on these 3 steps and on 20 steps of the rotated quadratic below (learning rate 0.01).

## Under the hood: why the rules look like this

**Momentum.** Hold the gradient fixed at $g$. The recursion $v \leftarrow \mu v + g$ converges to $v^* = g / (1 - \mu)$, which is $10g$ for $\mu = 0.9$. A steady gradient is amplified tenfold, so momentum changes the effective step size, not only the direction. (Derivation from the fixed point; assumes a constant gradient.)

**RMSprop.** On step 1, $s_1 = (1 - \alpha) g^2$, so the step is $\eta g / (\sqrt{1 - \alpha}\,|g|) = \eta\, \mathrm{sign}(g) / \sqrt{1 - \alpha}$. With $\alpha = 0.99$ that is $10\eta$ per weight, whatever the size of $g$. The normalisation removes the gradient's scale, which is useful and also dangerous (see the traps).

**Bias correction in Adam.** Write $m_t = (1 - \beta_1) \sum_{k=1}^{t} \beta_1^{\,t-k} g_k$. If every $g_k$ has the same mean $\bar g$ (an assumption, since real gradients drift), then $\mathbb{E}[m_t] = (1 - \beta_1^t)\,\bar g$. Dividing by $1 - \beta_1^t$ removes that bias, and $\hat v_t$ uses $1 - \beta_2^t$ the same way. Without the correction, a constant gradient gives a first step $0.1/\sqrt{0.001} \approx 3.16$ times too large. This is reasoning from the update, not a claim about convergence.

**Decoupled weight decay (AdamW).** Adam with an L2 penalty adds $\lambda w$ to the gradient. That term then passes through $m$ and is divided by $\sqrt{\hat v}$, so a weight with a large gradient history receives less decay. AdamW shrinks $w \leftarrow (1 - \eta\lambda) w$ directly instead. Loshchilov and Hutter (arXiv:1711.05101) show that for SGD the two are equivalent once $\lambda$ is rescaled by the learning rate, but not for Adam. PyTorch's `AdamW` applies `param.mul_(1 - lr * weight_decay)` before the Adam step (`torch/optim/adam.py`, torch 2.15.0).

## Benchmark 1: an ill-conditioned bowl

Take $f(w) = \tfrac{1}{2} w^\top H w$ with $H = \mathrm{diag}(1, 100)$. The curvature is 100 times larger in one direction, so the condition number is 100. Each coordinate evolves as $w \leftarrow (1 - \eta h) w$, which contracts only if $|1 - \eta h| < 1$, that is $\eta < 2/h$. For $h = 100$, plain gradient descent needs $\eta < 0.02$. The bowl is also rotated by 45 degrees, which keeps the same curvatures but breaks the alignment with the axes.

```python
import numpy as np

# f(w) = 0.5 * w^T H w, H = diag(1, 100): the valley is 100 times steeper in the second direction.
H_axis = np.diag([1.0, 100.0])
theta = np.radians(45.0)
R = np.array([[np.cos(theta), -np.sin(theta)], [np.sin(theta), np.cos(theta)]])
H_rot = R @ H_axis @ R.T                             # same curvatures, valley rotated 45 degrees

def steps_to_converge(H, make_step, w0=np.array([1.0, 0.37]), tol=1e-8, cap=20000):
    step, w = make_step(), w0.copy()
    with np.errstate(all="ignore"):
        for t in range(1, cap + 1):
            w = step(w, H @ w)                       # the gradient of 0.5 w^T H w is H w
            f = 0.5 * w @ H @ w
            if not np.isfinite(f):
                return None                          # diverged
            if f < tol:
                return t
    return None

def sgd(lr):
    return lambda: (lambda w, g: w - lr * g)

def momentum(lr):
    def make():
        v = [None]
        def step(w, g):
            v[0] = g.copy() if v[0] is None else 0.9 * v[0] + g
            return w - lr * v[0]
        return step
    return make

def rmsprop(lr):
    def make():
        s = [None]
        def step(w, g):
            s[0] = (1 - 0.99) * g * g if s[0] is None else 0.99 * s[0] + (1 - 0.99) * g * g
            return w - lr * g / (np.sqrt(s[0]) + 1e-8)
        return step
    return make

def adam(lr):                                        # AdamW with weight_decay = 0, i.e. plain Adam
    def make():
        st = {"m": None, "v": None, "t": 0}
        def step(w, g):
            st["t"] += 1
            st["m"] = (1 - 0.9) * g if st["m"] is None else 0.9 * st["m"] + (1 - 0.9) * g
            st["v"] = (1 - 0.999) * g * g if st["v"] is None else 0.999 * st["v"] + (1 - 0.999) * g * g
            m_hat = st["m"] / (1 - 0.9 ** st["t"])
            v_hat = st["v"] / (1 - 0.999 ** st["t"])
            return w - lr * m_hat / (np.sqrt(v_hat) + 1e-8)
        return step
    return make

# (optimizer, best lr on the axis-aligned valley, best lr on the rotated valley), from a log-spaced grid
table = [
    ("SGD",      sgd,      10 ** -1.75, 10 ** -1.75),
    ("Momentum", momentum, 10 ** -2.25, 10 ** -2.25),
    ("RMSprop",  rmsprop,  10 ** 0.5,   10 ** -2.25),
    ("AdamW",    adam,     10 ** -1.5,  10 ** -0.25),
]
for name, make, lr_axis, lr_rot in table:
    a = steps_to_converge(H_axis, make(lr_axis))
    r = steps_to_converge(H_rot, make(lr_rot))
    print(f"{name:9s} axis-aligned: {a} steps   rotated: {r} steps")
```

```output
SGD       axis-aligned: 495 steps   rotated: 493 steps
Momentum  axis-aligned: 149 steps   rotated: 149 steps
RMSprop   axis-aligned: 5 steps   rotated: 888 steps
AdamW     axis-aligned: 152 steps   rotated: 169 steps
```

The table reports the fewest steps to reach loss below $10^{-8}$, with each optimizer at its best learning rate from a 21-point log grid (spacing $10^{0.25}$). The full sweep is in `scripts/diagrams/lessons/21.3_experiment.py` in the course repository.

![Bar chart of steps to convergence for four optimizers on an axis-aligned and a rotated ill-conditioned bowl; RMSprop is 5 steps on the aligned bowl and 888 on the rotated one](diagrams/21.3-quadratic-steps.svg "Steps to loss below 1e-8, each optimizer at its best learning rate from the grid.")

Read the pattern, not the exact counts. SGD sits just below its stability bound: its best rate, 0.0178, is close to $2/100$. Momentum needs about a third as many steps (149 against 495), with a learning rate about 3 times smaller, because the velocity smooths the back-and-forth motion across the steep direction. RMSprop and AdamW normalise each coordinate, so they help when the valley lines up with the axes. RMSprop's 5 steps are a transient: its first step jumps to about $-30$ and the large squared-gradient average then shrinks the later steps. On the rotated bowl RMSprop needs 888 steps, while AdamW goes from 152 to 169. Changing the constant $1 - 0.99$ to the literal $0.01$ moved the rotated RMSprop count from 885 to 888 in an earlier run, so treat small counts as fragile.

## Benchmark 2: noisy minibatches

The second problem is logistic regression: 2000 synthetic examples with 20 features, minibatches of 32 (63 steps per epoch). The features are scaled from 1 to about 32, so the curvature is uneven across weights, as in real unnormalised inputs. The metric is the mean cross-entropy loss over the training set. Its starting value at $w = 0$ is $\ln 2 = 0.6931$. Each configuration uses 3 seeds, which change only the minibatch order.

```python
import math
import numpy as np

# Synthetic data: 2000 examples, 20 features. Feature j is scaled by 10**(1.5*j/19), so the
# features range from 1 to about 32 (unnormalised inputs make the curvature uneven across weights).
rng = np.random.default_rng(0)
N, D = 2000, 20
Xs = rng.standard_normal((N, D))
w_true = rng.standard_normal(D) / math.sqrt(D) * 3.0
y = (rng.random(N) < 1 / (1 + np.exp(-(Xs @ w_true)))).astype(float)
X = Xs * np.logspace(0, 1.5, D)

def loss_full(w):
    z = X @ w
    return float(np.mean(np.logaddexp(0.0, z) - y * z))   # mean binary cross-entropy

def grad_batch(w, idx):
    z = X[idx] @ w
    return X[idx].T @ (1 / (1 + np.exp(-z)) - y[idx]) / len(idx)

def train_adamw(lr, seed, wd=0.01, epochs=10, bs=32):
    m, v, t = np.zeros(D), np.zeros(D), 0
    w, r, at3 = np.zeros(D), np.random.default_rng(seed), None
    for ep in range(1, epochs + 1):
        perm = r.permutation(N)
        for s in range(0, N, bs):
            idx = perm[s:s + bs]
            g = grad_batch(w, idx)
            t += 1
            w = (1 - lr * wd) * w
            m = 0.9 * m + 0.1 * g
            v = 0.999 * v + 0.001 * g * g
            w = w - lr * (m / (1 - 0.9 ** t)) / (np.sqrt(v / (1 - 0.999 ** t)) + 1e-8)
        if ep == 3:
            at3 = loss_full(w)
    return at3, loss_full(w)

lr = 10 ** -2.5
runs = [train_adamw(lr, seed) for seed in (0, 1, 2)]
at3 = np.array([a for a, _ in runs]); final = np.array([f for _, f in runs])
print(f"initial loss (w = 0): {loss_full(np.zeros(D)):.4f}")
print(f"AdamW lr={lr:.4g}, 3 seeds, loss after 3 epochs: {at3.mean():.4f} +/- {at3.std():.4f}")
print(f"AdamW lr={lr:.4g}, 3 seeds, loss after 10 epochs: {final.mean():.4f}")
```

```output
initial loss (w = 0): 0.6931
AdamW lr=0.003162, 3 seeds, loss after 3 epochs: 0.3685 +/- 0.0015
AdamW lr=0.003162, 3 seeds, loss after 10 epochs: 0.3638
```

The code above runs one configuration. The sweep over 9 learning rates, from $10^{-4}$ to 1, gives:

| Optimizer | Best lr (3 epochs) | Loss at 3 epochs (mean ± sd) | Best lr (10 epochs) | Loss at 10 epochs |
|---|---|---|---|---|
| SGD | 3.16e-3 | 0.4423 ± 0.0217 | 3.16e-3 | 0.3756 |
| Momentum | 1e-3 | 0.4063 ± 0.0273 | 3.16e-4 | 0.3755 |
| RMSprop | 3.16e-3 | 0.3755 ± 0.0103 | 1e-3 | 0.3628 |
| AdamW | 3.16e-3 | 0.3685 ± 0.0015 | 3.16e-3 | 0.3638 |

![Line chart of training loss after 3 epochs against learning rate on log axes, one line per optimizer; SGD and Momentum rise steeply above lr 0.003, RMSprop and AdamW rise more gently](diagrams/21.3-lr-sensitivity.svg "Loss after 3 epochs against learning rate. Each point is the mean of 3 seeds; both axes are logarithmic.")

At 3 epochs AdamW has the lowest loss and the smallest spread across seeds. Over 10 epochs RMSprop and AdamW are within 0.001 of each other, and SGD and Momentum are about 0.012 higher, so the ranking depends on the budget. Sensitivity is the clearer signal: at $\eta = 0.01$ the loss after 3 epochs is 0.72 for SGD and 0.87 for Momentum (both above the starting 0.69, so these runs overshoot), against 0.44 for RMSprop and 0.38 for AdamW.

Four caveats apply. The learning rate is chosen on the same training loss that is reported, so this measures optimisation speed on this dataset, not generalisation. Wilson et al. (arXiv:1705.08292) report that adaptive methods found solutions that generalised worse than SGD in their experiments; this benchmark does not test that. AdamW here uses weight decay 0.01, so it does not isolate Adam from AdamW. The grid steps by about 3.16 and there is one synthetic dataset.

## Common traps

> [!TRAP]
> **RMSprop's first steps are large.** With $\alpha = 0.99$, step 1 is $10\eta$ per weight regardless of the gradient. The 5-step result above depends on a jump to about $-30$. Do not read a fast start as a sign of a good learning rate; check the trajectory.

> [!TRAP]
> **Momentum changes the effective step.** A constant gradient is amplified by $1/(1-\mu) = 10$ for $\mu = 0.9$. The best learning rate for Momentum was about 3 times smaller than for SGD here. Retune when you add momentum.

> [!TRAP]
> **`Adam(weight_decay=...)` is L2, not AdamW.** In PyTorch, `Adam` adds the penalty to the gradient (its docstring says "weight decay (L2 penalty)", `torch/optim/adam.py`). Use `AdamW` for decoupled decay.

> [!TRAP]
> **Start the step counter at 1.** If $t = 0$ on the first step, $1 - \beta_1^0 = 0$ and the bias correction divides by zero. Increment $t$ before computing $\hat m$ and $\hat v$.

> [!TRAP]
> **A small grid makes comparisons unfair.** Each optimizer's best rate is only known to within one grid step (a factor of 1.8 for the bowl, 3.2 for logistic regression), and the ranking changed between 3 and 10 epochs. Use the same grid and budget for every method, and report the spread across seeds.

## Summary

- Each rule keeps a different memory: none (SGD), a velocity (Momentum), a squared-gradient average (RMSprop), or two averages with decoupled decay (AdamW).
- On step 1 from $w = 2$ with $\eta = 0.1$, the weights go to 1.6, 1.6, 1.0 and 1.898: RMSprop's step is independent of the gradient's size.
- On a bowl with curvature 100, SGD needs $\eta < 0.02$ to converge, Momentum converges in about a third as many steps, and per-coordinate scaling helps only when the bowl is axis-aligned.
- On noisy minibatch logistic regression, AdamW and RMSprop reached lower loss than SGD and Momentum at both 3 and 10 epochs, and stayed below the starting loss at $\eta = 0.01$ where SGD and Momentum overshoot; over 10 epochs the gap is small.

Start at $w = 2$ with $\eta = 0.1$ on $f(w) = w^2$. What is $w$ after one step of SGD, and after one step of RMSprop with $\alpha = 0.99$?

SGD: $g = 4$, so $w_1 = 2 - 0.1 \cdot 4 = 1.6$. RMSprop: $s_1 = 0.01 \cdot 16 = 0.16$, so the step is $0.1 \cdot 4 / \sqrt{0.16} = 1.0$ and $w_1 = 1.0$.

### Question 2: Prediction

Now $f(w) = 1000\,w^2$, still starting at $w = 2$ with $\eta = 0.1$. Predict $w_1$ for SGD and for RMSprop ($\alpha = 0.99$).

<details><summary>Show solution</summary>

The gradient is $g = 2000 w = 4000$. SGD moves by $0.1 \cdot 4000 = 400$, so $w_1 = -398$. RMSprop gives $s_1 = 0.01 \cdot 4000^2$, so the step is $0.1 \cdot 4000 / (0.1 \cdot 4000) = 1.0$ and $w_1 = 1.0$, the same as before. RMSprop's step size is set by $\eta$ and $\alpha$, not by the gradient's scale.

### Question 3: Bug spotting

This NumPy Adam loop raises an error on its first iteration. Find the bug and fix it.

```python
m, v, t = 0.0, 0.0, 0
for g in [4.0, 3.2, 2.5]:
    m = 0.9 * m + 0.1 * g
    v = 0.999 * v + 0.001 * g * g
    m_hat = m / (1 - 0.9 ** t)
    v_hat = v / (1 - 0.999 ** t)
    print(m_hat, v_hat)
```

<details><summary>Show solution</summary>

The bug is that `t` is never incremented before the bias correction. On the first pass `t = 0`, so `1 - 0.9 ** 0 = 0` and the division fails. The fix is to write `t += 1` at the top of the loop body, so `t` runs 1, 2, 3. Then the correction is $1 - 0.9^1 = 0.1$ on the first step.

</details>

### Question 4: Explanation

Why does decoupled weight decay (AdamW) treat a weight with a large gradient history differently from Adam with an L2 penalty?

<details><summary>Show solution</summary>

With an L2 penalty, the term $\lambda w$ is added to $g$, so it enters $m$ and is divided by $\sqrt{\hat v}$. A weight with a large gradient history has a large $\sqrt{\hat v}$, so its decay is shrunk. AdamW multiplies $w$ by $(1 - \eta\lambda)$ directly, so every weight decays by the same fraction whatever its gradient history.

</details>
