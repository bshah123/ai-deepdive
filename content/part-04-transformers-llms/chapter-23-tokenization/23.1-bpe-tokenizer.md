A language model never sees text: it sees a list of integers called **tokens**. In this lesson you will build the tokenizer behind GPT-2 (Generative Pre-trained Transformer 2, OpenAI's 2019 language model) and its successors, **Byte-Pair Encoding (BPE)**: you will train it by hand on a four-word corpus, implement training, encoding and decoding in plain Python, make it byte-level so no input is ever "unknown", and check it against OpenAI's `tiktoken`.

**You need:** Python strings and how Unicode text becomes UTF-8 bytes (Lesson 3.3), and `collections.Counter` (Lesson 6.4).

## The problem a tokenizer solves

A model has a fixed **vocabulary**: a table mapping each allowed token to an integer id, and each id to a learned vector. The question is what the tokens should be.

![The unseen word lowest: word-level gives one unknown token, characters give six tokens, BPE gives two known tokens, low and est followed by the end-of-word marker](diagrams/23.1-granularity.svg "Three ways to split a word the training data never contained.")

- **Words** make short sequences, but any word not seen in training (a typo, a name, "lowest" when you only saw "low") becomes a single `[UNK]` ("unknown") token, and its meaning is lost.
- **Characters** never fail, but sequences get several times longer, and attention cost grows with the square of the sequence length (Lesson 25.1).
- **Subwords** sit in between: frequent words stay whole, rare words are built from frequent pieces. BPE is one way to learn those pieces from data.

## Where BPE comes from

BPE began as a data-compression trick: repeatedly replace the most frequent pair of bytes with a new, unused byte (Gage, 1994). Sennrich, Haddow and Birch (2016) adapted it to word segmentation for neural machine translation: start from characters and repeatedly **merge** the most frequent adjacent pair of symbols into a new symbol. The number of merges is the only hyperparameter, and the final vocabulary size is the starting alphabet plus the number of merges.

Two details from their paper matter for the code below:

- Each word gets an **end-of-word marker** (written `</w>` here), so "est" at the end of a word ("newest") is a different symbol from "est" inside one ("estimate"), and the original spacing can be restored.
- Pairs never cross word boundaries, so you can count over a dictionary of unique words weighted by their frequency instead of over the raw text.

## Worked example, by hand

The toy corpus from Sennrich et al. (2016, Algorithm 1): the word "low" appears 5 times, "lower" 2 times, "newest" 6 times and "widest" 3 times. Split every word into characters plus `</w>`, then count every adjacent pair, **weighted by word frequency**:

![The four corpus words as symbol boxes with their counts, and a bar chart of pair counts: e s, s t and t plus end marker tie at 9, then w e 8, l o 7, o w 7](diagrams/23.1-pair-counts.svg "Step 0: count adjacent pairs, weighted by how often each word occurs.")

1. **Count.** The pair `e s` appears in "newest" (6 times) and "widest" (3 times): 6 + 3 = 9. So do `s t` and `t </w>`.
2. **Break the tie.** Three pairs share the top count of 9. Our rule is "the first pair seen wins", which picks `e s`. Any fixed rule is fine, but it must be fixed, or training is not reproducible.
3. **Merge.** Replace every adjacent `e s` with the new symbol `es`. "newest" becomes `n e w es t </w>`. Record the rule `(e, s)` as **merge rank 1**.
4. **Repeat.** Recount. Now `es t` has count 9, so merge 2 is `es + t`, and merge 3 is `est + </w>` (9). Merge 4 is `l + o` (7), not `w e`: merge 1 turned "newest" into `n e w es t </w>`, so `w e` now survives only in "lower" and its count dropped from 8 to 2.

The last point is the whole trick: every merge changes the counts, so you must recount after each one. Code does the bookkeeping:

```python
from collections import Counter

# Word frequencies: the toy corpus from Sennrich et al. (2016), Algorithm 1
corpus = {"low": 5, "lower": 2, "newest": 6, "widest": 3}

# Each word becomes a tuple of symbols, plus an end-of-word marker
words = {tuple(w) + ("</w>",): f for w, f in corpus.items()}

def pair_counts(words):
    """Count adjacent symbol pairs, weighted by word frequency."""
    counts = Counter()
    for symbols, freq in words.items():
        for a, b in zip(symbols, symbols[1:]):
            counts[a, b] += freq
    return counts

def merge(words, pair):
    """Replace every occurrence of `pair` with one joined symbol."""
    a, b = pair
    out = {}
    for symbols, freq in words.items():
        new, i = [], 0
        while i < len(symbols):
            if i + 1 < len(symbols) and symbols[i] == a and symbols[i + 1] == b:
                new.append(a + b)          # merge, then skip both symbols
                i += 2
            else:
                new.append(symbols[i])
                i += 1
        out[tuple(new)] = freq
    return out

def train_bpe(words, num_merges):
    merges = []                            # the learned rules, in order
    for step in range(num_merges):
        counts = pair_counts(words)
        if not counts:
            break
        best = max(counts, key=counts.get) # ties: first pair seen wins
        merges.append(best)
        words = merge(words, best)
        print(f"merge {step + 1:2d}: {best[0]!r:7} + {best[1]!r:10} (count {counts[best]})")
    return merges, words

print("pair counts before any merge:", pair_counts(words).most_common(6))
merges, final = train_bpe(words, 10)
print("\nfinal segmentation:")
for symbols, freq in final.items():
    print(f"  {freq} x {' '.join(symbols)}")
```

```output
pair counts before any merge: [(('e', 's'), 9), (('s', 't'), 9), (('t', '</w>'), 9), (('w', 'e'), 8), (('l', 'o'), 7), (('o', 'w'), 7)]
merge  1: 'e'     + 's'        (count 9)
merge  2: 'es'    + 't'        (count 9)
merge  3: 'est'   + '</w>'     (count 9)
merge  4: 'l'     + 'o'        (count 7)
merge  5: 'lo'    + 'w'        (count 7)
merge  6: 'n'     + 'e'        (count 6)
merge  7: 'ne'    + 'w'        (count 6)
merge  8: 'new'   + 'est</w>'  (count 6)
merge  9: 'low'   + '</w>'     (count 5)
merge 10: 'w'     + 'i'        (count 3)

final segmentation:
  5 x low</w>
  2 x low e r </w>
  6 x newest</w>
  3 x wi d est</w>
```

Python's `max` returns the first maximal key it meets, and a `Counter` remembers insertion order, so "first pair seen" is exactly what the code does. After 10 merges the vocabulary holds 11 starting symbols (10 letters plus `</w>`) and 10 merged ones: 21 entries.

> [!KEY-INSIGHT]
> The output of BPE training is not just a vocabulary; it is an **ordered list of merge rules**. The order is part of the tokenizer: the same rules applied in a different order can split words differently.

## Encoding a new word

To tokenize a word, split it into characters plus `</w>`, then repeatedly apply the **lowest-ranked** (earliest learned) merge that matches an adjacent pair, until no learned pair is left. This is how GPT-2's reference `encoder.py` works: at each step it picks the adjacent pair with the smallest rank in its merge table.

![Encoding lowest step by step: rank 1 makes es, rank 2 est, rank 3 attaches the end marker, rank 4 lo, rank 5 low, ending at two tokens](diagrams/23.1-encode.svg "Encoding replays the training merges, earliest first.")

```python
# The 10 merges learned above, in order (rank 1 first)
merges = [("e", "s"), ("es", "t"), ("est", "</w>"), ("l", "o"), ("lo", "w"),
          ("n", "e"), ("ne", "w"), ("new", "est</w>"), ("low", "</w>"), ("w", "i")]
rank = {pair: r for r, pair in enumerate(merges)}      # lower rank = learned earlier

def merge_pair(symbols, pair):
    new, i = [], 0
    while i < len(symbols):
        if i + 1 < len(symbols) and (symbols[i], symbols[i + 1]) == pair:
            new.append(symbols[i] + symbols[i + 1])
            i += 2
        else:
            new.append(symbols[i])
            i += 1
    return new

def encode_word(word, verbose=False):
    """Split into characters, then keep applying the best-ranked merge."""
    symbols = list(word) + ["</w>"]
    while len(symbols) > 1:
        pairs = zip(symbols, symbols[1:])
        best = min(pairs, key=lambda p: rank.get(p, float("inf")))
        if best not in rank:
            break                                      # no learned merge applies
        symbols = merge_pair(symbols, best)
        if verbose:
            print(f"  rank {rank[best] + 1}: {best[0] + best[1]!r:9} -> {symbols}")
    return symbols

print("lowest:")
encode_word("lowest", verbose=True)
for w in ["lower", "newer", "slow", "zest"]:
    print(f"{w:6} -> {encode_word(w)}")
```

```output
lowest:
  rank 1: 'es'      -> ['l', 'o', 'w', 'es', 't', '</w>']
  rank 2: 'est'     -> ['l', 'o', 'w', 'est', '</w>']
  rank 3: 'est</w>' -> ['l', 'o', 'w', 'est</w>']
  rank 4: 'lo'      -> ['lo', 'w', 'est</w>']
  rank 5: 'low'     -> ['low', 'est</w>']
lower  -> ['low', 'e', 'r', '</w>']
newer  -> ['new', 'e', 'r', '</w>']
slow   -> ['s', 'low</w>']
zest   -> ['z', 'est</w>']
```

None of "lowest", "newer" or "slow" was in the training data, yet each splits into pieces the model has seen. Look at "zest", though: `z` never occurred in training, so it is not in the vocabulary. A character-level BPE still has an unknown-symbol problem, just a smaller one. The next section removes it.

## Byte-level BPE: nothing is ever unknown

Radford et al. (2019) note that a BPE over Unicode code points would need a base vocabulary of over 130,000 symbols before a single merge, far more than the 32,000 to 64,000 tokens typical of BPE vocabularies. Their fix for GPT-2: run BPE on the **UTF-8 bytes** of the text. There are only 256 possible byte values, and every string is a sequence of them.

![The string naïve plus a waving-hand emoji: ASCII letters are one byte each, ï is the two bytes 195 175, the emoji is the four bytes 240 159 145 139](diagrams/23.1-bytes.svg "Every character is 1 to 4 UTF-8 bytes, and every byte is already in the vocabulary.")

GPT-2 adds one more step, **pre-tokenization**: a regular expression first cuts the text into chunks, and merges never cross a chunk boundary. Radford et al. (2019) report that without it BPE wasted vocabulary slots on variants such as "dog.", "dog!" and "dog?", so they prevent merges across character categories (letters, digits, punctuation), with an exception for spaces. In the GPT-2 pattern, a word keeps its leading space: " better" is one chunk.

The code below trains a byte-level BPE on the Zen of Python, an 856-byte text that ships with every Python install. It uses a simplified, ASCII-only version of the GPT-2 pattern, because Python's built-in `re` module does not support the Unicode classes `\p{L}` (letters) and `\p{N}` (numbers) that the real pattern uses. It also leaves out the real pattern's first alternatives, which split off English contractions such as `'s`, `'t` and `'re`.

```python
import codecs, contextlib, io, re
from collections import Counter

with contextlib.redirect_stdout(io.StringIO()):
    import this                              # the Zen of Python, stored ROT13-encoded
text = codecs.decode(this.s, "rot13")

# Simplified GPT-2-style pre-tokenizer: a word keeps its leading space,
# and letters, digits and punctuation never share a chunk.
PAT = re.compile(r" ?[A-Za-z]+| ?[0-9]+| ?[^\sA-Za-z0-9]+|\s+(?!\S)|\s+")

def chunks(s):
    return [tuple(m.group().encode("utf-8")) for m in PAT.finditer(s)]

def merge_ids(ids, pair, new_id):
    out, i = [], 0
    while i < len(ids):
        if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
            out.append(new_id); i += 2
        else:
            out.append(ids[i]); i += 1
    return tuple(out)

def train(text, num_merges):
    words = Counter(chunks(text))            # chunk -> frequency
    vocab = {i: bytes([i]) for i in range(256)}   # 256 single-byte tokens
    merges = {}                              # (id, id) -> new id, in order
    for k in range(num_merges):
        counts = Counter()
        for w, f in words.items():
            for p in zip(w, w[1:]):
                counts[p] += f
        if not counts:
            break
        pair = max(counts, key=counts.get)
        new_id = 256 + k
        merges[pair] = new_id
        vocab[new_id] = vocab[pair[0]] + vocab[pair[1]]
        words = Counter({merge_ids(w, pair, new_id): f for w, f in words.items()})
    return merges, vocab

def encode(s, merges):
    ids = []
    for w in chunks(s):
        while len(w) > 1:
            pair = min(zip(w, w[1:]), key=lambda p: merges.get(p, float("inf")))
            if pair not in merges:
                break
            w = merge_ids(w, pair, merges[pair])
        ids.extend(w)
    return ids

def decode(ids, vocab):
    return b"".join(vocab[i] for i in ids).decode("utf-8", errors="replace")

merges, vocab = train(text, 200)
print("first 8 merges:", [vocab[i].decode() for i in range(256, 264)])
ids = encode(text, merges)
print(f"Zen of Python: {len(text.encode())} bytes -> {len(ids)} tokens "
      f"({len(text.encode()) / len(ids):.2f} bytes per token)")
print("round trip ok:", decode(ids, vocab) == text)

new = "Beautiful naïveté 👋"
ids = encode(new, merges)
print("unseen text :", new, "->", len(new.encode()), "bytes ->", len(ids), "tokens")
print("tokens      :", [vocab[i] for i in ids])
print("round trip ok:", decode(ids, vocab) == new)
```

```output
first 8 merges: [' t', ' i', ' b', ' th', 'er', ' be', 'pl', ' is']
Zen of Python: 856 bytes -> 284 tokens (3.01 bytes per token)
round trip ok: True
unseen text : Beautiful naïveté 👋 -> 24 bytes -> 15 tokens
tokens      : [b'Beautiful', b' n', b'a', b'\xc3', b'\xaf', b'v', b'e', b't', b'\xc3', b'\xa9', b' ', b'\xf0', b'\x9f', b'\x91', b'\x8b']
round trip ok: True
```

Six of the first eight merges start with a space (" t", " i", " b", " th", " be", " is"): in this pattern almost every word chunk begins with a space. The accented letters and the emoji were never seen in training, so they fall back to single bytes, but they still encode and decode exactly. A token can be a fragment of a character (`b'\xc3'` is half of "ï"), which is why `decode` joins all the bytes first and only then turns them back into text. (Real GPT-2 vocabulary files store each byte as a printable stand-in character; Lesson 23.3 explains that table, the source of the `Ġ` in GPT-2 token lists.)

How many merges should you learn? Each merge adds one vocabulary entry and makes sequences shorter:

![Line chart of bytes per token against number of merges on the Zen of Python: 1.00 at 0, 3.01 at 200, flattening at 4.30 when training stops at 285 merges](diagrams/23.1-compression.svg "Compression on the training text itself. Real vocabularies are trained on gigabytes.")

On this tiny text, training runs out of pairs after 285 merges, when every chunk has become a single token; at that point BPE has turned back into a word-level vocabulary for this one text. Real tokenizers train on far larger corpora and stop at a chosen size. GPT-2's vocabulary has 50,257 entries (Radford et al., 2019): `tiktoken` defines it as 50,256 byte-level BPE tokens plus one special token, <|endoftext|>, so 50,256 − 256 = 50,000 merges.

> [!TIP]
> Bytes per token on the training text overstates real compression: rare words in the training text got their own merges, which new text will not reuse (reasoning, not a measured result). Measure on held-out text before comparing tokenizers.

## Under the hood: cost

Reasoning from the code, not a published benchmark: each training step above rescans every unique chunk, so training costs roughly (number of merges) × (total symbols in the unique chunks). That is fine for an 856-byte text and hopeless for gigabytes. Sennrich et al. (2016) note that in practice they index all pairs and update the data structures incrementally; the point is that a merge only changes the counts of words that contain the merged pair, so only those need revisiting. Encoding a chunk of length L with the loop above takes up to L − 1 rounds, each scanning the chunk, so it is quadratic in chunk length; pre-tokenization keeps chunks short, and real encoders also cache results per chunk (GPT-2's `encoder.py` does). Lesson 23.3 measures how much that cache helps.

## Common traps

> [!TRAP]
> **Merging with `str.replace`.** If a word is stored as the string `"ab c d"`, replacing `"b c"` with `"bc"` gives `"abc d"`: it glues `ab` and `c` together even though `(b, c)` was never an adjacent pair. Store symbols as tuples, or use the boundary-aware regex from Sennrich et al. (2016).

> [!TRAP]
> **Unstated tie-breaking.** Hugging Face `tokenizers` 0.23.3, trained on the same toy corpus (with the end marker written as `_`), also picks `e + s` first but picks `t + _` second: same counts, different tie rule. If two of your tokenizers must agree, fix the rule, or keep the exact merge list.

> [!TRAP]
> **Silently dropped characters.** A character-level BPE has no id for an unseen character. In that same `tokenizers` run, with no `unk_token` set, `"zest_"` encoded to `['est_']`: the `z` simply vanished. Byte-level BPE avoids this, but only if all 256 bytes are in the vocabulary; Lesson 23.3 shows the same silent loss in a byte-level BPE trained without them.

> [!TRAP]
> **An ASCII-only pre-tokenizer.** The simplified pattern in this lesson treats "ï" as punctuation, so " naïveté" is cut into four chunks (`' na'`, `'ï'`, `'vet'`, `'é'`). The real GPT-2 pattern uses `\p{L}` from the third-party `regex` module.

> [!ADVANCED]
> BPE is greedy: it never revisits a merge, and each word always gets the same segmentation. BPE-dropout (Provilkov, Emelianenko and Voita, 2020) keeps the learned merge table but, when segmenting the model's training data, drops each candidate merge with probability p (usually 0.1), so the model sees many segmentations of the same word; at inference it uses plain BPE (p = 0). The Unigram language-model tokenizer in Lesson 23.2 takes a probabilistic route instead.

## Summary

- A tokenizer maps text to integer ids. Subword tokenizers sit between words (unknown-word problem) and characters (long sequences).
- BPE training repeats one step: count adjacent pairs weighted by frequency, merge the most frequent, record the merge. Vocabulary size = starting alphabet + number of merges.
- The tokenizer is the **ordered** merge list. Encoding replays merges by rank, earliest first; ties in training must be broken by a fixed rule.
- Byte-level BPE (GPT-2) starts from the 256 byte values, so every string can be encoded and decoded exactly. Pre-tokenization keeps merges inside word-like chunks.

## Quiz time

### Question 1: Train by hand

A corpus has the word counts hug 10, pug 5, pun 12, bun 4, hugs 5 (no end-of-word marker). Which two merges does BPE learn first, and with what counts?

<details><summary>Show Solution</summary>

Step 0 counts: `u g` appears in hug, pug and hugs: 10 + 5 + 5 = 20. `p u` = 5 + 12 = 17, `u n` = 12 + 4 = 16, `h u` = 10 + 5 = 15. Merge 1 is `u + g` (20).

After it, hug is `h ug`, pug is `p ug`, hugs is `h ug s`. `p u` now only occurs in pun (12), while `u n` still occurs in pun and bun (16) and `h ug` is 15. Merge 2 is `u + n` (16). Running `train_bpe` on this corpus prints exactly these two, followed by `h + ug` (15).

</details>

### Question 2: Predict the merge

The word `a a a a` is one symbol tuple. How many times does `pair_counts` count the pair `(a, a)`, and what does `merge` turn the word into?

<details><summary>Show Solution</summary>

`zip(symbols, symbols[1:])` yields 3 overlapping pairs, so the count is 3. But `merge` scans left to right and skips both symbols after each match, so only 2 merges fit: the result is `('aa', 'aa')`. Pair counts can overstate how many merges actually happen when a pair overlaps itself; this is normal, and the `tiktoken._educational` trainer used later in this lesson behaves the same way.

</details>

### Question 3: Spot the bug

This merge function, a shortcut you will often see, stores each word as a space-separated string. Find an input where it produces a wrong word.

```python
def merge_vocab(pair, v_in):
    bigram, replacement = " ".join(pair), "".join(pair)
    return [(word.replace(bigram, replacement), freq) for word, freq in v_in]
```

<details><summary>Show Solution</summary>

Take the word `"ab c d"` (symbols `ab`, `c`, `d`) and the pair `("b", "c")`. `"ab c d".replace("b c", "bc")` returns `"abc d"`, merging `ab` with `c`. The substring match ignores symbol boundaries. Sennrich et al. (2016) guard against this with a regex that requires whitespace or the string edge on both sides: `(?<!\S)b c(?!\S)` leaves `"ab c d"` unchanged. Storing symbols as tuples, as this lesson does, avoids the problem entirely.

</details>

### Question 4: Count the vocabulary

GPT-2's vocabulary has 50,257 entries and is byte-level. How many merges were learned, and why is the answer not 50,257 − 256?

<details><summary>Show Solution</summary>

One entry, <|endoftext|> (id 50,256), is a special token added by hand, not learned by merging. That leaves 50,256 BPE tokens, of which 256 are the single bytes, so 50,256 − 256 = 50,000 merges.

</details>

### Question 5: Explain the failure

The character-level tokenizer from this lesson encodes "zest" as `['z', 'est</w>']`. Why is this a problem, and why can the byte-level tokenizer never hit it?

<details><summary>Show Solution</summary>

`z` never appeared in the training corpus, so it is not in the vocabulary and has no id: the model cannot receive it (a real system would map it to `[UNK]` or drop it). The byte-level tokenizer's base vocabulary is all 256 byte values, and every UTF-8 string is a sequence of bytes, so the worst case is that an unseen character falls back to its raw bytes, as "ï" and the emoji did above.

</details>

## Exercise: decode and round-trip

Using `encode_word` and the 10 toy merges, write `encode(text)`, which splits on spaces and encodes each word, and `decode(tokens)`, which turns the tokens back into the original text. Test that `"the newest wider lowest slow"` survives the round trip. (Run your code after the encoding block, so `encode_word` exists.)

<details><summary>Show Solution</summary>

The `</w>` marker is what makes decoding possible: join all tokens, then turn each marker back into a space.

```python
def encode(text):
    return [tok for word in text.split() for tok in encode_word(word)]

def decode(tokens):
    return "".join(tokens).replace("</w>", " ").rstrip()

text = "the newest wider lowest slow"
tokens = encode(text)
print(tokens)
print(repr(decode(tokens)), decode(tokens) == text)
```

```output
['t', 'h', 'e', '</w>', 'newest</w>', 'wi', 'd', 'e', 'r', '</w>', 'low', 'est</w>', 's', 'low</w>']

```

Note that `t`, `h`, `e` and `</w>` stay separate: the toy merges never saw "the". The decoder only round-trips text with single spaces between words. The byte-level tokenizer above has no such limit: spaces, tabs and newlines are bytes like any other, so any spacing survives.
