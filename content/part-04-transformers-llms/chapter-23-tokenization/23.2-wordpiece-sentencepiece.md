Byte-Pair Encoding (BPE, Lesson 23.1) is one way to build a subword vocabulary. In this lesson you will implement the two other ways that matter in practice: **WordPiece**, the tokenizer behind BERT (Bidirectional Encoder Representations from Transformers), and the **Unigram language model**, the probabilistic tokenizer that **SentencePiece** made popular. You will encode words by hand, train a tiny Unigram vocabulary from scratch, and see why SentencePiece can turn tokens back into the exact original text.

**You need:** BPE training and encoding (Lesson 23.1), Python dictionaries, and logarithms ($\log(ab) = \log a + \log b$).

## The problem these methods solve

The pipeline from Lesson 23.1 has three weak spots that these methods attack:

- **Merge choice.** BPE merges the *most frequent* pair. A pair can be frequent just because both halves are common letters, like `e` and `s`. WordPiece asks a sharper question: do these two pieces occur together *more than chance*?
- **One answer only.** BPE gives every word exactly one segmentation. But "hugs" could be `hug s` or `hu gs`, and a model that sees several plausible splits during training can become more robust. The Unigram model assigns a *probability* to every split (Kudo, 2018).
- **Lost spaces.** Classic tokenizers (BERT's, or the `</w>` version in Lesson 23.1) first split text on spaces and punctuation, then throw the spaces away. You cannot recover the original string (GPT-2's byte-level BPE avoids this part by keeping each space as a byte), and languages written without spaces (Japanese, Chinese, Thai) need a separate word splitter. SentencePiece treats the space as an ordinary symbol, `▁` (Kudo and Richardson, 2018).

The names are easy to mix up, so fix them first. **WordPiece** and **Unigram** are *algorithms*. **SentencePiece** is a *library* that implements two algorithms, BPE and Unigram:

![Three columns comparing WordPiece, BPE and Unigram LM by how they train and encode, with a dashed box showing that the SentencePiece library covers BPE and Unigram](diagrams/23.2-family.svg "Two algorithms that grow a vocabulary, one that shrinks it, and the library that ships two of them.")

Sources for the "used by" row: BERT uses WordPiece with a 30,000-token vocabulary (Devlin et al., 2018); the original LLaMA uses BPE "using the implementation from SentencePiece" (Touvron et al., 2023); the Hugging Face course lists T5, ALBERT and XLNet as Unigram users, and T5's released `spiece.model` file indeed records `model_type: UNIGRAM`.

## WordPiece encoding: greedy longest match

WordPiece was introduced for Japanese and Korean voice search (Schuster and Nakajima, 2012) and later used in Google's translation system (Wu et al., 2016) and BERT. In BERT, a piece that continues a word carries the prefix `##`, so `##able` means "able, but not at the start of a word". Encoding one word works like this (BERT's `tokenization.py` calls it "greedy longest-match-first"):

1. Start at the first character. Try the **longest** remaining substring; if it is not in the vocabulary, drop one character from the end and try again.
2. Keep the first match, move to where it ended, and repeat with `##` added in front.
3. If at some position **nothing** matches, give up on the whole word and output `[UNK]` (unknown).

![The word unaffable as nine character cells; three steps match un after 8 tries, ##aff after 5 tries and ##able on the first try](diagrams/23.2-maxmatch.svg "Greedy longest-match-first on unaffable. Each step tries the longest candidate first.")

Here it is in pure Python, with a tiny vocabulary:

```python
def wordpiece_encode(word, vocab, unk="[UNK]", prefix="##"):
    """Greedy longest-match-first (MaxMatch), as in BERT's WordpieceTokenizer."""
    pieces, start = [], 0
    while start < len(word):
        end = len(word)
        while end > start:                       # try the longest candidate first
            piece = word[start:end]
            if start > 0:
                piece = prefix + piece           # non-initial pieces carry "##"
            if piece in vocab:
                break
            end -= 1
        else:                                    # no piece matched at all
            return [unk]                         # the WHOLE word becomes [UNK]
        pieces.append(piece)
        start = end
    return pieces

vocab = {"[UNK]", "u", "un", "a", "aff", "able", "##a", "##f", "##aff",
         "##able", "##ab", "##le", "##s", "b", "##b", "##u", "##n"}

for w in ["unaffable", "unable", "affable", "bun", "buns", "unzip"]:
    print(f"{w:<10} -> {wordpiece_encode(w, vocab)}")
```

## WordPiece training: merge by a ratio, not a count

Training starts, like BPE, from single characters (with `##` on non-initial ones) and merges pairs until the vocabulary is big enough. Google never released its WordPiece training code. The rule below is the Hugging Face course's reconstruction from the literature. It scores each adjacent pair $(a, b)$:

$$
\text{score}(a, b) = \frac{\text{count}(ab)}{\text{count}(a)\,\text{count}(b)}
$$

**Worked example.** Take the corpus `low`×5, `lower`×2, `newest`×6, `widest`×3. The pair `##e ##s` occurs 9 times, tied with `##s ##t` for the most of any pair, so BPE merges it first (ties go to the pair seen first). But `##e` occurs 17 times in total, so its score is only $9 / (17 \times 9) = 0.059$. The pair `w ##i` occurs just 3 times, but `w` and `##i` *never appear apart*: $3 / (3 \times 3) = 0.333$, the highest score. WordPiece merges `w ##i` first.

```python
from collections import Counter

corpus = {"low": 5, "lower": 2, "newest": 6, "widest": 3}      # word -> frequency
splits = {w: [w[0]] + ["##" + c for c in w[1:]] for w in corpus} # "low" -> l ##o ##w

unit, pair = Counter(), Counter()
for w, f in corpus.items():
    s = splits[w]
    for u in s:
        unit[u] += f
    for a, b in zip(s, s[1:]):
        pair[a, b] += f

score = {ab: pair[ab] / (unit[ab[0]] * unit[ab[1]]) for ab in pair}
print(f"{'pair':<14}{'count(ab)':>10}{'count(a)':>10}{'count(b)':>10}{'score':>8}")
for (a, b) in sorted(pair, key=pair.get, reverse=True):
    print(f"{a + ' ' + b:<14}{pair[a, b]:>10}{unit[a]:>10}{unit[b]:>10}{score[a, b]:>8.3f}")
print("BPE merges first:      ", max(pair, key=pair.get))
print("WordPiece merges first:", max(score, key=score.get))
```

```python
from collections import Counter

corpus = {"low": 5, "lower": 2, "newest": 6, "widest": 3}

def stats(splits):
    unit, pair = Counter(), Counter()
    for w, f in corpus.items():
        s = splits[w]
        for u in s:
            unit[u] += f
        for a, b in zip(s, s[1:]):
            pair[a, b] += f
    return unit, pair

def merge(a, b, splits):
    new = a + b.removeprefix("##")              # "w" + "##i" -> "wi"
    for w, s in splits.items():
        out, i = [], 0
        while i < len(s):
            if s[i:i + 2] == [a, b]:
                out.append(new); i += 2
            else:
                out.append(s[i]); i += 1
        splits[w] = out
    return new

for name in ["BPE", "WordPiece"]:
    splits = {w: [w[0]] + ["##" + c for c in w[1:]] for w in corpus}
    merges = []
    for _ in range(5):
        unit, pair = stats(splits)
        if name == "BPE":
            best = max(pair, key=pair.get)       # ties: first pair seen wins
        else:
            best = max(pair, key=lambda ab: pair[ab] / (unit[ab[0]] * unit[ab[1]]))
        merges.append(merge(*best, splits))
    print(f"{name:<9} merges: {merges}")
    print(f"{'':<9} newest -> {splits['newest']}, widest -> {splits['widest']}")
```

**What the score measures** (reasoning from the formula, not a published derivation). Let $N$ be the total number of units in the corpus, and estimate $p(a) = \text{count}(a)/N$ and $p(ab) = \text{count}(ab)/N$ (using $N$ for pairs too is an approximation: there are slightly fewer pairs than units). Then $\text{score} \cdot N = p(ab) / \big(p(a)\,p(b)\big)$: how much more often $a$ and $b$ sit side by side than they would if they were placed independently. Its logarithm is the *pointwise mutual information* of the pair. Multiplying every score by the same $N$ does not change which pair wins.

> [!KEY-INSIGHT]
> BPE rewards pairs that are *common*. WordPiece rewards pairs that are *glued together*: a rare pair whose parts almost never occur apart beats a frequent pair of common letters.

## The Unigram language model

The Unigram model flips the question. Instead of building rules for *how* to split, it gives every piece $x$ a probability $p(x)$ and assumes pieces occur independently. The probability of one segmentation $\mathbf{x} = (x_1, \dots, x_M)$ is the product (Kudo, 2018, Eq. 6):

$$
P(\mathbf{x}) = \prod_{i=1}^{M} p(x_i), \qquad \sum_{x \in V} p(x) = 1
$$

where $V$ is the vocabulary. To encode a word, pick the segmentation with the highest $P(\mathbf{x})$.

**Worked example.** Suppose the vocabulary contains these pieces (along with many others): `h` 0.05, `u` 0.05, `g` 0.05, `s` 0.10, `hu` 0.05, `ug` 0.10, `gs` 0.05, `hug` 0.15. The word "hugs" has six valid segmentations:

- `hug s`: $0.15 \times 0.10 = 0.015$
- `hu gs`: $0.05 \times 0.05 = 0.0025$
- `h ug s`: $0.05 \times 0.10 \times 0.10 = 0.0005$
- three more using only short pieces, each below 0.0003.

So the encoding is `hug s`. Long, probable pieces win because every extra piece multiplies in another factor smaller than 1.

Listing every split is exponential in word length, so real tokenizers use the **Viterbi algorithm** (dynamic programming). Draw the word as a graph: nodes are the positions between characters, and every vocabulary piece is an edge from where it starts to where it ends. Walk left to right, and at each node keep only the best log-probability of reaching it:

![A lattice with nodes 0 to 4 between the letters h, u, g, s; edges for each vocabulary piece labelled with its probability; the path hug then s is highlighted, with best log probabilities 0, -3.00, -3.00, -1.90, -4.20 under the nodes](diagrams/23.2-lattice.svg "Every path from node 0 to node 4 is one segmentation. Viterbi keeps only the best way to reach each node.")

```python
import math
from itertools import combinations

# A few pieces from a (larger) unigram vocabulary, with their probabilities p(piece)
p = {"h": 0.05, "u": 0.05, "g": 0.05, "s": 0.10,
     "hu": 0.05, "ug": 0.10, "gs": 0.05, "hug": 0.15}

def viterbi(word, p):
    """Most probable segmentation under P(x) = prod p(x_i). Works in log space."""
    n = len(word)
    best = [0.0] + [-math.inf] * n     # best[i] = best log-prob of word[:i]
    back = [0] * (n + 1)               # back[i] = start of the last piece
    for end in range(1, n + 1):
        for start in range(end):
            piece = word[start:end]
            if piece in p and best[start] + math.log(p[piece]) > best[end]:
                best[end] = best[start] + math.log(p[piece])
                back[end] = start
    pieces, end = [], n
    while end > 0:
        pieces.append(word[back[end]:end]); end = back[end]
    return pieces[::-1], best[n]

def all_segmentations(word, p):
    """Brute force: every way to cut the word, keeping cuts whose pieces are all in p."""
    n = len(word)
    for k in range(n):
        for cuts in combinations(range(1, n), k):
            bounds = (0, *cuts, n)
            pieces = [word[a:b] for a, b in zip(bounds, bounds[1:])]
            if all(x in p for x in pieces):
                yield pieces, math.prod(p[x] for x in pieces)

segs = sorted(all_segmentations("hugs", p), key=lambda t: -t[1])
Z = sum(prob for _, prob in segs)          # P("hugs") summed over all segmentations
for pieces, prob in segs:
    print(f"{' '.join(pieces):<10} P = {prob:.7f}   P(x | 'hugs') = {prob / Z:.3f}")
best, logp = viterbi("hugs", p)
print("Viterbi:", best, f"log P = {logp:.3f}, P = {math.exp(logp):.7f}")
```

hug s      P = 0.0150000   P(x | 'hugs') = 0.816
hu gs      P = 0.0025000   P(x | 'hugs') = 0.136
h ug s     P = 0.0005000   P(x | 'hugs') = 0.027
hu g s     P = 0.0002500   P(x | 'hugs') = 0.014
h u gs     P = 0.0001250   P(x | 'hugs') = 0.007
h u g s    P = 0.0000125   P(x | 'hugs') = 0.001

Viterbi agrees with brute force. The last column, $P(\mathbf{x} \mid X) = P(\mathbf{x}) / \sum_{\mathbf{x}'} P(\mathbf{x}')$, is the probability of each segmentation *given* the word $X$. BPE and WordPiece cannot produce this number; the next two sections use it.

## Training Unigram: start big, then prune

The Unigram vocabulary is learned top-down (Kudo, 2018, Section 3.2):

1. **Seed** a large vocabulary: all characters plus frequent substrings.
2. **EM** (expectation–maximisation): with the vocabulary fixed, re-estimate $p(x)$. The E-step computes how often each piece is *expected* to appear, averaged over all segmentations weighted by their probability. The M-step normalises those expected counts into probabilities.
3. **Prune**: for each piece, measure how much the corpus log-likelihood $L = \sum_{\text{words}} \text{freq} \cdot \log P(\text{word})$ would drop if it were removed. Keep the top $\eta\%$ (the paper's example is 80%) and *never* remove single characters, so every word can still be encoded.
4. Repeat 2–3 until the target size is reached.

We ran exactly this loop on a toy corpus: 8 common verbs in four forms ("walk, walks, walked, walking", …) plus 12 rare words seen once. The vocabulary shrinks from 211 seed pieces to 36: the 24 characters plus 12 learned pieces. Merging goes the other way. Run on the same corpus, BPE climbs from 24 to 36 in 12 merges; WordPiece starts higher, at 32 units, because `k` and `##k` are different symbols:

![Chart of vocabulary size on a log scale: Unigram falls in 8 pruning rounds from 211 through 168, 134, 107, 85, 68, 54, 43 to 36; BPE climbs in 12 merges from 24 to 36 and WordPiece from 32 to 44](diagrams/23.2-grow-vs-prune.svg "Same toy corpus. Merging grows up from the alphabet; Unigram prunes down from 211 pieces.")

The surviving pieces are mostly the stems plus `ed` and `ing`, so on this toy corpus the model recovers the morphology: `walking → walk ing`, `talked → talk ed`, and the unseen word `stalking → s talk ing`. BPE's first 12 merges on the same corpus also include `ed` and `ing`, so the toy cannot tell the two apart; Bostrom and Durrett (2020) measure the difference at scale and find Unigram pieces align more closely with morphology than BPE's.

Simplifications compared with SentencePiece: the loss of each piece is computed exactly by recomputing $L$ (SentencePiece approximates it by assuming each removed piece is replaced by its second-best segmentation), and character probabilities have a tiny floor so that no word becomes impossible to encode.

```python
import math
import random
from collections import Counter

# Toy corpus: word -> frequency. 8 common verbs in 4 forms, plus a long tail of
# 12 rare words seen once (real corpora always have such a tail).
random.seed(0)
suffixes = ["", "s", "ed", "ing"]
common = ["walk", "talk", "jump", "play", "look", "cook", "help", "kick"]
rare = ["jog", "nod", "hop", "zip", "mix", "fix", "pack", "lock", "rock", "wish", "rush", "bark"]
corpus = {stem + suf: random.randint(3, 9) for stem in common for suf in suffixes}
for stem in rare:
    corpus[stem + random.choice(suffixes)] = 1

def pieces_in(word, p):
    """Every (start, end, piece) in the lattice of `word`."""
    return [(i, j, word[i:j]) for i in range(len(word))
            for j in range(i + 1, len(word) + 1) if word[i:j] in p]

def forward(word, p):          # alpha[j] = P(all segmentations of word[:j])
    alpha = [1.0] + [0.0] * len(word)
    for i, j, x in sorted(pieces_in(word, p), key=lambda t: t[1]):
        alpha[j] += alpha[i] * p[x]
    return alpha

def backward(word, p):         # beta[i] = P(all segmentations of word[i:])
    beta = [0.0] * len(word) + [1.0]
    for i, j, x in sorted(pieces_in(word, p), key=lambda t: -t[0]):
        beta[i] += p[x] * beta[j]
    return beta

def log_likelihood(p):         # L = sum over words of freq * log P(word)
    return sum(f * math.log(forward(w, p)[-1]) for w, f in corpus.items())

def em_step(p):
    """E-step: expected count of each piece over ALL segmentations. M-step: normalise."""
    counts = Counter()
    for w, f in corpus.items():
        alpha, beta = forward(w, p), backward(w, p)
        for i, j, x in pieces_in(w, p):
            counts[x] += f * alpha[i] * p[x] * beta[j] / alpha[-1]
    for c in chars:            # tiny floor so every word stays encodable (toy safeguard)
        counts[c] = max(counts[c], 1e-3)
    total = sum(counts.values())
    return {x: c / total for x, c in counts.items()}

def normalise(q):
    s = sum(q.values())
    return {x: v / s for x, v in q.items()}

def viterbi(word, p):
    best, back = [0.0] + [-math.inf] * len(word), [0] * (len(word) + 1)
    for i, j, x in sorted(pieces_in(word, p), key=lambda t: t[1]):
        if best[i] + math.log(p[x]) > best[j]:
            best[j], back[j] = best[i] + math.log(p[x]), i
    out, j = [], len(word)
    while j > 0:
        out.append(word[back[j]:j]); j = back[j]
    return out[::-1]

# 1. Seed vocabulary: all characters + every substring seen at least twice.
seed = Counter()
for w, f in corpus.items():
    for i in range(len(w)):
        for j in range(i + 1, len(w) + 1):
            seed[w[i:j]] += f
p = normalise({x: c for x, c in seed.items() if len(x) == 1 or c >= 2})
chars = {x for x in p if len(x) == 1}
target = len(chars) + 12                   # 12 multi-character pieces
print(f"seed: {len(p)} pieces ({len(chars)} characters), L = {log_likelihood(p):.1f}")

# 2. Repeat: EM, then drop the 20% of pieces whose removal hurts L least.
sizes = [len(p)]
while len(p) > target:
    for _ in range(3):
        p = em_step(p)
    base = log_likelihood(p)
    loss = {x: base - log_likelihood(normalise({y: v for y, v in p.items() if y != x}))
            for x in p if x not in chars}  # characters are never removed
    n_keep = max(target, int(0.8 * len(p))) - len(chars)
    survivors = set(sorted(loss, key=loss.get, reverse=True)[:n_keep]) | chars
    p = normalise({x: v for x, v in p.items() if x in survivors})
    sizes.append(len(p))
    print(f"pruned to {len(p):>3} pieces, L = {log_likelihood(p):.1f}")
for _ in range(3):
    p = em_step(p)

print("sizes:", sizes)
print("multi-character pieces:", sorted((x for x in p if len(x) > 1), key=p.get, reverse=True))
for w in ["walking", "talked", "played", "jumps", "stalking", "replayed", "unhelpful"]:
    print(f"{w:<9} -> {viterbi(w, p)}{'   (unseen)' if w not in corpus else ''}")
```

Read the log-likelihood column: the first few prunings remove pieces nobody needs and $L$ barely moves; once the vocabulary is tight, every removal costs likelihood. Delete the 12 rare words and rerun: the model keeps the 8 stems but stores `walking`, `talking`, `cooking` and `helping` whole and never learns `ed` or `ing`. With every word frequent, whole words are cheap; the rare tail is what makes reusable suffixes pay off.

</details>

## Subword regularisation: sampling segmentations

Because Unigram defines $P(\mathbf{x} \mid X)$, you can **sample** a segmentation instead of always taking the best one. Kudo (2018) does this during training, a fresh sample for each update, so the model sees `hug s` most of the time and `hu gs` occasionally. He calls it **subword regularisation** and reports consistent gains in translation, especially for low-resource and out-of-domain data. A parameter $\alpha$ reshapes the distribution as $P(\mathbf{x} \mid X)^{\alpha}$, renormalised: small $\alpha$ flattens it, large $\alpha$ approaches the Viterbi answer.

```python
import math, random
from collections import Counter
from itertools import combinations

p = {"h": 0.05, "u": 0.05, "g": 0.05, "s": 0.10,
     "hu": 0.05, "ug": 0.10, "gs": 0.05, "hug": 0.15}

def all_segmentations(word, p):
    n = len(word)
    for k in range(n):
        for cuts in combinations(range(1, n), k):
            b = (0, *cuts, n)
            pieces = tuple(word[i:j] for i, j in zip(b, b[1:]))
            if all(x in p for x in pieces):
                yield pieces, math.prod(p[x] for x in pieces)

segs = dict(all_segmentations("hugs", p))
rng = random.Random(0)
for alpha in [1.0, 0.1]:
    w = {s: prob ** alpha for s, prob in segs.items()}     # sharpen or flatten
    Z = sum(w.values())
    draws = Counter(rng.choices(list(w), weights=list(w.values()), k=1000))
    print(f"alpha = {alpha}")
    for s in sorted(w, key=w.get, reverse=True):
        print(f"   {' '.join(s):<9} P = {w[s] / Z:.3f}   drawn {draws[s]:>3} / 1000")
```

```output

   hug s     P = 0.816   drawn 806 / 1000
   hu gs     P = 0.136   drawn 148 / 1000
   h ug s    P = 0.027   drawn  28 / 1000
   hu g s    P = 0.014   drawn  10 / 1000
   h u gs    P = 0.007   drawn   6 / 1000
   h u g s   P = 0.001   drawn   2 / 1000
alpha = 0.1
   hug s     P = 0.231   drawn 226 / 1000
   hu gs     P = 0.193   drawn 184 / 1000
   h ug s    P = 0.165   drawn 144 / 1000

```

Real sentences have far too many segmentations to list, so SentencePiece samples directly from the lattice with a forward-filtering, backward-sampling pass (Kudo, 2018, Section 3.3).

## SentencePiece: whitespace is just a symbol

SentencePiece (Kudo and Richardson, 2018) trains directly on raw sentences. Before training it replaces every space with the meta-symbol `▁` (U+2581) and puts one in front of the sentence, so "Eva cooked." becomes `▁Eva▁cooked.`. The space is now part of the pieces, and decoding is a plain string join (the README calls detokenization "a simple, lossless string join operation"). WordPiece, in contrast, discards spaces during pre-tokenization, so different inputs can collapse to the same tokens:

![Top: two WordPiece inputs with different spacing map to identical tokens and decode to one guessed string. Bottom: two SentencePiece inputs map to different token sequences that each decode back exactly](diagrams/23.2-lossless.svg "Both token sequences come from code in this lesson: the tokenizers block above and the SentencePiece block below.")

SentencePiece's default algorithm is Unigram (`model_type`, default `"unigram"`, in the options docs); `model_type="bpe"` gives BPE. Its version of the pruning loop is controlled by `shrinking_factor` (default 0.75) and `num_sub_iterations` (EM steps per round, default 2).

## Common traps

> [!TRAP]
> **"SentencePiece" does not mean "Unigram".** It is a library. The original LLaMA uses SentencePiece *BPE*; T5 uses SentencePiece *Unigram*. Check `model_type` in the model's tokenizer before reasoning about its behaviour.

> [!TRAP]
> **Lossless only after normalisation.** By default SentencePiece applies `nmt_nfkc` (based on Unicode NFKC, Normalization Form Compatibility Composition, which for example maps the full-width letter U+FF21 to the ordinary A) and `remove_extra_whitespaces=true`. So an input with two spaces between "Eva" and "walked" decodes with one. The round trip is exact for the *normalised* text, not for every byte you feed in.

> [!TRAP]
> **Unknown characters.** A character never seen in training gets the `<unk>` id, as "Zoe" showed. The piece *string* still reads `Z`, which hides the problem; the id (0) and the decoded ⁇ (the default `unk_surface`: U+2047 with a space on each side) give it away. Lesson 23.3 covers **byte fallback**, which LLaMA enables so that unknown characters decompose into UTF-8 bytes instead (Touvron et al., 2023).

> [!TRAP]
> **Hugging Face's `WordPieceTrainer` is BPE inside.** In tokenizers 0.23.3, the trainer builds a `BpeTrainer` with the `##` prefix and converts the result (`trainer.rs`). It merges by raw frequency, not by the WordPiece score above. Only *encoding* is true longest-match WordPiece.

## Summary

- **WordPiece** encodes by greedy longest match with `##` for word-internal pieces. If any position fails, the whole word becomes `[UNK]`. Its training merges the pair with the highest count(ab)/(count(a)·count(b)), which favours pairs that stick together.
- **Unigram LM** scores a segmentation as $\prod p(x_i)$ and encodes with Viterbi. It trains top-down: seed a big vocabulary, run EM, prune the pieces whose removal costs least likelihood, and never remove characters.
- Unigram gives a probability for every segmentation, which enables **subword regularisation** (sampling splits during training, sharpened or flattened by $\alpha$).
- **SentencePiece** is a library implementing BPE and Unigram on raw text. Turning spaces into `▁` makes decoding a lossless join, up to its normalisation.

## Quiz time

### Question 1: Score a pair

In the corpus `low`×5, `lower`×2, `newest`×6, `widest`×3, compute the WordPiece score of `l ##o`. Would BPE or WordPiece merge it earlier, relative to `##e ##s`?

<details>
<summary>Show Solution</summary>

`l ##o` occurs 7 times (in "low" and "lower"). `l` occurs 7 times and `##o` occurs 7 times, so the score is $7 / (7 \times 7) = 0.143$. `##e ##s` scores $9 / (17 \times 9) = 0.059$. BPE prefers `##e ##s` (count 9 beats 7); WordPiece prefers `l ##o` (0.143 beats 0.059). That matches the run: BPE's first merge was `##es`, while WordPiece made `lo` its third merge, after `wi` and `wid`.

</details>

### Question 2: Predict the output

With `vocab = {"a", "ab", "##bc", "##c"}`, what does `wordpiece_encode("abc", vocab)` return? What if you delete `"##c"` from the vocabulary?

<details>
<summary>Show Solution</summary>

With `##c`: the longest match at position 0 is `ab` ("abc" is not in the vocabulary), then `##c` matches, giving `['ab', '##c']`. Without `##c`: after `ab`, nothing matches at position 2, so the whole word becomes `['[UNK]']`, even though `a ##bc` was a valid segmentation. Greedy matching never goes back to reconsider `a`. Viterbi over a Unigram model cannot fail like this as long as every character is in the vocabulary. Both answers were checked by running the function.

</details>

### Question 3: When does the winner change?

In the "hugs" example, `hug s` wins with $p(\text{hug}) \times 0.10$ and the runner-up `hu gs` has probability 0.0025. Below what value of $p(\text{hug})$ does Viterbi switch to `hu gs`? (Keep every other probability fixed.)

<details>
<summary>Show Solution</summary>

`hug s` wins while $0.10 \cdot p(\text{hug}) > 0.0025$, that is while $p(\text{hug}) > 0.025$. Below 0.025, `hu gs` has the higher probability. The other segmentations do not use `hug` and all stay below 0.0025, so they never win.

</details>

### Question 4: Explain the round trip

A colleague says: "SentencePiece is lossless, but I encoded and decoded a sentence with two spaces between 'Eva' and 'walked', and got it back with one. Is it broken?" Explain.

<details>
<summary>Show Solution</summary>

It is not broken. Text is normalised *before* encoding; the default rules (`nmt_nfkc` with `remove_extra_whitespaces=true`) collapse the two spaces into one. Encoding and decoding are lossless for the normalised string, so the double space was gone before the pieces were built. If you need exact whitespace, train with `remove_extra_whitespaces=False` (and pick a normalisation rule that suits your data).

</details>

### Question 5: Spot the bug

This evaluation loop gives a slightly different accuracy every run, even though the model and data are fixed. Why?

```python
for text, label in test_set:
    ids = sp.encode(text, enable_sampling=True, alpha=0.1, nbest_size=-1)
    correct += model.predict(ids) == label
```

<details>
<summary>Show Solution</summary>

`enable_sampling=True` draws a random segmentation on every call: that is subword regularisation, which is meant for *training*. At test time, use the deterministic Viterbi encoding, `sp.encode(text)`, so each input always gets the same tokens.

</details>

## Exercise: the forward algorithm

The brute-force code summed 6 segmentations to get $P(\text{hugs}) = 0.0183875$. Write `forward(word, p)` that computes the same total with dynamic programming: replace Viterbi's max with a sum, and do not use logs. Then use the same function to *count* the segmentations.

<details>
<summary>Show Solution</summary>

`alpha[end]` is the total probability of all segmentations of `word[:end]`. Every piece ending at `end` extends every segmentation that ends where the piece starts. Setting every probability to 1 turns the same recursion into a counter.

```python
p = {"h": 0.05, "u": 0.05, "g": 0.05, "s": 0.10,
     "hu": 0.05, "ug": 0.10, "gs": 0.05, "hug": 0.15}

def forward(word, p):
    alpha = [1.0] + [0.0] * len(word)        # alpha[0] = 1: the empty prefix
    for end in range(1, len(word) + 1):
        for start in range(end):
            if word[start:end] in p:
                alpha[end] += alpha[start] * p[word[start:end]]
    return alpha[-1]

def count_segmentations(word, p):            # same recursion with every p replaced by 1
    return forward(word, {x: 1.0 for x in p})

Z = forward("hugs", p)
print(f"P('hugs') = {Z:.7f}")
print("segmentations:", int(count_segmentations("hugs", p)))
print(f"P(hug s | hugs) = {0.15 * 0.10 / Z:.3f}")
```

```output
P('hugs') = 0.0183875
segmentations: 6
P(hug s | hugs) = 0.816
```

This sum is exactly $P(X)$ in the training objective of Section 3.2 of Kudo (2018), and its forward and backward versions give the expected counts in the EM step of the trainer above. Skipping the logs is fine for a 4-letter word; for whole sentences you would add probabilities in log space to avoid underflow.

</details>
