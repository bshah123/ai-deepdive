# 24.2 — Sinusoidal Absolute Positional Encodings (Vaswani et al.)

## Opening Motivation & Context

In the realm of natural language processing and sequence modeling, understanding the order of elements in a sequence is crucial. However, traditional models like RNNs and LSTMs process sequences sequentially, which can be computationally expensive and may not capture long-range dependencies effectively. Transformers, introduced in the seminal paper "Attention is All You Need" by Vaswani et al., address this by using self-attention mechanisms that process all elements of a sequence in parallel. But how do Transformers know the order of elements in a sequence?

This is where positional encodings come into play. Positional encodings are a way to inject information about the relative or absolute position of the tokens in the sequence into the model. In this lesson, we will explore sinusoidal absolute positional encodings, a method proposed by Vaswani et al. for the Transformer architecture.

## Core Concepts Breakdown

Positional encodings are added to the input embeddings to provide information about the position of each token in the sequence. The sinusoidal positional encoding is a function of the position and the dimension of the embedding. It uses sine and cosine functions of different frequencies to encode the position information.

> [!KEY-INSIGHT]
> The sinusoidal positional encoding captures the relative positions of tokens through the properties of sine and cosine functions. This allows the model to learn to attend to nearby positions more than distant positions, which is a desirable property for sequence modeling.

> [!BEST-PRACTICE]
> When implementing sinusoidal positional encodings, ensure that the encoding is added to the input embeddings before passing them through the Transformer layers. This ensures that the positional information is available to the self-attention mechanisms.

> [!WARNING]
> Adding positional encodings to the input embeddings after the Transformer layers will not provide the positional information to the self-attention mechanisms, as the embeddings are already processed by the Transformer layers.

## Code Demonstration & Runtime Output

```python
import torch
import torch.nn as nn
import math

class PositionalEncoding(nn.Module):
    def __init__(self, d_model: int, max_len: int = 5000):
        super(PositionalEncoding, self).__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        pe = pe.unsqueeze(0)
        self.register_buffer('pe', pe)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        x = x + self.pe[:, :x.size(1)]
        return x

# Example usage
if __name__ == "__main__":
    d_model = 512
    max_len = 100
    pos_encoder = PositionalEncoding(d_model, max_len)
    x = torch.randn(1, 10, d_model)  # (batch_size, seq_len, d_model)
    output = pos_encoder(x)
    print(output.shape)
```

