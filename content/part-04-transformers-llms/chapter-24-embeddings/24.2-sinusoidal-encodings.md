Sinusoidal positional encodings add a fixed table of sine and cosine values to the token embeddings, so that attention can tell where each token sits in the sequence. By the end you will be able to build the table for any even width, check the two identities that give it its structure, and say where those identities stop helping.

**You need:** token embeddings (Lesson 24.1) and dot products and matrix products (Lesson 20.1).

## The problem: attention cannot see order

Self-attention gives each token a weighted mix of every token's vector, and the weights depend only on the vectors themselves. Reorder the input and the same weights are applied to the reordered vectors, so the output is reordered the same way. The model cannot tell "dog bites man" from "man bites dog" unless the word vectors carry position information.

Write $X$ for the input matrix (one row per token), $P$ for a permutation matrix, $Q = XW_Q$, $K = XW_K$, and $A = QK^\top/\sqrt{d_k}$ for the scaled scores. Permuting the rows gives $PQ$ and $PK$, so the scores become $PAP^\top$. Softmax works row by row, so $\mathrm{softmax}(PAP^\top) = P\,\mathrm{softmax}(A)\,P^\top$. Multiplying by $PV$ then gives $P\,\mathrm{softmax}(A)\,V$: the output for the shuffled input is the shuffled output.

![Two word orders with the same three tokens. Without positions the output for dog is identical in both orders; with position encodings it differs](diagrams/24.2-permutation.svg "Same tokens, different order. Without positions the model cannot distinguish them.")

The code below checks this with fixed, non-random matrices, so the output is reproducible.

```python
import numpy as np

def softmax(x):
    z = np.exp(x - x.max(axis=-1, keepdims=True))
    return z / z.sum(axis=-1, keepdims=True)

def attention(X, Wq, Wk, Wv):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    return softmax(Q @ K.T / np.sqrt(Q.shape[1])) @ V

def sinusoidal_encoding(n_positions, d_model):
    pos = np.arange(n_positions)[:, None]
    i = np.arange(0, d_model, 2)[None, :]
    omega = 10000.0 ** (-i / d_model)
    angle = pos * omega
    pe = np.zeros((n_positions, d_model))
    pe[:, 0::2] = np.sin(angle)
    pe[:, 1::2] = np.cos(angle)
    return pe

d = 8
idx = np.arange(d)
emb = {"dog": np.sin(idx + 1.0), "bites": np.cos(1.3 * idx + 0.5), "man": np.sin(0.4 * idx + 2.0)}
Wq = np.cos(np.outer(idx, idx + 1) * 0.11) / np.sqrt(d)
Wk = np.sin(np.outer(idx + 2, idx) * 0.07) / np.sqrt(d)
Wv = np.cos(np.outer(idx, idx + 3) * 0.05) / np.sqrt(d)

A = np.stack([emb["dog"], emb["bites"], emb["man"]])   # dog bites man
B = np.stack([emb["man"], emb["bites"], emb["dog"]])   # man bites dog

outA, outB = attention(A, Wq, Wk, Wv), attention(B, Wq, Wk, Wv)
print("no positions, outputs are a reordering:", np.allclose(outB, outA[[2, 1, 0]], atol=1e-12))
print("no positions, dog identical in both orders:", np.allclose(outA[0], outB[2], atol=1e-12))

pe3 = sinusoidal_encoding(3, d)
outA2 = attention(A + pe3, Wq, Wk, Wv)
outB2 = attention(B + pe3, Wq, Wk, Wv)
print("with positions, dog differs by", f"{np.abs(outA2[0] - outB2[2]).max():.3f}")
```

```output
no positions, outputs are a reordering: True
no positions, dog identical in both orders: True
with positions, dog differs by 0.147
```

## The encoding table

Let $d$ be the model width (even) and $pos$ the position, starting at 0. For pair index $i = 0, \dots, d/2 - 1$, define

$$
\omega_i = 10000^{-2i/d}
$$

and set

$$
PE(pos, 2i) = \sin(pos\,\omega_i), \qquad PE(pos, 2i+1) = \cos(pos\,\omega_i)
$$

as in Vaswani et al. (2017, Section 3.5). Each pair of dimensions is a sine and a cosine at one frequency $\omega_i$. The encoding is added to the token embedding, $x_{pos} + PE(pos)$, and the table is computed from the formula rather than learned.

Take $d = 4$, so there are two pairs with $\omega_0 = 10000^0 = 1$ and $\omega_1 = 10000^{-1/2} = 0.01$. For position 1, $PE(1) = (\sin 1, \cos 1, \sin 0.01, \cos 0.01) = (0.8415, 0.5403, 0.0100, 0.99995)$, which the table rounds to 1.0000. Position 0 is always $(0, 1, 0, 1)$. The figure lists all four rows, and the first code block reproduces them.

![Four-dimensional encodings for positions 0 to 3, with the position 1 row highlighted](diagrams/24.2-worked-d4.svg "The d = 4 table. Row 1 is the worked example above.")

```python
import numpy as np

def sinusoidal_encoding(n_positions, d_model):
    """Return the (n_positions, d_model) table of sinusoidal encodings."""
    pos = np.arange(n_positions)[:, None]        # (n, 1): position of each row
    i = np.arange(0, d_model, 2)[None, :]        # (1, d/2): the even index 2i
    omega = 10000.0 ** (-i / d_model)            # omega_i = 10000^(-2i/d)
    angle = pos * omega                          # (n, d/2): position times omega_i
    pe = np.zeros((n_positions, d_model))
    pe[:, 0::2] = np.sin(angle)                  # even dimensions get sine
    pe[:, 1::2] = np.cos(angle)                  # odd dimensions get cosine
    return pe

pe = sinusoidal_encoding(4, 4)
for p, row in enumerate(pe):
    print(f"pos {p}:", "  ".join(f"{v:7.4f}" for v in row))

# wavelengths lambda_i = 2 pi / omega_i for a 512-wide model
omega512 = 10000.0 ** (-np.arange(0, 512, 2) / 512)
wavelength = 2 * np.pi / omega512
print(f"d=512 wavelengths: first {wavelength[0]:.2f}, last {wavelength[-1]:.0f}")
```

```output
pos 0:  0.0000   1.0000   0.0000   1.0000
pos 1:  0.8415   0.5403   0.0100   1.0000
pos 2:  0.9093  -0.4161   0.0200   0.9998
pos 3:  0.1411  -0.9900   0.0300   0.9996
d=512 wavelengths: first 6.28, last 60611
```

Pair $i$ has wavelength $\lambda_i = 2\pi/\omega_i$. Pair 0 repeats every 6.28 positions, while the last pair needs tens of thousands of positions per cycle. The wavelengths form a geometric progression from $2\pi$ to $2\pi \cdot 10000^{(d-2)/d}$, which is 60,611 for $d = 512$ and approaches $10000 \cdot 2\pi$ as $d$ grows. The paper states the progression as running from $2\pi$ to $10000 \cdot 2\pi$.

![Sine component of four frequency pairs over positions 0 to 60, for d = 64](diagrams/24.2-pe-waves.svg "Fast pairs wrap many times over the sequence; slow pairs barely move.")

## Why the table encodes offsets

Two identities explain the design. Write $\varphi = k\omega_i$ and use $\cos(a - b) = \cos a \cos b + \sin a \sin b$.

Identity 1: the dot product of two encodings depends only on the offset $k$:

$$
PE(p)\cdot PE(p+k) = \sum_i \big[\sin(p\omega_i)\sin((p+k)\omega_i) + \cos(p\omega_i)\cos((p+k)\omega_i)\big] = \sum_i \cos(k\omega_i)
$$

Identity 2: for each pair, moving from position $p$ to $p+k$ is a rotation by $\varphi$:

$$
\begin{pmatrix}\sin((p+k)\omega_i)\\ \cos((p+k)\omega_i)\end{pmatrix}
=
\begin{pmatrix}\cos\varphi & \sin\varphi\\ -\sin\varphi & \cos\varphi\end{pmatrix}
\begin{pmatrix}\sin(p\omega_i)\\ \cos(p\omega_i)\end{pmatrix}
$$

The rotation matrix depends on $k$ and $\omega_i$, not on $p$. So $PE(p+k) = M_k\,PE(p)$ for one block-diagonal matrix $M_k$ that serves every position. This is the linear-function property that Vaswani et al. (2017, Section 3.5) state for any fixed offset. The rotation figure shows one pair as a point on a circle.

![One sine-cosine pair drawn as a point on a circle; a shift by k turns the point through k times omega](diagrams/24.2-rotation.svg "A shift by k rotates each pair by k times omega.")

The second code block checks both identities numerically and prints the similarity curve.

```python
import numpy as np

def sinusoidal_encoding(n_positions, d_model):
    pos = np.arange(n_positions)[:, None]
    i = np.arange(0, d_model, 2)[None, :]
    omega = 10000.0 ** (-i / d_model)
    angle = pos * omega
    pe = np.zeros((n_positions, d_model))
    pe[:, 0::2] = np.sin(angle)
    pe[:, 1::2] = np.cos(angle)
    return pe

d = 64
pe = sinusoidal_encoding(300, d)
omega = 10000.0 ** (-np.arange(0, d, 2) / d)

# identity 1: PE(p) . PE(p+k) = sum_i cos(k * omega_i), which depends only on k
errs = [abs(pe[p] @ pe[p + k] - np.cos(k * omega).sum())
        for p in [0, 9, 111] for k in [0, 2, 7, 33]]
print("dot-product identity holds:", max(errs) < 1e-10)

# identity 2: each (sin, cos) pair is rotated by the angle k * omega_i
p, k = 17, 10
ok = True
for j in range(d // 2):
    s, c = pe[p, 2 * j], pe[p, 2 * j + 1]
    phi = k * omega[j]
    ok &= np.isclose(np.cos(phi) * s + np.sin(phi) * c, pe[p + k, 2 * j])
    ok &= np.isclose(-np.sin(phi) * s + np.cos(phi) * c, pe[p + k, 2 * j + 1])
print("rotation identity holds:", bool(ok))

# normalised similarity S(k) = PE(0) . PE(k) / (d/2), so S(0) = 1
for k in [1, 2, 8, 16, 32, 64, 128]:
    print(f"S({k}) = {pe[0] @ pe[k] / (d / 2):.3f}")
print("dot product PE(5).PE(7) =", round(float(pe[5] @ pe[7]), 3), " PE(0).PE(2) =", round(float(pe[0] @ pe[2]), 3))
```

```output
dot-product identity holds: True
rotation identity holds: True
S(1) = 0.966
S(2) = 0.884
S(8) = 0.700
S(16) = 0.605
S(32) = 0.611
S(64) = 0.435
S(128) = 0.284
dot product PE(5).PE(7) = 28.304  PE(0).PE(2) = 28.304
```

Normalising the dot product by $d/2$ gives $S(k) = PE(0)\cdot PE(k)/(d/2)$, which equals 1 at $k = 0$. For $d = 64$ the code gives $S(8) = 0.700$, $S(16) = 0.605$, $S(32) = 0.611$ and $S(128) = 0.284$. The values fall with offset, but not monotonically: $S(32) > S(16)$. Each term is a cosine at its own frequency, and the sum has bumps where several terms happen to be near 1 together.

![Normalised dot product of PE(0) and PE(k) against offset k from 0 to 128, for d = 64](diagrams/24.2-similarity.svg "The trend falls with offset; the curve is not monotone.")

## The catch: learned projections break the identity

The identities concern the raw encodings. Attention does not use them directly: it computes scores from learned projections, $\mathrm{score}(p, q) = (x_p W_Q)(x_q W_K)^\top$. The bare dot product in identity 1 is a special case with $W_Q = W_K = I$. The fourth code block replaces the learned matrices with fixed ones. With the raw encodings, scores are constant along each diagonal. With the projections, the scores on a diagonal vary with position.

```python
import numpy as np

def sinusoidal_encoding(n_positions, d_model):
    pos = np.arange(n_positions)[:, None]
    i = np.arange(0, d_model, 2)[None, :]
    omega = 10000.0 ** (-i / d_model)
    angle = pos * omega
    pe = np.zeros((n_positions, d_model))
    pe[:, 0::2] = np.sin(angle)
    pe[:, 1::2] = np.cos(angle)
    return pe

d, n = 16, 40
pe = sinusoidal_encoding(n, d)
idx = np.arange(d)
Wq = np.cos(np.outer(idx, idx + 1) * 0.3) / 4     # fixed matrices standing in for learned W_Q, W_K
Wk = np.sin(np.outer(idx + 2, idx) * 0.2) / 4

def diagonal_spread(S):
    # largest standard deviation, over offsets 1 to 5, of the scores S[p, p+k] taken along each diagonal
    return max(np.array([S[p, p + k] for p in range(n - k)]).std() for k in range(1, 6))

print("raw encodings, scores constant on diagonals:", diagonal_spread(pe @ pe.T) < 1e-10)
print("with projections, spread across positions:", f"{diagonal_spread((pe @ Wq) @ (pe @ Wk).T):.2f}")
```

```output
raw encodings, scores constant on diagonals: True
with projections, spread across positions: 0.51
```

Vaswani et al. hypothesised that sinusoids would let a model attend by relative position (Section 3.5). The identities show that the encodings have that structure. Whether trained projections keep it is an empirical question, and this lesson does not answer it.

## Where the table enters the model

The encoding is added to the embedding, not concatenated. The paper multiplies the embedding weights by $\sqrt{d_{\text{model}}}$ before this step (Section 3.4) and gives no reason in the text, so treat that scaling as an implementation choice. The paper also trained a version with learned position embeddings and reports "nearly identical results" (Section 3.5, Table 3 row (E)). On its benchmark, the choice of encoding was not decisive. The paper also suggests the sinusoids may let a model extrapolate to longer sequences than it saw in training. This lesson does not test that claim.

## Common traps

> [!TRAP] Odd width
> The formulas pair each sine with a cosine, so $d$ must be even. With odd $d$, the sine and cosine slices differ in width, and NumPy raises a `ValueError`.

> [!TRAP] Adding the encoding too late
> Attention only sees the tensor it is given. The encoding must be in the input to the first attention layer. Added after the last layer, it affects nothing the attention has already computed.

> [!TRAP] A finite table
> The table has one row per position it was built for. A longer input needs a longer table, or a call with the longer length. The formula itself defines a value at every position.

> [!TRAP] Raw dot products are not attention scores
> Identity 1 holds for the raw encodings. Once learned projections are applied, the score can depend on the absolute positions, as the fourth code block shows.

> [!TRAP] "Closer means more similar" is only an average
> For $d = 64$, $S(32) > S(16)$. Read the curve, not a rule of thumb.

## Summary

- Attention is permutation-equivariant, so positions must be added to its input.
- Each pair uses frequency $\omega_i = 10000^{-2i/d}$; wavelengths run from $2\pi$ to about $10000 \cdot 2\pi$.
- For raw encodings, $PE(p)\cdot PE(p+k) = \sum_i \cos(k\omega_i)$ and $PE(p+k) = M_k\,PE(p)$, so both depend only on $k$.
- Similarity falls with offset on average but not monotonically, and learned projections break the diagonal structure.

### Question 1: Compute PE(2) for d = 4 by hand.

<details><summary>Show Solution</summary>

With $\omega_0 = 1$ and $\omega_1 = 0.01$, $PE(2) = (\sin 2, \cos 2, \sin 0.02, \cos 0.02) = (0.9093, -0.4161, 0.0200, 0.9998)$.

### Question 2: For d = 64, what is PE(5)·PE(7), without reading it from the table?

<details><summary>Show Solution</summary>

By identity 1 with $k = 2$, PE(5)·PE(7) = PE(0)·PE(2) = $\sum_i \cos(2\omega_i)$. The code block prints 28.304 for both. The answer does not depend on the absolute positions 5 and 7.

</details>

### Question 3: The helper from the first code block is called as `sinusoidal_encoding(4, 5)`. What happens, and how do you fix it?

<details><summary>Show Solution</summary>

With $d = 5$, `np.arange(0, 5, 2)` gives three frequencies. The slice `pe[:, 0::2]` has three columns, but `pe[:, 1::2]` has two, so assigning the three-column cosine array to it raises a `ValueError` (shape mismatch). The formulas assume an even width, so use an even $d$. If an odd width is needed, that is a design decision, not a bug fix, and this lesson does not cover it.

</details>

### Question 4: Why is identity 2 not enough to make attention scores depend only on the offset?

<details><summary>Show Solution</summary>

Identity 2 holds for the raw encodings, and the rotation $M_k$ depends only on $k$ and $\omega_i$. Attention scores are $(x_p W_Q)(x_q W_K)^\top$, so a general learned matrix sits between the two encodings. The cancellation that gives identity 1 is a bare dot product, and it does not survive an arbitrary matrix in between. The fourth code block shows the diagonal scores vary with position.

</details>
