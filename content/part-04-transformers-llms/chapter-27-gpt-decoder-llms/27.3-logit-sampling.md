After a large language model (LLM) produces logits for the next token, something must choose one token. In this lesson you will turn logits into probabilities by hand, apply temperature, top-k, top-p (nucleus) and min-p filters, and check that a sampler's frequencies match the distribution it is meant to draw from.

**You need:** softmax and probabilities (Lesson 25.1), and the generation loop of Lesson 27.2, in which a sampler replaces the argmax and runs once per generated token.

## The problem sampling solves

Greedy decoding always takes the single most likely token. It is deterministic. Sampling from the full distribution adds variety, but a vocabulary has tens of thousands of tokens. Their long tail of unlikely tokens carries real probability in total, so every draw has a small chance of an incoherent word. Holtzman et al. (2019) motivate truncation by this unreliable low-probability end of the distribution [1].

What is needed is something in between: keep the plausible tokens, cut the tail, and reshape what remains.

## From logits to probabilities

A logit $z_i$ is an unnormalized score for token $i$. Softmax turns the scores into probabilities that are positive and sum to 1:

$$
p_i = \frac{e^{z_i}}{\sum_j e^{z_j}}
$$

Worked example. Five candidate tokens, "the", "a", "cat", "dog" and "zebra", have logits $z = [3, 2, 1, 0, -1]$. The exponentials are $e^3 = 20.086$, $e^2 = 7.389$, $e^1 = 2.718$, $e^0 = 1$ and $e^{-1} = 0.368$. They sum to 31.561. Dividing each by the sum gives $p = [0.6364, 0.2341, 0.0861, 0.0317, 0.0117]$.

![Five bars for the worked example. "the" has p = 0.636; the bars for "dog" and "zebra" are below the min-p cut-off line at 0.064](diagrams/27.3-worked-probs.svg "The worked example's probabilities, with the min-p cut-off. Blue bars pass the cut.")

The most likely token gets 0.636, but it does not dominate. The last two tokens together hold about 4% of the mass.

Run this code to reproduce every number in this lesson. It is NumPy only, so it runs in the browser.

```python
import numpy as np

def softmax(logits, temperature=1.0):
    z = logits / temperature
    z = z - z.max()                          # subtract the max: avoids overflow in exp
    e = np.exp(z)
    return e / e.sum()

def top_k_filter(p, k):
    keep = np.zeros(len(p), dtype=bool)
    keep[np.argsort(p)[::-1][:k]] = True     # the k most likely tokens
    return keep

def top_p_filter(p, top_p):
    order = np.argsort(p)[::-1]              # most likely first
    cum = np.cumsum(p[order])
    n_keep = int(np.argmax(cum >= top_p)) + 1  # smallest prefix whose mass reaches top_p
    keep = np.zeros(len(p), dtype=bool)
    keep[order[:n_keep]] = True
    return keep

def min_p_filter(p, base):
    return p >= base * p.max()               # threshold scales with the top token's probability

def renormalize(p, keep):
    q = np.where(keep, p, 0.0)               # zero out the removed tokens
    return q / q.sum()                       # kept probabilities must sum to 1 again

logits = np.array([3.0, 2.0, 1.0, 0.0, -1.0])   # one score per token: the, a, cat, dog, zebra
p = softmax(logits)
print("probs      :", np.round(p, 4))
print("top-k 3    :", top_k_filter(p, 3))
print("top-p 0.9  :", top_p_filter(p, 0.9))
print("min-p 0.1  :", min_p_filter(p, 0.1))
q = renormalize(p, top_p_filter(p, 0.9))
print("renormalized top-p:", np.round(q, 4))
rng = np.random.default_rng(0)
print("ten draws  :", rng.choice(len(q), size=10, p=q).tolist())
print("hot (T=2)  :", np.round(softmax(logits, temperature=2.0), 4))
d = renormalize(p, top_k_filter(p, 3))                 # top-k first ...
d = renormalize(d, top_p_filter(d, 0.9))               # ... then top-p on the renormalized result
d = renormalize(d, min_p_filter(d, 0.1))               # ... then min-p
print("pipeline   :", np.round(d, 4))
flat = softmax(np.array([1.0, 0.95, 0.9, 0.85, 0.8, 0.75, 0.7, 0.65, 0.6, 0.55]))
print("flat probs :", np.round(flat, 3))
print("flat top-k 3 keeps mass", round(float(flat[top_k_filter(flat, 3)].sum()), 3))
print("flat top-p 0.9 keeps", int(top_p_filter(flat, 0.9).sum()), "tokens")
freq = np.bincount(np.random.default_rng(0).choice(len(q), size=200_000, p=q), minlength=len(q)) / 200_000
print("200k draws :", np.round(freq[:3], 4))
```

## Temperature rescales the logits

Temperature $T > 0$ divides the logits before the softmax:

$$
p_i(T) = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}
$$

Dividing by a positive $T$ keeps the order of the logits, so temperature never changes which token is most likely. It changes how the mass is spread. Values below 1 sharpen the distribution, and values above 1 flatten it. As $T \to 0$ the distribution approaches a one-hot vector on the argmax (the index of the largest value), which is why implementations treat $T = 0$ as greedy decoding instead of dividing by zero. As $T \to \infty$ it approaches uniform. Hinton, Vinyals and Dean write the same softmax with temperature and state that a higher value gives a softer distribution [4].

Check $T = 2$ by hand. Dividing the logits by 2 gives $[1.5, 1, 0.5, 0, -0.5]$. Their exponentials are $4.482$, $2.718$, $1.649$, $1$ and $0.607$, which sum to $10.456$. The probability of "the" is therefore $4.482 / 10.456 = 0.4287$, matching the output above.

![Three groups of bars for the same logits at temperatures 0.5, 1 and 2. The top bar drops from 0.86 to 0.43 as temperature rises, and the entropy rises from 0.66 to 2.01 bits](diagrams/27.3-temperature.svg "Same logits, three temperatures. Entropy is the average surprise, in bits, of a draw from the distribution.")

Entropy in bits, $H = -\sum_i p_i \log_2 p_i$, measures how spread the distribution is. It rises from 0.66 bits at $T = 0.5$ to 1.44 bits at $T = 1$ and 2.01 bits at $T = 2$.

## Top-k: keep a fixed count

Top-k keeps the $k$ most likely tokens, sets the rest to zero, and renormalizes. Fan, Lewis and Dauphin (2018) describe sampling from the $k = 10$ most likely candidates in their generation experiments [3]. On the worked example, $k = 3$ keeps $0.957$ of the mass. The renormalized probabilities are $0.6652$, $0.2447$ and $0.0900$.

The weakness is that $k$ is fixed, whatever the shape of the distribution. The next diagram shows the same three rules on a peaked distribution (the worked example) and on a flat one (ten logits from 1.0 down to 0.55, with probabilities from 0.124 down to 0.079).

![Two panels. The peaked panel keeps three tokens under all three rules. The flat panel keeps three tokens under top-k, nine under top-p and all ten under min-p](diagrams/27.3-peaked-vs-flat.svg "Which tokens each rule keeps. Top-k keeps 3 of 10 flat tokens, only 35% of the mass.")

On the flat distribution top-k keeps 3 tokens, which hold only 0.354 of the mass. Top-k is still choosing 3 tokens when the model has no clear favourite.

## Top-p (nucleus): keep a fixed mass

Holtzman et al. define the nucleus $V^{(p)}$ as the smallest set of tokens whose probabilities sum to at least $p$, then renormalize the kept tokens [1]. Their prose says the cumulative mass "exceeds" $p$, but their equation uses $\geq$. This lesson follows the equation, so a set that reaches $p$ exactly stops there.

On the worked example with $p = 0.9$, the cumulative sums are $0.6364$, $0.8705$ and $0.9566$. The third token is the first to reach 0.9, so three tokens are kept. The same three also come from top-k with $k = 3$, but that is a coincidence of this example. On the flat distribution, top-p keeps nine tokens, because it needs nine of them to reach 0.9.

The number of kept tokens therefore depends on the distribution. At $T = 0.5$, top-p with $p = 0.9$ keeps 2 tokens, and at $T = 2$ it keeps 4.

## Min-p: a threshold relative to the top token

Nguyen et al. (2024) keep every token whose probability is at least $p_{\text{base}}$ times the probability of the most likely token, then renormalize [2]. Their main experiments use $p_{\text{base}}$ values of 0.05 and 0.1 [2].

With $p_{\text{base}} = 0.1$ on the worked example, the threshold is $0.1 \times 0.6364 = 0.0636$. The token "cat" (0.0861) passes, and "dog" (0.0317) does not. On the flat distribution the top probability is 0.124, so the threshold is 0.0124. Every token passes, because the smallest probability is 0.079. At $T = 2$ the top probability falls to 0.429, the threshold falls to 0.043, and five tokens pass.

## Combining the filters

Real samplers chain these filters. This lesson applies them in a fixed order: temperature, then top-k, then top-p, then min-p. Each step works on the renormalized output of the step before it. This is one convention rather than a standard, and libraries differ, so check the documentation of the library you use.

![Six boxes in sequence: logits, softmax, top-k, top-p, min-p and sample. Under each box, the number of tokens left. After top-k, three tokens remain; after top-p, two; min-p keeps both](diagrams/27.3-pipeline.svg "The example through the pipeline. Each step renormalizes the tokens it keeps.")

Top-k leaves $[0.6652, 0.2447, 0.0900]$. Top-p is then applied to that renormalized vector, and its cumulative sums are $0.6652$ and $0.9099$. The second token is enough to pass 0.9, so only two tokens remain. After renormalizing they are $[0.7311, 0.2689]$, and min-p keeps both.

The order matters. Applying top-p to the original distribution would keep three tokens. After top-k renormalizes, the top token's share rises, so the cumulative sum reaches 0.9 one token sooner.

## Measured: the sampler matches its target

If a sampler is correct, its frequencies over many draws should match the renormalized distribution. The code draws 200,000 tokens from the top-p distribution with a fixed seed. The observed frequencies are $[0.666, 0.2452, 0.0888]$, against the target $[0.6652, 0.2447, 0.0900]$. The largest gap is 0.0013. For the smallest kept token, the standard error of a frequency is $\sqrt{0.09 \times 0.91 / 200000} \approx 0.0006$. The gap is about two standard errors, which is within sampling noise.

> [!TRAP]
> **Forgetting to renormalize.** After filtering, the kept probabilities sum to less than 1 (here 0.957 for top-k). NumPy's `choice` rejects such a vector with `ValueError: Probabilities do not sum to 1`, which checks the sum in NumPy 2.5.5.

> [!TRAP]
> **Temperature zero.** The formula divides by $T$, so $T = 0$ fails. Implementations special-case it as greedy argmax decoding.

> [!TRAP]
> **Filter order changes the result.** The example gives two tokens for top-k then top-p, and three for top-p alone. Two libraries with the same parameter names can produce different samples.

> [!TRAP]
> **Equality at the threshold.** Top-p is defined with $\geq$ in the Holtzman equation, but a sum that should equal $p$ can land just below it in floating point. Test the boundary case rather than assuming it is handled.

> [!TRAP]
> **Reproducibility.** Sampled text changes from run to run unless you fix the seed. Compare two sampler versions on the same seed and the same probabilities, not on free-running generations.

## Summary

- Softmax turns logits into probabilities. Temperature divides the logits by $T$ before the softmax. It reshapes the distribution but never reorders the tokens.
- Top-k keeps a fixed count of tokens. Top-p keeps the smallest set whose probability reaches $p$. Min-p keeps tokens with probability at least $p_{\text{base}}$ times the top probability.
- Every cut is followed by renormalization, and the number of tokens kept depends on the shape of the distribution.
- Filters applied in sequence can give a different answer from filters applied to the original distribution, so state the order.
- To check a sampler, draw many samples and compare their frequencies with the target distribution.

## Quiz time

### Question 1: Calculation

For logits $z = [3, 2, 1, 0, -1]$ at temperature $T = 2$, what is the probability of "the"?

<details><summary>Show Solution</summary>

Divide the logits by 2 to get $[1.5, 1, 0.5, 0, -0.5]$. Their exponentials sum to $4.482 + 2.718 + 1.649 + 1 + 0.607 = 10.456$. So $p(\text{the}) = 4.482 / 10.456 = 0.4287$.

</details>

### Question 2: Prediction

You set top-k to 1 and temperature to 5. Which token does the sampler return on every call, and why does the temperature not matter?

<details><summary>Show Solution</summary>

It returns the most likely token every time. Top-k with $k = 1$ keeps only one token, and renormalizing a single token gives it probability 1. Temperature changes the probabilities before the cut, but the cut leaves no choice to make.

</details>

### Question 3: Find the bug

```python
import numpy as np

p = np.array([0.6364, 0.2341, 0.0861, 0.0317, 0.0117])
keep = np.zeros(len(p), dtype=bool)
keep[np.argsort(p)[::-1][:3]] = True      # top-k with k = 3
q = np.where(keep, p, 0.0)
token = np.random.default_rng(0).choice(len(q), p=q)   # what goes wrong here?
print(token)
```

<details><summary>Show Solution</summary>

The vector `q` is not renormalized. Its sum is 0.957, so `choice` raises `ValueError: Probabilities do not sum to 1`. The fix is `q = q / q.sum()` before sampling.

</details>

### Question 4: Explain

Why does min-p keep three of the five tokens in the peaked example, but all ten in the flat one?

<details><summary>Show Solution</summary>

The min-p threshold is $p_{\text{base}} \times p_{\max}$, so it depends on the top probability. In the peaked example the top probability is 0.636, so the threshold is 0.064, and three tokens pass. In the flat example the top probability is 0.124, so the threshold is 0.0124, and the smallest probability (0.079) passes too.

</details>

### Question 5: Explain

Top-k with $k = 3$ followed by top-p with $p = 0.9$ keeps two tokens. Top-p alone on the original distribution keeps three. Why?

<details><summary>Show Solution</summary>

Top-k renormalizes, so the top token's share rises from 0.636 to 0.665. Its cumulative sum with the second token is then $0.6652 + 0.2447 = 0.9099$, which reaches 0.9. On the original distribution the same two-token sum is $0.6364 + 0.2341 = 0.8705$, which is below 0.9, so a third token is needed.

</details>
