In this lesson you will convert a training run into a compute budget, measured in floating-point operations (FLOPs), and find the model size that gives the lowest predicted loss for a fixed budget. You will use the parametric law fitted by Hoffmann et al. (2022), the "Chinchilla" paper.

**You need:** the training loop from Lesson 27.1, and the idea of a token from Lesson 23.1.

## The problem: a fixed budget, two knobs

A lab has a fixed amount of accelerator time, so it has a fixed number of FLOPs to spend. It can spend them on a larger model or on more training text. Around 2021 the largest dense models were trained on about 300 billion tokens each, and most of the extra budget went into parameters. Gopher had 280 billion parameters and 300 billion tokens (Table 1 of Hoffmann et al.). Was that the right split?

Two terms first. A **parameter** is a learned weight. The **loss** is the average cross-entropy per token, in nats (natural logarithm units). Lower is better.

## Compute is roughly 6ND

![Compute equals six times N parameters times D tokens, with the Chinchilla and Gopher budgets worked out](diagrams/28.1-budget.svg "Training compute: N parameters, D tokens, C FLOPs.")

For a dense transformer, each token costs about 2 FLOPs per parameter in the forward pass (one multiply and one add). The backward pass costs about twice the forward pass, so the total is about 4 FLOPs per parameter per token. Therefore $C \approx 6ND$. Hoffmann et al. (Appendix F) call $C \approx 6ND$ the common approximation and attribute it to Kaplan et al. (2020). Their own per-layer count is within about 10% of it for models from 73M to 6.8B parameters (their Table A4 ratios run from 0.99 to 1.10).

This is an approximation, not a law. It ignores attention cost over long contexts and the embedding layers, and it assumes one pass over the data.

Worked by hand: Chinchilla is 70B parameters and 1.4T tokens, so $C = 6 \times 70\times10^9 \times 1.4\times10^{12} = 5.88\times10^{23}$ FLOPs. The rounded Gopher values give $6 \times 280\times10^9 \times 300\times10^9 = 5.04\times10^{23}$. The Gopher comparison below explains why these two numbers should not be compared too precisely.

## The loss depends on N and D

Hoffmann et al. fit the final loss as a function of parameters $N$ and tokens $D$:

$$L(N, D) = E + \frac{A}{N^{\alpha}} + \frac{B}{D^{\beta}}, \qquad E = 1.69,\; A = 406.4,\; B = 410.7,\; \alpha = 0.34,\; \beta = 0.28$$

The three terms have clear meanings. $E$ is the entropy of natural text, which no model can beat. $A/N^{\alpha}$ is the cost of a model that is too small to represent the data. $B/D^{\beta}$ is the cost of seeing too few tokens. The fit uses training runs from 70M to over 16B parameters on 5 to 500B tokens (the abstract of Hoffmann et al.). Any prediction beyond that range is an extrapolation.

Fix a budget $C$. Then $D = C/(6N)$ is forced by $N$, so making the model bigger leaves fewer tokens. The curve of loss against $N$ at fixed $C$ therefore has a valley. The next figure shows it.

![Loss against parameter count for two fixed budgets: each curve dips to a minimum, at 1.8B parameters for 1e21 FLOPs and 14.6B for 1e23 FLOPs](diagrams/28.1-isoflop.svg "Each curve is a fixed budget. The dot marks the lowest predicted loss.")

Worked by hand at $C = 10^{21}$ FLOPs with $N = 1.8\times10^{9}$: $D = C/(6N) = 9.26\times10^{10}$ tokens. The model term is $406.4 / (1.8\times10^9)^{0.34} = 0.290$. The data term is $410.7 / (9.26\times10^{10})^{0.28} = 0.349$. So $L = 1.69 + 0.290 + 0.349 = 2.329$. The code reproduces this value.

```python
import math

E, A, B, ALPHA, BETA = 1.69, 406.4, 410.7, 0.34, 0.28  # Hoffmann et al. (2022), Eq. 10

def loss(N, D):
    """Predicted loss in nats per token for N parameters trained on D tokens."""
    return E + A / N**ALPHA + B / D**BETA

def tokens_for(C, N):
    """Tokens D that spend exactly C FLOPs on N parameters, from C = 6 N D."""
    return C / (6 * N)

C = 1e21
grid = [10 ** (8 + 3 * k / 600) for k in range(601)]   # 601 log-spaced sizes, 1e8 to 1e11
N_best = min(grid, key=lambda N: loss(N, tokens_for(C, N)))
print(f"budget C = {C:.0e} FLOPs")
D_best = tokens_for(C, N_best)
print(f"grid search: N = {N_best:.3e}, D = {D_best:.3e}, loss = {loss(N_best, D_best):.4f}")

a = BETA / (ALPHA + BETA)                              # exponent on C
G = (ALPHA * A / (BETA * B)) ** (1 / (ALPHA + BETA))   # prefactor
N_closed = G * (C / 6) ** a
print(f"closed form: N_opt = G (C/6)^a = {N_closed:.3e}, a = {a:.4f}")
```

```output
budget C = 1e+21 FLOPs
grid search: N = 1.820e+09, D = 9.159e+10, loss = 2.3289
closed form: N_opt = G (C/6)^a = 1.824e+09, a = 0.4516
```

## The optimum, and how it scales

Substitute $D = C/(6N)$ into the loss. Up to constants, $L(N) = E + A N^{-\alpha} + B (C/6)^{-\beta} N^{\beta}$. Setting $dL/dN = 0$ gives $\alpha A N^{-\alpha} = \beta B (C/6)^{-\beta} N^{\beta}$, so

$$N_{\text{opt}}(C) = G\left(\frac{C}{6}\right)^{a}, \qquad D_{\text{opt}}(C) = \frac{1}{G}\left(\frac{C}{6}\right)^{b}, \qquad a = \frac{\beta}{\alpha+\beta},\; b = \frac{\alpha}{\alpha+\beta},\; G = \left(\frac{\alpha A}{\beta B}\right)^{1/(\alpha+\beta)}$$

The stationary point is the minimum, because the $N^{-\alpha}$ term falls as $N$ grows and the $N^{\beta}$ term rises. The grid search and the closed form agree to about 0.2%.

The exponents are the important output. Hoffmann et al. report $a = 0.46$ and $b = 0.54$ for approach 3 (their Table 2), and $a \approx b \approx 0.5$ for the other two approaches. Kaplan et al. (2020, Introduction) had estimated $N \propto C^{0.73}$ and $D \propto C^{0.27}$. Under Kaplan's split, a tenfold increase in compute goes mostly into parameters. Under Hoffmann's, parameters and tokens grow at about the same rate.

> [!TRAP]
> **The printed constants are rounded.** The exponents $\alpha$ and $\beta$ are given to two decimals. Over the rounding box ($\alpha \in [0.335, 0.345]$, $\beta \in [0.275, 0.285]$), $a$ ranges from 0.444 to 0.460, and the predicted $N_{\text{opt}}$ at Gopher's budget ($5.76\times10^{23}$ FLOPs) ranges from $2.2\times10^{10}$ to $4.7\times10^{10}$. Hoffmann et al. project about 40B. Trust the exponents more than the absolute frontier.

## Gopher against Chinchilla

![Gopher with 280B parameters and 300B tokens against Chinchilla with 70B parameters and 1.4T tokens, with predicted losses 1.99 and 1.94](diagrams/28.1-gopher-chinchilla.svg "Same budget, different split. The loss values are predictions from Eq. 10.")

Chinchilla uses about 4.7 times as many tokens and a quarter of the parameters. Hoffmann et al. state that it was trained with the same compute as Gopher, and they report that it "uniformly and significantly outperforms" Gopher on downstream tasks, reaching 67.5% average accuracy on MMLU (a multiple-choice knowledge benchmark). Those downstream results are measurements. The loss values in the figure are not: they come from Eq. 10, with $N$ and $D$ inserted, and they show a predicted gap of 0.057 nats. Over the rounding box the gap stays between 0.043 and 0.071, so its sign is stable.

The budget comparison is looser. The paper counts Gopher at $5.76\times10^{23}$ FLOPs. Our 6ND calculation from the rounded table values gives $5.04\times10^{23}$ for Gopher and $5.88\times10^{23}$ for Chinchilla, a gap of 17%. The difference comes from rounding and from the 6ND approximation, which is why the figure should not be read to two significant figures.

## Common traps

> [!TRAP]
> **"Chinchilla means 20 tokens per parameter at every budget."** The ratio 20 comes from approach 1 (Table 3: 1B parameters with 20.2B tokens). Approach 3 gives a ratio that grows with compute: its Table A3 lists 4.1T tokens for 67B parameters (61 tokens per parameter) and 20.1T for 280B (72).

> [!TRAP]
> **"Kaplan got it wrong" is too simple.** The two papers ran different experiments. Hoffmann et al. matched each run's learning-rate schedule to that run's token count (their footnotes 4 and 7), and they fit at several budgets with different methods. Why the exponents differ is not something I verified; I only checked that both papers report them.

> [!TRAP]
> **Extrapolation.** The fit uses runs up to 16B parameters. Predicting Gopher's 280B is an extrapolation by a factor of about 17 in $N$. The law can be right in shape and wrong in the constant.

> [!TRAP]
> **Loss is tokenizer-specific.** A loss of 1.94 nats per token counts text in this paper's tokenizer. It is not comparable to another model's per-token loss unless the tokenizers match. Compare per byte or per word instead.

## Summary

- A training run costs about $C \approx 6ND$ FLOPs: 2 per parameter per token for the forward pass, and about 4 for the backward pass.
- Hoffmann et al.'s fit $L = E + A/N^{0.34} + B/D^{0.28}$ has an irreducible term, a model-size term and a data term. At fixed $C$, the loss has a valley in $N$.
- The compute-optimal model size scales as $C^{a}$ and the token count as $C^{b}$, with $a \approx 0.46$ and $b \approx 0.54$. Parameters and tokens should grow at about the same rate.
- The printed constants are rounded, so the exponents are more reliable than the absolute frontier.
- The predicted gap between Gopher and Chinchilla is 0.057 nats. The downstream gains reported by the paper are measurements.

### Question 2: Prediction

At $C = 10^{21}$ FLOPs, is a model with $N = 10^{10}$ parameters predicted to do better or worse than one with $N = 1.8\times10^{9}$? Use Eq. 10.

<details><summary>Show Solution</summary>

For $N = 10^{10}$: $D = 10^{21}/(6\times10^{10}) = 1.67\times10^{10}$ tokens. The model term is $406.4/(10^{10})^{0.34} = 0.162$, and the data term is $410.7/(1.67\times10^{10})^{0.28} = 0.564$. So $L = 1.69 + 0.162 + 0.564 = 2.416$. That is worse than 2.329 for $N = 1.8\times10^{9}$, so the 10B model is predicted to be worse. It is past the valley.

</details>

### Question 3: Find the bug

```python
def tokens_for(C, N):
    return C * 6 / N
```

<details><summary>Show Solution</summary>

The formula should be $D = C/(6N)$. The code computes $6C/N$, which is 36 times too many tokens. A quick check: with $N = 10^9$ and $C = 10^{21}$, the correct value is $1.67\times10^{11}$ tokens, and the buggy version returns $6\times10^{12}$.

Fixed version:

```python
def tokens_for(C, N):
    return C / (6 * N)
```

</details>

### Question 4: Explain the valley

Why does the predicted loss at fixed $C$ fall and then rise as $N$ increases?

<details><summary>Show Solution</summary>

Increasing $N$ lowers the model term $A/N^{\alpha}$. At fixed $C$, it also lowers $D = C/(6N)$, which raises the data term $B/D^{\beta}$. For small $N$ the model term dominates and the loss falls. For large $N$ the data term dominates and the loss rises. The minimum is where the two marginal changes balance, at $N_{\text{opt}} = G(C/6)^{a}$.

</details>
