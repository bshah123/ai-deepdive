A pretrained language model continues text; it does not yet follow instructions or prefer the answers people like. In this lesson you will learn the three post-training signals that close that gap: supervised fine-tuning (SFT) on demonstrations, reinforcement learning from human feedback (RLHF) with proximal policy optimisation (PPO), and direct preference optimisation (DPO). You will implement the preference loss and the DPO update in NumPy and check that DPO reaches the same policy as the reward-model route.

**You need:** the idea of a probability distribution over a finite set and the logarithm (natural log, written $\log$ here), and a pretrained model of the kind built in Lesson 27.1.

## The problem

Take a pretrained model and the prompt "Explain photosynthesis to a child." It may continue with more questions, because that is what similar documents look like on the web. What we want is an answer that is helpful, correct and safe, and people can tell which of two answers is better more reliably than they can write a perfect one. Post-training uses both facts: demonstrations teach the format, and comparisons teach preference.

The InstructGPT pipeline of Ouyang et al. (2022) is the reference design. It has three stages, shown below in one picture.

![Two routes from preference pairs: RLHF trains a reward model and then runs PPO against it, while DPO optimises the policy directly with a loss on the same pairs](diagrams/28.3-routes.svg "Both routes start from the SFT model and use the same preference pairs.")

## Supervised fine-tuning

SFT is ordinary next-token training on human-written demonstrations. The loss for one target token is the negative log-probability the model gives it:

$$\mathcal{L}_{\text{SFT}} = -\log \pi_\theta(y_t \mid x, y_{<t})$$

Worked example. If the model gives the correct next token probability 0.5, the loss is $-\log 0.5 = 0.6931$ nats (nats are units of information when the log is natural). The perplexity, $e^{\mathcal{L}}$, is 2: the model is as uncertain as a fair coin. With probability 0.9 the loss is 0.1054 nats, and with probability 0.1 it is 2.3026 nats. SFT only ever sees correct answers, so it cannot learn that one correct-looking answer is worse than another.

## Preferences: the Bradley-Terry model

Human labellers compare two responses $y_w$ (chosen) and $y_l$ (rejected) to the same prompt. The Bradley-Terry model is a standard pairwise choice model. It turns a scalar reward $r$ into a probability of winning:

$$P(y_w \succ y_l) = \sigma\big(r(y_w) - r(y_l)\big), \qquad \sigma(z) = \frac{1}{1 + e^{-z}}$$

A reward gap of 0 is a coin flip, and a gap of 2 gives 0.88. The loss is the negative log of that probability, $-\log \sigma(r_w - r_l)$. The reward is defined only up to an additive constant, because only differences enter.

![The Bradley-Terry curve: the probability that the chosen response wins rises with the reward gap, with four worked points](diagrams/28.3-bradley-terry.svg "Reward gap to win probability and loss, at four gaps.")

## The RLHF objective and its closed-form optimum

RLHF maximises the expected reward while staying close to the SFT policy $\pi_{\text{ref}}$:

$$J(\pi) = \mathbb{E}_{y \sim \pi}[r(y)] - \beta\, \mathrm{KL}(\pi \,\|\, \pi_{\text{ref}})$$

Here $\mathrm{KL}$ is the Kullback-Leibler divergence and $\beta > 0$ sets how strongly the policy is held near the reference. Its maximiser has a closed form (Rafailov et al., 2023, Eqs. 3-4):

$$\pi^*(y) = \frac{1}{Z}\, \pi_{\text{ref}}(y)\, \exp\!\left(\frac{r(y)}{\beta}\right)$$

where $Z$ is a normaliser. Hand check with the toy problem below ($\beta = 0.5$, five responses). For the response with $\pi_{\text{ref}} = 0.15$ and $r = 1.5$, the unnormalised weight is $0.15\, e^{3} = 3.013$. Summing the five unnormalised weights gives 5.218, so $\pi^*$ of that response is $3.013 / 5.218 = 0.577$. The experiment's value is 0.5774.

We do not run PPO in this lesson. PPO (Schulman et al., 2017) optimises a clipped surrogate of this objective with sampled rollouts: with probability ratio $\rho_t = \pi_\theta / \pi_{\text{old}}$ and advantage $A_t$, it maximises $\min(\rho_t A_t, \mathrm{clip}(\rho_t, 1-\epsilon, 1+\epsilon) A_t)$ with $\epsilon = 0.2$ (Section 3 of the paper). The clip removes the incentive to move the ratio far outside $[1-\epsilon, 1+\epsilon]$ in the direction the advantage favours. InstructGPT used a per-token KL penalty with coefficient $\beta = 0.02$ and clip ratio 0.2 (Ouyang et al., 2022, Appendix).

![Clipped surrogate for positive and negative advantage: the objective is flat beyond the clip band, so the gradient stops there](diagrams/28.3-ppo-clip.svg "The clipped PPO term, one timestep, epsilon 0.2.")

## DPO: the reward is implicit in the policy

Rafailov et al. (2023) noticed that Eq. 4 can be inverted. Solving for the reward gives $r(x, y) = \beta \log\frac{\pi(y \mid x)}{\pi_{\text{ref}}(y \mid x)} + \beta \log Z(x)$ (their Eq. 5). The term $\beta \log Z(x)$ depends only on the prompt, so it cancels in any reward difference for the same prompt. Substituting into the Bradley-Terry loss gives the DPO loss (their Eq. 7):

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\left[\log \sigma\!\left(\beta \log \frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)} - \beta \log \frac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}\right)\right]$$

No reward model and no sampling from the policy are needed, only the log-probabilities of two fixed responses under the policy and the reference. For a tabular softmax policy with logits $\theta$, the gradient of one pair's loss is $-\beta\, \sigma(-m)\,(e_w - e_l)$, where $m$ is the margin inside the sigmoid and $e_k$ is the one-hot vector. The normaliser's gradient cancels, which is why the code below never computes $Z$. This derivation is my own working from the loss, checked numerically.

## Worked example and code

The code uses five responses with a hidden reward, a reference policy, 4000 simulated pairs, and two fits: a reward model followed by the RLHF closed form, and DPO on the logits. It is standalone NumPy and runs in the browser.

```python
import numpy as np

# Toy problem: one prompt, five candidate responses
pi_ref = np.array([0.40, 0.25, 0.15, 0.12, 0.08])    # reference (SFT) policy
r_true = np.array([0.20, 0.90, 1.50, -1.00, 0.00])   # hidden reward, unknown to the learner
beta = 0.5                                            # strength of the KL penalty
K = len(pi_ref)

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def softmax(z):
    e = np.exp(z - z.max())
    return e / e.sum()

# 1. The RLHF optimum, in closed form
pi_star = softmax(np.log(pi_ref) + r_true / beta)
print("pi_star:", pi_star.round(4))

# 2. Bradley-Terry: probability and loss for a reward gap of 1.0
print("P(chosen wins) =", round(float(sigmoid(1.0)), 4), " loss =", round(float(-np.log(sigmoid(1.0))), 4))

# 3. Simulate 4000 labelled pairs; labels follow Bradley-Terry with the hidden reward
rng = np.random.default_rng(7)
i = rng.integers(0, K, 4000)
j = (i + rng.integers(1, K, 4000)) % K
i_wins = rng.random(4000) < sigmoid(r_true[i] - r_true[j])
w = np.where(i_wins, i, j)                            # chosen (winner) index
l = np.where(i_wins, j, i)                            # rejected (loser) index
print("chosen response is truly better in", round(float(np.mean(r_true[w] > r_true[l])), 4), "of pairs")

# 4. Reward model: fit one reward per response by gradient descent on the BT loss
r_hat = np.zeros(K)
for _ in range(3000):
    d = sigmoid(r_hat[w] - r_hat[l])
    grad = np.zeros(K)
    np.add.at(grad, w, -(1 - d))
    np.add.at(grad, l, (1 - d))
    r_hat -= 0.5 * grad / len(w)
r_hat -= r_hat.mean()                                 # reward is defined up to a constant
pi_rm = softmax(np.log(pi_ref) + r_hat / beta)        # RLHF optimum under the learned reward
print("reward model:", r_hat.round(2))

# 5. DPO: gradient descent directly on the policy logits, starting from pi_ref
theta = np.log(pi_ref).copy()
for _ in range(3000):
    logp = theta - np.log(np.exp(theta).sum())
    m = beta * ((logp[w] - np.log(pi_ref[w])) - (logp[l] - np.log(pi_ref[l])))
    coef = -beta * sigmoid(-m)
    grad = np.zeros(K)
    np.add.at(grad, w, coef)
    np.add.at(grad, l, -coef)
    theta -= 2.0 * grad / len(w)
pi_dpo = softmax(theta)
print("pi_dpo:     ", pi_dpo.round(4))
print("DPO optimum equals reward-model RLHF optimum:", bool(np.allclose(pi_dpo, pi_rm, atol=1e-8)))
print("KL(pi_dpo || pi_star) =", round(float(np.sum(pi_dpo * np.log(pi_dpo / pi_star))), 4))
```

```output
pi_star: [0.1144 0.2898 0.5774 0.0031 0.0153]
P(chosen wins) = 0.7311  loss = 0.3133
chosen response is truly better in 0.7455 of pairs
reward model: [-0.1   0.64  1.13 -1.35 -0.32]
pi_dpo:      [0.1206 0.3309 0.5297 0.003  0.0157]
DPO optimum equals reward-model RLHF optimum: True
KL(pi_dpo || pi_star) = 0.005
```

Three things to read off the output. First, the DPO policy matches the policy from the reward-model route to floating-point precision (the experiment's maximum difference is $3 \times 10^{-16}$). This is expected: DPO's implicit reward is a reparameterisation of the Bradley-Terry reward, so the two losses have the same minimiser (reasoning, checked numerically). Second, both differ from the true optimum $\pi^*$ because 4000 labels are a finite sample: the KL divergence from $\pi^*$ is 0.005. Third, only 74.6% of pairs have the truly better response chosen, so the labels are noisy in the sense that matters: a better response can lose.

The data-size sweep below uses the same toy, averaged over 20 seeds, measuring $\mathrm{KL}(\pi_{\text{DPO}} \,\|\, \pi^*)$. The experiment script is in the course repository.

| Pairs | Mean KL to $\pi^*$ | Range over 20 seeds |
|---|---|---|
| 100 | 0.1228 | 0.0044 to 0.5812 |
| 400 | 0.0258 | 0.0047 to 0.0951 |
| 1600 | 0.0072 | 0.0002 to 0.0199 |
| 6400 | 0.0015 | 0.0000 to 0.0065 |

The mean falls by roughly 4× for each 4× more pairs, which is what estimation error shrinking with data looks like. This is a pattern in five responses with a tabular policy, not a proven rate.

## Common traps

> [!TRAP]
> The DPO loss needs the reference term. Writing $-\log\sigma(\beta(\log\pi_w - \log\pi_l))$ without dividing by $\pi_{\text{ref}}$ is a different objective, and it drops the anchor to the SFT model.

> [!TRAP]
> A reward model's scale carries no meaning on its own. The loss is invariant to adding a constant, so compare rewards only as differences, or centre them as the code does.

> [!TRAP]
> A loss of $\log 2 = 0.6931$ at initialisation is not "69% accuracy". At the start every margin is zero, so the loss is $-\log \sigma(0)$ and the policy has not yet learned anything.

> [!TRAP]
> A lower DPO loss on training pairs does not mean the model is better. The pairs are fixed, and DPO is trained on them offline, so a low loss can come from fitting the label noise.

> [!TRAP]
> The toy policy is tabular: one logit per response. A real LLM shares parameters across responses, so its implicit reward is constrained, and the equivalence above does not carry over.

## Summary

- SFT maximises the likelihood of demonstrations, with loss $-\log \pi(y_t)$ per token; it cannot express that one correct answer beats another.
- The Bradley-Terry model turns a reward gap into a win probability, $\sigma(r_w - r_l)$, and its loss is defined only up to a constant.
- The KL-regularised RLHF optimum is $\pi^* \propto \pi_{\text{ref}}\, e^{r/\beta}$; PPO approximates it with a clipped surrogate and sampled rollouts.
- DPO inverts this relation, so the policy's log-ratio to the reference acts as the reward; it trains on fixed pairs with no reward model and no sampling.
- In the tabular toy, the DPO optimum equals the reward-model RLHF optimum, and both approach $\pi^*$ as data grows.

## Quiz time

### Question 1: Calculation

A reward model gives the chosen response reward 2.0 and the rejected response reward $-0.5$. What is the Bradley-Terry probability that the chosen response wins, and what is the loss?

<details><summary>Show solution</summary>

The gap is $2.0 - (-0.5) = 2.5$. Then $\sigma(2.5) = 1/(1 + e^{-2.5}) = 0.9241$, and the loss is $-\log 0.9241 = 0.0789$.

</details>

### Question 2: Prediction

At initialisation $\pi_\theta = \pi_{\text{ref}}$, so every margin $m$ in the DPO loss is zero. What is the mean loss over any set of pairs, and what happens to the gradient on the first step?

<details><summary>Show solution</summary>

Each term is $-\log\sigma(0) = \log 2 = 0.6931$, regardless of the data. The gradient per pair is $-\beta\sigma(-0)(e_w - e_l) = -\frac{\beta}{2}(e_w - e_l)$, which is non-zero. So the first update moves probability toward chosen responses and away from rejected ones, as intended.

</details>

### Question 3: Bug spotting

A colleague computes the DPO loss as `-np.log(sigmoid(beta * (logp_w - logp_l)))`, with `logp` the log-probabilities under the policy only. Explain what is missing and what can go wrong.

<details><summary>Show solution</summary>

The reference log-probabilities are missing, so the loss is not the DPO objective. The implicit reward is $\beta\log(\pi/\pi_{\text{ref}})$, and without the subtraction the loss rewards raising the probability of chosen responses in absolute terms, with nothing anchoring the policy to the SFT model. The policy can drift arbitrarily far from $\pi_{\text{ref}}$, and the code runs without any error, so the bug is silent.

</details>

### Question 4: Explanation

For a positive advantage ($A > 0$), why does the clipped PPO term stop giving gradient once $\rho > 1.2$, but not once $\rho < 0.8$?

<details><summary>Show solution</summary>

For $A > 0$, the objective is $\min(\rho A, \mathrm{clip}(\rho)A)$. Above $1.2$ the clipped term is the smaller one: $1.2A < \rho A$, so the minimum is the constant $1.2A$, and its gradient in $\rho$ is zero. Below $0.8$ the unclipped term is smaller, $\rho A < 0.8A$, so the minimum is $\rho A$, which still has gradient. The clip therefore limits how much the ratio can grow for a good action, but it does not stop the update from raising a ratio that is too small.

</details>

### Question 5: Explanation

Why does $\mathrm{KL}(\pi_{\text{DPO}} \,\|\, \pi^*)$ in the sweep fall as the number of pairs grows, even though DPO never sees $\pi^*$ or the true reward?

<details><summary>Show solution</summary>

DPO sees only the labels, which are drawn from Bradley-Terry with the true reward. With more labels, the empirical preference frequencies approach their true values, so the fitted reward approaches the true reward up to a constant, and the policy approaches $\pi^*$. The error is an estimation error from finite data, not an optimisation error, since the same optimiser reaches the same answer as the reward-model route with 4000 pairs.

</details>
