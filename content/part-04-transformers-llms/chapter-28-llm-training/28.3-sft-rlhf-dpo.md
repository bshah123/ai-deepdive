# 28.3 — Post-Training: SFT, RLHF (PPO) & Direct Preference Optimization (DPO)

## Opening Motivation & Context

After pre-training a large language model (LLM), the next critical phase is post-training. This involves fine-tuning the model to better suit specific tasks or user preferences. Three key techniques in this phase are Supervised Fine-Tuning (SFT), Reinforcement Learning from Human Feedback (RLHF) using Proximal Policy Optimization (PPO), and Direct Preference Optimization (DPO).

- **Supervised Fine-Tuning (SFT)**: This involves further training the model on a labeled dataset to improve its performance on specific tasks.
- **Reinforcement Learning from Human Feedback (RLHF)**: This technique uses human feedback to guide the model's learning process, making it more aligned with human preferences.
- **Direct Preference Optimization (DPO)**: This method directly optimizes the model to align with human preferences, bypassing the need for a separate reward model.

These techniques are crucial for creating LLMs that are not only powerful but also aligned with human values and preferences.

## Core Concepts Breakdown

### Supervised Fine-Tuning (SFT)

SFT is a straightforward method of fine-tuning an LLM on a labeled dataset. The model is trained to predict the correct output given a specific input.

> [!KEY-INSIGHT]
> SFT is the most direct way to adapt an LLM to a specific task, but it requires a high-quality labeled dataset.

> [!BEST-PRACTICE]
> Always validate the quality of your labeled dataset before starting SFT to ensure the model learns the correct patterns.

> [!WARNING]
> Overfitting is a common issue with SFT. Ensure your dataset is diverse and representative to avoid this.

### Reinforcement Learning from Human Feedback (RLHF)

RLHF is a more complex technique that involves training a reward model based on human feedback and then using this model to guide the LLM's learning process via PPO.

> [!KEY-INSIGHT]
> RLHF allows for the incorporation of human preferences into the model's learning process, making it more aligned with human values.

> [!BEST-PRACTICE]
> Use a diverse and representative set of human feedback data to train the reward model. This ensures the model learns a broad range of preferences.

> [!WARNING]
> RLHF can be computationally expensive due to the need to train a separate reward model and perform PPO updates.

### Direct Preference Optimization (DPO)

DPO is a newer technique that directly optimizes the model to align with human preferences, bypassing the need for a separate reward model.

> [!KEY-INSIGHT]
> DPO simplifies the RLHF process by directly optimizing the model's parameters to align with human preferences.

> [!BEST-PRACTICE]
> Use DPO when you have a clear understanding of the preferences you want the model to learn. It can be more efficient than RLHF.

> [!WARNING]
> DPO may not be as flexible as RLHF when dealing with complex or evolving preferences.

## Code Demonstration & Runtime Output

Here is a simplified example of how you might implement SFT using Python and the Hugging Face Transformers library:

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer, Trainer, TrainingArguments
from datasets import load_dataset
import torch

# Load the pre-trained model and tokenizer
model_name = "bert-base-uncased"
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)
tokenizer = AutoTokenizer.from_pretrained(model_name)

# Load the labeled dataset
dataset = load_dataset("imdb", split="train[:1%]")  # Using a small subset for demonstration

# Tokenize the dataset
def tokenize_function(examples):
    return tokenizer(examples["text"], padding="max_length", truncation=True)

tokenized_dataset = dataset.map(tokenize_function, batched=True)

# Define the training arguments
training_args = TrainingArguments(
    output_dir="./results",
    per_device_train_batch_size=8,
    num_train_epochs=3,
    save_steps=10_000,
    save_total_limit=2,
)

# Define the trainer
trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset,
)

# Start training
trainer.train()

# Save the fine-tuned model
model.save_pretrained("./fine_tuned_model")
tokenizer.save_pretrained("./fine_tuned_model")
```

### How this works (Line-by-Line Breakdown)

1. **Import Libraries**: The necessary libraries, including `AutoModelForSequenceClassification`, `AutoTokenizer`, `Trainer`, and `TrainingArguments` from the Hugging Face Transformers library, and `load_dataset` from the Hugging Face Datasets library, are imported.
2. **Load Model and Tokenizer**: The pre-trained model and tokenizer are loaded using the `AutoModelForSequenceClassification` and `AutoTokenizer` classes. The `num_labels` parameter is set to 2 for binary classification.
3. **Load Dataset**: The labeled dataset is loaded using the `load_dataset` function. In this example, a small subset of the IMDB dataset is used for demonstration.
4. **Tokenize Dataset**: The dataset is tokenized using the `tokenize_function` function, which uses the tokenizer to convert the text into input IDs and attention masks. The `map` function is used to apply the tokenization to the entire dataset.
5. **Define Training Arguments**: The training arguments are defined using the `TrainingArguments` class. These arguments include the output directory, batch size, number of epochs, and saving steps.
6. **Define Trainer**: The trainer is defined using the `Trainer` class. The model, training arguments, and tokenized dataset are passed to the trainer.
7. **Start Training**: The `train` method of the trainer is called to start the training process. The model is fine-tuned on the labeled dataset.
8. **Save Model**: The fine-tuned model and tokenizer are saved to the specified directory using the `save_pretrained` method.

> [!ADVANCED]
> The `Trainer` class from the Hugging Face Transformers library handles the training loop, including batching, gradient computation, and optimization. The `TrainingArguments` class provides a convenient way to configure the training process, including hyperparameters and logging settings.

## Summary & Key Takeaways

- SFT is a direct method for fine-tuning an LLM on a labeled dataset.
- RLHF involves training a reward model based on human feedback and using PPO to guide the model's learning process.
- DPO directly optimizes the model to align with human preferences, simplifying the RLHF process.
- Always validate the quality of your labeled dataset before starting SFT.
- Use a diverse and representative set of human feedback data to train the reward model in RLHF.
- DPO can be more efficient than RLHF when dealing with clear and well-defined preferences.

<details><summary>Show Solution</summary>

**A: The bug is that the `tokenize_function` is not correctly handling the tokenization of the dataset. The fixed code snippet is as follows:**

```python
from transformers import AutoModelForSequenceClassification, AutoTokenizer, Trainer, TrainingArguments
from datasets import load_dataset

model_name = "bert-base-uncased"
model = AutoModelForSequenceClassification.from_pretrained(model_name, num_labels=2)
tokenizer = AutoTokenizer.from_pretrained(model_name)

dataset = load_dataset("imdb", split="train[:1%]")

def tokenize_function(examples):
    return tokenizer(examples["text"], padding="max_length", truncation=True, return_tensors="pt")

tokenized_dataset = dataset.map(tokenize_function, batched=True)

training_args = TrainingArguments(
    output_dir="./results",
    per_device_train_batch_size=8,
    num_train_epochs=3,
    save_steps=10_000,
    save_total_limit=2,
)

trainer = Trainer(
    model=model,
    args=training_args,
    train_dataset=tokenized_dataset,
)

trainer.train()

model.save_pretrained("./fine_tuned_model")
tokenizer.save_pretrained("./fine_tuned_model")
```

**The fix involves adding `return_tensors="pt"` to the `tokenizer` call in the `tokenize_function` to ensure the tokenized outputs are returned as PyTorch tensors.**
