After this lesson you will be able to follow `AutoModel.from_pretrained` from a checkpoint's `config.json` file to a ready model object, predict which class and which weights a call will load, and read the list of missing and unexpected weights it reports. You will build a NumPy version of the mechanism, because this environment has no PyTorch and no downloaded weights.

**You need:** Python classes and dictionaries, and the transformer block from Lesson 26.1.

## The problem: many architectures, one call

The Hugging Face `transformers` library ships dozens of model families. BERT (Bidirectional Encoder Representations from Transformers) and GPT-2 (Generative Pre-trained Transformer 2) have different parameter names, different layers and different output heads. A script that loads "a model from a checkpoint" cannot know in advance which class to build, so the checkpoint has to say it.

It does, in a file named `config.json`. The name is the constant `CONFIG_NAME = "config.json"` in `src/transformers/utils/hub.py` on the library's main branch (fetched 2026-11-22). Inside that file, the field `model_type` names the family, for example `"bert"`. The Hugging Face Auto classes documentation says the configuration class "is selected based on the `model_type` property of the config object that is loaded" (opened 2026-11-22).

`AutoModel` is a dispatcher. It does not implement BERT. It reads the config and forwards the call to the right class.

Without this layer, a script would import the exact class, such as `BertModel`, and hard-code its name. Switching to a GPT-2 checkpoint would mean editing the import and the call. With the Auto class, the same line works for every family in the mapping, and adding a family means adding one mapping entry rather than changing every call site. This is reasoning from the layout of the source files, not a measured result.

![Four boxes in a row: checkpoint folder, CONFIG_MAPPING turning model_type bert into BertConfig, MODEL_MAPPING turning BertConfig into BertModel, and from_pretrained loading weights and setting eval mode](diagrams/30.1-dispatch.svg "Figure 1: The lookups AutoModel.from_pretrained performs, in order.")

## Worked example, by hand

Take this `config.json`, abbreviated to the fields that matter:

```json
{"model_type": "bert", "hidden_size": 4, "vocab_size": 10, "architectures": ["BertForSequenceClassification"]}
```

1. Read `model_type`: it is `"bert"`.
2. `CONFIG_MAPPING["bert"]` gives `BertConfig`. A config is plain data here: hidden size $H = 4$, vocabulary size $V = 10$.
3. `MODEL_MAPPING[BertConfig]` gives `BertModel`. The mapping holds one class for this config, so `architectures` is not consulted.
4. `BertModel(config)` creates its parameters from the config's shapes. `embeddings.weight` has shape $V \times H = 10 \times 4$, which is 40 numbers. `encoder.weight` has shape $H \times H = 4 \times 4$, which is 16 numbers. Total: 56.
5. The checkpoint's arrays are copied in by name, and the model is set to evaluation mode.

Now use `AutoModelForSequenceClassification` on the same config. The mapping sends `BertConfig` to `BertForSequenceClassification`, which adds `classifier.weight` with shape (number of labels) $\times H = 2 \times 4 = 8$ numbers. Total: 64.

> [!KEY-INSIGHT]
> The config picks the class. The class defines the parameter names and shapes. The checkpoint supplies only numbers, matched to those names.

## Choosing among several classes

Some configs map to a list of classes rather than one. The library then looks at `config.architectures`, a list of class names saved with the model, and picks the first entry whose name matches. If nothing matches, it takes the first entry of the list.

![Left: a mapping entry holding two classes. Right: architectures empty gives entry 0 by fallback, architectures naming GPT2LMHeadModel gives entry 1](diagrams/30.1-list-pick.svg "Figure 2: Resolving a list-valued mapping entry, as _get_model_class does.")

In the library this rule is `_get_model_class` in `auto_factory.py`. It indexes the mapping by `type(config)`, returns a single class directly, and for a list loops over `config.architectures` and finally returns `supported_models[0]`. The GPT-2 entries in the code below are a toy list that shows the rule, not a copy of the library's table.

## A NumPy mirror of the mechanism

The real code lives in three places: `auto_factory.py` (dispatch), `configuration_auto.py` (the config lookup) and `modeling_utils.py` (the base class and weight loading). This mirror keeps their three lookups and their key-matching rule. It drops the tokenizer, the Hub downloads, the file formats and everything else. Its tensors are NumPy arrays, so the code runs in the browser.

```python
import json
import numpy as np


class PretrainedConfig:
    """Plain data: what a checkpoint's config.json describes."""
    model_type = "base"

    def __init__(self, **kwargs):
        self.hidden_size = kwargs.get("hidden_size", 4)
        self.vocab_size = kwargs.get("vocab_size", 10)
        self.num_labels = kwargs.get("num_labels", 2)
        self.architectures = kwargs.get("architectures", [])


class BertConfig(PretrainedConfig):
    model_type = "bert"


class GPT2Config(PretrainedConfig):
    model_type = "gpt2"


# model_type string -> config class (the library keeps this table in one place)
CONFIG_MAPPING = {"bert": BertConfig, "gpt2": GPT2Config}


class PreTrainedModel:
    """Base class: creates named parameters, loads weights, sets eval mode."""
    base_model_prefix = ""

    def __init__(self, config):
        self.config = config
        self.training = True                      # a freshly built model is in training mode
        rng = np.random.default_rng(0)
        self.params = {name: rng.normal(0.0, 0.02, size=shape)
                       for name, shape in type(self).shapes(config).items()}
        self.load_report = None

    @classmethod
    def from_pretrained(cls, checkpoint, config=None):
        if config is None:
            config = auto_config(checkpoint)
        model = cls(config)
        model.load_report = load_weights(model, checkpoint["weights"])
        model.training = False                    # eval mode by default
        return model


class BertModel(PreTrainedModel):
    base_model_prefix = "bert"

    @staticmethod
    def shapes(c):
        return {"embeddings.weight": (c.vocab_size, c.hidden_size),
                "encoder.weight": (c.hidden_size, c.hidden_size)}

    def forward(self, ids):
        x = self.params["embeddings.weight"][ids]          # (seq, hidden)
        return np.tanh(x @ self.params["encoder.weight"])  # "last_hidden_state"


class BertForSequenceClassification(PreTrainedModel):
    base_model_prefix = "bert"

    @staticmethod
    def shapes(c):
        base = {"bert." + k: v for k, v in BertModel.shapes(c).items()}
        base["classifier.weight"] = (c.num_labels, c.hidden_size)
        return base


class GPT2Model(PreTrainedModel):
    base_model_prefix = "transformer"

    @staticmethod
    def shapes(c):
        return {"wte.weight": (c.vocab_size, c.hidden_size),
                "mlp.weight": (c.hidden_size, c.hidden_size)}


class GPT2ForSequenceClassification(PreTrainedModel):
    base_model_prefix = "transformer"

    @staticmethod
    def shapes(c):
        base = {"transformer." + k: v for k, v in GPT2Model.shapes(c).items()}
        base["score.weight"] = (c.num_labels, c.hidden_size)
        return base


class GPT2LMHeadModel(PreTrainedModel):
    base_model_prefix = "transformer"

    @staticmethod
    def shapes(c):
        base = {"transformer." + k: v for k, v in GPT2Model.shapes(c).items()}
        base["lm_head.weight"] = (c.vocab_size, c.hidden_size)
        return base


# config class -> model class (one class, or a list to choose from by config.architectures)
MODEL_MAPPING = {BertConfig: BertModel, GPT2Config: GPT2Model}
SEQ_CLS_MAPPING = {BertConfig: BertForSequenceClassification,
                   GPT2Config: [GPT2ForSequenceClassification, GPT2LMHeadModel]}


def auto_config(checkpoint):
    data = json.loads(checkpoint["config.json"])          # 1. read model_type from the file
    return CONFIG_MAPPING[data["model_type"]](**data)     # 2. look up the config class


def pick_class(config, mapping):
    candidates = mapping[type(config)]                    # 3. config class -> model class
    if not isinstance(candidates, list):
        return candidates
    by_name = {cls.__name__: cls for cls in candidates}
    for arch in config.architectures:                     # 4. list: match architectures
        if arch in by_name:
            return by_name[arch]
    return candidates[0]                                  # 5. otherwise the first entry


def load_weights(model, weights):
    expected = set(model.params)
    prefix = model.base_model_prefix + "."
    renamed = {}
    for key, value in weights.items():
        new = key
        if model.base_model_prefix and key not in expected:
            if key.startswith(prefix):
                new = key[len(prefix):]               # saved with prefix, loading the bare base
            elif prefix + key in expected:
                new = prefix + key                    # saved from the bare base, loading a head
        renamed[new] = value
    for name in sorted(expected & set(renamed)):
        if model.params[name].shape != renamed[name].shape:
            raise ValueError(f"shape mismatch for {name}: checkpoint {renamed[name].shape}, "
                             f"model {model.params[name].shape}")
    for name in expected & set(renamed):
        model.params[name] = renamed[name].copy()
    return {"missing": sorted(expected - set(renamed)),
            "unexpected": sorted(set(renamed) - expected)}


class AutoModel:
    mapping = MODEL_MAPPING

    @classmethod
    def from_pretrained(cls, checkpoint):
        config = auto_config(checkpoint)
        return pick_class(config, cls.mapping).from_pretrained(checkpoint, config=config)


class AutoModelForSequenceClassification(AutoModel):
    mapping = SEQ_CLS_MAPPING


def n_params(model):
    return sum(p.size for p in model.params.values())


# ---- demo ----
rng = np.random.default_rng(42)
bert_json = json.dumps({"model_type": "bert", "hidden_size": 4, "vocab_size": 10,
                        "architectures": ["BertForSequenceClassification"]})
base_weights = {"embeddings.weight": rng.normal(size=(10, 4)),
                "encoder.weight": rng.normal(size=(4, 4))}
base_ckpt = {"config.json": bert_json, "weights": base_weights}   # saved from the bare encoder

print("1. config class:", type(auto_config(base_ckpt)).__name__)

m = AutoModel.from_pretrained(base_ckpt)
print("2. AutoModel ->", type(m).__name__, "| training =", m.training)
print("   missing:", m.load_report["missing"], "| unexpected:", m.load_report["unexpected"])
print("   last_hidden_state shape:", m.forward(np.array([1, 5, 2])).shape, "| params:", n_params(m))

h = AutoModelForSequenceClassification.from_pretrained(base_ckpt)
print("3. AutoModelForSequenceClassification ->", type(h).__name__)
print("   missing:", h.load_report["missing"], "| unexpected:", h.load_report["unexpected"])
print("   params:", n_params(h))

head_weights = {"bert." + k: v for k, v in base_weights.items()}
head_weights["classifier.weight"] = rng.normal(size=(2, 4))
m2 = AutoModel.from_pretrained({"config.json": bert_json, "weights": head_weights})
print("4. head checkpoint into BertModel -> missing:", m2.load_report["missing"],
      "| unexpected:", m2.load_report["unexpected"])

for archs in (["GPT2LMHeadModel"], []):
    cfg = json.dumps({"model_type": "gpt2", "architectures": archs})
    chosen = pick_class(auto_config({"config.json": cfg}), SEQ_CLS_MAPPING)
    print(f"5. architectures={archs} -> {chosen.__name__}")

bad_json = json.dumps({"model_type": "bert", "hidden_size": 8, "vocab_size": 10})
try:
    AutoModel.from_pretrained({"config.json": bad_json, "weights": base_weights})
except ValueError as err:
    print("6. shape mismatch ->", err)
```

```output
1. config class: BertConfig
2. AutoModel -> BertModel | training = False
   missing: [] | unexpected: []
   last_hidden_state shape: (3, 4) | params: 56
3. AutoModelForSequenceClassification -> BertForSequenceClassification
   missing: ['classifier.weight'] | unexpected: []
   params: 64
4. head checkpoint into BertModel -> missing: [] | unexpected: ['classifier.weight']
5. architectures=['GPT2LMHeadModel'] -> GPT2LMHeadModel
5. architectures=[] -> GPT2ForSequenceClassification
6. shape mismatch -> shape mismatch for embeddings.weight: checkpoint (10, 4), model (10, 8)
```

Each numbered line of the output checks one claim from the worked example.

Output 1 is step 2: `model_type` selects `BertConfig`. Output 2 is steps 3 to 5. The base checkpoint matches the base model exactly, so nothing is missing and nothing is unexpected. The forward pass maps three token ids to a $3 \times 4$ array, one 4-number vector per token, and the parameter count is 56, as computed by hand.

Output 3 shows the head class. The base checkpoint has no `classifier.weight`, so that tensor keeps its random start and is listed as missing. The parameter count rises to 64.

Output 4 is the head checkpoint loaded into the bare base. The `bert.` prefix is stripped so the encoder weights load, and `classifier.weight` has no home in `BertModel`, so it is reported as unexpected and ignored.

Output 5 shows the list rule from Figure 2: the named architecture wins, and an empty list takes entry 0.

Output 6 is the failure mode for a shape mismatch. The error names the first mismatched tensor in alphabetical order, here `embeddings.weight`, with both shapes.

## How the prefix rule works

Each model class has a `base_model_prefix` attribute. `PreTrainedModel` defines it as an empty string (`modeling_utils.py`, line 1094). `BertModel` uses `"bert"`, meaning that when it sits inside a larger model, its weights live under `bert.`. The loader then strips or adds that prefix when names disagree. Near line 4650, a helper in `modeling_utils.py` applies the same add-or-remove step when it matches missing weight names to modules. The mirror above does the same thing in fewer cases.

![Two panels. Top: embeddings.weight and encoder.weight from a base checkpoint gain the bert. prefix, while classifier.weight has no source and is marked missing. Bottom: bert.-prefixed keys lose the prefix, while classifier.weight has no target and is marked unexpected](diagrams/30.1-key-match.svg "Figure 3: Name matching in both directions, with the leftovers each side reports.")

The two leftover lists are the most useful diagnostic in the whole loading path. A missing key means a tensor you expected kept its random start. An unexpected key means a tensor in the file was never used.

> [!TRAP]
> **AutoModel returns the bare encoder.** It has no task head, so there is no `logits` attribute to read. For classification, use `AutoModelForSequenceClassification`, as in output 3.

> [!TRAP]
> **Missing keys are random numbers.** A missing weight keeps its initial random values. A classifier with random weights gives random predictions, however clean the code looks. Read the missing list before you trust a result.

> [!TRAP]
> **from_pretrained leaves the model in evaluation mode.** The docstring of `auto_factory.py` says the model is set to evaluation mode, so dropout is off (line 93 of that file). In a hand-written training loop, call `model.train()` before fine-tuning, or dropout stays off with no error. Lesson 30.3 covers `Trainer`, which runs its own loop.

> [!TRAP]
> **A list fallback is silent.** If `architectures` is empty or names nothing in the list, `_get_model_class` returns the first entry without raising an error. When the choice matters, pass the class explicitly.

> [!TRAP]
> **A shape mismatch means the config changed.** Output 6 is what happens when someone edits `hidden_size` but keeps old weights. Fix the config so it matches the weights. Do not reshape tensors by hand to force a load.

The real library runs on PyTorch and downloads weights from the Hub. On a machine with PyTorch installed, `AutoModel.from_pretrained("bert-base-uncased")` follows this same dispatch. This lesson did not run that call, because this environment has no PyTorch and no network weights. Everything shown above was run.

## Summary

- `AutoModel` reads `model_type` from `config.json`, then makes two lookups: the config class, then the model class.
- The config class defines parameter names and shapes. The checkpoint supplies numbers, matched by name.
- The `base_model_prefix` rule lets a base checkpoint load into a head model, and vice versa. Leftovers are reported as missing or unexpected.
- `from_pretrained` returns the model in evaluation mode. A missing weight is a random weight.

## Quiz time

### Question 1: Calculation

In the mirror, a config has `model_type` "bert", `hidden_size` 6, `vocab_size` 12 and `num_labels` 3. How many numbers does `AutoModel` create, and how many does `AutoModelForSequenceClassification` create?

<details><summary>Show Solution</summary>

`AutoModel` builds `embeddings.weight` with $12 \times 6 = 72$ numbers and `encoder.weight` with $6 \times 6 = 36$ numbers, so 108 in total. `AutoModelForSequenceClassification` adds `classifier.weight` with $3 \times 6 = 18$ numbers, so 126 in total. The count is for this mirror only. The real BERT has more tensors, so its counts are different.

</details>

### Question 2: Prediction

A checkpoint was saved from `BertForSequenceClassification`. Its keys are `bert.embeddings.weight`, `bert.encoder.weight` and `classifier.weight`. You load it with `AutoModel`. Which keys are missing, and which are unexpected?

<details><summary>Show Solution</summary>

Missing: none. The `bert.` prefix is stripped, so both encoder tensors match. Unexpected: `classifier.weight`. It has no home in `BertModel`, so it is ignored. This is output 4.

</details>

### Question 3: Bug-spotting

A colleague writes `model = AutoModel.from_pretrained(path)` for a sentiment task, then reads `model(ids).logits` and says BERT "loaded correctly". What is wrong, and what should change?

<details><summary>Show Solution</summary>

`AutoModel` returns the base encoder with no classification head, so there is no `logits` attribute. The fix is `AutoModelForSequenceClassification.from_pretrained(path)`. The colleague should also read the missing-keys list. If `classifier.weight` is missing, the head is random and the sentiment predictions mean nothing.

</details>

### Question 4: Explanation

Why does loading a head checkpoint into `BertModel` leave `classifier.weight` unused instead of raising an error?

<details><summary>Show Solution</summary>

The loader matches names only. `BertModel` has no parameter named `classifier.weight`, so the key cannot be matched and is reported as unexpected. Only a name that matches and has the wrong shape raises an error, as in output 6. The unexpected list makes the discarded tensor visible, so the reader can decide whether discarding it was intended.

</details>
