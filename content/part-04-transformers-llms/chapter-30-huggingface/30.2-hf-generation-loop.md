# 30.2 — GenerationConfig, Stopping Criteria & Custom Generation Loops

## Opening Motivation & Context

In the realm of natural language processing, the ability to generate coherent and contextually relevant text is a cornerstone of modern AI applications. Transformers, with their self-attention mechanisms, have revolutionized this field by enabling models to understand and generate text with unprecedented accuracy. However, the process of text generation is not as straightforward as it might seem. It involves a series of decisions and configurations that can significantly impact the quality and efficiency of the generated text.

This lesson delves into the intricacies of text generation using Hugging Face Transformers. We will explore the `GenerationConfig` class, which allows you to fine-tune the generation process, and the `StoppingCriteria` class, which provides a way to control when the generation process should stop. Additionally, we will examine how to create custom generation loops to tailor the text generation process to specific needs.

## Core Concepts Breakdown

### GenerationConfig

The `GenerationConfig` class in Hugging Face Transformers is a powerful tool that allows you to configure various parameters of the text generation process. These parameters include:

- `max_length`: The maximum length of the generated text.
- `min_length`: The minimum length of the generated text.
- `do_sample`: Whether to use sampling or greedy decoding.
- `temperature`: The temperature parameter for sampling.
- `top_k`: The number of highest probability vocabulary tokens to keep for top-k-filtering.
- `top_p`: The cumulative probability for nucleus sampling.
- `num_beams`: The number of beams for beam search.
- `early_stopping`: Whether to stop the beam search when at least `num_beams` sentences are finished per batch.

> [!KEY-INSIGHT]
> The `GenerationConfig` class provides a centralized way to manage the parameters of the text generation process, making it easier to experiment with different configurations and reproduce results.

> [!BEST-PRACTICE]
> When using sampling-based methods like top-k or nucleus sampling, it is often beneficial to adjust the `temperature` parameter. A higher temperature will result in more diverse outputs, while a lower temperature will produce more conservative outputs.

### StoppingCriteria

The `StoppingCriteria` class in Hugging Face Transformers provides a way to control when the text generation process should stop. This can be useful in scenarios where you want to stop the generation process based on specific conditions, such as the presence of a certain word or phrase, or when the generated text has reached a certain length.

> [!KEY-INSIGHT]
> The `StoppingCriteria` class allows you to implement custom stopping conditions, giving you fine-grained control over the text generation process.

> [!WARNING]
> When implementing custom stopping criteria, it is important to ensure that the criteria are well-defined and that the generation process will eventually terminate. Otherwise, you may end up with an infinite loop.

### Custom Generation Loops

Custom generation loops allow you to tailor the text generation process to specific needs. This can involve modifying the way the model generates text, or implementing additional logic to process the generated text.

> [!KEY-INSIGHT]
> Custom generation loops provide a way to extend the capabilities of the text generation process, allowing you to implement complex logic and tailor the generated text to specific requirements.

> [!BEST-PRACTICE]
> When implementing custom generation loops, it is important to ensure that the loop is efficient and that the generated text meets the desired quality standards.

## Code Demonstration & Runtime Output

```python
from transformers import AutoModelForCausalLM, AutoTokenizer, GenerationConfig, StoppingCriteria, StoppingCriteriaList
import torch

class CustomStoppingCriteria(StoppingCriteria):
    def __init__(self, max_length: int, stop_sequences: list):
        self.max_length = max_length
        self.stop_sequences = stop_sequences

    def __call__(self, input_ids: torch.LongTensor, scores: torch.FloatTensor, **kwargs) -> bool:
        # Stop if the maximum length is reached
        if input_ids.shape[-1] >= self.max_length:
            return True

        # Stop if any of the stop sequences are found
        for seq in self.stop_sequences:
            if seq in input_ids[0].tolist():
                return True

        return False

def generate_text(model, tokenizer, prompt: str, generation_config: GenerationConfig, stopping_criteria: StoppingCriteriaList):
    inputs = tokenizer(prompt, return_tensors="pt")
    outputs = model.generate(
        **inputs,
        generation_config=generation_config,
        stopping_criteria=stopping_criteria
    )
    return tokenizer.decode(outputs[0], skip_special_tokens=True)

def main():
    model_name = "gpt2"
    model = AutoModelForCausalLM.from_pretrained(model_name)
    tokenizer = AutoTokenizer.from_pretrained(model_name)

    prompt = "Once upon a time"

    # Configure the generation process
    generation_config = GenerationConfig(
        max_length=50,
        min_length=20,
        do_sample=True,
        temperature=0.7,
        top_k=50,
        top_p=0.95,
        num_beams=5,
        early_stopping=True
    )

    # Define the stopping criteria
    stopping_criteria = StoppingCriteriaList([
        CustomStoppingCriteria(max_length=50, stop_sequences=[tokenizer.encode("end")[0]])
    ])

    # Generate the text
    generated_text = generate_text(model, tokenizer, prompt, generation_config, stopping_criteria)
    print(generated_text)

if __name__ == "__main__":
    main()
```

## How this works (Line-by-Line Breakdown)

1. **Imports**: We import the necessary classes and functions from the `transformers` library, as well as `torch` for tensor operations.
2. **CustomStoppingCriteria**: We define a custom stopping criteria class that inherits from `StoppingCriteria`. This class takes a maximum length and a list of stop sequences as input.
3. **__call__ method**: The `__call__` method is called during the text generation process. It checks if the maximum length has been reached or if any of the stop sequences have been found in the generated text. If either condition is met, the method returns `True`, indicating that the generation process should stop.
4. **generate_text function**: This function takes a model, tokenizer, prompt, generation configuration, and stopping criteria as input. It tokenizes the prompt, generates the text using the model, and decodes the generated text.
5. **main function**: In the `main` function, we load the GPT-2 model and tokenizer. We define a prompt and configure the generation process using the `GenerationConfig` class. We also define the stopping criteria using the `StoppingCriteriaList` class and our custom `CustomStoppingCriteria` class. Finally, we generate the text and print it.

> [!ADVANCED]
> The `generate_text` function uses the `model.generate` method, which is implemented in PyTorch. This method takes the tokenized input, generation configuration, and stopping criteria as input and generates the text. The generated text is then decoded using the tokenizer.
