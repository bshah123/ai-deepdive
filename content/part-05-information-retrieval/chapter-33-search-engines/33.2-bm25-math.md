By the end of this lesson you will compute a BM25 score by hand, explain why a term's credit stops growing as the term repeats, and spot the IDF form that turns negative. This lesson is about the scoring formula only; the index that supplies the counts is in Lesson 33.1, and a fast engine is in Lesson 33.3.

**You need:** logarithms and fractions, and the idea of document frequency from Lesson 33.1.

## The problem

Suppose the query is `cat dog`. Document A says "cat" 50 times and nothing else. Document B says "cat" once and "dog" once. A plain count gives A the larger score (50 against 2), even though B covers both query words. A good ranking needs three things:

1. A repeated word should add less each time. Saturation.
2. A rare word should count for more than a common one. Inverse document frequency (IDF).
3. A long document should not win just because it is long. Length normalization.

BM25 (Best Matching 25) combines all three in one sum over the query terms.

## The formula

For a query $Q$ of terms $t$ and a document $D$:

$$
\mathrm{BM25}(D, Q) = \sum_{t \in Q} \mathrm{IDF}(t) \cdot \frac{f(t, D)\,(k_1 + 1)}{f(t, D) + k_1\left(1 - b + b\,\dfrac{|D|}{\mathrm{avgdl}}\right)}
$$

- $f(t, D)$: how many times term $t$ occurs in $D$.
- $|D|$: the length of $D$ in tokens; $\mathrm{avgdl}$: the mean length over the collection.
- $n(t)$: document frequency, the number of documents that contain $t$ (called df in Lesson 33.1); $N$: the number of documents.
- $k_1 \ge 0$: controls saturation. $b \in [0, 1]$: controls length normalization. Lucene's defaults are $k_1 = 1.2$ and $b = 0.75$ ([Lucene BM25Similarity documentation](https://lucene.apache.org/core/9_11_0/core/org/apache/lucene/search/similarities/BM25Similarity.html)).

The part inside the sum has two pieces. The fraction is the **tf part**, which depends on the count and the length of one document. The $\mathrm{IDF}$ factor depends only on how common the term is in the collection.

## Worked example, by hand

Take four documents, each with four tokens, so $\mathrm{avgdl} = 4$ and $N = 4$:

| Doc | Text | $\lvert D \rvert$ |
|---|---|---|
| d1 | cat cat dog bird | 4 |
| d2 | cat fish owl owl | 4 |
| d3 | dog dog dog fish | 4 |
| d4 | bird fish owl whale | 4 |

Both query terms appear in two documents, so $n(\mathrm{cat}) = n(\mathrm{dog}) = 2$. With the Lucene IDF form (defined in the IDF section below):

$$
\mathrm{IDF}(\mathrm{cat}) = \log\!\left(1 + \frac{4 - 2 + 0.5}{2 + 0.5}\right) = \log 2 = 0.6931
$$

For d1, $|D|/\mathrm{avgdl} = 1$, so the length term is $k_1 (1 - b + b) = k_1 = 1.2$. The tf part for "cat" ($f = 2$) is $\dfrac{2 \times 2.2}{2 + 1.2} = 1.375$. For "dog" ($f = 1$) it is $\dfrac{1 \times 2.2}{1 + 1.2} = 1.0$.

![Four steps for one term in document d1: count 2, tf part 1.375, weight 0.953, then the score 1.646 after adding dog](diagrams/33.2-term-weight-steps.svg "One query term, one document, four steps. The score is the sum of the term weights.")

So $\mathrm{BM25}(d_1) = 0.6931 \times (1.375 + 1.0) = 1.6462$. The other documents follow the same way: d3 has $f(\mathrm{dog}) = 3$, a tf part of $6.6 / 4.2 = 1.5714$, and a score of $1.0892$; d2 has only "cat", score $0.6931$; d4 has neither term, score $0$.

Check every number in Python. This block uses only the standard library, so it runs in the browser:

```python
import math

docs = {
    "d1": "cat cat dog bird".split(),
    "d2": "cat fish owl owl".split(),
    "d3": "dog dog dog fish".split(),
    "d4": "bird fish owl whale".split(),
}
query = ["cat", "dog"]
K1, B = 1.2, 0.75                      # Lucene's defaults

N = len(docs)                          # number of documents
avgdl = sum(len(d) for d in docs.values()) / N

def df(term):                          # how many documents contain the term
    return sum(1 for d in docs.values() if term in d)

def idf(term):                         # Lucene form of IDF
    n = df(term)
    return math.log(1 + (N - n + 0.5) / (n + 0.5))

def tf_part(f, dl, k1=K1, b=B):        # BM25 term-frequency component
    norm = k1 * (1 - b + b * dl / avgdl)
    return f * (k1 + 1) / (f + norm)

def bm25(doc):
    total = 0.0
    for term in query:
        f = doc.count(term)
        if f:
            total += idf(term) * tf_part(f, len(doc))
    return total

print(f"N = {N}, avgdl = {avgdl}")
for t in query:
    print(f"{t}: df = {df(t)}, idf = {idf(t):.4f}")
for name, doc in docs.items():
    print(f"{name}: score = {bm25(doc):.4f}")
print("ranking:", sorted(docs, key=lambda k: -bm25(docs[k])))
```

```output
N = 4, avgdl = 4.0
cat: df = 2, idf = 0.6931
dog: df = 2, idf = 0.6931
d1: score = 1.6462
d2: score = 0.6931
d3: score = 1.0892
d4: score = 0.0000
ranking: ['d1', 'd3', 'd2', 'd4']
```

## Term saturation

Take $|D| = \mathrm{avgdl}$, so the length term is $k_1$. The tf part becomes $g(f) = \dfrac{f(k_1 + 1)}{f + k_1}$. Three properties follow directly from this:

- $g(0) = 0$: a missing term adds nothing.
- $g$ is increasing, but it approaches a ceiling. As $f \to \infty$, $\dfrac{f}{f + k_1} \to 1$, so $g(f) \to k_1 + 1$. With $k_1 = 1.2$ the ceiling is $2.2$.
- $g$ is concave: the step from $f$ to $f + 1$ gets smaller as $f$ grows. From 1 to 2 the tf part gains $0.375$; from 2 to 3 it gains $0.196$.

![Grouped bars for f from 1 to 10: amber bars for raw counts rise linearly to 10, blue bars for the BM25 tf part flatten near 2.0 and stay under the 2.2 ceiling](diagrams/33.2-saturation.svg "Raw counts grow without limit; the BM25 tf part saturates at k1 + 1.")

The same numbers appear in Python. The output for $f = 100$ is still under the ceiling:

```python
import math

K1, B = 1.2, 0.75

def tf_part(f, dl_over_avg, k1=K1, b=B):
    norm = k1 * (1 - b + b * dl_over_avg)
    return f * (k1 + 1) / (f + norm)

for f in [1, 2, 3, 5, 10, 20, 100]:
    print(f"f = {f:>3}   linear = {f:>3}   bm25 = {tf_part(f, 1.0):.4f}")
print()
for b in [0.0, 0.75, 1.0]:
    row = [tf_part(2, r, b=b) for r in (0.5, 1.0, 2.0)]
    print(f"b = {b:<4}", "   ".join(f"{x:.4f}" for x in row))
print()
N = 1000
for n in (500, 900):
    rsj = math.log((N - n + 0.5) / (n + 0.5))
    lucene = math.log(1 + (N - n + 0.5) / (n + 0.5))
    print(f"n = {n}: RSJ = {rsj:.4f}   Lucene = {lucene:.4f}")
```

```output

f =   2   linear =   2   bm25 = 1.3750
f =   3   linear =   3   bm25 = 1.5714
f =   5   linear =   5   bm25 = 1.7742
f =  10   linear =  10   bm25 = 1.9643
f =  20   linear =  20   bm25 = 2.0755
f = 100   linear = 100   bm25 = 2.1739

b = 0.0  1.3750   1.3750   1.3750
b = 0.75 1.6000   1.3750   1.0732
b = 1.0  1.6923   1.3750   1.0000

n = 500: RSJ = 0.0000   Lucene = 0.6931
```

The parameter $k_1$ sets how fast the curve flattens. Hand check at $f = 5$: $k_1 = 0$ gives $5 \cdot 1 / 5 = 1$ (presence only); $k_1 = 1.2$ gives $11 / 6.2 = 1.774$; $k_1 = 3$ gives $20 / 8 = 2.5$. As $k_1$ grows, the curve approaches the linear count.

## Length normalization

The length term is $k_1(1 - b + b\,|D|/\mathrm{avgdl})$. The parameter $b$ sets how much it matters:

- $b = 0$: the length term is $k_1$ for every document. Length is ignored.
- $b = 1$: the length term is proportional to $|D|/\mathrm{avgdl}$. A document twice the average length needs twice the count to earn the same credit.

![Grid of tf part values for f = 2: rows b = 0, 0.75, 1; columns short (0.5), average (1), long (2). The b = 0.75 row is highlighted; short documents gain and long documents lose](diagrams/33.2-length-grid.svg "Same count, different length. The highlighted row is the common default b = 0.75.")

With $b = 0.75$ and $f = 2$, a short document ($|D| = 0.5\,\mathrm{avgdl}$) scores $1.600$, which is 16% above the average-length value of $1.375$. A long document ($|D| = 2\,\mathrm{avgdl}$) scores $1.073$, which is 22% below it. These are the effects of the formula, not of a tuned dataset. Whether $b = 0.75$ suits your collection is an empirical question.

## Inverse document frequency

The IDF has several forms in the literature. Two matter here.

- Robertson–Spärck Jones (RSJ) form: $\mathrm{IDF}_{\mathrm{RSJ}}(t) = \log\dfrac{N - n + 0.5}{n + 0.5}$. This is negative when $n > N/2$, that is, when the term appears in more than half the documents.
- Lucene form: $\mathrm{IDF}(t) = \log\!\left(1 + \dfrac{N - n + 0.5}{n + 0.5}\right)$. Algebra gives $\log\dfrac{N + 1}{n + 0.5}$, which is positive for every $n \le N$.

Derivation of the second line: $1 + \dfrac{N - n + 0.5}{n + 0.5} = \dfrac{(n + 0.5) + (N - n + 0.5)}{n + 0.5} = \dfrac{N + 1}{n + 0.5}$.

![Two IDF curves against the fraction of documents containing the term: the RSJ curve crosses zero at one half and goes to minus 6.5; the Lucene curve stays above zero](diagrams/33.2-idf-forms.svg "RSJ IDF turns negative for common terms. The Lucene form stays positive.")

At $N = 1000$, a term in 900 documents has $\mathrm{IDF}_{\mathrm{RSJ}} = -2.1928$ and $\mathrm{IDF}_{\mathrm{Lucene}} = 0.1058$ (the output above). A negative IDF means a common query word lowers the score of the documents that contain it, which is rarely what you want.

> [!WARNING]
> A term that appears in every document does not have IDF 0 under either form. With $N = 3$ and $n = 3$, the Lucene form gives $\log(4/3.5) = 0.1335$ and the RSJ form gives $\log(0.5/3.5) = -1.9459$. Do not assume a zero IDF.

## Common traps

> [!TRAP]
> **Repeated query words.** The formula above sums over distinct query terms. If your engine treats `cat cat dog` as two clauses, the score changes. Check the library's convention before comparing numbers.

> [!TRAP]
> **Average length is over the indexed corpus.** $\mathrm{avgdl}$ is the mean of $|D|$ over all documents in the index, not the mean over the matching documents. Recomputing it per query changes every score.

> [!TRAP]
> **Only the order matters within one query.** BM25 scores are not probabilities, and they are not comparable across queries. Ranking within one query is the usual use.

> [!TRAP]
> **Parameter defaults are conventions.** Lucene uses $k_1 = 1.2$, $b = 0.75$. Other values appear in the literature. Neither default is derived from your data; tune them on labelled queries.

> [!TRAP]
> **Scores from different libraries will not match.** Different implementations use different IDF and length forms; the scoring-variants study in the references is one place this is documented. Compare like with like.

## Summary

- BM25 scores a document as a sum over query terms of IDF times a tf part.
- The tf part rises with the count $f$ but saturates at $k_1 + 1$; $k_1$ sets how fast.
- $b$ scales the effect of document length relative to the average; $b = 0$ ignores length.
- The Lucene IDF form $\log\frac{N+1}{n+0.5}$ stays positive; the RSJ form goes negative for terms in more than half the documents.
- Use the exact formula your library implements, and tune $k_1$ and $b$ on labelled queries.

## Quiz time

### Question 1: Calculate

Using the corpus above, what is the tf part for a document where "cat" appears 3 times and $|D| = \mathrm{avgdl}$?

<details><summary>Show solution</summary>

$g(3) = \dfrac{3 \times 2.2}{3 + 1.2} = \dfrac{6.6}{4.2} = 1.5714$.

</details>

### Question 2: Predict

Set $b = 0$. Does document length change a BM25 score? Explain.

<details><summary>Show solution</summary>

No. With $b = 0$ the length term is $k_1(1 - 0 + 0 \cdot |D|/\mathrm{avgdl}) = k_1$ for every document, so the tf part depends only on $f$. Length is ignored.

</details>

### Question 3: Find the bug

```python
N = len(docs)
avgdl = len(docs)          # bug
```

Why does this give the right answer on the four-document corpus above but wrong answers in general?

<details><summary>Show solution</summary>

`len(docs)` is the number of documents, not the mean length in tokens. On the corpus above both are 4, so the bug is invisible. Try a corpus with document lengths 2 and 6: the mean length is 4, but `len(docs)` is 2, and every length ratio is wrong. The fix is `avgdl = sum(len(d) for d in docs.values()) / N`.

</details>

### Question 4: Explain

A document repeats "dog" 100 times. Another mentions it once. Under raw counts the first document has 100 times the credit. Under BM25 with $k_1 = 1.2$ and $|D| = \mathrm{avgdl}$, how much more credit does it get, roughly?

<details><summary>Show solution</summary>

The tf parts are $g(100) = 2.1739$ and $g(1) = 1.0$, so the ratio is about 2.17. The ceiling $k_1 + 1 = 2.2$ caps the credit for repetition, so the first document gets about twice the credit, not 100 times. This is the intended behaviour, and it limits keyword stuffing.

</details>
