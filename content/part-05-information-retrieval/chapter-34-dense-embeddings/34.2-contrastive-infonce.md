A bi-encoder (Lesson 34.1) is shaped by its training loss. In this lesson you will write the InfoNCE loss, the objective behind the `MultipleNegativesRankingLoss` of the sentence-transformers library (InfoNCE stands for information noise-contrastive estimation), check its gradient numerically, and measure how batch size and temperature change retrieval on synthetic data.

**You need:** the bi-encoder idea (Lesson 34.1), softmax (Lesson 25.1) and matrix multiplication.

## The problem this idea solves

A bi-encoder turns a query and a document into vectors and ranks documents by cosine similarity. Training it needs a signal that says "this document should score above that one". Labelled pairs give positives. A ranking loss also needs negatives, and labelling negatives for every query is expensive. Contrastive learning gets negatives almost for free: the other documents in the same batch serve as negatives for each query. Random in-batch negatives are often easy, since a query about cooking rarely needs to beat a document about tax law. The loss focuses on harder negatives only through the softmax, so the temperature matters; the sections below measure how much.

## Intuition: one batch is a grid

![A batch of four query-document pairs as a 4 by 4 grid of similarity scores; the diagonal holds the positives and the off-diagonal cells are free negatives](diagrams/34.2-batch-grid.svg "Each row is one classification problem: query i must pick document i out of the batch.")

Encode a batch of B query-document pairs (B is the batch size). The B by B matrix of cosine similarities then holds B positives on the diagonal and B(B − 1) negatives elsewhere. Each row is a classification problem with B classes, and the row's correct class is its own document. A batch of 64 pairs thus gives 64 × 63 = 4032 negative comparisons for 128 encoder calls.

## Worked example, by hand

For query $i$, InfoNCE (van den Oord et al., 2018) is the cross-entropy of the softmax over its row:

$$
\ell_i = -\log \frac{\exp(s_{ii}/\tau)}{\sum_{j=1}^{B} \exp(s_{ij}/\tau)}
$$

Here $s_{ij}$ is the cosine similarity between query $i$ and document $j$, and $\tau > 0$ is the temperature. The batch loss is the mean of the $\ell_i$. Dividing by $\tau$ multiplies every score gap by $1/\tau$, so a small $\tau$ makes the softmax decisive.

Take one query whose positive has cosine 0.8, and whose two negatives have cosines 0.1 and −0.2, with $\tau = 0.1$.

![Five steps from similarities 0.8, 0.1, -0.2 to a loss of 0.00096: divide by tau to get 8, 1, -2; exponentiate; normalise to 0.99904, 0.00091, 0.00005; take minus log of the first entry](diagrams/34.2-worked-example.svg "One query, one positive, two negatives. The loss is small because the positive already wins by a wide margin.")

The logits are 8, 1 and −2. Their exponentials sum to 2983.811, so the positive's softmax probability is 2980.958 / 2983.811 = 0.99904, and the loss is −log 0.99904 = 0.00096. The block below reproduces this, implements the loss and the gradient, and checks the gradient against finite differences.

With respect to the scaled logits $S = \text{cosine}/\tau$, the gradient of the batch loss is $(P - I)/B$, where $P$ is the row-wise softmax and $I$ the identity matrix (the positives). With respect to the cosines it is multiplied by $1/\tau$. The block also varies $\tau$ with the four similarities held fixed.

```python
import numpy as np

np.set_printoptions(precision=5, suppress=True)

def row_lse(S):
    # log-sum-exp of each row, shifted by the row maximum for numerical stability
    m = S.max(axis=1, keepdims=True)
    return (m + np.log(np.exp(S - m).sum(axis=1, keepdims=True))).ravel()

def infonce_loss(S):
    # S[i, j] = cosine(query i, doc j) / tau. The positive for query i is doc i (the diagonal).
    return float(np.mean(row_lse(S) - np.diag(S)))

def infonce_grad(S):
    # dL/dS = (softmax probabilities - one-hot targets) / B
    P = np.exp(S - row_lse(S)[:, None])
    return (P - np.eye(len(S))) / len(S)

# 1. Worked example: one query, its positive (index 0) and two negatives
sims = np.array([0.8, 0.1, -0.2])
tau = 0.1
logits = sims / tau
expl = np.exp(logits)
p = expl / expl.sum()
print("logits :", logits)
print("exp    :", expl)
print("softmax:", p)
print("loss   :", round(-np.log(p[0]), 5))

# 2. Temperature changes how the same similarities are weighted
sims4 = np.array([0.8, 0.7, 0.1, -0.2])   # positive, hard negative, two easy negatives
for t in [1.0, 0.5, 0.1, 0.05, 0.02]:
    lg = sims4 / t
    pp = np.exp(lg - lg.max())
    pp = pp / pp.sum()
    print(f"tau={t:<5} p={pp} loss={-np.log(pp[0]):.5f}")

# 3. Gradient check against finite differences
rng = np.random.default_rng(7)
S = rng.normal(size=(5, 5))
eps = 1e-6
num = np.zeros_like(S)
for i in range(5):
    for j in range(5):
        Sp, Sm = S.copy(), S.copy()
        Sp[i, j] += eps
        Sm[i, j] -= eps
        num[i, j] = (infonce_loss(Sp) - infonce_loss(Sm)) / (2 * eps)
print("gradient check passed:", bool(np.abs(infonce_grad(S) - num).max() < 1e-6))

# 4. Two identical documents in one batch (a false negative)
print("duplicate-doc loss:", round(infonce_loss(np.ones((2, 2))), 6), "log 2 =", round(float(np.log(2)), 6))
```

## Training a bi-encoder with InfoNCE

The next block trains two linear bi-encoders. Queries are $\mathbf{x}$ vectors in 32 dimensions and documents are $\mathbf{y}$ vectors, each projected to 16 dimensions and normalised. The data are synthetic: each query and document is a noisy linear view of a shared 24-dimensional latent item. This is a stand-in for real text, so the absolute numbers mean nothing outside this setup. Every number in the listings below is the output of that run; a different seed or batch size will print different numbers. The mechanism does carry over. Recall@1 is the fraction of held-out queries whose own document ranks first among 1000 held-out documents; chance is 0.001.

Because the encoders are linear, the block derives the backward pass by hand. The gradient flows from the similarity matrix through the normalisation, $\partial \mathbf{u}/\partial \mathbf{r} = (I - \mathbf{u}\mathbf{u}^\top)/\lVert \mathbf{r} \rVert$, and the final check confirms it on two weight entries.

```python
import numpy as np

def row_lse(S):
    m = S.max(axis=1, keepdims=True)
    return (m + np.log(np.exp(S - m).sum(axis=1, keepdims=True))).ravel()

def infonce_loss(S):
    return float(np.mean(row_lse(S) - np.diag(S)))

def infonce_grad(S):
    P = np.exp(S - row_lse(S)[:, None])
    return (P - np.eye(len(S))) / len(S)

def normalize_rows(R):
    n = np.linalg.norm(R, axis=1, keepdims=True)
    return R / n, n

def loss_and_grads(Wq, Wd, X, Y, tau):
    # Linear bi-encoders: u = normalize(Wq x), v = normalize(Wd y); S = U V^T / tau
    U, nq = normalize_rows(X @ Wq.T)
    V, nd = normalize_rows(Y @ Wd.T)
    S = U @ V.T / tau
    G = infonce_grad(S)
    dU = G @ V / tau
    dV = G.T @ U / tau
    # Backprop through the row normalisation: d(u)/d(r) = (I - u u^T) / ||r||
    dRq = (dU - np.sum(dU * U, axis=1, keepdims=True) * U) / nq
    dRd = (dV - np.sum(dV * V, axis=1, keepdims=True) * V) / nd
    return infonce_loss(S), dRq.T @ X, dRd.T @ Y

IN, D, LAT, NOISE = 32, 16, 24, 0.6
rng = np.random.default_rng(2026)
A_x = rng.normal(size=(IN, LAT)) / np.sqrt(LAT)
A_y = rng.normal(size=(IN, LAT)) / np.sqrt(LAT)

def make(n):
    # Paired data: query and document are two noisy views of the same latent item z
    z = rng.normal(size=(n, LAT))
    return z @ A_x.T + NOISE * rng.normal(size=(n, IN)), z @ A_y.T + NOISE * rng.normal(size=(n, IN))

Xtr, Ytr = make(4000)
Xte, Yte = make(1000)

def recall_at_k(Wq, Wd, k):
    U, _ = normalize_rows(Xte @ Wq.T)
    V, _ = normalize_rows(Yte @ Wd.T)
    top = np.argsort(-(U @ V.T), axis=1)[:, :k]
    return float(np.mean(np.any(top == np.arange(len(Xte))[:, None], axis=1)))

def train(B, tau, lr=0.5, steps=400, seed=0):
    r = np.random.default_rng(seed)
    Wq = r.normal(0, 1 / np.sqrt(IN), (D, IN))
    Wd = r.normal(0, 1 / np.sqrt(IN), (D, IN))
    hist = []
    for _ in range(steps):
        idx = r.choice(len(Xtr), B, replace=False)
        L, gq, gd = loss_and_grads(Wq, Wd, Xtr[idx], Ytr[idx], tau)
        Wq -= lr * gq
        Wd -= lr * gd
        hist.append(L)
    return Wq, Wd, hist

# Check the encoder-level gradient on one entry of each weight matrix
r = np.random.default_rng(7)
Wq0 = r.normal(0, 1 / np.sqrt(IN), (D, IN))
Wd0 = r.normal(0, 1 / np.sqrt(IN), (D, IN))
X, Y = Xtr[:6], Ytr[:6]
_, gq, gd = loss_and_grads(Wq0, Wd0, X, Y, 0.05)
eps = 1e-6
Wp, Wm = Wq0.copy(), Wq0.copy(); Wp[3, 7] += eps; Wm[3, 7] -= eps
nq_ = (loss_and_grads(Wp, Wd0, X, Y, 0.05)[0] - loss_and_grads(Wm, Wd0, X, Y, 0.05)[0]) / (2 * eps)
Wp, Wm = Wd0.copy(), Wd0.copy(); Wp[3, 7] += eps; Wm[3, 7] -= eps
nd_ = (loss_and_grads(Wq0, Wp, X, Y, 0.05)[0] - loss_and_grads(Wq0, Wm, X, Y, 0.05)[0]) / (2 * eps)
print("encoder gradient check passed:", bool(abs(nq_ - gq[3, 7]) < 1e-6 and abs(nd_ - gd[3, 7]) < 1e-6))

# Loss at random initialisation versus log B
r0 = np.random.default_rng(1)
Wq0 = r0.normal(0, 1 / np.sqrt(IN), (D, IN))
Wd0 = r0.normal(0, 1 / np.sqrt(IN), (D, IN))
for B in [4, 16, 64, 256]:
    idx = r0.choice(len(Xtr), B, replace=False)
    print(f"init B={B:<4} loss={loss_and_grads(Wq0, Wd0, Xtr[idx], Ytr[idx], 0.05)[0]:.4f} log B={np.log(B):.4f}")

# Sweeps: 400 steps, 5 seeds each, mean and sample standard deviation of recall
SEEDS = [0, 1, 2, 3, 4]

def sweep(name, B, tau, lr):
    r1, r5, fl = [], [], []
    for s in SEEDS:
        Wq, Wd, hist = train(B, tau, lr=lr, seed=s)
        r1.append(recall_at_k(Wq, Wd, 1))
        r5.append(recall_at_k(Wq, Wd, 5))
        fl.append(np.mean(hist[-20:]))
    print(f"{name:<12} R@1={np.mean(r1):.3f}+-{np.std(r1, ddof=1):.3f} "
          f"R@5={np.mean(r5):.3f}+-{np.std(r5, ddof=1):.3f} last-20-loss={np.mean(fl):.3f}")

print("batch size (tau=0.05, lr=0.5):")
for B in [4, 16, 64, 256]:
    sweep(f"B={B}", B, 0.05, 0.5)
print("temperature (B=64, lr=0.5):")
for t in [0.5, 0.2, 0.1, 0.05, 0.02]:
    sweep(f"tau={t}", 64, t, 0.5)
```

Three results from this run.

First, the random-initialised loss is far above log B: 6.47 at B = 4, where log 4 = 1.39. The value log B is what you get only when all logits are equal. Random encoders at τ = 0.05 spread the logits widely, so the loss starts high and falls during training.

Second, batch size helps, with diminishing returns. Mean recall@1 rises from 0.204 at B = 4 to 0.486 at B = 16 and 0.596 at B = 64. The step from 64 to 256 (0.596 to 0.614) is 0.018, about 1.6 times the seed-to-seed standard deviation at B = 64 (sd 0.011), so it is weak evidence. Batch size is also not free: the similarity matrix grows as B², and the fixed budget of 400 steps means larger batches see more pairs per step, which this sweep does not separate from the effect of more negatives.

![Bar chart of recall@1 against batch size at tau 0.05: 0.204, 0.486, 0.596 and 0.614 for B equal to 4, 16, 64 and 256, with error bars of one standard deviation over five seeds](diagrams/34.2-batch-size.svg "Recall@1 rises with batch size and then flattens. Error bars are one standard deviation over five seeds.")

Third, temperature has an interior optimum. At B = 64 the best mean recall@1 is at τ = 0.2 (0.618 ± 0.005), and τ = 0.1 (0.609) is close. The sentence-transformers default corresponds to τ = 0.05 (cosine scale 20, below), which gave 0.596 ± 0.011 here, and τ = 0.02 falls to 0.532. The learning rate was fixed while the weight gradient scales like 1/τ, so the effective step size also changes across rows; treat the temperature ranking as specific to this setup.

## Common traps

> [!TRAP]
> Duplicate documents in a batch are labelled negatives. If two rows share the same positive text, the loss treats one of them as a false negative. A perfect encoder then cannot push the loss below log 2 (the duplicate-document output above).

![Two-by-two matrix for two queries and two identical documents; each row has probability 0.5 on each document, so the loss is minus log 0.5, which equals log 2 for any temperature](diagrams/34.2-duplicate-trap.svg "Two identical documents: the best achievable row loss is log 2.")

> [!TRAP]
> A default temperature is not an optimum. `MultipleNegativesRankingLoss` uses a cosine scale of 20, which is temperature 0.05, but in the sweep above τ = 0.2 did better at the same batch size. Tune τ on a validation set.

> [!TRAP]
> Losses are comparable only at equal batch size. The final loss rises with B overall (0.203 at B = 4, 0.768 at B = 256) because a larger softmax is a harder classification problem. Compare retrieval metrics instead.

> [!TRAP]
> Positives on the diagonal are an index convention. If the code takes the target from the wrong column, the loss is still a number, but it trains on the wrong pairs. Check that the target index of row i is the index of query i's own document.

## Summary

- InfoNCE is the cross-entropy of a softmax over one row of a batch similarity matrix, whose diagonal holds the positives; a batch of B pairs gives B(B − 1) negatives.
- Dividing scores by the temperature τ sets how sharply the softmax favours the best candidate; the best τ is empirical.
- Training uses an analytic gradient, $(P - I)/B$ with respect to the scaled logits, which the block checks against finite differences.
- Larger batches give more negatives and better recall, with diminishing returns; duplicates in a batch set a loss floor of log 2.

## Quiz time

### Question 1: Counting negatives

A batch contains B = 8 query-document pairs. How many negatives does each query get, and how many negative comparisons does the whole batch contain?

<details><summary>Show Solution</summary>

Each query has B − 1 = 7 negatives, the other documents in its row. The batch has B(B − 1) = 56 negative comparisons, excluding the 8 diagonal positives.

</details>

### Question 2: Predicting the effect of temperature

In the first block, the four similarities are fixed and the positive's softmax probability is 0.36 at τ = 1 and 0.45 at τ = 0.5. Explain why it rises when τ is halved, without re-running the code.

<details><summary>Show Solution</summary>

Dividing the similarities by τ multiplies all score gaps by 1/τ. With τ = 0.5 the gap between the positive (0.8) and the hard negative (0.7) becomes 0.2 in logit units, not 0.1, so the top score gains weight relative to the others. The positive has the largest similarity, so its probability rises.

</details>

### Question 3: Find the bug

Someone writes the batch loss as `np.mean(row_lse(S) - S[:, 0])` and uses it on a batch where query i's positive is document i. What goes wrong, and how do you fix it?

<details><summary>Show Solution</summary>

`S[:, 0]` takes the score against document 0 for every row, so only row 0 is scored against its own positive. The other rows are trained to match the similarity with document 0, which is a negative for them. The fix is `np.diag(S)`, which takes each row's score with its own document, as in the code above.

</details>

### Question 4: Explanation

Why does `MultipleNegativesRankingLoss` need a large, varied batch, and what does a duplicate positive in that batch do to the loss?

<details><summary>Show Solution</summary>

Every other document in the batch is a free negative, so more and more varied documents give more informative comparisons; the measured recall rises with B and then flattens. A duplicate positive is scored as a negative for the query, so the softmax can put at most probability 0.5 on the correct document, and the loss has a floor of log 2 that no encoder can remove.

</details>
