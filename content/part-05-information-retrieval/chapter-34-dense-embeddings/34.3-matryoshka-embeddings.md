In this lesson you will train a small embedding model whose first 2, 8 or 32 numbers each work as an embedding, and measure what happens when an ordinary embedding is cut down instead. You will need the bi-encoder idea from Lesson 34.1, the softmax function, and cross-entropy loss.

**You need:** Lesson 34.1 (an embedding is a vector, and a bi-encoder compares query and document vectors), and basic NumPy array slicing.

## The problem: vectors are large to store and compare

A dense embedding is a fixed-length list of real numbers. A 768-dimensional model stores each number as a 32-bit float (float32, 4 bytes), so one vector costs 3,072 bytes. Storage scales with the number of documents, and the cost of a search scales with the number of dimensions, because each comparison is a dot product over all of them.

Measure the storage for a 10-million-document index (GB means gigabytes, 10^9 bytes; index overhead is not included):

```python
N_DOCS = 10_000_000
for dims in [768, 256, 64, 32]:
    per_vec = 4 * dims
    print(f"{dims:4d} dims: {per_vec:5d} bytes/vector, {per_vec * N_DOCS / 1e9:6.2f} GB for 10M vectors")
```

```output
 768 dims:  3072 bytes/vector,  30.72 GB for 10M vectors
 256 dims:  1024 bytes/vector,  10.24 GB for 10M vectors
  64 dims:   256 bytes/vector,   2.56 GB for 10M vectors
  32 dims:   128 bytes/vector,   1.28 GB for 10M vectors
```

A 12-fold cut from 768 to 64 dimensions is attractive. The question this lesson answers is whether the cut can be made after training, by keeping only the first $m$ numbers, without losing the ranking.

## Intuition: one vector, several usable sizes

**Matryoshka Representation Learning (MRL)**, from Kusupati et al. (2022), trains one embedding so that every prefix (its first $m$ coordinates) is itself a good embedding. The name refers to nested Russian dolls: the small doll sits inside the larger one.

![One 32-dimensional vector shown as three rows: the whole vector, the first 8 coordinates, and the first 2 coordinates, each a filled prefix of the same cells](diagrams/34.3-nested-prefix.svg "One vector, three usable sizes. A Matryoshka model is trained so that each filled prefix works on its own.")

A normal model has no such guarantee. Its embedding is trained only at full size, so nothing asks its first two numbers to carry any meaning on their own.

## Worked example, by hand

Take a query $q = (1, 1, 1, 1)$ and two documents $a = (0, 0, 3, 3)$ and $b = (2, 1, -1, -1)$. Use the dot product (no normalisation in this example), and cut each vector to its first $m$ coordinates.

- Full size ($m = 4$): $q \cdot a = 0 + 0 + 3 + 3 = 6$ and $q \cdot b = 2 + 1 - 1 - 1 = 1$. Document a wins.
- $m = 2$: $q \cdot a = 0 + 0 = 0$ and $q \cdot b = 2 + 1 = 3$. Document b wins.
- $m = 3$: $q \cdot a = 0 + 0 + 3 = 3$ and $q \cdot b = 2 + 1 - 1 = 2$. Document a wins again.

![Table of dot-product scores for prefix sizes 1 to 4: the winner is b at m = 1 and 2, a at m = 3 and 4](diagrams/34.3-worked-flip.svg "The same query and documents. Cutting the vectors changes which document ranks first.")

Document a is strong in the later coordinates, and document b in the early ones. A cut at $m = 2$ throws away exactly what made a win, so the ranking flips. Nothing guarantees that a short prefix ranks documents the way the full vector does. The code reproduces the four rows:

```python
import numpy as np

q = np.array([1, 1, 1, 1])
a = np.array([0, 0, 3, 3])
b = np.array([2, 1, -1, -1])
for m in range(1, 5):
    sa, sb = q[:m] @ a[:m], q[:m] @ b[:m]
    print(f"m={m}: score a={sa}, score b={sb}, winner={'a' if sa > sb else 'b'}")
```

```output
m=1: score a=0, score b=2, winner=b
m=2: score a=0, score b=3, winner=b
m=3: score a=3, score b=2, winner=a
m=4: score a=6, score b=1, winner=a
```

## Training: one loss per prefix

MRL fixes this by putting a loss on every prefix during training. The recipe has four steps:

1. Encode each input into a full vector $e = Wx$, where $x$ is the input and $W$ is the learned encoder matrix.
2. Choose a set of prefix sizes $M$, for example $\{2, 8, 32\}$.
3. For each $m \in M$, take the first $m$ coordinates $e_{1:m}$ and pass them through their own linear head $V_m$. Compute a cross-entropy loss (CE, the standard classification loss) on those logits.
4. Sum the losses and update $W$ and all heads from the total.

![Flow diagram: an encoder produces a vector; three branches take the first 2, the first 8 and all 32 dimensions, each with its own head and loss; the three losses are summed](diagrams/34.3-training-heads.svg "MRL training. Every prefix has a loss, and all losses update the same encoder.")

Written as a formula, with $c_m$ a weight per prefix (we use $c_m = 1$):

$$
\mathcal{L}_{\text{MRL}} = \sum_{m \in M} c_m \, \mathrm{CE}\big(V_m \, e_{1:m},\, y\big)
$$

The early coordinates now receive gradient from the $m = 2$ loss, which asks them to classify alone. Each head sees only its own prefix; a shared head on the full vector would let the full-size loss do all the work.

> [!KEY-INSIGHT]
> The same encoder is trained to be useful at every size at once. The price is a sum of losses, and no extra model at inference time.

## Code: a toy MRL model in NumPy

The toy has 10 classes and 64-dimensional inputs whose variance decays with index, with a random rotation so that no input axis is special. A linear encoder maps to a 32-dimensional embedding. The gallery is 2,000 training vectors and the queries are 1,000 test vectors. The metric is P@10 (precision at 10): for each query, the fraction of its 10 nearest gallery items (cosine similarity on the prefix) that share the query's label. Chance is 0.10.

```python
import numpy as np

K, D_IN, D_FULL = 10, 64, 32
NESTED = [2, 4, 8, 16, 32]
EVAL = [2, 4, 8, 16, 32]
STEPS, LR = 600, 0.5

def make_data(seed):
    rng = np.random.default_rng(seed)
    s = 0.85 ** np.arange(D_IN)
    means = 2.0 * s * rng.standard_normal((K, D_IN))
    Q, _ = np.linalg.qr(rng.standard_normal((D_IN, D_IN)))
    def sample(n_per_class):
        y = np.repeat(np.arange(K), n_per_class)
        X = means[y] + s * rng.standard_normal((len(y), D_IN))
        return X @ Q, y
    Xtr, ytr = sample(200)
    Xte, yte = sample(100)
    return Xtr, ytr, Xte, yte

def softmax(z):
    z = z - z.max(axis=1, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=1, keepdims=True)

def train(X, y, dims, seed, steps=STEPS, lr=LR):
    rng = np.random.default_rng(1000 + seed)
    D = max(dims)
    W = rng.standard_normal((D, D_IN)) / np.sqrt(D_IN)
    V = {m: rng.standard_normal((K, m)) / np.sqrt(m) for m in dims}
    Y = np.eye(K)[y]
    N = len(y)
    for _ in range(steps):
        E = X @ W.T
        dE = np.zeros_like(E)
        dV = {}
        for m in dims:
            Em = E[:, :m]
            G = (softmax(Em @ V[m].T) - Y) / N
            dV[m] = G.T @ Em
            dE[:, :m] += G @ V[m]
        W -= lr * (dE.T @ X)
        for m in dims:
            V[m] -= lr * dV[m]
    return W

def p_at_10(gal, gal_y, qry, qry_y, k=10):
    g = gal / np.linalg.norm(gal, axis=1, keepdims=True)
    q = qry / np.linalg.norm(qry, axis=1, keepdims=True)
    top = np.argpartition(-(q @ g.T), k, axis=1)[:, :k]
    return float((gal_y[top] == qry_y[:, None]).mean())

SEEDS = range(1)
for seed in SEEDS:
    Xtr, ytr, Xte, yte = make_data(seed)
    W_mrl = train(Xtr, ytr, NESTED, seed)
    W_std = train(Xtr, ytr, [D_FULL], seed)
    print(f"seed {seed}: P@10 by prefix size (chance = 0.10)")
    print("prefix m:          " + "".join(f"{m:8d}" for m in EVAL))
    for name, W in [("MRL", W_mrl), ("standard, truncated", W_std)]:
        Gtr, Gte = Xtr @ W.T, Xte @ W.T
        print(f"{name:19s}" + "".join(f"{p_at_10(Gtr[:, :m], ytr, Gte[:, :m], yte):8.3f}" for m in EVAL))
```

```output
seed 0: P@10 by prefix size (chance = 0.10)
prefix m:                 2       4       8      16      32
MRL                   0.672   0.988   0.998   0.999   0.999
standard, truncated   0.414   0.835   0.981   0.994   0.997
```

Three choices matter for reading this code:

- `train` takes a list of prefix sizes. `dims=[32]` is ordinary training; `dims=[2, 4, 8, 16, 32]` is MRL. The two models share the same seed, data and number of steps, so the only difference is the loss.
- `p_at_10` normalises each prefix before the dot product, so each prefix is compared by cosine similarity and the length of the prefix does not decide the ranking.
- The gradient step is written by hand (full-batch gradient descent on the summed loss). That keeps the example in plain NumPy; a framework would compute the same `dE` by automatic differentiation.

One seed is noisy. The table gives mean ± standard deviation over five seeds (0 to 4) from the same code, run with `SEEDS = range(5)` and averaged; the sweep script is `scripts/diagrams/lessons/34.3_data.py` in the course repository.

![Line chart of P@10 against prefix size for five methods; the MRL, separate-model and PCA lines meet at about 1.0 from m = 8 upward, and the standard truncated line sits lowest among the learned models at m = 2 and 4](diagrams/34.3-prefix-quality.svg "P@10 against prefix size, mean over five seeds. Chance is 0.10.")

Read the table in four ways:

- At $m = 2$ and $m = 4$, the MRL model is well ahead of the standard model cut to the same size (0.721 against 0.406, and 0.982 against 0.822).
- MRL matches a separate model trained for each size (0.721 against 0.715 at $m = 2$; the difference is inside one standard deviation). That is the claim the abstract makes for real models, here reproduced in the toy.
- The column $m = 32$ for "separate model" is the same training run as the standard model, so the two rows agree exactly. That is a check that the two code paths match.
- At $m \ge 8$ every learned method is near 1.0. This toy saturates, so the choice of $m$ matters only at the small end here.

## Common traps

> [!TRAP]
> Cutting a standard embedding and expecting the prefix to work. In the toy, the standard model cut to 2 dimensions scores 0.406, below the PCA of the same embedding (0.476) and far below MRL (0.721).

> [!TRAP]
> Comparing truncated vectors with a raw dot product. Shorter prefixes have smaller norms, so the scores are not on a common scale. Normalise each prefix first, as `p_at_10` does.

> [!TRAP]
> Choosing $m$ from a saturated region. At $m \ge 8$ all methods tie in the toy. Choose $m$ on your own data, at the size you will deploy.

> [!TRAP]
> Reading one seed as a result. Seed 0 gives MRL 0.672 at $m = 2$; the five-seed mean is 0.721 with a standard deviation of 0.051.

> [!WARNING]
> The toy is 64-dimensional synthetic Gaussian data with a linear encoder and classification losses. It is not a text model. Its numbers do not transfer to a real retrieval system; the paper's numbers, quoted below, do not come from this toy.

## Summary

- MRL trains one embedding so that each prefix of its coordinates is usable on its own, by putting a separate head and loss on each prefix and summing them.
- Cutting a normal embedding is not safe: the first coordinates carry no special meaning, and the ranking can flip as the cut gets shorter.
- In our five-seed toy, MRL matches a separate model per size and beats truncating a standard embedding at $m = 2$ and $m = 4$. PCA of the standard embedding is a strong baseline that needs no retraining.
- Normalise prefixes before comparing them, and measure quality at the sizes you will deploy.

### Question 1: Calculation

Using the worked example ($q = (1,1,1,1)$, $a = (0,0,3,3)$, $b = (2,1,-1,-1)$), which document ranks first at $m = 2$, and which at $m = 3$?

<details><summary>Show Solution</summary>

At $m = 2$, the scores are a: 0 and b: 3, so b ranks first. At $m = 3$, the scores are a: 3 and b: 2, so a ranks first.

</details>

### Question 2: Prediction

You store 1 million vectors of 1,536 float32 dimensions. How many gigabytes is that, and how many gigabytes if you keep only the first 256 dimensions?

<details><summary>Show Solution</summary>

Full size: 1,536 × 4 bytes × 1,000,000 = 6.144 × 10^9 bytes, which is 6.14 GB. Prefix of 256: 256 × 4 × 1,000,000 = 1.024 × 10^9 bytes, which is 1.02 GB. The ratio is 6, the same as 1,536 divided by 256.

</details>

### Question 3: Find the bug

```python
def prefix_scores(gal, qry, m):
    return qry[:, :m] @ gal[:, :m].T
```

This is meant to rank gallery items by cosine similarity on the first m coordinates. What is wrong?

<details><summary>Show Solution</summary>

The function computes a raw dot product. The norm of a prefix depends on m, and it differs between items, so items with large early coordinates win regardless of direction. The fix is to divide each row of the prefix by its norm before the product, as `p_at_10` does: `g = gal[:, :m] / np.linalg.norm(gal[:, :m], axis=1, keepdims=True)`, and likewise for the query.

</details>

### Question 4: Explain

Why does MRL use a separate head $V_m$ for each prefix size instead of one head that reads the full 32-dimensional vector?

<details><summary>Show Solution</summary>

A single head on the full vector can classify using all 32 coordinates, so the loss would not force the first 2 coordinates to carry class information by themselves. Each prefix loss needs a head that sees only its prefix; otherwise the $m = 2$ term does not constrain $e_{1:2}$ alone.

</details>
