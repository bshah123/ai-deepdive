# 36.1 — Lexical vs Dense Retrieval: Strengths, Weaknesses & Failure Modes

## Opening Motivation & Context

In the realm of information retrieval, two primary approaches dominate: lexical retrieval and dense retrieval. Lexical retrieval, often associated with traditional search engines, relies on exact keyword matching and statistical analysis. Dense retrieval, on the other hand, leverages machine learning to create dense vector representations of documents and queries, enabling semantic understanding and similarity-based search.

Understanding the strengths, weaknesses, and failure modes of these approaches is crucial for selecting the right tool for your specific use case. This lesson will delve into the intricacies of both methods, providing a comprehensive comparison to help you make informed decisions.

## Core Concepts Breakdown

### Lexical Retrieval

Lexical retrieval is based on the exact matching of terms between a query and a document. It typically involves:

1. **Tokenization**: Breaking down text into individual words or tokens.
2. **Normalization**: Converting tokens to a standard form (e.g., lowercase, stemming).
3. **Indexing**: Creating an inverted index that maps terms to documents.
4. **Scoring**: Calculating a relevance score for each document based on term frequency and inverse document frequency (TF-IDF).

> [!KEY-INSIGHT]
> Lexical retrieval excels at exact keyword matching and is computationally efficient, making it suitable for large-scale document collections.

> [!BEST-PRACTICE]
> Use lexical retrieval when you need fast, exact matches for specific terms or phrases.

> [!WARNING]
> Lexical retrieval struggles with synonyms, homonyms, and semantic variations, leading to potential misses in search results.

### Dense Retrieval

Dense retrieval, also known as vector search, represents documents and queries as dense vectors in a high-dimensional space. This approach involves:

1. **Embedding**: Converting text into dense vectors using a pre-trained language model.
2. **Indexing**: Storing these vectors in a specialized index for efficient similarity search.
3. **Scoring**: Calculating the similarity between query and document vectors using metrics like cosine similarity or dot product.

> [!KEY-INSIGHT]
> Dense retrieval captures semantic meaning and relationships, enabling more nuanced and context-aware search results.

> [!BEST-PRACTICE]
> Use dense retrieval when you need to understand the semantic meaning of queries and documents, such as in question answering or recommendation systems.

> [!WARNING]
> Dense retrieval requires significant computational resources for embedding and indexing, and the quality of results depends heavily on the quality of the embeddings.

## Code Demonstration & Runtime Output

```python
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sentence_transformers import SentenceTransformer

# Sample documents
documents = [
    "The quick brown fox jumps over the lazy dog.",
    "A quick brown dog outpaces a fast fox.",
    "The lazy dog sleeps all day.",
    "The fox is quick and the dog is lazy."
]

# Sample query
query = "A fast fox outpaces a lazy dog."

# Lexical retrieval using TF-IDF
vectorizer = TfidfVectorizer()
tfidf_matrix = vectorizer.fit_transform(documents)
query_vec = vectorizer.transform([query])
lexical_scores = np.dot(query_vec, tfidf_matrix.T).toarray()[0]

# Dense retrieval using Sentence-BERT
model = SentenceTransformer('all-MiniLM-L6-v2')
doc_embeddings = model.encode(documents)
query_embedding = model.encode(query)
dense_scores = np.dot(query_embedding, doc_embeddings.T)

# Print results
print("Lexical Retrieval Scores:")
for i, score in enumerate(lexical_scores):
    print(f"Document {i+1}: {score:.4f}")

print("\nDense Retrieval Scores:")
for i, score in enumerate(dense_scores):
    print(f"Document {i+1}: {score:.4f}")
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import necessary libraries, including `numpy` for numerical operations, `TfidfVectorizer` for lexical retrieval, and `SentenceTransformer` for dense retrieval.
2. **Sample Documents and Query**: We define a list of sample documents and a query string.
3. **Lexical Retrieval**:
   - **Vectorization**: We create a `TfidfVectorizer` object and fit it to the documents to transform them into TF-IDF vectors.
   - **Query Transformation**: We transform the query into a TF-IDF vector using the same vectorizer.
   - **Scoring**: We calculate the dot product between the query vector and the document vectors to get lexical retrieval scores.
4. **Dense Retrieval**:
   - **Model Loading**: We load a pre-trained Sentence-BERT model for generating embeddings.
   - **Embedding Generation**: We encode the documents and the query into dense vectors using the model.
   - **Scoring**: We calculate the dot product between the query embedding and the document embeddings to get dense retrieval scores.
5. **Results**: We print the lexical and dense retrieval scores for each document.

> [!ADVANCED]
> The `TfidfVectorizer` uses a sparse matrix representation for the TF-IDF vectors, which is memory-efficient for large document collections. The `SentenceTransformer` model leverages deep learning to generate high-quality embeddings, capturing semantic relationships between words and phrases.

## Summary & Key Takeaways

- Lexical retrieval is efficient and suitable for exact keyword matching but struggles with semantic variations.
- Dense retrieval captures semantic meaning and relationships but requires significant computational resources.
- The choice between lexical and dense retrieval depends on the specific use case, the nature of the data, and the trade-offs between speed, accuracy, and resource usage.

<details><summary>Show Solution</summary>

The bug in the code is that the `np.dot` function is not being used correctly. The correct usage should be `np.dot(query_embedding, doc_embeddings.T)` to calculate the dot product between the query embedding and each document embedding. Here is the fixed code:

```python
import numpy as np
from sentence_transformers import SentenceTransformer

documents = [
    "The quick brown fox jumps over the lazy dog.",
    "A quick brown dog outpaces a fast fox.",
    "The lazy dog sleeps all day.",
    "The fox is quick and the dog is lazy."
]

query = "A fast fox outpaces a lazy dog."

model = SentenceTransformer('all-MiniLM-L6-v2')
doc_embeddings = model.encode(documents)
query_embedding = model.encode(query)
scores = np.dot(query_embedding, doc_embeddings.T)

for i, score in enumerate(scores):
    print(f"Document {i+1}: {score:.4f}")
```
