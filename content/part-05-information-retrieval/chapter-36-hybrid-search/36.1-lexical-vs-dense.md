Lexical retrieval matches the words of a query against the words of each document. Dense retrieval compares vectors that a model produces for the query and for each document. In this lesson you will compute both scores by hand and in NumPy, measure where each one ranks the right document first and where it fails, and name the failure modes that the literature reports.

**You need:** the inverted index and BM25 (Lesson 33.2), and the idea of an embedding vector (Lesson 34.1).

## The problem: each method fails on different queries

Take two queries against a car-maintenance knowledge base. "error E4471" needs an exact code: a document that says "E4417" describes a different error. "avoid losing traction in icy weather" needs a document about skidding on ice, which may never use the word "traction". Word matching fails the second query, and vector matching can fail the first. Which failures occur, and how often, is an empirical question.

## Two ways to decide that a document matches

![Lexical matching turns text into tokens and sums term weights from an index; dense matching turns text into vectors and takes the cosine between them](diagrams/36.1-two-ways-to-match.svg "The lexical path compares tokens. The dense path compares vectors. Neither looks at the other's representation.")

**Lexical (BM25).** The text is split into tokens, and an inverted index maps each token to the documents that contain it (Lesson 33.1). BM25 (Best Matching 25) scores a document by summing, over the query's terms, an inverse-document-frequency weight times a saturating term-frequency factor:

$$
\text{score}(q,d)=\sum_{t\in q}\operatorname{idf}(t)\cdot\frac{f(t,d)\,(k_1+1)}{f(t,d)+k_1\left(1-b+b\,\dfrac{|d|}{\overline{|d|}}\right)},
\qquad
\operatorname{idf}(t)=\ln\!\left(1+\frac{N-\mathrm{df}(t)+0.5}{\mathrm{df}(t)+0.5}\right)
$$

Here $f(t,d)$ is how often term $t$ occurs in document $d$, $|d|$ is its length in tokens, $\overline{|d|}$ is the average length, $N$ is the number of documents, and $\mathrm{df}(t)$ is the number of documents that contain $t$. The constants $k_1$ and $b$ control term saturation and length normalization. I use $k_1 = 1.2$ and $b = 0.75$, common defaults that I did not tune.

**Dense (cosine on vectors).** A model maps each text to a vector, and the score is the cosine similarity $\cos(q,d) = \dfrac{q \cdot d}{\lVert q\rVert\,\lVert d\rVert}$. The cosine depends only on the angle between the vectors, not on their length.

The sandbox has no pretrained neural encoder and no model weights, so the dense side here is **latent semantic analysis** (LSA): a truncated singular value decomposition (SVD) of the TF-IDF (term frequency times inverse document frequency) matrix. LSA learns word associations from co-occurrence in this corpus, not from pretraining. Its failure mechanisms are real for LSA, but its numbers are not those of a neural encoder, so do not transfer them.

## Worked example by hand: query "error E4471" on document 3

The corpus has $N = 12$ documents and 151 tokens in total, so $\overline{|d|} = 151/12 = 12.583$. Document 3 is "Error E4471 means the firmware failed its checksum; reflash the controller image.", which has $|d| = 12$ tokens.

- **Term "e4471".** It appears in one document, so $\mathrm{df} = 1$ and $\operatorname{idf} = \ln(1 + 11.5/1.5) = \ln 8.667 = 2.1595$. Here $f = 1$. The length factor is $1.2 \times (0.25 + 0.75 \times 12/12.583) = 1.1583$, so the denominator is $1 + 1.1583 = 2.1583$. Contribution $= 2.1595 \times 2.2 / 2.1583 = 2.2012$.
- **Term "error".** It appears in documents 3 and 4, so $\mathrm{df} = 2$ and $\operatorname{idf} = \ln 5.2 = 1.6487$. With the same length and $f = 1$, the contribution is $1.6487 \times 2.2 / 2.1583 = 1.6806$.
- **Total:** $2.2012 + 1.6806 = 3.8818$. The NumPy run below prints the first term as 2.2012 and the diagram shows the total as 3.88.

## Experiment: 12 documents, 10 queries

The corpus is 12 short maintenance notes I wrote for this lesson. I wrote the relevant documents for each query before running any scorer. A query can have more than one relevant document. For each query I record the rank of the best relevant document (1 = first). Ties are counted against the document: a relevant document with score 0 is ranked below every document that scores 0 as well. I summarise the ranks with the mean reciprocal rank (MRR), the average of $1/\text{rank}$ over the queries.

The code uses only NumPy and the standard library, so it runs in the in-browser Python on this page:

```python
# Lesson 36.1 experiment: BM25 (lexical) vs LSA (a dense stand-in) on a tiny hand-written corpus.
# NumPy and the standard library only, so the same code runs in the lesson's in-browser Python.
import re
import numpy as np

DOCS = [
    "Replace the brake pads when the rotor shows scoring and the pedal feels soft.",
    "Winter tyres grip better on snow and ice than summer tyres because of softer rubber.",
    "Wheel slip on frozen roads is reduced by lowering speed and leaving more distance.",
    "Error E4471 means the firmware failed its checksum; reflash the controller image.",
    "The controller reports error code E4417 when the sensor cable is disconnected.",
    "Regular oil changes extend engine life and keep the engine running smoothly.",
    "Skidding on black ice happens when the road temperature falls below freezing.",
    "Snow chains improve traction for trucks driving up mountain passes in winter.",
    "Brake fluid absorbs water over time, which lowers its boiling point.",
    "Cruise control holds a constant speed on motorway driving and saves fuel.",
    "Traction control cuts engine power when the wheels spin on a slippery surface.",
    "Battery terminals corroded with white powder should be cleaned with baking soda.",
]

# (id, query, indices of relevant documents). Relevance was written by hand before any scoring.
QUERIES = [
    ("A", "avoid losing traction in icy weather", {2, 6, 10}),
    ("B", "error E4471", {3}),
    ("C", "controller error code 4471", {3}),
    ("D", "winter tyres grip on snow", {1, 7}),
    ("E", "wheels spin on slippery surface", {10}),
    ("F", "clean corroded battery terminals", {11}),
    ("G", "how often to service the engine", {5}),
    ("H", "keep steady speed on motorway", {9}),
    ("I", "brake pads and brake fluid", {0, 8}),
    ("J", "snow chains for trucks in mountains", {7}),
]

K1, B = 1.2, 0.75   # common BM25 defaults (widely used, e.g. in Lucene); not tuned


def tokens(text):
    """Lowercase, split on anything that is not a letter or digit. No stemming."""
    return re.findall(r"[a-z0-9]+", text.lower())


def bm25_scores(query, docs_tok, k1=K1, b=B):
    n = len(docs_tok)
    avgdl = np.mean([len(d) for d in docs_tok])
    scores = np.zeros(n)
    for t in set(tokens(query)):
        df = sum(t in d for d in docs_tok)
        if df == 0:
            continue                              # term never seen: contributes nothing
        idf = np.log(1 + (n - df + 0.5) / (df + 0.5))
        for i, d in enumerate(docs_tok):
            tf = d.count(t)
            if tf:
                norm = k1 * (1 - b + b * len(d) / avgdl)
                scores[i] += idf * tf * (k1 + 1) / (tf + norm)
    return scores


def build_lsa(docs_tok, k):
    vocab = sorted({t for d in docs_tok for t in d})
    col = {t: j for j, t in enumerate(vocab)}
    n = len(docs_tok)
    counts = np.zeros((n, len(vocab)))
    for i, d in enumerate(docs_tok):
        for t in d:
            counts[i, col[t]] += 1
    df = (counts > 0).sum(axis=0)
    idf = np.log(n / df) + 1.0                    # smoothed idf, as in scikit-learn
    X = counts * idf
    X = X / np.linalg.norm(X, axis=1, keepdims=True)   # unit-length rows
    _, _, Vt = np.linalg.svd(X, full_matrices=False)
    P = Vt[:k].T                                  # vocab x k projection
    return col, idf, P, X @ P                     # documents as k-dimensional vectors


def lsa_scores(query, lsa):
    col, idf, P, doc_lat = lsa
    q = np.zeros(len(col))
    for t in tokens(query):
        if t in col:
            q[col[t]] += idf[col[t]]
    if not q.any():
        return np.zeros(len(doc_lat))
    q_lat = q @ P                                 # fold the query into the same k dimensions
    denom = np.linalg.norm(doc_lat, axis=1) * np.linalg.norm(q_lat) + 1e-12
    return doc_lat @ q_lat / denom                # cosine similarity


def best_rank(scores, rel):
    """1 = top. Pessimistic on ties: a document ties with everything it equals or beats."""
    return min(int(np.sum(scores >= scores[r])) for r in rel)


docs_tok = [tokens(d) for d in DOCS]
N = len(DOCS)
avgdl = float(np.mean([len(d) for d in docs_tok]))
K_DIMS = 4
lsa = build_lsa(docs_tok, K_DIMS)

print(f"N = {N} documents, average length avgdl = {avgdl:.3f} tokens, vocabulary = {len(lsa[0])} terms")
print(f"BM25 k1 = {K1}, b = {B}; LSA k = {K_DIMS} dimensions")

# Hand-check target: the term e4471 in document 3
df_e = sum("e4471" in d for d in docs_tok)
idf_e = np.log(1 + (N - df_e + 0.5) / (df_e + 0.5))
tf_e = docs_tok[3].count("e4471")
len_e = len(docs_tok[3])
term = idf_e * tf_e * (K1 + 1) / (tf_e + K1 * (1 - B + B * len_e / avgdl))
print(f"hand-check term e4471 in doc 3: df={df_e} idf={idf_e:.4f} tf={tf_e} |d|={len_e} contribution={term:.4f}")

print()
print("query  BM25 rank  LSA rank  BM25 top  LSA top  query")
results = []
for qid, qtext, rel in QUERIES:
    bm = bm25_scores(qtext, docs_tok)
    ls = lsa_scores(qtext, lsa)
    rb, rl = best_rank(bm, rel), best_rank(ls, rel)
    results.append({"id": qid, "query": qtext, "rel": sorted(rel), "bm25": bm.tolist(), "lsa": ls.tolist(), "rank_bm25": rb, "rank_lsa": rl})
    print(f"{qid:<6} {rb:>9}  {rl:>8}  {int(np.argmax(bm)):>8}  {int(np.argmax(ls)):>7}  {qtext}")

mrr_bm = float(np.mean([1 / r["rank_bm25"] for r in results]))
mrr_ls = float(np.mean([1 / r["rank_lsa"] for r in results]))
print(f"\nMRR (mean reciprocal rank) BM25 = {mrr_bm:.3f}   LSA k={K_DIMS} = {mrr_ls:.3f}")

print("\nLSA sensitivity to k:")
sens = {}
for k in (2, 4, 6, 8):
    L = build_lsa(docs_tok, k)
    ranks = [best_rank(lsa_scores(q, L), rel) for _, q, rel in QUERIES]
    sens[k] = float(np.mean([1 / r for r in ranks]))
    print(f"  k={k}: MRR = {sens[k]:.3f}  ranks = {ranks}")

print("\nQuery A, all documents (score BM25 | LSA):")
for i in range(N):
    print(f"  doc {i:>2}: {results[0]['bm25'][i]:.4f} | {results[0]['lsa'][i]:+.4f}  {DOCS[i][:60]}")
```

## Results

![A grid of ten queries with the rank of the best relevant document under BM25 and under LSA, coloured green for rank 1, amber for 2 to 3, rose for 4 or more](diagrams/36.1-rank-grid.svg "Rank of the best relevant document. Two queries are ranked first by both methods; query F is the only big split.")

BM25 has an MRR of 0.90 and LSA with $k = 4$ has an MRR of 0.80. Those two numbers are the summary, but the failures are more useful, so I go through three of them.

### Vocabulary mismatch: query A

![Scores for query A: BM25 is zero for documents 2 and 6, the relevant ones without shared words; LSA gives document 6 a positive cosine and document 7, which is not relevant, the highest score](diagrams/36.1-query-a-scores.svg "Scores for query A. The highest score belongs to a document I did not label as relevant.")

BM25 gives document 6 ("Skidding on black ice happens when...") a score of 0.00. The query says "icy" and the document says "ice", and no token matches. Document 2 ("Wheel slip on frozen roads...") also scores 0.00, because it shares no token with the query at all. The top BM25 hit is document 7, with 3.88, because it contains "traction" and "in". The word "in" is rare here only because the corpus is tiny. A real system removes such stopwords. LSA gives document 6 a cosine of +0.52, so the vector method recovers it because "ice" and "skidding" co-occur in the corpus. The best relevant document ranks second under BM25 and third under LSA.

### Tokenization: query C

Query C, "controller error code 4471", fails in both methods for the same reason. The document says "E4471", and the tokenizer keeps "e4471" as one token, so the token "4471" matches nothing. Document 3 receives only "controller" and "error". Document 4 ("The controller reports error code E4417...") also contains "code", so it ranks first and document 3 ranks second. Both methods see the tokens before they do anything else, so a tokenizer that splits letters from digits is the first fix to try. I have not tested that fix here.

### Rare terms lost in a low-dimensional space: query F

Query F, "clean corroded battery terminals", is where the methods split. BM25 ranks document 11 first, since its words are rare and each appears only in that document. LSA with $k = 4$ ranks it seventh, and its top hit is document 2, which shares no word with the query. My explanation, from the method rather than a measurement, is that LSA keeps only the four strongest co-occurrence patterns, and a term in a single document is too weak to survive the projection.

The sweep over $k$ supports this. LSA's MRR is 0.73 at $k = 2$, 0.80 at $k = 4$, 0.88 at $k = 6$ and 0.90 at $k = 8$, and document 11 is first at $k \geq 6$. This is a sensitivity result, not a general property of dense retrieval. With 12 documents there are at most 12 non-zero singular values, so $k = 8$ is not a real compression test.

### BM25 saturates term frequency

![BM25 contribution of one term rises steeply at first and approaches the limit k1 + 1 = 2.2; values at tf = 1, 2, 5 and 10 are labelled](diagrams/36.1-bm25-saturation.svg "The contribution of one term when the document length equals the average. Repeating a word gives diminishing returns.")

The saturating factor means that a word repeated ten times scores 1.96, against 1.00 for one occurrence, not ten times as much. The curve is the formula above with $|d| = \overline{|d|}$; other lengths shift it.

## What the literature reports

- **Dense models win when they are trained for the task.** Karpukhin et al. (2020) report that their dense passage retriever outperforms a Lucene BM25 system by 9 to 19 points of top-20 passage accuracy on open-domain question answering, in-domain (established result, arXiv abstract).
- **BM25 is a hard baseline across domains.** Thakur et al. (2021, BEIR) describe BM25 as "a robust baseline" in zero-shot evaluation, and they report that dense and sparse retrieval models "often underperform other approaches." The abstract does not state the per-dataset comparison, so I did not verify it.
- **Rare named entities are a documented dense failure.** Sciavolino et al. (2021) report that dense retrievers "drastically underperform sparse methods" on EntityQuestions, a set of entity-centric questions. The abstract compares against sparse methods in general and does not name BM25.

> [!TRAP]
> A score of 0.00 does not mean the document is irrelevant. BM25 scores only shared tokens, so a relevant document that uses a synonym gets 0.00. Check the relevant documents by reading them, not by reading the scores.

> [!TRAP]
> An MRR over ten queries is not a benchmark. Moving query F from rank 7 to rank 1 changes LSA's MRR by $(1 - 1/7)/10 \approx 0.09$. A difference of 0.1 here is one query.

> [!TRAP]
> Tie-breaking can silently inflate a metric. A rule that counts only strictly higher scores ranks a zero-score document near the top. Always state the tie rule.

> [!TRAP]
> A high cosine can come from shared topic words rather than shared meaning. Check the top results by reading them.

## Summary

- Lexical retrieval (BM25) is exact and cheap, and it scores only the tokens a query and a document share.
- Dense retrieval compares vectors, so it can match paraphrases, but a compressed vector can lose rare exact tokens.
- The two methods fail differently: vocabulary mismatch hurts lexical retrieval, and rare identifiers and low-rank compression hurt dense retrieval.
- BM25 saturates term frequency: repeating a word gives diminishing returns.
- Measure both methods on your own queries and label the relevant documents before you choose one.

## Quiz time

### Question 1: Calculation

A term appears in 1 of 12 documents. In that document $f = 2$ and $|d| = \overline{|d|}$. Using $k_1 = 1.2$, what is the term's BM25 contribution?

<details><summary>Show solution</summary>

$\operatorname{idf} = 2.1595$ (from the worked example). With $|d| = \overline{|d|}$ the length factor is exactly $k_1 = 1.2$, so the denominator is $2 + 1.2 = 3.2$. The saturating factor is $2 \times 2.2 / 3.2 = 1.375$. The contribution is $2.1595 \times 1.375 = 2.97$.

</details>

### Question 2: Bug-spotting

A colleague computes the rank of a relevant document as `1 + np.sum(scores > scores[r])` instead of counting documents with `scores >= scores[r]`. For query A, what rank does document 2 receive under each rule, and why does the colleague's MRR come out too high when the relevant document has no shared word with the query?

<details><summary>Show solution</summary>

Document 2 has score 0. Under the colleague's rule, the count is the number of documents with a score strictly above 0, which is 2 (documents 7 and 10), so the rank is 3. Under the rule in the code, every document with a score of 0 or more counts, which is all 12 documents, so the rank is 12. The colleague's rule places a zero-score document near the top, which raises its reciprocal rank. A metric that rewards ties is inflated.

</details>

### Question 3: Explanation

Document 3 contains "controller" and "error", both query words in query C. Why does BM25 still rank it second?

<details><summary>Show solution</summary>

The query token "4471" does not match the document token "e4471", so it contributes nothing. Document 4 contains "controller", "error" and "code", and "code" appears in no other document, so document 4 gets the highest score.

</details>

### Question 4: Explanation

Give two reasons a 4-dimensional LSA can lose a rare term, and one experiment that would distinguish between them.

<details><summary>Show solution</summary>

Reason one: a term in one document has small loadings on the leading singular vectors, so truncation discards it. Reason two: the query is compared in the reduced space, where the term cannot pull its document forward. Test: rerun with the full-rank matrix. If the rare term's document then ranks first, truncation is the cause.

</details>
