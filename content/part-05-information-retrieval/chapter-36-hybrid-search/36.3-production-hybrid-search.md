This lesson builds a complete hybrid search pipeline: a lexical index (BM25), an approximate dense index (an inverted file, IVF), reciprocal rank fusion (RRF) and a metadata filter. You will measure where each stage helps and where it hurts, and why a pipeline that looks sensible can score below its simplest part.

**You need:** Lesson 36.1 (lexical versus dense retrieval) and Lesson 36.2 (RRF). Basic NumPy.

## The problem one retriever cannot solve

Two kinds of query fail for different reasons. A **topic query** is one word that names a subject, such as `c39w5` in the code below: a word that relevant documents use, though not all of them do. An **identifier query** is a product code such as `SKU01789` plus a generic word. Exactly one document is relevant.

Lexical retrieval matches tokens exactly. `SKU01789` occurs in one document, so its inverse document frequency (IDF, a measure of how rare a term is) is high, and BM25 ranks that document first. Dense retrieval embeds the query as a vector. A code such as `SKU01789` has no meaning in embedding space, so the vector says little about which document owns it. Topic queries reverse the pattern: a word and its synonyms share meaning, which a dense vector captures even when the exact word is absent.

A production system must also answer three questions that a single benchmark score hides. Can the approximate index avoid scanning every vector? How do you combine two ranked lists whose scores are not comparable? How do you apply a filter, such as "only category 3", without losing results?

![Four stages: a query goes to a BM25 index and an IVF dense index, both feed RRF, a metadata filter follows, and the top 10 are returned](diagrams/36.3-pipeline.svg "The pipeline. Each box is measured in this lesson.")

## The test setup: a controlled corpus

We need documents whose relevance is known in advance. The corpus is generated: 3,000 documents, 50 topics, and 60 words per topic. Each document belongs to one topic, uses 8 of that topic's words (25 tokens), adds 8 background tokens and one unique SKU. Each document also has a category from 0 to 9, which the filter uses.

The dense side is **simulated**. Each word's vector is its topic's random unit vector plus Gaussian noise of scale 0.25, so synonyms are close but not identical. A document vector is the normalised mean of its word vectors, which is mean pooling, a common and simple way to build a document embedding. No trained model is involved. The numbers show how the pipeline behaves under these assumptions. They are not benchmark results and must not be compared with real embedding models.

Relevance is fixed by construction. A topic query is relevant to all 60 documents of its topic. An identifier query is relevant only to its own document.

## Stage 1: two retrievers

BM25 (Okapi BM25, the lexical ranking function from Lesson 36.1) scores only documents that share a query term, using an inverted index of term-to-document lists. The code keeps only positive scores, so the lexical list can be shorter than the depth requested.

The dense index is an inverted file index (IVF). K-means partitions the 3,000 vectors into 64 cells. At query time the query is compared with the 64 cell centroids, and only the vectors in the `nprobe` nearest cells are scored exactly. Fewer probes means fewer vectors scanned and lower recall. Hierarchical navigable small world graphs (HNSW) are the other common approximate index; Malkov and Yashunin state a logarithmic scaling result (arXiv:1603.09320), which this lesson does not test.

Stage 2 fuses the two lists with RRF, the formula from Lesson 36.2. Each document scores the sum of $1/(k + \text{rank})$ over the lists it appears in, with $k = 60$. RRF uses only ranks, so the incomparable BM25 and cosine scores never meet. That is its appeal, and, as Experiment 1 shows, its limit.

Stage 3 is the filter. The code supports two strategies. A post-filter applies the mask after fusion. A pre-filter applies it inside each retriever, before ranking.

## Worked example: one query through every stage

The figure traces the first identifier query. Its target, document 1789, is rank 1 in BM25 and rank 2 in the dense list. Its fused score is $1/(60+1) + 1/(60+2) = 0.03252$. Document 239 is rank 2 in BM25 but rank 16 in the dense list, so its score is $1/62 + 1/76 = 0.02929$. RRF rewards agreement between lists, and here it works for the target.

The full pipeline and its experiments are below. They use only NumPy and the standard library, so they run in the browser. The seed is fixed, so the output is reproducible.

```python
import math
from collections import Counter, defaultdict
import numpy as np

rng = np.random.default_rng(36)


def unit(v):
    return v / np.linalg.norm(v)


# ---- 1. A controlled corpus: every query has known relevant documents ----
N_DOCS, N_CONCEPTS, WORDS_PER_CONCEPT, N_BG, DIM = 3000, 50, 60, 200, 32
N_CATEGORIES, NOISE = 10, 0.25

concept_vec = np.stack([unit(v) for v in rng.standard_normal((N_CONCEPTS, DIM))])

# Simulated embedder: a word's vector is its concept vector plus noise,
# so synonyms land close together but not on top of each other.
word_vec = {}
for c in range(N_CONCEPTS):
    for j in range(WORDS_PER_CONCEPT):
        word_vec[f"c{c}w{j}"] = unit(concept_vec[c] + NOISE * rng.standard_normal(DIM))
for j in range(N_BG):
    word_vec[f"bg{j}"] = unit(rng.standard_normal(DIM))

doc_tokens, doc_concept, doc_cat, doc_words = [], [], [], []
for d in range(N_DOCS):
    c = d % N_CONCEPTS
    words = rng.choice(WORDS_PER_CONCEPT, size=8, replace=False)   # 8 of the concept's 60 words
    toks = [f"c{c}w{j}" for j in words[rng.integers(8, size=25)]]
    toks += [f"bg{rng.integers(N_BG)}" for _ in range(8)]
    sku = f"SKU{d:05d}"
    word_vec[sku] = unit(rng.standard_normal(DIM))                  # an identifier carries no concept
    toks.append(sku)
    doc_tokens.append(toks)
    doc_concept.append(c)
    doc_cat.append(int(rng.integers(N_CATEGORIES)))
    doc_words.append(words)
doc_cat_arr = np.array(doc_cat)

# ---- 2. Queries: 100 one-word topic queries, 100 identifier queries ----
queries = []   # (kind, query tokens, relevant doc ids)
for c in range(N_CONCEPTS):
    relevant = {d for d in range(N_DOCS) if doc_concept[d] == c}
    for _ in range(2):
        queries.append(("topic", [f"c{c}w{rng.integers(WORDS_PER_CONCEPT)}"], relevant))
for d in rng.choice(N_DOCS, size=100, replace=False):
    d = int(d)
    word = f"c{doc_concept[d]}w{rng.choice(doc_words[d])}"
    queries.append(("identifier", [f"SKU{d:05d}", word], {d}))
filter_cats = [int(rng.integers(N_CATEGORIES)) for _ in queries]


# ---- 3. Indexes: lexical (BM25) and dense (exact and IVF) ----
def tokens_to_vec(tokens):
    """Simulated bi-encoder: mean-pool the word vectors, then normalise."""
    return unit(np.mean([word_vec[t] for t in tokens], axis=0))


class BM25:
    """Okapi BM25 over an inverted index: term -> list of (doc, term frequency)."""

    def __init__(self, docs, k1=1.2, b=0.75):
        self.k1, self.b, self.N = k1, b, len(docs)
        self.len = np.array([len(t) for t in docs], dtype=float)
        self.avglen = self.len.mean()
        self.postings = defaultdict(list)
        for i, toks in enumerate(docs):
            for term, tf in Counter(toks).items():
                self.postings[term].append((i, tf))

    def scores(self, query_terms):
        s = np.zeros(self.N)
        for term in set(query_terms):
            plist = self.postings.get(term, [])
            if not plist:
                continue
            df = len(plist)
            idf = math.log(1 + (self.N - df + 0.5) / (df + 0.5))
            for i, tf in plist:
                norm = self.k1 * (1 - self.b + self.b * self.len[i] / self.avglen)
                s[i] += idf * tf * (self.k1 + 1) / (tf + norm)
        return s


def kmeans(X, k, iters=15):
    C = X[rng.choice(len(X), size=k, replace=False)].copy()
    for _ in range(iters):
        assign = np.argmax(X @ C.T, axis=1)
        for j in range(k):
            members = X[assign == j]
            if len(members):
                C[j] = members.mean(axis=0)
        C = np.stack([unit(c) for c in C])
    return C, np.argmax(X @ C.T, axis=1)


class IVFFlat:
    """Inverted file: k-means cells; exact scoring only inside the nprobe nearest cells."""

    def __init__(self, X, nlist):
        self.X = X
        self.C, assign = kmeans(X, nlist)
        self.lists = [np.flatnonzero(assign == j) for j in range(nlist)]

    def candidates(self, q, nprobe):
        cells = np.argsort(-(self.C @ q), kind="stable")[:nprobe]
        ids = np.concatenate([self.lists[j] for j in cells])
        return ids, self.X[ids] @ q


docs_vec = np.stack([tokens_to_vec(t) for t in doc_tokens])
bm25 = BM25(doc_tokens)
ivf = IVFFlat(docs_vec, nlist=64)

# ---- 4. Retrieval stages and fusion ----
DEPTH = 100      # candidates kept from each retriever before fusion
K_RRF = 60       # RRF constant (see Lesson 36.2)


def ranked(scores, depth, positive_only=False):
    order = np.argsort(-scores, kind="stable")
    if positive_only:
        order = order[scores[order] > 0]
    return order[:depth]


def lexical(q, allowed=None, depth=DEPTH):
    s = bm25.scores(q)
    if allowed is not None:
        s = np.where(allowed, s, -np.inf)
    return ranked(s, depth, positive_only=True)


def dense_exact(q, allowed=None, depth=DEPTH):
    s = docs_vec @ tokens_to_vec(q)
    if allowed is not None:
        s = np.where(allowed, s, -np.inf)
    return ranked(s, depth)


def dense_ivf(q, nprobe, allowed=None, depth=DEPTH):
    """Returns (ranked ids, number of vectors scored before any filter)."""
    ids, sc = ivf.candidates(tokens_to_vec(q), nprobe)
    scanned = len(ids)
    if allowed is not None:
        keep = allowed[ids]
        ids, sc = ids[keep], sc[keep]
    return ids[np.argsort(-sc, kind="stable")][:depth], scanned


def rrf(lists, k=K_RRF):
    score = defaultdict(float)
    for ranking in lists:
        for r, d in enumerate(ranking, start=1):
            score[int(d)] += 1.0 / (k + r)
    return sorted(score.items(), key=lambda kv: (-kv[1], kv[0]))


def hybrid(q, nprobe, allowed=None, depth=DEPTH, k=10):
    den, scanned = dense_ivf(q, nprobe, allowed, depth)
    fused = rrf([lexical(q, allowed, depth), den])
    return [d for d, _ in fused][:k], scanned


def hybrid_exact(q, k=10):
    fused = rrf([lexical(q), dense_exact(q)])
    return [d for d, _ in fused][:k]


# ---- 5. Metrics ----
def ndcg10(ranking, relevant):
    dcg = sum(1 / math.log2(r + 2) for r, d in enumerate(ranking[:10]) if int(d) in relevant)
    idcg = sum(1 / math.log2(r + 2) for r in range(min(len(relevant), 10)))
    return dcg / idcg


def mean_ndcg(system, kind=None):
    vals = [ndcg10(system(q), rel) for k_, q, rel in queries if kind in (None, k_)]
    return float(np.mean(vals))


RESULTS = {}

# ---- 6. Experiment 1: which retriever, which query type ----
systems = {
    "random ranking": lambda q: rng.permutation(N_DOCS),
    "BM25 (lexical)": lambda q: lexical(q),
    "dense, exact cosine": lambda q: dense_exact(q),
    "dense, IVF nprobe=8": lambda q: dense_ivf(q, 8)[0],
    "hybrid, BM25 + exact dense": lambda q: hybrid_exact(q),
    "hybrid, BM25 + IVF nprobe=8": lambda q: hybrid(q, 8)[0],
}
print(f"{N_DOCS} docs, {N_CONCEPTS} topics; queries: "
      f"{sum(k == 'topic' for k, _, _ in queries)} topic, "
      f"{sum(k == 'identifier' for k, _, _ in queries)} identifier")
print(f"{'system':<30}{'topic':>8}{'identifier':>12}{'all':>8}")
RESULTS["table1"] = {}
for name, fn in systems.items():
    t, i, a = mean_ndcg(fn, "topic"), mean_ndcg(fn, "identifier"), mean_ndcg(fn)
    RESULTS["table1"][name] = [t, i, a]
    print(f"{name:<30}{t:8.3f}{i:12.3f}{a:8.3f}")

# ---- 7. Experiment 2: how much of the corpus must the ANN scan? ----
print(f"\n{'nprobe':>6}{'scanned':>9}{'recall@100':>12}{'hybrid nDCG':>13}")
RESULTS["nprobe"] = []
for nprobe in [1, 2, 4, 8, 16, 32]:
    scanned, recall = [], []
    for _, q, _ in queries:
        exact = set(dense_exact(q).tolist())
        ids, n = dense_ivf(q, nprobe)
        scanned.append(n)
        recall.append(len(exact & set(ids.tolist())) / len(exact))
    h = mean_ndcg(lambda q: hybrid(q, nprobe)[0])
    frac = float(np.mean(scanned)) / N_DOCS
    RESULTS["nprobe"].append([nprobe, frac, float(np.mean(recall)), h])
    print(f"{nprobe:>6}{frac:9.1%}{np.mean(recall):12.3f}{h:13.3f}")

# ---- 8. Experiment 3: metadata filter keeping 10% of docs ----
def post_filter(q, allowed, depth):
    den, _ = dense_ivf(q, 8, None, depth)
    fused = rrf([lexical(q, None, depth), den])
    return [d for d, _ in fused if allowed[d]][:10]


def pre_filter(q, allowed, depth):
    return hybrid(q, 8, allowed, depth)[0]


print(f"\n{'filter strategy':<30}{'returned/10':>12}{'full 10':>9}{'nDCG@10':>9}")
RESULTS["filter"] = []
for label, fn in [("post-filter, candidates=10", lambda q, a: post_filter(q, a, 10)),
                  ("post-filter, candidates=100", lambda q, a: post_filter(q, a, 100)),
                  ("pre-filter, candidates=100", lambda q, a: pre_filter(q, a, 100))]:
    counts, full, nd = [], [], []
    for (kind, q, rel), cat in zip(queries, filter_cats):
        if kind != "topic":
            continue
        allowed = doc_cat_arr == cat
        out = fn(q, allowed)
        counts.append(len(out))
        full.append(len(out) == 10)
        nd.append(ndcg10(out, {d for d in rel if allowed[d]}))
    RESULTS["filter"].append([label, float(np.mean(counts)), float(np.mean(full)), float(np.mean(nd))])
    print(f"{label:<30}{np.mean(counts):12.2f}{np.mean(full):9.0%}{np.mean(nd):9.3f}")

# ---- 9. Worked example: one identifier query through every stage ----
_, q, rel = next(x for x in queries if x[0] == "identifier")
target = next(iter(rel))
lex_full = lexical(q)
den_full, _ = dense_ivf(q, 8)


def rank_of(lst, d):
    hits = np.flatnonzero(np.asarray(lst) == d)
    return int(hits[0]) + 1 if len(hits) else None


fused = rrf([lex_full, den_full])[:5]
print(f"\nquery {q}, target doc {target}")
print("target rank in BM25 list:", rank_of(lex_full, target),
      "| in dense IVF list:", rank_of(den_full, target))
for d, s in fused:
    print(f"  doc {d:4d}: BM25 rank {rank_of(lex_full, d)}, dense rank {rank_of(den_full, d)}, RRF {s:.5f}")
RESULTS["example"] = {"target": int(target),
                      "ranks": [rank_of(lex_full, target), rank_of(den_full, target)],
                      "fused_top5": [[int(d), float(s)] for d, s in fused]}


# ---- 10. Experiment 4: weight the BM25 list, tuned on half the queries ----
def weighted_hybrid(q, nprobe, w, k=10):
    """RRF where the BM25 list counts w times as much as the dense list."""
    den, _ = dense_ivf(q, nprobe)
    score = defaultdict(float)
    for r, d in enumerate(lexical(q), start=1):
        score[int(d)] += w / (K_RRF + r)
    for r, d in enumerate(den, start=1):
        score[int(d)] += 1.0 / (K_RRF + r)
    return [d for d, _ in sorted(score.items(), key=lambda kv: (-kv[1], kv[0]))][:k]


# Self-check: w = 1 must reproduce the unweighted hybrid exactly.
assert all(weighted_hybrid(q, 8, 1.0) == hybrid(q, 8)[0] for _, q, _ in queries)

tune = [x for i, x in enumerate(queries) if i % 2 == 0]
held = [x for i, x in enumerate(queries) if i % 2 == 1]


def score_on(split, fn, kind=None):
    return float(np.mean([ndcg10(fn(q), rel) for k_, q, rel in split if kind in (None, k_)]))


grid = [0.5, 1.0, 2.0, 3.0, 5.0, 10.0, 20.0]
best_w = max(grid, key=lambda w: score_on(tune, lambda q: weighted_hybrid(q, 8, w)))
print(f"\nselected on tuning half: w = {best_w}")
print(f"{'system (held-out half)':<28}{'topic':>8}{'identifier':>12}{'all':>8}")
RESULTS["weights"] = {"selected": best_w, "rows": []}
rows = [("BM25 alone", lambda q: lexical(q))] + [
    (f"weighted RRF, w={w}", (lambda w: lambda q: weighted_hybrid(q, 8, w))(w)) for w in grid]
for name, fn in rows:
    t, i, a = score_on(held, fn, "topic"), score_on(held, fn, "identifier"), score_on(held, fn)
    RESULTS["weights"]["rows"].append([name, t, i, a])
    print(f"{name:<28}{t:8.3f}{i:12.3f}{a:8.3f}")
```

## What the experiments show

**Experiment 1: which retriever, which query type.** The metric is nDCG@10 (normalised discounted cumulative gain over the top 10; 1 is perfect). 
![Grouped horizontal bars of nDCG@10 for four systems, topic and identifier queries shown in two colours](diagrams/36.3-systems.svg "nDCG@10 for topic (blue) and identifier (amber) queries.")

Random ranking scores 0.008, so every system here is far above chance. Dense retrieval is good on topic queries (0.959) and nearly useless on identifiers (0.274). BM25 shows the reverse pattern (0.816 and 0.987).

The hybrid rows matter most. On topic queries the hybrid (0.985) beats both parts. On identifier queries it falls to 0.691, below BM25 alone (0.987). Over all queries, BM25 alone (0.902) beats both hybrids (0.838 and 0.821).

The mechanism follows from the RRF arithmetic. A target with BM25 rank 1 and dense rank $r$ scores $1/61 + 1/(60+r)$. A document with BM25 rank 2 and dense rank 1 scores $1/62 + 1/61$, which is higher whenever $r \geq 3$. A dense favourite that sits near the top of BM25 can therefore overtake an exact match that the dense list ranks low. RRF counts ranks equally in every list and has no notion of confidence.

**Experiment 2: the fusion weight.** Weighted RRF multiplies the BM25 term by a weight $w$. With $w = 1$ it is the unweighted hybrid; the code asserts that the two agree. The weight is tuned on one half of the queries and reported on the other, because tuning on all queries would flatter the result. Held-out half: 50 topic and 50 identifier queries.

| BM25 weight $w$ | topic | identifier | all |
|---|---|---|---|
| BM25 alone | 0.826 | 0.974 | 0.900 |
| 0.5 | 0.973 | 0.398 | 0.685 |
| 1 | 0.977 | 0.607 | 0.792 |
| 3 | 0.977 | 0.698 | 0.838 |
| 10 | 0.977 | 0.841 | 0.909 |
| 20 | 0.977 | 0.899 | 0.938 |

![Line chart of held-out nDCG@10 against the BM25 weight for topic, identifier and all queries, with BM25 alone as a dashed line](diagrams/36.3-fusion-weight.svg "Held-out nDCG@10 against the BM25 weight. The dashed line is BM25 alone.")

The tuning half selected $w = 20$, the grid's largest value, so the optimum may lie beyond it; I did not extend the grid. At $w = 20$ the overall score beats BM25 alone (0.938 against 0.900), but identifier queries still fall short (0.899 against 0.974). The gain is on topic queries, where BM25 returns few matches (by construction, one topic word appears in about 8 of the 60 topic documents), so the dense list fills the empty positions. My own reasoning, not tested here: routing SKU-like queries to BM25 alone would probably beat any single weight on this corpus.

**Experiment 3: how far the ANN must scan.** The `nprobe` setting controls how many of the 64 cells are scanned. Recall@100 is the overlap between the top 100 from IVF and the top 100 from exact search.

![Scatter plot of recall at 100 against the percent of vectors scanned, with each point labelled by its nprobe value from 1 to 32](diagrams/36.3-nprobe.svg "Recall@100 against the share of vectors scanned.")

Recall rises from 0.416 at nprobe 1 (1.9% of vectors scanned) to 0.925 at nprobe 8 (12.9%) and 0.997 at nprobe 32 (49.9%). Hybrid nDCG@10 moves the other way, from 0.850 to 0.821. Better dense recall brings in more dense-favoured documents, which RRF can rank above exact matches, so higher recall need not improve the answers a user sees. The scanned share is a work proxy; latency depends on hardware and was not measured.

**Experiment 4: filters.** The filter keeps 10% of documents (those whose category equals the query's category). It is applied to the 100 topic queries. A post-filter fuses first and drops documents that fail the filter afterwards.

![Three horizontal bars showing how many of 10 results each filter strategy returns; the post-filter with 10 candidates returns 1.23](diagrams/36.3-filter.svg "Results returned out of 10 for three filter strategies.")

With 10 candidates per retriever, the post-filter returns 1.23 results on average and never fills the list. With 100 candidates it returns 9.04 and fills all 10 in 55% of queries. The pre-filter, which applies the mask inside each retriever, returns 10 for every query, with nDCG@10 of 0.908. Rule of thumb (my reasoning, consistent with the numbers): post-filter depth should be about $k$ divided by selectivity, here $10 / 0.1 = 100$. The pre-filter searches only the probed IVF cells, so it may miss more at higher selectivity; I did not test that.

## Production checklist

- Keep a fixed evaluation set and report scores per query type. The average in Experiment 1 hides the identifier collapse.
- Tune fusion weights or routing on a tuning split, and report the held-out split. The $w = 20$ result above is a warning, not a recipe.
- Set post-filter depth from the filter's selectivity, or use a pre-filter. Check the result count, not only the quality score.
- BM25 is a hard baseline to beat. The BEIR benchmark describes it as "a robust baseline" for zero-shot retrieval (Thakur et al., arXiv:2104.08663).
- Reranking, a second model that rescores the fused list, is common in production (my own reasoning); this lesson does not measure one.

## Common traps

> [!TRAP]
> "Hybrid is always better." With equal weights, identifier nDCG fell from 0.987 (BM25 alone) to 0.691, and the overall score fell from 0.902 to 0.838. Always compare a combined system with each of its parts.

> [!TRAP]
> Judging an approximate index by recall alone. Recall@100 rose from 0.416 to 0.997 while hybrid nDCG@10 fell from 0.850 to 0.821.

> [!TRAP]
> A post-filter with a short candidate list. With 10 candidates it returned 1.23 of 10 results on average.

> [!TRAP]
> Transferring simulated numbers. The dense results depend on the noise level (0.25) and the corpus construction; re-run with a real embedder before drawing production conclusions.

## Summary

- A hybrid pipeline has three decisions: what each retriever returns, how the lists are fused, and where the filter is applied.
- On this corpus, equal-weight RRF beat BM25 on topic queries but lost badly on identifier queries, so the overall result was worse than BM25 alone.
- Fusion weights must be tuned on held-out data; the weight selected here sat at the edge of its grid.
- Approximate search trades recall for work. Higher recall did not give better fused results here.
- A post-filter needs a candidate depth of about $k$ divided by the filter's selectivity, or a pre-filter should be used.

### Question 1: Calculation

A document has BM25 rank 3 and dense rank 1. With $k = 60$, what is its RRF score?

$1/(60+3) + 1/(60+1) = 1/63 + 1/61 = 0.015873 + 0.016393 \approx 0.03227$.

### Question 2: Explanation

Why does equal-weight RRF lower identifier nDCG compared with BM25 alone, even though the dense list has no useful signal for codes like `SKU01789`?

<details><summary>Show Solution</summary>

RRF gives every list the same weight, so a document the noisy dense list ranks near the top gains score. It can overtake an exact match that BM25 ranks first but the dense list ranks low.

</details>

### Question 3: Bug spotting

This post-filter omits the mask.

```python
def post_filter(q, allowed, depth=10):
    fused = rrf([lexical(q, None, depth), dense_ivf(q, 8, None, depth)[0]])
    return [d for d, _ in fused][:10]
```

<details><summary>Show Solution</summary>

The `allowed` argument is never used, so nothing is filtered. The return line should be `return [d for d, _ in fused if allowed[d]][:10]`. A depth of 10 is also too shallow for a 10% filter; use about 100.

</details>

### Question 4: Explanation

Why must the fusion weight be chosen on a different set of queries from the one whose score is reported?

<details><summary>Show Solution</summary>

The weight is a free parameter. Choosing it to maximise the score on the same queries fits noise in those queries, so the reported score overstates performance on new queries. The experiment selects $w$ on one half and reports the other half, which is the minimum needed for an honest number.

</details>
