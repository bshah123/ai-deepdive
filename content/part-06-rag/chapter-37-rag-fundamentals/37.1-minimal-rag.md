# 37.1 — RAG Foundations: Why Vector Search is Not RAG

## Opening Motivation & Context

Retrieval-Augmented Generation (RAG) is a cutting-edge technique in the field of natural language processing (NLP) that combines the strengths of information retrieval and generative models. While vector search is a powerful tool for finding similar items in a high-dimensional space, it is not the same as RAG. Understanding the distinction between vector search and RAG is crucial for building effective AI systems that can retrieve and generate information accurately.

## Core Concepts Breakdown

### Vector Search vs. RAG

> [!KEY-INSIGHT]
> Vector search is a method for finding similar items in a high-dimensional space, while RAG is a framework that combines retrieval and generation to produce more accurate and context-aware responses.

> [!BEST-PRACTICE]
> Use vector search as a component within the RAG framework to enhance the retrieval step. This allows you to leverage the strengths of both techniques to build more effective AI systems.

> [!WARNING]
> Avoid treating vector search as a standalone solution for tasks that require both retrieval and generation. Instead, consider using RAG to combine these capabilities for better results.

## Code Demonstration & Runtime Output

```python
import numpy as np
from typing import List, Tuple

class VectorSearch:
    def __init__(self, vectors: List[np.ndarray], documents: List[str]):
        self.vectors = vectors
        self.documents = documents

    def search(self, query_vector: np.ndarray, k: int = 1) -> List[Tuple[str, float]]:
        similarities = [self._cosine_similarity(query_vector, vec) for vec in self.vectors]
        top_k_indices = np.argsort(similarities)[-k:][::-1]
        return [(self.documents[i], similarities[i]) for i in top_k_indices]

    def _cosine_similarity(self, a: np.ndarray, b: np.ndarray) -> float:
        return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

class RAG:
    def __init__(self, vector_search: VectorSearch, generator):
        self.vector_search = vector_search
        self.generator = generator

    def generate(self, query: str, k: int = 1) -> str:
        query_vector = self._generate_query_vector(query)
        retrieved_docs = self.vector_search.search(query_vector, k)
        context = " ".join([doc for doc, _ in retrieved_docs])
        return self.generator.generate(context, query)

    def _generate_query_vector(self, query: str) -> np.ndarray:
        # In a real implementation, this would use a pre-trained model to generate the vector
        return np.random.rand(100)

class Generator:
    def generate(self, context: str, query: str) -> str:
        # In a real implementation, this would use a pre-trained language model to generate the response
        return f"Generated response based on context: {context} and query: {query}"

if __name__ == "__main__":
    # Example usage
    vectors = [np.random.rand(100) for _ in range(5)]
    documents = ["Document 1", "Document 2", "Document 3", "Document 4", "Document 5"]
    vector_search = VectorSearch(vectors, documents)
    generator = Generator()
    rag = RAG(vector_search, generator)

    query = "What is the meaning of life?"
    response = rag.generate(query)
    print(response)
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import the necessary libraries, including `numpy` for numerical operations and `List` and `Tuple` from the `typing` module for type hints.
2. **VectorSearch Class**: This class is responsible for performing vector search. It takes a list of vectors and corresponding documents as input.
   - **`__init__`**: Initializes the class with the provided vectors and documents.
   - **`search`**: Performs a vector search to find the most similar documents to the query vector. It calculates the cosine similarity between the query vector and each document vector, sorts the results, and returns the top `k` documents.
   - **`_cosine_similarity`**: A helper method that calculates the cosine similarity between two vectors.
3. **RAG Class**: This class combines vector search and generation to produce more accurate responses.
   - **`__init__`**: Initializes the class with a `VectorSearch` instance and a generator.
   - **`generate`**: Takes a query and retrieves the most relevant documents using the `VectorSearch` instance. It then combines the retrieved documents with the query to generate a response using the generator.
   - **`_generate_query_vector`**: A helper method that generates a vector representation of the query. In a real implementation, this would use a pre-trained model.
4. **Generator Class**: This class is responsible for generating responses based on the provided context and query.
   - **`generate`**: Takes the context and query as input and generates a response. In a real implementation, this would use a pre-trained language model.
5. **Example Usage**: We create instances of the `VectorSearch`, `Generator`, and `RAG` classes, and use the `RAG` instance to generate a response to a sample query.

> [!ADVANCED]
> The `VectorSearch` class uses cosine similarity to measure the similarity between vectors. Cosine similarity is a measure of similarity between two non-zero vectors of an inner product space that measures the cosine of the angle between them. It is widely used in information retrieval and NLP tasks. The `RAG` class combines the retrieval and generation steps to produce more accurate responses. The `Generator` class uses a simple template-based approach to generate responses, but in a real implementation, it would use a pre-trained language model.
