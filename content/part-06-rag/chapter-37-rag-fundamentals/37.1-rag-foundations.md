By the end of this lesson you can say exactly what vector search returns, list the steps that retrieval-augmented generation (RAG) adds on top of it, and measure where each step fails. We build a toy version with NumPy and check every score by hand.

**You need:** what an embedding is and the cosine similarity between two vectors (Lesson 24.1).

## The problem

A language model stores what it knows in its weights. That knowledge stops at the training cutoff, the model cannot name the document a fact came from, and when it does not know an answer it can still write a fluent one. Three things are missing: current facts, a source you can check, and a refusal when the answer is absent.

RAG gives the generator a second memory that it reads at answer time. Lewis et al. (2020) combined a pre-trained sequence-to-sequence model, which they call the parametric memory, with a dense vector index of Wikipedia, which they call the non-parametric memory. They report state-of-the-art results on three open-domain question-answering tasks [1]. That is an established result (a); the design is the idea this lesson unpacks.

## Vector search is one step

Vector search does one thing. An embedding model turns each text chunk into a vector and stores the vectors in an index. At query time it turns the question into a vector and returns the k chunks with the highest cosine similarity. Karpukhin et al. (2020) showed that learned dense vectors beat the sparse keyword ranking BM25 by 9 to 19 points of top-20 passage accuracy on their benchmark [2].

![Vector search ends at the ranked chunks; RAG adds a cited prompt, a generator and a rule for abstaining](diagrams/37.1-pipeline.svg "Vector search is the first three boxes. RAG is the whole chain.")

Three properties of vector search matter for RAG:

- It returns chunks and scores, never an answer.
- It always returns k results, even when none of them is relevant.
- Nothing forces a generator to use the chunks or to cite them.

We have no model weights in this lesson, so the embedding is a stand-in. Each word is hashed into one of 4,096 buckets, the counts form a vector, and the vector is scaled to length 1. It captures word overlap and nothing else. The numbers below describe how the pipeline behaves on a toy handbook. They say nothing about how good a learned embedding is.

The toy handbook has eight sentences, and we ask thirteen questions: ten that the handbook can answer and three that it cannot.

## Worked example by hand

Take the question "How much annual leave do employees accrue each month?" Stop words (how, much, do, each and similar) are removed, which leaves five query words: annual, leave, employees, accrue, month.

If the query and a chunk each have one count per distinct word, and they share $s$ words, then

$$\cos(q, c) = \frac{s}{\sqrt{n_q\, n_c}}$$

where $n_q$ and $n_c$ are the numbers of distinct words left after stop-word removal. This assumes no two words land in the same bucket, which holds for these words (the script confirms it by reproducing the numbers exactly).

- Chunk 1, "Northwind Robotics employees accrue 1.5 days of annual leave ...", keeps 12 words and shares 5 with the query. So $\cos = 5/\sqrt{5 \cdot 12} = \sqrt{5/12} \approx 0.645$.
- Chunk 3, "Employees who are ill ...", keeps 9 words and shares "employees". So $\cos = 1/\sqrt{45} \approx 0.149$.
- Chunk 2, "Unused leave carries over ...", keeps 10 words and shares "leave". So $\cos = 1/\sqrt{50} \approx 0.141$.

Those three numbers are the top-3 result. The code reproduces them:

```python
import re, zlib
import numpy as np

DIM = 4096
STOP = {"a", "an", "the", "of", "to", "do", "does", "is", "are", "how", "many", "much", "what",
        "who", "when", "which", "for", "each", "by", "be", "must", "can", "if", "it", "and", "in",
        "on", "at", "from", "that", "this", "with", "or", "was", "its", "their", "before", "after",
        "than", "up", "long", "fast", "often"}

def embed(text):
    """Stand-in embedding: hashed word counts, scaled to unit length (not a learned model)."""
    v = np.zeros(DIM)
    for word in re.findall(r"[a-z0-9]+", text.lower()):
        if word not in STOP:
            v[zlib.crc32(word.encode()) % DIM] += 1.0
    n = np.linalg.norm(v)
    return v / n if n else v

chunks = [
    "Northwind Robotics employees accrue 1.5 days of annual leave for each completed month of service.",
    "Unused leave carries over to the next calendar year up to a limit of 10 days.",
    "Employees who are ill for more than three consecutive days must submit a medical certificate.",
    "Travel expenses are reimbursed within 30 days of receipt of a signed claim form.",
    "Claims above 500 dollars require approval from a department head before payment.",
    "The office Wi-Fi password is rotated every quarter by the IT team.",
    "Remote work requests must be approved by a line manager in writing.",
    "Parental leave is 16 weeks for the primary carer and 4 weeks for the secondary carer.",
]
matrix = np.stack([embed(c) for c in chunks])   # one row per chunk

def vector_search(query, k=3):
    scores = matrix @ embed(query)              # unit vectors: dot product = cosine
    order = np.argsort(-scores, kind="stable")[:k]
    return [(int(i), float(scores[i])) for i in order]

def build_prompt(question, hits):
    context = "\n".join(f"[{n}] {chunks[i]}" for n, (i, _) in enumerate(hits, start=1))
    return f"Answer only from the sources and cite them as [n].\n{context}\nQuestion: {question}"

def rag_answer(question, threshold=0.2):
    hits = vector_search(question)
    if hits[0][1] < threshold:                  # the abstention rule is a score rule, not part of search
        return "I cannot answer this from the handbook."
    # Stub generator: a real LLM would read build_prompt(...). Here we return the top chunk with its citation.
    return f"{chunks[hits[0][0]]} [1]"

query = "How much annual leave do employees accrue each month?"
for rank, (i, score) in enumerate(vector_search(query), start=1):
    print(f"rank {rank}: chunk {i + 1}  score {score:.3f}  {chunks[i][:40]}...")
print()
print(rag_answer(query))
print()
print(rag_answer("What is the company's stock price policy?"))
```

```output
rank 1: chunk 1  score 0.645  Northwind Robotics employees accrue 1.5 ...
rank 2: chunk 3  score 0.149  Employees who are ill for more than thre...
rank 3: chunk 2  score 0.141  Unused leave carries over to the next ca...

Northwind Robotics employees accrue 1.5 days of annual leave for each completed month of service. [1]

I cannot answer this from the handbook.
```

The top-3 list is ranked, not filtered. Ranks 2 and 3 are non-zero only because each shares one word with the query. The list alone does not tell you whether any chunk answers the question. That decision belongs to the RAG layer.

![Cosine scores of one query against eight chunks; the gold chunk scores highest](diagrams/37.1-top-k.svg "The query scores 0.65 against its answer and at most 0.15 against the rest.")

## Chunking decides what can be retrieved

Retrieval returns whole chunks, so a chunk that splits the evidence cannot help, however well it is ranked. The next example splits a sentence at three chunk settings. A chunk of $w$ words with overlap $o$ starts a new window every $w - o$ words.

```python
def chunk(text, size, overlap):
    """Split text into word windows of `size` words; consecutive windows share `overlap` words."""
    words = text.split()
    out, i = [], 0
    while True:
        out.append(" ".join(words[i:i + size]))
        if i + size >= len(words):
            break
        i += size - overlap
    return out

doc = ("Northwind Robotics employees accrue 1.5 days of annual leave for each completed month of service. "
       "Unused leave carries over to the next calendar year up to a limit of 10 days. "
       "Employees who are ill for more than three consecutive days must submit a medical certificate.")
gold = "Employees who are ill for more than three consecutive days must submit a medical certificate."

for size, overlap in [(10, 0), (20, 0), (20, 10)]:
    pieces = chunk(doc, size, overlap)
    intact = any(gold in p for p in pieces)
    print(f"size {size:2d}, overlap {overlap:2d}: {len(pieces):2d} chunks, gold sentence intact: {intact}")
```

```output
size 10, overlap  0:  5 chunks, gold sentence intact: False
size 20, overlap  0:  3 chunks, gold sentence intact: False
size 20, overlap 10:  4 chunks, gold sentence intact: True
```

The gold sentence has 15 words. A 10-word chunk can never hold it, and a 20-word chunk with no overlap cuts it in two. Ten words of overlap restores it. The same effect on the full set of ten answerable questions, where we count the gold sentence fully inside one of the top-3 chunks:

![Gold sentence fully inside a top-3 chunk for six chunking settings](diagrams/37.1-chunking.svg "Evidence recall on ten answerable questions, by chunk size and overlap.")

- A chunk size of 10 words, with or without overlap, recovers the evidence for 0 of 10 questions. The handbook's sentences have 12 to 16 words.
- A chunk size of 20 words recovers it for 5 of 10 questions without overlap, and for 8 of 10 with 10 words of overlap.
- A chunk size of 40 words recovers it for 7 of 10 questions. Its boundaries split some sentences.
- One chunk containing the whole handbook recovers it for 10 of 10, but the handbook is 112 words. A real corpus cannot be sent to a generator whole, so chunking is a trade-off between recall and prompt length, not a detail.

## Abstention needs a rule outside search

Three questions have no answer in the handbook. Their top-1 scores are all 0.000, because they share no word with it. The ten answerable questions score between 0.333 and 0.764. A threshold of 0.2 separates the two groups, so the function above abstains on the stock-price question.

![Top-1 score for ten answerable and three unanswerable questions, with a threshold at 0.2](diagrams/37.1-abstain.svg "Answerable questions score 0.33 to 0.76; unanswerable ones score 0.00.")

This separation is a property of the toy corpus, not of retrieval. Unrelated questions in a real corpus can share common words, and a learned embedding can place an off-topic question near a passage. A threshold has to be calibrated on labelled answerable and unanswerable questions (my reasoning, not a measured result). Liu et al. (2023) add a related warning: in long prompts, models use information at the start and end of the context much better than information in the middle [3]. More retrieved chunks are not automatically better, and their order matters.

## Common traps

> [!TRAP]
> Vector search always returns k results. A top-3 list is not evidence that any of them answers the question. Check the scores and the content before you call the list an answer.

> [!TRAP]
> A 10-of-10 hit rate on a toy corpus says nothing about retrieval quality. Our questions reuse the handbook's words, so lexical overlap does the work. Test paraphrased questions before you trust any retriever.

> [!TRAP]
> A chunk shorter than the evidence cannot contain it. Chunk size and overlap decide what can be retrieved at all.

> [!TRAP]
> A relevant chunk in the middle of a long prompt may be ignored. Retrieval recall does not guarantee use [3].

> [!TRAP]
> A threshold tuned on three unanswerable questions is not calibrated. Use a labelled set of questions with both kinds of answer.

## Summary

- Vector search returns the k chunks most similar to the query, with their scores. It does not write an answer.
- RAG adds a prompt that carries the chunks with citation markers, a generator that answers from them, and a rule for abstaining.
- Each step fails differently: a ranking error, a chunk boundary that splits the evidence, or a generator that ignores the context.
- On the toy handbook, a 10-word chunk recovers the evidence for 0 of 10 questions, and 20-word chunks with 10 words of overlap recover it for 8 of 10.
- Measure each stage on its own, with labelled questions, before you judge the whole system.

### Question 1: Calculation

A query keeps 4 distinct words after stop-word removal. A chunk keeps 9 distinct words, and 2 of them match the query. Under the hashed stand-in, with no bucket collisions, what is the cosine similarity? Give three decimals.

<details><summary>Show Solution</summary>

$\cos = \dfrac{2}{\sqrt{4 \cdot 9}} = \dfrac{2}{6} = 0.333$

### Question 3: Find the bug

```python
def answer(question):
    hits = vector_search(question, k=3)
    if not hits:
        return "I cannot answer this from the handbook."
    return f"{chunks[hits[0][0]]} [1]"
```

<details><summary>Show Solution</summary>

`vector_search` returns k items even when every score is 0, so `not hits` is never true and the function never abstains. The fix is to test the score, as `rag_answer` does: `if hits[0][1] < threshold`.

</details>

### Question 4: Explanation

Why is a top-3 list of chunks with scores not, by itself, a RAG system? Name two things RAG needs that search does not provide.

<details><summary>Show Solution</summary>

Search returns sources and scores, not an answer. RAG needs (1) a prompt that places the retrieved text in the context, with instructions to answer from it and cite it, and a generator that does so, and (2) a rule for abstaining when the retrieved text does not support an answer.

</details>
