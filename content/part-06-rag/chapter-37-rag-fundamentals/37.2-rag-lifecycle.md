# 37.2 — The End-to-End RAG Lifecycle: Ingestion, Retrieval, Generation

## Opening Motivation & Context

Retrieval-Augmented Generation (RAG) is a powerful technique that combines the strengths of information retrieval and generative models to produce more accurate and contextually relevant outputs. The RAG lifecycle consists of three main stages: ingestion, retrieval, and generation. In this lesson, we'll explore each of these stages in detail, understand their importance, and see how they work together to create a robust RAG system.

## Core Concepts Breakdown

### Ingestion

Ingestion is the process of loading and preprocessing data into a format that can be easily retrieved and used by the RAG system. This stage involves several key steps:

1. **Data Collection**: Gathering relevant documents, articles, or other sources of information.
2. **Preprocessing**: Cleaning and normalizing the data to remove noise and inconsistencies.
3. **Chunking**: Dividing the data into smaller, manageable pieces called chunks.
4. **Indexing**: Storing the chunks in a searchable index for efficient retrieval.

> [!KEY-INSIGHT]
> Effective ingestion is crucial for the overall performance of the RAG system. Poorly preprocessed or chunked data can lead to irrelevant or inaccurate retrieval results, which in turn can degrade the quality of the generated outputs.

> [!BEST-PRACTICE]
> Use a consistent and well-defined chunking strategy. For example, you might split documents into paragraphs or sentences, or use a fixed-size sliding window approach.

### Retrieval

Retrieval is the process of finding the most relevant chunks of information from the indexed data based on a given query. This stage involves:

1. **Query Processing**: Cleaning and normalizing the query to match the format of the indexed data.
2. **Similarity Search**: Comparing the query to the indexed chunks to find the most similar ones.
3. **Ranking**: Sorting the retrieved chunks based on their relevance to the query.

> [!KEY-INSIGHT]
> The quality of the retrieval stage directly impacts the quality of the generated outputs. If the retrieved chunks are not relevant or accurate, the generative model will produce poor results.

> [!BEST-PRACTICE]
> Use a diverse set of retrieval techniques, such as keyword-based search, semantic search, or a combination of both, to ensure that the most relevant information is retrieved.

### Generation

Generation is the process of using a generative model to produce a response based on the retrieved chunks and the given query. This stage involves:

1. **Context Preparation**: Combining the retrieved chunks and the query into a single context that the generative model can understand.
2. **Model Inference**: Using the generative model to produce a response based on the prepared context.
3. **Post-processing**: Cleaning and formatting the generated response to make it more readable and user-friendly.

> [!KEY-INSIGHT]
> The generative model is responsible for the final quality of the RAG system's outputs. A poorly trained or fine-tuned model will produce inaccurate or nonsensical responses, regardless of the quality of the retrieved chunks.

> [!BEST-PRACTICE]
> Fine-tune the generative model on a diverse set of tasks and domains to ensure that it can handle a wide range of queries and produce high-quality responses.

## Code Demonstration & Runtime Output

Let's look at a simple implementation of the RAG lifecycle in Python. We'll use the `transformers` library for the generative model and the `sentence-transformers` library for the retrieval stage.

```python
from typing import List, Tuple
from transformers import pipeline
from sentence_transformers import SentenceTransformer, util
import numpy as np

class RAGSystem:
    def __init__(self, model_name: str = "distilbert-base-uncased", embedding_model_name: str = "all-MiniLM-L6-v2"):
        self.generator = pipeline("text-generation", model=model_name)
        self.embedding_model = SentenceTransformer(embedding_model_name)
        self.indexed_chunks = []
        self.embeddings = []

    def ingest(self, documents: List[str], chunk_size: int = 100) -> None:
        """Ingest documents into the RAG system."""
        for doc in documents:
            chunks = [doc[i:i+chunk_size] for i in range(0, len(doc), chunk_size)]
            self.indexed_chunks.extend(chunks)
            self.embeddings.extend(self.embedding_model.encode(chunks))

    def retrieve(self, query: str, top_k: int = 3) -> List[str]:
        """Retrieve the most relevant chunks based on the query."""
        query_embedding = self.embedding_model.encode(query)
        similarities = util.cos_sim(query_embedding, self.embeddings)[0]
        top_indices = np.argsort(similarities)[-top_k:][::-1]
        return [self.indexed_chunks[i] for i in top_indices]

    def generate(self, query: str, context: List[str]) -> str:
        """Generate a response based on the query and context."""
        context_str = "\n".join(context)
        prompt = f"Context:\n{context_str}\n\nQuery: {query}\n\nResponse:"
        response = self.generator(prompt, max_length=100, num_return_sequences=1)
        return response[0]['generated_text']

    def rag_pipeline(self, query: str) -> str:
        """End-to-end RAG pipeline."""
        context = self.retrieve(query)
        return self.generate(query, context)

if __name__ == "__main__":
    # Example usage
    documents = [
        "The capital of France is Paris. Paris is known for its art, fashion, and culture.",
        "The Eiffel Tower is a wrought-iron lattice tower on the Champ de Mars in Paris.",
        "The Louvre Museum is the world's largest art museum and a historic monument in Paris."
    ]

    rag_system = RAGSystem()
    rag_system.ingest(documents)

    query = "What is the Eiffel Tower?"
    response = rag_system.rag_pipeline(query)
    print(response)
```

```
Response: The Eiffel Tower is a wrought-iron lattice tower on the Champ de Mars in Paris. It is one of the most famous landmarks in the world and a symbol of France. The tower was built for the 1889 Exposition Universelle and was designed by Gustave Eiffel. It stands 300 meters tall and is a popular tourist attraction.
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import the necessary libraries and modules, including `transformers` for the generative model, `sentence-transformers` for the retrieval stage, and `numpy` for numerical operations.
2. **RAGSystem Class**: We define a class `RAGSystem` to encapsulate the RAG lifecycle.
3. **Initialization**: The `__init__` method initializes the generative model and the embedding model, as well as empty lists to store the indexed chunks and their embeddings.
4. **Ingestion**: The `ingest` method takes a list of documents and a chunk size, splits the documents into chunks, and stores them along with their embeddings.
5. **Retrieval**: The `retrieve` method takes a query and the number of chunks to retrieve, computes the similarity between the query and the indexed chunks, and returns the most similar chunks.
6. **Generation**: The `generate` method takes a query and a list of context chunks, combines them into a prompt, and uses the generative model to produce a response.
7. **RAG Pipeline**: The `rag_pipeline` method combines the retrieval and generation stages to create an end-to-end RAG pipeline.
8. **Example Usage**: In the `__main__` block, we create an instance of the `RAGSystem` class, ingest some example documents, and use the RAG pipeline to generate a response to a query.

> [!ADVANCED]
> The `transformers` library uses PyTorch under the hood to perform the text generation. The `sentence-transformers` library uses the `transformers` library to compute the sentence embeddings, which are then used to compute the cosine similarity between the query and the indexed chunks. The `numpy` library is used to sort the similarities and retrieve the most relevant chunks.

> [!QA]
> Q: When should I prefer a keyword-based search over a semantic search for the retrieval stage?
> A: Keyword-based search is generally faster and more efficient, but it may not be as accurate as semantic search, especially for complex or ambiguous queries. Semantic search is more accurate but computationally more expensive. You should choose the retrieval technique based on your specific requirements and constraints.

### Question #3: Find and fix the bug

```python
from typing import List
from transformers import pipeline

def generate_response(prompt: str) -> str:
    generator = pipeline("text-generation", model="distilbert-base-uncased")
    response = generator(prompt, max_length=50)
    return response[0]["generated_text"]

prompt = "The capital of France is"
response = generate_response(prompt)
print(response)
```

<details><summary>Show Solution</summary>
The bug in the code is that the `pipeline` function returns a list of responses, but the code tries to access the first response using an index of 0. To fix the bug, we should use the `num_return_sequences` parameter to specify the number of responses to generate and then access the first response using an index of 0.

Here is the fixed code:

```python
from typing import List
from transformers import pipeline

def generate_response(prompt: str) -> str:
    generator = pipeline("text-generation", model="distilbert-base-uncased")
    response = generator(prompt, max_length=50, num_return_sequences=1)
    return response[0]["generated_text"]

prompt = "The capital of France is"
response = generate_response(prompt)
print(response)
```
</details>
