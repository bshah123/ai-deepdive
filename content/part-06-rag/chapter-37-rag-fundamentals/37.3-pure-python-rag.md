Retrieval-Augmented Generation (RAG) answers a question by finding the relevant passages in your documents and handing them to a language model, which answers from them and cites them. In this lesson you will build the whole pipeline in pure Python (chunking, an inverted index, BM25 scoring, an abstention gate, prompt assembly and citations), then measure how each choice changes what the system can find.

**You need:** Lessons 37.1 and 37.2, and comfort with dictionaries and `collections.Counter`. The program uses only the standard library and runs in the browser, with no model weights and no API keys. The generator is a stand-in, so this lesson measures retrieval, not answer quality.

## The problem

A language model answers from what it learned in training. It cannot read your leave policy, and it does not know when it is guessing. RAG addresses both: retrieve the passages that bear on the question, put them into the prompt with numbers, and require citations. Lesson 37.1 argued that this needs more than vector search, and Lesson 37.2 listed the stages. Here we build the stages ourselves.

The test corpus is eight short policy documents written for this lesson, with one known answer per question. Because we know each answer, we can count hits instead of judging by eye.

![Pipeline from documents to chunks, an index, top-three retrieval, a gate, a prompt, a generator and a cited answer](diagrams/37.3-pipeline.svg "The pipeline. Only the generator is a stand-in in this lesson.")

Documents are cut into chunks and indexed once. For each question we score every chunk, keep the top three, and abstain if the best score falls below a gate. The retrieved chunks are numbered into a prompt. A real system would send that prompt to a language model; ours returns the best-matching sentence instead.

## Worked example, by hand

Take the question "How much annual leave do I earn each month?" and focus on the word *annual*. We score it with BM25 (Best Match 25; see Robertson and Zaragoza in the references). For a query $q$ and chunk $d$:

$$
\mathrm{score}(q,d)=\sum_{t\in q}\mathrm{idf}(t)\,\frac{f_{t,d}\,(k_1+1)}{f_{t,d}+k_1\left(1-b+b\,\frac{|d|}{\mathrm{avgdl}}\right)},
\qquad
\mathrm{idf}(t)=\ln\!\left(1+\frac{N-\mathrm{df}(t)+0.5}{\mathrm{df}(t)+0.5}\right)
$$

Here $N$ is the number of chunks, $\mathrm{df}(t)$ the number of chunks containing term $t$ (document frequency), $f_{t,d}$ the count of $t$ in $d$ (term frequency), $|d|$ the chunk length in terms, and avgdl the average length. We use $k_1 = 1.2$ and $b = 0.75$, the defaults in Apache Lucene's BM25Similarity. The factor $(k_1+1)$ multiplies every term equally, so it does not change the ranking; we keep it to match the classic form.

For *annual* in the top chunk, "Leave policy" ($N = 21$, $\mathrm{df} = 2$, $f = 2$, $|d| = 32$, avgdl $= 23.76$):

- idf $= \ln(1 + 19.5/2.5) = \ln 8.8 = 2.1748$
- length term $= 1 - 0.75 + 0.75 \times 32/23.76 = 1.2601$
- saturation $= 2 \times 2.2 / (2 + 1.2 \times 1.2601) = 1.2528$
- contribution $= 2.1748 \times 1.2528 = 2.725$

The code below prints the same 2.725. Repetition saturates: at average length, one occurrence scores 1.000, two score 1.375, four score 1.692 and eight score 1.913, so eight occurrences do not count eight times. A chunk twice the average length scores only 0.710 for one occurrence.

Rare terms carry the weight. The inverted index in the next figure shows why *annual* (in 2 of 8 documents) outweighs *days* (in 6 of 8).

## Build it

The library and demo below form one block that runs in the browser. Read `BM25.scores` first: it is the postings loop from the index figure, with the BM25 term added. `RAG` wires chunking, indexing and retrieval together, and `answer` adds the gate.

```python
import math
import re
from collections import Counter, defaultdict

# Function words are ignored when scoring; otherwise "is" or "the" would add noise to every score.
STOP = set("a an and are as at be by do does each for from how i if in is it me my of on or so "
           "that the there this to what when which with any after".split())

def words(text):
    """Lowercase word tokens, stop words included. Used to match gold answers."""
    return re.findall(r"[a-z0-9]+", text.lower())

def terms(text):
    """Scoring terms: word tokens minus stop words."""
    return [w for w in words(text) if w not in STOP]

def chunk(text, size, overlap=0):
    """Split text into windows of `size` words; consecutive windows share `overlap` words."""
    w = text.split()
    step = size - overlap
    out, start = [], 0
    while True:
        out.append(" ".join(w[start:start + size]))
        if start + size >= len(w):
            return out
        start += step

class BM25:
    """BM25 over a list of passages, using an inverted index."""
    def __init__(self, passages, k1=1.2, b=0.75):
        self.passages, self.k1, self.b = passages, k1, b
        self.lengths = [len(terms(p)) for p in passages]
        self.avgdl = sum(self.lengths) / len(passages)
        self.postings = defaultdict(list)            # term -> [(passage id, term frequency)]
        for i, p in enumerate(passages):
            for term, tf in Counter(terms(p)).items():
                self.postings[term].append((i, tf))

    def idf(self, term):
        n = len(self.passages)
        df = len(self.postings.get(term, []))        # passages that contain the term
        return math.log(1 + (n - df + 0.5) / (df + 0.5))

    def scores(self, query):
        out = defaultdict(float)
        for term in set(terms(query)):               # each distinct query term counts once
            idf = self.idf(term)
            for i, tf in self.postings.get(term, []):
                norm = 1 - self.b + self.b * self.lengths[i] / self.avgdl
                out[i] += idf * tf * (self.k1 + 1) / (tf + self.k1 * norm)
        return out

    def search(self, query, k=3):
        ranked = sorted(self.scores(query).items(), key=lambda kv: (-kv[1], kv[0]))
        return ranked[:k]

    def explain(self, query, i):
        """Per-term contributions to passage i's score: the terms of `scores`, one at a time."""
        out = {}
        for term in set(terms(query)):
            for j, tf in self.postings.get(term, []):
                if j == i:
                    norm = 1 - self.b + self.b * self.lengths[i] / self.avgdl
                    out[term] = self.idf(term) * tf * (self.k1 + 1) / (tf + self.k1 * norm)
        return out

class RAG:
    """Ingest documents into chunks, index them, and retrieve the best chunks for a query."""
    def __init__(self, docs, size=40, overlap=10):
        self.chunks = []                              # (title, chunk text), one entry per chunk
        for title, text in docs:
            for c in chunk(text, size, overlap):
                self.chunks.append((title, c))
        self.index = BM25([c for _, c in self.chunks])

    def retrieve(self, query, k=3):
        return [(*self.chunks[i], score) for i, score in self.index.search(query, k)]

def sentences(text):
    return [s for s in re.split(r"(?<=[.;])\s+", text) if s]

def build_prompt(query, hits):
    lines = ["Answer using only the sources. Cite them as [n].", ""]
    lines += [f"[{n}] {title}: {text}" for n, (title, text, _) in enumerate(hits, 1)]
    lines += ["", f"Question: {query}"]
    return "\n".join(lines)

def extractive_answer(query, hits):
    """Stand-in for a generator: return the retrieved sentence sharing the most terms with the query."""
    q = set(terms(query))
    best = (0, None, None)
    for n, (_, text, _) in enumerate(hits, 1):
        for s in sentences(text):
            overlap = len(q & set(terms(s)))
            if overlap > best[0]:
                best = (overlap, s, n)
    return f"{best[1]} [{best[2]}]" if best[1] else None

def answer(rag, query, k=3, tau=4.0):
    hits = rag.retrieve(query, k)
    if not hits or hits[0][2] < tau:                  # abstain: the best evidence is too weak
        return None, hits
    return extractive_answer(query, hits), hits

DOCS = [
    ("Leave policy", "Annual leave. Full-time employees accrue 1.5 days of paid annual leave for each completed month of service. Unused leave carries over to the next calendar year up to a limit of 10 days. Leave requests go to your line manager at least five working days in advance, except for sickness, which may be reported on the same day. Public holidays are listed in the yearly calendar published on the intranet in December. Part-time staff accrue leave in proportion to their contracted hours."),
    ("Expense claims", "Expense claims. Submit travel and office expense claims through the finance portal within 30 days of the purchase date. Each claim needs an itemised receipt; a card slip alone is not accepted. Claims above 500 USD need written approval from a department head before purchase. Reimbursement is paid with the next monthly payroll run after approval. Claims that miss the deadline are paid only with a written exception from the finance director."),
    ("Remote work", "Remote work. Employees may work from home up to three days per week with manager approval. Core hours are 10:00 to 15:00 local time, during which staff must be reachable on chat. A home office stipend of 150 USD per year is available once the employee completes a workstation self-assessment form. Equipment that leaves the office must be logged in the asset register. Remote arrangements are reviewed every six months."),
    ("Account security", "Account security. Passwords must be at least 14 characters long and must not reuse any of the last eight passwords. Passwords expire after 180 days. Accounts lock for 30 minutes after five failed sign-in attempts. To reset a forgotten password, use the self-service portal or call the service desk and verify your identity with your employee badge number. Never share a password, even with the service desk."),
    ("Business travel", "Business travel. Book flights through the approved travel agency at least 14 days before departure to qualify for the economy fare cap. Economy class is the default for flights under six hours. Hotel rates are capped at 180 USD per night in most cities and 240 USD in the listed high-cost cities. Rail travel within the country is economy unless a medical reason is documented. Cancellations must be made through the same agency."),
    ("Parental leave", "Parental leave. Primary caregivers receive 16 weeks of paid parental leave. Secondary caregivers receive 4 weeks. The leave may be taken in one block or split into two blocks, provided each block lasts at least two weeks. Notify HR at least 60 days before the expected start date, or as early as practical if the date is unknown. Leave may also be taken in the first year after the birth or adoption."),
    ("Office access", "Office access. Badges are issued on the first working day and must be worn visibly in all common areas. Lost badges must be reported to facilities within 24 hours so the card can be deactivated. Visitors must sign in at reception and wear a visitor pass. The server room is accessible only to the infrastructure team and needs a second authorised person present. Tailgating through secure doors is a disciplinary matter."),
    ("Learning budget", "Learning budget. Each employee has an annual learning budget of 800 USD for courses, books and conferences. Courses that lead to a recognised certificate may be funded above this limit with director approval. Unused budget does not carry over. Claims follow the same route as expense claims through the finance portal. Budget balances are shown on the employee dashboard each month."),
]

QUERIES = [  # (question, gold answer text, index of the document that holds it)
    ("How much annual leave do I earn each month?", "1.5 days of paid annual leave", 0),
    ("What is the deadline to submit an expense claim?", "within 30 days of the purchase date", 1),
    ("How many days a week can I work from home?", "up to three days per week", 2),
    ("After how many failed sign-in attempts does an account lock?", "after five failed sign-in attempts", 3),
    ("How far in advance should I book flights?", "at least 14 days before departure", 4),
    ("How long is paid leave for a primary caregiver?", "16 weeks of paid parental leave", 5),
    ("What happens if I lose my badge?", "reported to facilities within 24 hours", 6),
    ("What is the yearly allowance for training?", "annual learning budget of 800 USD", 7),
]

OUT_OF_CORPUS = ["What is the capital of France?", "How do I configure a Kubernetes ingress?"]

if __name__ == "__main__":
    rag = RAG(DOCS, size=40, overlap=10)
    print(f"{len(DOCS)} documents, {len(rag.chunks)} chunks")
    for q in [QUERIES[0][0], QUERIES[6][0], OUT_OF_CORPUS[0]]:
        ans, hits = answer(rag, q)
        print("\nQ:", q)
        for title, text, score in hits:
            print(f"  {score:6.3f}  {title}")
        print("A:", ans if ans else "I don't know: the sources do not say.")
    top = rag.index.search(QUERIES[0][0], 1)[0][0]
    parts = rag.index.explain(QUERIES[0][0], top)
    print("per-term contributions:", {t: round(v, 3) for t, v in sorted(parts.items())})
    print("\n" + build_prompt(QUERIES[0][0], rag.retrieve(QUERIES[0][0], 2)))
```

## What the measurements say

A script executes the block above and produces every number in this section, so the figures and the text agree.

### Chunk size decides what can be found

Chunks overlap by about a quarter of their length (2 words at size 10, 20 at size 80), so a sentence cut at one boundary still appears whole in the next window. Retrieval returns chunks, which makes the chunk size a retrieval decision. We ran all eight questions at five sizes.

At 10 words, the gold answer sits whole inside some chunk for only 1 of 8 questions: most answers straddle a boundary, and no chunk contains them intact. From 20 words up, all eight survive. Top-three retrieval then finds 6 of 8 at every size from 20 words up. Context grows with size: the top three carried 51 words at size 20 and 156 at size 80, which is prompt budget spent on sentences the answer does not need.

![Grouped bars per chunk size: gold answer kept whole in some chunk, and gold answer in the top three](diagrams/37.3-chunk-sweep.svg "Chunk size on eight questions. Small windows split answers; large windows cost context.")

### Two misses are vocabulary problems

Neither miss is a chunking problem. "What happens if I lose my badge?" ranks the account-security chunk first (score 2.544), because it matches only *badge*. The policy says "Lost badges" and "badges", and without stemming (reducing words to a base form) *lose* does not match *lost* and *badge* does not match *badges*. "What is the yearly allowance for training?" ranks the leave policy first (2.561), because *yearly* appears in "the yearly calendar". The answer says *annual learning budget* and never uses *training*. Weighting alone cannot close this gap. Dense (embedding) retrieval is one response to it, and Lesson 37.1 covers vector search.

### Naive counting ties BM25 on this set

A naive baseline counts how many distinct query terms appear in each chunk. On these eight questions it finds the gold answer in the top three exactly as often as BM25 does, 6 of 8. This set therefore cannot show that idf and length normalisation help. A claim that BM25 beats simple overlap needs a larger, held-out set, which this lesson does not provide.

### The gate needs measuring on your corpus

Correct hits score at least 5.77. The two misses score at most 2.561. The two out-of-corpus questions score exactly 0.0, since none of their terms occur in the corpus. A gate at 4.0 separates the groups, and the code uses it.

![Dot plot of top BM25 scores for out-of-corpus questions, misses and correct hits, with the gate at 4.0](diagrams/37.3-abstain.svg "Top score by outcome. The gap is real on this corpus and nowhere else yet.")

Eight questions give no confidence interval, and BM25 scores depend on corpus size and passage length. Before trusting a gate, label questions from your own corpus and measure the error rate at each threshold.

## The generator is a stand-in

`build_prompt` numbers the retrieved chunks and asks for citations. `extractive_answer` returns the sentence that shares the most terms with the question. It cannot paraphrase, combine sentences or refuse on its own, and we did not measure answer quality. The prompt is the part a language model would receive; the retrieval, the gate and the prompt format are what this lesson measures.

A real system should also check citations: every [n] in a generated answer must refer to a chunk you actually passed in. The extractive answer satisfies this by construction. A language model does not.

## Common traps

> [!TRAP]
> Chunks that are too small split answers. At 10 words the gold answer was intact in only 1 of 8 queries, and top-three retrieval could not recover it.

> [!TRAP]
> Lexical matching misses inflected and synonymous wording. "lose" does not match "lost", and "yearly" does not match "annual".

> [!TRAP]
> A word shared by two chunks still scores. *Month* gave the learning-budget chunk 2.243 for the leave question, because "each month" appears there.

> [!TRAP]
> A gate tuned on eight questions is a guess. The 4.0 threshold works on this corpus and says nothing about another one.

> [!TRAP]
> Nothing here checks citations. A generator can cite [4] when only three chunks were passed, so check every citation against the chunk list.

## Summary

- RAG needs retrieval you can measure: chunks, an index and a ranking, each with a number you can check.
- BM25 weights a term by rarity (idf), saturates repeated counts and normalises by length. For *annual* in the top chunk, the worked example gives 2.725.
- On eight questions, chunks of 20 words and above keep every answer intact. Chunks of 10 words split most of them.
- Lexical retrieval misses inflected and synonymous wording, and the gate's threshold is specific to the corpus it was measured on.
- The generator here is a stand-in. The measured parts are retrieval, abstention and prompt format.

## Quiz time

### Question 1: Calculation

A corpus has $N = 21$ chunks, and the term *leave* appears in $\mathrm{df} = 6$ of them. Compute its idf with the lesson's formula. Then say whether a term that appears in all 21 chunks gets a positive idf.

<details><summary>Show solution</summary>

$\mathrm{idf} = \ln(1 + (21 - 6 + 0.5)/(6 + 0.5)) = \ln(1 + 15.5/6.5) = \ln(3.3846) \approx 1.219$.

For $\mathrm{df} = N = 21$: $\ln(1 + 0.5/21.5) = \ln(1.0233) \approx 0.023$. It is positive, because the $+1$ inside the logarithm keeps idf above zero.

</details>

### Question 3: Find the bug

```python
def chunk(text, size, overlap=0):
    w = text.split()
    return [" ".join(w[i:i + size]) for i in range(0, len(w), size)]
```

What does this change, and which measured failure does it cause?

<details><summary>Show solution</summary>

The `overlap` argument is ignored and the stride equals `size`, so consecutive windows share no words. An answer that straddles a boundary now appears in no chunk. A containment test like the sweep's would then fail for answers that straddle a boundary, and nothing raises an error. The fix is to step by `size - overlap`.

</details>

### Question 4: Explanation

Why can the gate value 4.0 not be copied to a corpus of one million passages?

<details><summary>Show solution</summary>

Idf depends on $N$ and on each term's document frequency, and BM25 scores depend on passage lengths and the average length. The score distributions of correct and wrong hits both shift with corpus size and vocabulary. The gate must be measured on labelled questions from that corpus, with the error rate reported at each threshold.

</details>
