# 37.3 — Building a Minimalist Zero-Framework RAG System in Pure Python

## Opening Motivation & Context

Retrieval-Augmented Generation (RAG) is a cutting-edge technique in natural language processing that combines the strengths of information retrieval and text generation. In this lesson, we'll build a minimalist RAG system from scratch using pure Python, without relying on any external machine learning frameworks. This will give you a deep understanding of how RAG systems work under the hood.

## Core Concepts Breakdown

RAG systems typically consist of two main components:

1. **Retriever**: This component is responsible for finding relevant documents or passages from a knowledge base given a user query.
2. **Generator**: This component takes the retrieved information and generates a coherent response to the user's query.

> [!KEY-INSIGHT]
> The key innovation of RAG is that it allows the generator to "look up" relevant information when needed, rather than relying solely on its pre-trained knowledge.

> [!BEST-PRACTICE]
> When building a RAG system, it's important to carefully consider the trade-off between retrieval accuracy and generation quality. A more accurate retriever might not always lead to better overall performance.

> [!WARNING]
> Without proper preprocessing, your RAG system might struggle with queries that use different wording than the documents in your knowledge base.

## Code Demonstration & Runtime Output

```python
import re
from typing import List, Dict, Tuple
from collections import defaultdict

class SimpleRetriever:
    def __init__(self, documents: List[str]):
        self.documents = documents
        self.inverted_index = self._build_inverted_index()

    def _build_inverted_index(self) -> Dict[str, List[int]]:
        index = defaultdict(list)
        for doc_id, doc in enumerate(self.documents):
            words = re.findall(r'\w+', doc.lower())
            for word in set(words):  # Using set to avoid duplicate entries for the same word
                index[word].append(doc_id)
        return index

    def retrieve(self, query: str, k: int = 3) -> List[Tuple[int, float]]:
        query_words = re.findall(r'\w+', query.lower())
        doc_scores = defaultdict(float)

        for word in query_words:
            if word in self.inverted_index:
                for doc_id in self.inverted_index[word]:
                    doc_scores[doc_id] += 1  # Simple term frequency scoring

        # Sort documents by score in descending order and return top k
        sorted_docs = sorted(doc_scores.items(), key=lambda x: x[1], reverse=True)
        return sorted_docs[:k]

class SimpleGenerator:
    def __init__(self, documents: List[str]):
        self.documents = documents
        self.vocab = self._build_vocab()

    def _build_vocab(self) -> Dict[str, int]:
        vocab = defaultdict(int)
        for doc in self.documents:
            words = re.findall(r'\w+', doc.lower())
            for word in words:
                vocab[word] += 1
        return vocab

    def generate(self, retrieved_docs: List[Tuple[int, float]], query: str) -> str:
        # Simple generation: concatenate the retrieved documents and the query
        context = " ".join([self.documents[doc_id] for doc_id, _ in retrieved_docs])
        return f"Based on the information provided: {context}\n\nResponse to your query '{query}': [Generated response would go here]"

class MinimalistRAG:
    def __init__(self, documents: List[str]):
        self.retriever = SimpleRetriever(documents)
        self.generator = SimpleGenerator(documents)

    def answer(self, query: str) -> str:
        retrieved_docs = self.retriever.retrieve(query)
        return self.generator.generate(retrieved_docs, query)

if __name__ == "__main__":
    documents = [
        "The capital of France is Paris.",
        "Paris is known for its art and culture.",
        "The Eiffel Tower is located in Paris.",
        "Machine learning is a subset of artificial intelligence.",
        "Deep learning uses neural networks with many layers.",
        "Python is a popular programming language for machine learning."
    ]

    rag_system = MinimalistRAG(documents)
    print(rag_system.answer("What is Paris known for?"))
```

## How this works (Line-by-Line Breakdown)

1. **Imports and Class Definitions**:
   - We import necessary modules and define our three main classes: `SimpleRetriever`, `SimpleGenerator`, and `MinimalistRAG`.

2. **SimpleRetriever Class**:
   - `__init__`: Initializes the retriever with documents and builds an inverted index.
   - `_build_inverted_index`: Creates a dictionary mapping words to document IDs where they appear.
   - `retrieve`: Takes a query and returns the top k most relevant documents based on term frequency.

3. **SimpleGenerator Class**:
   - `__init__`: Initializes the generator with documents and builds a vocabulary.
   - `_build_vocab`: Creates a dictionary counting word frequencies across all documents.
   - `generate`: Combines retrieved documents with the query to form a response.

4. **MinimalistRAG Class**:
   - `__init__`: Initializes both retriever and generator components.
   - `answer`: Orchestrates the RAG process by first retrieving relevant documents and then generating a response.

5. **Main Block**:
   - Defines a list of sample documents.
   - Creates a RAG system instance and demonstrates its usage with a sample query.

> [!ADVANCED]
> The inverted index implementation uses Python's `defaultdict` for efficient word-to-document mapping. The retrieval scoring is based on simple term frequency, which could be enhanced with techniques like TF-IDF or BM25 for better performance.

> [!QA]
> Q: When should I prefer a more sophisticated retrieval method over this simple term frequency approach?
> A: You should consider more advanced retrieval methods when:
> - Your documents are very large and term frequency alone isn't discriminative enough
> - You need to handle synonyms or related terms
> - You want to incorporate document structure or metadata
> - You're working with a domain where semantic similarity matters more than exact term matches

```python
class FixedRetriever:
    def __init__(self, documents):
        self.documents = documents
        self.index = self.build_index()

    def build_index(self):
        index = {}
        for doc_id, doc in enumerate(self.documents):
            words = doc.split()
            for word in words:
                if word not in index:
                    index[word] = []
                if doc_id not in index[word]:  # Avoid duplicate document IDs
                    index[word].append(doc_id)
        return index

    def retrieve(self, query):
        query_words = query.split()
        results = set()  # Use a set to avoid duplicate document IDs
        for word in query_words:
            if word in self.index:
                results.update(self.index[word])
        return list(results)

documents = ["hello world", "hello python", "python is great"]
retriever = FixedRetriever(documents)
print(retriever.retrieve("hello python"))
```

The fixed version:
1. Avoids duplicate document IDs in the index
2. Uses a set to collect results and convert to list at the end
3. This ensures each document is only returned once, even if it contains multiple query words
