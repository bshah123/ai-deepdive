# 38.3 — Metadata Extraction, Hierarchical Chunking & Parent-Child Retrieval

## Opening Motivation & Context

In the realm of Retrieval-Augmented Generation (RAG), the quality of the retrieved documents significantly impacts the performance of the generative model. Metadata extraction, hierarchical chunking, and parent-child retrieval are advanced techniques that enhance the retrieval process by organizing and contextualizing documents more effectively. These techniques help in understanding the hierarchical relationships within documents, improving the relevance of retrieved chunks, and providing a more comprehensive context for the generative model.

## Core Concepts Breakdown

### Metadata Extraction

Metadata extraction involves extracting relevant information from documents that can provide additional context and improve retrieval accuracy. This can include document titles, authors, publication dates, and other structured data.

> [!KEY-INSIGHT]
> Metadata extraction helps in understanding the context and relevance of documents, which is crucial for effective retrieval in RAG systems.

> [!BEST-PRACTICE]
> Use structured metadata fields to ensure consistency and ease of extraction. Common metadata fields include title, author, date, and keywords.

### Hierarchical Chunking

Hierarchical chunking involves breaking down documents into smaller, more manageable chunks while maintaining their hierarchical relationships. This can include sections, subsections, paragraphs, and sentences. By preserving the hierarchical structure, the retrieval process can be more context-aware and retrieve more relevant chunks.

> [!KEY-INSIGHT]
> Hierarchical chunking helps in maintaining the contextual relationships within documents, which is essential for effective retrieval in RAG systems.

> [!BEST-PRACTICE]
> Use a consistent chunking strategy, such as fixed-size chunks or semantic-based chunks, to ensure uniformity and ease of retrieval.

### Parent-Child Retrieval

Parent-child retrieval involves retrieving documents based on their hierarchical relationships. This can include retrieving parent documents along with their child documents or retrieving child documents based on their parent documents. By leveraging hierarchical relationships, the retrieval process can be more context-aware and retrieve more relevant documents.

> [!KEY-INSIGHT]
> Parent-child retrieval helps in understanding the contextual relationships within documents, which is essential for effective retrieval in RAG systems.

> [!BEST-PRACTICE]
> Use hierarchical indexing techniques, such as inverted indexes or hierarchical clustering, to facilitate parent-child retrieval.

## Code Demonstration & Runtime Output

```python
import re
from typing import List, Dict, Tuple

class Document:
    def __init__(self, title: str, author: str, date: str, content: str):
        self.title = title
        self.author = author
        self.date = date
        self.content = content
        self.metadata = self.extract_metadata()

    def extract_metadata(self) -> Dict[str, str]:
        """Extract metadata from the document content."""
        metadata = {
            'title': self.title,
            'author': self.author,
            'date': self.date,
            'keywords': self.extract_keywords()
        }
        return metadata

    def extract_keywords(self) -> List[str]:
        """Extract keywords from the document content."""
        keywords = re.findall(r'\b\w{5,}\b', self.content)
        return list(set(keywords))

    def hierarchical_chunking(self) -> List[Tuple[str, str]]:
        """Break down the document into hierarchical chunks."""
        sections = re.split(r'\n\s*\n', self.content)
        chunks = []
        for section in sections:
            paragraphs = re.split(r'\n', section)
            for paragraph in paragraphs:
                sentences = re.split(r'(?<=[.!?])\s+', paragraph)
                for sentence in sentences:
                    if sentence.strip():
                        chunks.append((section, sentence))
        return chunks

def parent_child_retrieval(documents: List[Document], query: str) -> List[Document]:
    """Retrieve documents based on parent-child relationships."""
    retrieved_documents = []
    for document in documents:
        if query.lower() in document.content.lower():
            retrieved_documents.append(document)
    return retrieved_documents

if __name__ == "__main__":
    # Example documents
    doc1 = Document(
        title="Introduction to Python",
        author="John Doe",
        date="2023-01-01",
        content="Python is a high-level programming language. It is widely used for web development, data analysis, and machine learning."
    )

    doc2 = Document(
        title="Advanced Python Techniques",
        author="Jane Smith",
        date="2023-02-01",
        content="Advanced Python techniques include hierarchical chunking and parent-child retrieval. These techniques are essential for effective retrieval in RAG systems."
    )

    documents = [doc1, doc2]

    # Extract metadata
    for doc in documents:
        print(f"Metadata for {doc.title}: {doc.metadata}")

    # Hierarchical chunking
    for doc in documents:
        chunks = doc.hierarchical_chunking()
        print(f"\nHierarchical chunks for {doc.title}:")
        for section, sentence in chunks:
            print(f"Section: {section}, Sentence: {sentence}")

    # Parent-child retrieval
    query = "hierarchical chunking"
    retrieved_docs = parent_child_retrieval(documents, query)
    print(f"\nRetrieved documents for query '{query}':")
    for doc in retrieved_docs:
        print(doc.title)
```

> [!QA]
> Q: When should I prefer hierarchical chunking over fixed-size chunking?
> A: Hierarchical chunking is preferred when the document has a natural hierarchical structure, such as sections, subsections, and paragraphs. Fixed-size chunking is preferred when the document does not have a natural hierarchical structure or when a consistent chunk size is required.

The bug in the code is that the `extract_keywords` method returns a list of keywords without removing duplicates. To fix this, we need to convert the list of keywords to a set to remove duplicates and then convert it back to a list.
