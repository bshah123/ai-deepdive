# 38.2 — Chunking Strategies: Fixed-Size, Recursive Character & Semantic Chunking

## Opening Motivation & Context

Chunking is a fundamental preprocessing step in Retrieval-Augmented Generation (RAG) systems. It involves breaking down large documents into smaller, manageable pieces called chunks. These chunks are then used to create embeddings, which are numerical representations of the text that can be used for semantic search and retrieval. Effective chunking strategies are crucial for the performance of RAG systems, as they directly impact the quality of the embeddings and the relevance of the retrieved information.

In this lesson, we will explore three common chunking strategies: Fixed-Size Chunking, Recursive Character Chunking, and Semantic Chunking. Each strategy has its own advantages and is suitable for different types of documents and use cases.

## Core Concepts Breakdown

### Fixed-Size Chunking

Fixed-size chunking is the simplest form of chunking, where documents are divided into chunks of a fixed, predetermined size. This approach is straightforward and easy to implement, but it may not always produce optimal results, especially for documents with varying content density or structure.

> [!KEY-INSIGHT]
> Fixed-size chunking is a simple and efficient method for dividing documents into smaller pieces, but it may not always capture the semantic meaning of the text.

> [!BEST-PRACTICE]
> Use fixed-size chunking when you need a simple and fast way to divide documents into smaller pieces, and when the documents have a relatively uniform structure.

> [!WARNING]
> Fixed-size chunking may result in chunks that are semantically incomplete or contain unrelated information, which can negatively impact the quality of the embeddings and the retrieval performance.

### Recursive Character Chunking

Recursive character chunking is a more sophisticated approach to chunking, where documents are divided into chunks based on the presence of specific characters or patterns. This method is particularly useful for documents with a well-defined structure, such as code or markup languages, where certain characters or patterns indicate the boundaries of logical units.

> [!KEY-INSIGHT]
> Recursive character chunking can capture the semantic meaning of the text by dividing it into logical units based on specific characters or patterns.

> [!BEST-PRACTICE]
> Use recursive character chunking when you are working with documents that have a well-defined structure, such as code or markup languages, and when you need to capture the semantic meaning of the text.

> [!WARNING]
> Recursive character chunking may not work well for documents with a more fluid or ambiguous structure, where the boundaries of logical units are not clearly defined.

### Semantic Chunking

Semantic chunking is a more advanced approach to chunking, where documents are divided into chunks based on their semantic meaning. This method uses natural language processing (NLP) techniques to identify the most important concepts and ideas in the text and to divide it into chunks that capture these concepts and ideas.

> [!KEY-INSIGHT]
> Semantic chunking can produce high-quality embeddings and improve the retrieval performance of RAG systems by capturing the semantic meaning of the text.

> [!BEST-PRACTICE]
> Use semantic chunking when you need to produce high-quality embeddings and improve the retrieval performance of your RAG system, and when you are working with documents that have a rich and complex semantic structure.

> [!WARNING]
> Semantic chunking can be computationally expensive and may require significant resources to implement, especially for large documents or datasets.

## Code Demonstration & Runtime Output

In this section, we will demonstrate the implementation of the three chunking strategies using Python. We will use the `langchain` library, which provides a convenient and efficient way to implement and compare different chunking strategies.

```python
from langchain.text_splitter import RecursiveCharacterTextSplitter, CharacterTextSplitter
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import FAISS
from typing import List, Dict, Any

def fixed_size_chunking(text: str, chunk_size: int = 1000, chunk_overlap: int = 200) -> List[str]:
    """
    Divide the input text into chunks of a fixed size.

    Args:
        text: The input text to be chunked.
        chunk_size: The size of each chunk.
        chunk_overlap: The number of characters to overlap between chunks.

    Returns:
        A list of chunks.
    """
    text_splitter = CharacterTextSplitter(
        separator="\n",
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        length_function=len,
    )
    chunks = text_splitter.split_text(text)
    return chunks

def recursive_character_chunking(text: str, chunk_size: int = 1000, chunk_overlap: int = 200) -> List[str]:
    """
    Divide the input text into chunks based on the presence of specific characters or patterns.

    Args:
        text: The input text to be chunked.
        chunk_size: The size of each chunk.
        chunk_overlap: The number of characters to overlap between chunks.

    Returns:
        A list of chunks.
    """
    text_splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        length_function=len,
    )
    chunks = text_splitter.split_text(text)
    return chunks

def semantic_chunking(text: str, embeddings: OpenAIEmbeddings, chunk_size: int = 1000, chunk_overlap: int = 200) -> List[str]:
    """
    Divide the input text into chunks based on their semantic meaning.

    Args:
        text: The input text to be chunked.
        embeddings: The embeddings to use for semantic chunking.
        chunk_size: The size of each chunk.
        chunk_overlap: The number of characters to overlap between chunks.

    Returns:
        A list of chunks.
    """
    text_splitter = RecursiveCharacterTextSplitter(
        chunk_size=chunk_size,
        chunk_overlap=chunk_overlap,
        length_function=len,
    )
    chunks = text_splitter.split_text(text)
    vectorstore = FAISS.from_texts(chunks, embeddings)
    query = "What is the main topic of this text?"
    docs = vectorstore.similarity_search(query)
    semantic_chunks = [doc.page_content for doc in docs]
    return semantic_chunks

if __name__ == "__main__":
    text = """

RAG systems typically consist of two main components: a retriever and a generator. The retriever is responsible for retrieving relevant information from a large corpus of documents, while the generator is responsible for generating the final output based on the retrieved information.

    One of the key challenges in RAG systems is the effective chunking of the input documents. Chunking involves breaking down large documents into smaller, manageable pieces called chunks. These chunks are then used to create embeddings, which are numerical representations of the text that can be used for semantic search and retrieval. Effective chunking strategies are crucial for the performance of RAG systems, as they directly impact the quality of the embeddings and the relevance of the retrieved information.

    In this lesson, we will explore three common chunking strategies: Fixed-Size Chunking, Recursive Character Chunking, and Semantic Chunking. Each strategy has its own advantages and is suitable for different types of documents and use cases.
    """

    # Fixed-size chunking
    fixed_size_chunks = fixed_size_chunking(text)
    print("Fixed-size chunks:")
    for i, chunk in enumerate(fixed_size_chunks):
        print(f"Chunk {i+1}: {chunk[:100]}...")

    # Recursive character chunking
    recursive_character_chunks = recursive_character_chunking(text)
    print("\nRecursive character chunks:")
    for i, chunk in enumerate(recursive_character_chunks):
        print(f"Chunk {i+1}: {chunk[:100]}...")

    # Semantic chunking
    embeddings = OpenAIEmbeddings()
    semantic_chunks = semantic_chunking(text, embeddings)
    print("\nSemantic chunks:")
    for i, chunk in enumerate(semantic_chunks):
        print(f"Chunk {i+1}: {chunk[:100]}...")
```
