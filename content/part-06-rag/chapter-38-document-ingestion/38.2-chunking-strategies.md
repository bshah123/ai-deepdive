Retrieval-augmented generation (RAG) answers a question by fetching passages from a corpus and giving them to a language model. Before anything can be fetched, each document must be cut into chunks. In this lesson you will cut one document three ways, measure what each cut destroys, and see why "semantic" chunking is only as good as the similarity signal under it.

**You need:** a document as plain text (Lesson 38.1), and the idea that a text can be turned into a vector, an embedding (Lesson 24.1).

## The problem chunking solves

A retriever scores passages against a question and passes the best ones to the model (Lewis et al., 2020). A chunk has to satisfy two limits at once. It must be small, so the retrieved text is focused and fits the context window. It must also be large enough that each answer sentence sits inside one chunk. A cut through the answer sentence can hide it from the retriever, because neither half matches the question well.

The sizes in this lesson count characters. Models count tokens, so a real system converts its limits into tokens.

## Three strategies

![Three overlapping fixed-size windows over the first 520 characters, with cuts at 200, 360 and 520](diagrams/38.2-fixed-cuts.svg "Fixed-size windows ignore the text. Size 200, overlap 40.")

**Fixed-size windows** cut every `size` characters, stepping forward by `size - overlap`, so each chunk shares `overlap` characters with the next. The cut positions ignore the text completely.

![Four separator levels: paragraphs, lines, words, characters, with recursion only into pieces that are still too long](diagrams/38.2-separator-ladder.svg "Recursive splitting, as LangChain's RecursiveCharacterTextSplitter does it.")

**Recursive character splitting** tries separators from coarse to fine. A piece that fits is kept. A piece that does not fit is split on the next separator, and small pieces are packed back together up to the size. The default list in LangChain's `RecursiveCharacterTextSplitter` is `["\n\n", "\n", " ", ""]` (LangChain source, `character.py`). No entry in that list is a sentence end.

**Semantic chunking** splits the text into sentences, embeds a window of neighbouring sentences around each one, and starts a new chunk where the distance between neighbouring windows is unusually large. The window-and-distance design follows a public notebook on levels of text splitting, which uses cosine distance between neighbouring window embeddings (FullStackRetrieval-com, Level 4). "Unusually large" is a choice you make. Here it means above the 90th percentile of the gaps.

## Worked example by hand

The document has 1,868 characters. With size 200 and overlap 40, the step is 200 - 40 = 160, so chunks start at characters 0, 160, 320, and so on up to 1,760. That makes 12 chunks, since $\lceil (1868 - 200) / 160 \rceil + 1 = 12$.

Chunk 1 covers characters 0 to 199 and ends with "pair of adjacent symbols". The full stop at character 200 falls into chunk 2, which starts at character 160 with "e most frequent". So chunk 2 opens in the middle of a word, and chunk 1 stops one character before the full stop of its last sentence.

Overlap costs storage. The 11 overlaps add 11 × 40 = 440 characters. The 12 chunks hold 11 × 200 + 108 = 2,308 characters, which is 2,308 / 1,868 ≈ 1.24 times the original text.

## Code and measured results

The script below implements all three strategies in NumPy and Python, and then measures them on the same document. Nothing here calls a model. The semantic part uses TF-IDF (term frequency weighted by inverse document frequency) vectors in place of a neural embedding; the reason is covered below.

```python
import re
import numpy as np

CORPUS = """A tokenizer splits raw text into the units that a language model actually reads. Byte-pair encoding (BPE) starts from single characters and repeatedly merges the most frequent pair of adjacent symbols. After enough merges, common words become single tokens while rare words are split into several pieces.

Each token is then mapped to an integer ID, so the model never sees the original characters. The same vocabulary must be used at training time and at inference time, or the IDs will not match. Tokenization also sets how many tokens a prompt costs, since billing and context limits count tokens rather than words.

A vector index stores one embedding for every chunk in the corpus. At query time, the question is embedded with the same model and compared with each stored vector by cosine similarity. Exhaustive search compares against every vector, which is exact but slow for large corpora.

Approximate nearest-neighbour structures such as HNSW (hierarchical navigable small world graphs) trade a little recall for a large speed-up. Index memory grows linearly with the number of chunks and with the embedding dimension. Metadata such as the source file and page number is usually stored beside each vector so that results can be traced back.

A retrieval evaluation needs a set of questions whose correct source passages are known in advance. Recall at k asks whether the correct passage appears anywhere among the top k retrieved chunks. If the answer sentence is split across two chunks, recall at k can fall even when the retriever ranks the topic correctly.

Answer quality needs a separate judge, which may be a human annotator or a second language model. Report results on a held-out question set, otherwise the chunk size may be tuned to the test questions. Keep the number of questions large enough that one lucky query does not change the conclusion."""

# The nine "evidence" sentences: each one carries an answer that a reader would need intact.
EVIDENCE = {
    "Byte-pair encoding (BPE) starts from single characters and repeatedly merges the most frequent pair of adjacent symbols.",
    "After enough merges, common words become single tokens while rare words are split into several pieces.",
    "At query time, the question is embedded with the same model and compared with each stored vector by cosine similarity.",
    "Approximate nearest-neighbour structures such as HNSW (hierarchical navigable small world graphs) trade a little recall for a large speed-up.",
    "Metadata such as the source file and page number is usually stored beside each vector so that results can be traced back.",
    "Recall at k asks whether the correct passage appears anywhere among the top k retrieved chunks.",
    "If the answer sentence is split across two chunks, recall at k can fall even when the retriever ranks the topic correctly.",
    "Answer quality needs a separate judge, which may be a human annotator or a second language model.",
    "Report results on a held-out question set, otherwise the chunk size may be tuned to the test questions.",
}

# Separator ladder used by LangChain's RecursiveCharacterTextSplitter (paragraph, line, word, character).
SEPARATORS = ["\n\n", "\n", " ", ""]
SENT = re.compile(r"(?<=[.?!])\s+")


def sentence_spans(text):
    spans, pos = [], 0
    for s in SENT.split(text):
        a = text.find(s, pos)
        spans.append((a, a + len(s)))
        pos = a + len(s)
    return spans


def fixed_chunks(text, size, overlap):
    """Naive sliding window: cut every `size` characters, stepping by size - overlap."""
    spans = []
    for start in range(0, len(text), size - overlap):
        end = min(start + size, len(text))
        spans.append((start, end, text[start:end]))
        if end == len(text):
            break
    return spans


def merge(pieces, sep, size, overlap):
    """Pack consecutive pieces into chunks of at most `size`, keeping about `overlap` chars of tail."""
    docs, cur, total = [], [], 0
    for p in pieces:
        if cur and total + len(sep) + len(p) > size:
            docs.append(sep.join(cur))
            while cur and (total > overlap or total + len(sep) + len(p) > size):
                total -= len(cur[0]) + (len(sep) if len(cur) > 1 else 0)
                cur.pop(0)
        total += (len(sep) if cur else 0) + len(p)
        cur.append(p)
    if cur:
        docs.append(sep.join(cur))
    return docs


def recursive_chunks(text, size, overlap, seps=SEPARATORS):
    """Split on the coarsest separator that occurs; recurse on any piece still too large."""
    if len(text) <= size:
        return [text]
    for i, sep in enumerate(seps):
        if sep == "" or sep in text:
            rest = seps[i + 1:]
            break
    pieces = list(text) if sep == "" else text.split(sep)
    chunks, small = [], []
    for piece in pieces:
        if len(piece) <= size:
            small.append(piece)
        else:
            chunks += merge(small, sep, size, overlap)
            small = []
            chunks += recursive_chunks(piece, size, overlap, rest)
    chunks += merge(small, sep, size, overlap)
    return chunks


def locate(chunks, text):
    out, pos = [], 0
    for c in chunks:
        s = text.find(c, pos)
        assert s >= 0, "chunk is not a substring of the text"
        out.append((s, s + len(c), c))
        pos = s + 1
    return out


def audit(spans, text, sents, evidence):
    starts = {0} | {a for a, _ in sents}
    ends = {b for _, b in sents}
    mid_word = sum(
        1 for s, e, _ in spans
        if (s > 0 and text[s - 1].isalnum() and text[s].isalnum())
        or (e < len(text) and text[e - 1].isalnum() and text[e].isalnum()))
    cut_sent = sum(1 for s, e, _ in spans if s not in starts or e not in ends)
    kept = sum(1 for a, b in evidence if any(s <= a and b <= e for s, e, _ in spans))
    lens = [e - s for s, e, _ in spans]
    return dict(chunks=len(spans), mean_len=round(float(np.mean(lens)), 1),
                amplification=round(sum(lens) / len(text), 2),
                mid_word_chunks=mid_word, sentence_cut_chunks=cut_sent,
                evidence_kept=f"{kept}/{len(evidence)}")


def tfidf(docs):
    toks = [re.findall(r"[a-z0-9]+", d.lower()) for d in docs]
    vocab = sorted({t for ts in toks for t in ts})
    idx = {t: i for i, t in enumerate(vocab)}
    tf = np.zeros((len(docs), len(vocab)))
    for r, ts in enumerate(toks):
        for t in ts:
            tf[r, idx[t]] += 1
    df = (tf > 0).sum(axis=0)
    X = tf * (np.log((1 + len(docs)) / (1 + df)) + 1)
    return X / np.linalg.norm(X, axis=1, keepdims=True)


def semantic_breaks(sentences, buffer, pct):
    """Embed a window of +-buffer sentences around each sentence; break where the cosine distance to the next window is in the top (100 - pct) percent."""
    windows = [" ".join(sentences[max(0, i - buffer): i + buffer + 1]) for i in range(len(sentences))]
    X = tfidf(windows)
    dist = 1 - np.sum(X[:-1] * X[1:], axis=1)
    thr = np.percentile(dist, pct)
    return dist, [i for i, d in enumerate(dist) if d > thr]


def main():
    text = CORPUS
    sents = sentence_spans(text)
    sentences = [text[a:b] for a, b in sents]
    evidence = [(a, b) for a, b in sents if text[a:b] in EVIDENCE]
    assert len(evidence) == len(EVIDENCE) == 9
    print(f"characters={len(text)} sentences={len(sents)}")
    for size in (120, 200, 300):
        overlap = size // 5
        print(f"--- size={size} overlap={overlap}")
        print("fixed    ", audit(fixed_chunks(text, size, overlap), text, sents, evidence))
        print("recursive", audit(locate(recursive_chunks(text, size, overlap), text), text, sents, evidence))
    print("--- first three fixed-size chunks (size 200, overlap 40):")
    for s, e, c in fixed_chunks(text, 200, 40)[:3]:
        print(f"[{s}, {e})  ...{c[-30:]!r}")
    truth = {5, 11}   # sentence indices after which the topic changes
    for buf in (0, 1):
        dist, pred = semantic_breaks(sentences, buf, 90)
        order = sorted(range(len(dist)), key=lambda i: -dist[i])
        print(f"--- semantic buffer={buf}, breakpoint = 90th percentile of distances")
        print("distances:", [round(float(d), 3) for d in dist])
        print("rank of true boundaries (1 = largest gap):", {t: order.index(t) + 1 for t in sorted(truth)})
        print("predicted breaks after sentence:", pred, "true:", sorted(truth))


if __name__ == "__main__":
    main()
```

Read the output this way. Fixed windows cut inside a word in 17 of 20 chunks at size 120 and in 8 of 8 at size 300. Recursive splitting cut no word at any size, because a space is tried before the character separator. It still ended a sentence in the middle in 18 of 20 chunks at size 120, because a space is a word boundary and not a sentence boundary. At size 400 it happened to cut no sentence.

The sweep is the more useful measurement. Nine "evidence" sentences were marked in advance, each one a sentence a reader would need whole. The chart counts how many survive intact in at least one chunk.

![Bar chart: evidence sentences kept whole, out of 9, for fixed and recursive chunking at sizes 120 to 400](diagrams/38.2-survival-sweep.svg "Counts from one document with nine evidence sentences. Fixed windows: 2, 3, 6, 7, 5, 9. Recursive: 4, 2, 7, 9, 6, 9.")

Three evidence sentences are longer than 120 characters, so no chunk of size 120 can hold them whole. Beyond that, survival is not monotone in size. Fixed windows fall from 7 kept at size 240 to 5 at size 300, because each size moves every cut. A sentence survives only when no cut falls inside it, and the cut positions change with the size.

These are nine sentences from one document. A difference of one or two sentences is noise, not evidence that one strategy wins. The lesson is the mechanism: survival depends on where the cuts land, and no single size guarantees it.

## Semantic chunking, measured with a stand-in

This environment has no embedding model weights, so the windows were embedded with TF-IDF. TF-IDF measures shared words, weighted by how rare each word is across the windows. It is a lexical signal, not a meaning signal, so these results test the breakpoint mechanism only. They say nothing about neural embeddings.

The corpus has three topics of six sentences each. The true topic changes fall after sentences 5 and 11 (counting from 0). With one sentence of context on each side and a 90th-percentile threshold, the rule predicts breaks after sentences 2 and 6. Precision and recall are both 0. With single-sentence windows it predicts 2 and 9, which also misses. The two true changes rank 9th and 11th of the 17 gaps.

![Bar chart of the cosine distance between neighbouring windows; the two true topic changes are not among the largest gaps](diagrams/38.2-semantic-gaps.svg "Lexical distances on this text. The dashed line is the 90th percentile.")

The cause is that neighbouring sentences on one topic can share few words, while sentences on different topics can share generic words. A breakpoint rule is only as good as the similarity under it. A different route is late chunking (Günther et al., 2024): embed the whole document with a long-context model first and split afterwards, so each chunk vector carries context from its neighbours. The authors report better retrieval performance without extra training. Whether a neural semantic chunker beats fixed windows on this text is a question for real embeddings, which this lesson did not test.

## Common traps

> [!TRAP]
> **Overlap is not a guarantee.** It copies text: 11 overlaps add 440 characters here. At size 200 with overlap 40, fixed windows kept 6 of 9 evidence sentences whole. The other 3 were cut.

> [!TRAP]
> **The default separators know nothing about sentences.** Recursive splitting avoids mid-word cuts. It does not avoid mid-sentence cuts.

> [!TRAP]
> **Characters are not tokens.** A 200-character chunk is not a 200-token chunk. Set the size in the unit your embedding model counts.

> [!TRAP]
> **One document, nine sentences.** Do not choose a chunk size from this table. Measure answer survival on your own corpus with real questions.

> [!TRAP]
> **A breakpoint rule always returns breaks.** It fails silently. Check its breaks against known topic changes before you trust a semantic chunker.

## Summary

- Fixed-size windows ignore structure and split words in most chunks: 17 of 20 at size 120 here.
- Recursive splitting never splits a word, but its default separators do not include sentence ends, so sentences still get cut.
- Overlap is a storage cost, here 1.24 times the original text at size 200, and it does not guarantee that answers survive.
- Semantic chunking is only as good as the similarity between neighbouring windows. A lexical stand-in misses both topic changes in this text.
- Measure answer survival on your own documents before you choose a size.

### Question 2: Find the bug

```python
chunks = fixed_chunks(text, size=200, overlap=200)
```

What happens, and why?

<details><summary>Show solution</summary>

It raises `ValueError: range() arg 3 must not be zero`. The step is size - overlap = 0, and `range` cannot step by zero. The overlap must be smaller than the size. Check that before calling the function.

</details>

### Question 3: Explain the result

Recursive splitting produced no mid-word cuts at any size, while fixed windows produced many. Why?

<details><summary>Show solution</summary>

Recursive splitting tries the paragraph, line and space separators before the empty character separator. It splits on spaces, so a word is cut only when a single word is longer than the size. Fixed windows cut every `size` characters whatever the text contains, so most cut positions land inside a word.

</details>

### Question 4: Interpret the breakpoints

The rule that picks the largest 10 percent of gaps misses both true topic changes, although the rule is sound. What is the likely cause, and what would you check before blaming the threshold?

<details><summary>Show solution</summary>

The cause is the similarity signal. The gaps are cosine distances between TF-IDF vectors, which count shared words. Sentences on one topic can share few words, and sentences on different topics can share generic words, so the true changes rank 9th and 11th of 17 gaps rather than at the top. Before blaming the threshold, check the ranks: a threshold cannot fix a signal in which the true changes are not the largest gaps. Replacing TF-IDF with a neural embedding is the test that this run did not perform.

</details>
