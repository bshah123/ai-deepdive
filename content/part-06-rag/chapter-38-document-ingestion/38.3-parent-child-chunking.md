In this lesson you will attach metadata to every chunk, index small child chunks while returning their larger parent to the language model, and measure the trade-off on a controlled corpus. You need the chunking basics from Lesson 38.2 and the retrieve-then-generate loop from Lesson 37.2.

**You need:** cosine similarity (the dot product of two vectors divided by the product of their lengths) and NumPy arrays.

## The problem: retrieval wants small pieces, answers want big ones

A retriever ranks chunks by how well each one matches the query. A chunk that covers one fact matches a question about that fact cleanly. A chunk that covers a whole section mixes many topics, so its vector is diluted and it can lose to a rival that is less relevant but more focused.

The language model, however, needs enough surrounding text to answer. A single sentence often lacks the definition, the unit or the exception that makes it correct. So the chunk size that is best for matching is often too small for answering.

Parent-child retrieval separates the two jobs. You index small **children** for matching, and each child stores the id of its larger **parent**. A search hit on a child returns the parent to the model.

## Intuition: one section, two granularities

![One parent section is split into four child chunks, each carrying a parent_id; the children are the only items in the vector index](diagrams/38.3-hierarchy.svg "The index holds children. The model receives parents.")

Each child carries a small metadata record, so you can filter, cite and deduplicate later. The fields that matter in practice are the document id, the heading path, the page, the word offsets and the `parent_id`. The record below is printed at the end of the experiment in the next section, for the first child of the first section.

```output
child record: {'chunk_id': 0, 'parent_id': 0, 'section_title': '1. pump maintenance', 'start': 0, 'end': 38, 'n_words': 38, 'text': 'pressure this each unit a and the during limit voltage pump ...'}
```

## Worked example by hand: rank children, then count parents

Take a query $q = [3, 4]$ and three children. Children $c_1$ and $c_2$ belong to parent $P_1$, and $c_3$ belongs to parent $P_2$.

- $c_1 = [3, 4]$: $q \cdot c_1 = 9 + 16 = 25$, and $\|q\|\,\|c_1\| = 5 \times 5 = 25$, so the cosine is $1.00$.
- $c_2 = [4, 3]$: $q \cdot c_2 = 12 + 12 = 24$, and $\|c_2\| = 5$, so the cosine is $24 / 25 = 0.96$.
- $c_3 = [0, 1]$: $q \cdot c_3 = 4$, and $\|c_3\| = 1$, so the cosine is $4 / 5 = 0.80$.

![Three children ranked by cosine: c1 1.00 and c2 0.96 both point to parent P1, and c3 0.80 points to P2; two children give one distinct parent, three give two](diagrams/38.3-cosine-walk.svg "Count distinct parents, not children.")

If you return the top $k = 2$ children, both point to $P_1$, so the model receives one parent. To receive two parents you must keep walking down the ranked list until you have two distinct parents. The code below reproduces these three numbers.

```python
import numpy as np

q = np.array([3.0, 4.0])
children = {"c1": (np.array([3.0, 4.0]), "P1"),
            "c2": (np.array([4.0, 3.0]), "P1"),
            "c3": (np.array([0.0, 1.0]), "P2")}
for name, (v, parent) in children.items():
    cos = q @ v / (np.linalg.norm(q) * np.linalg.norm(v))
    print(name, "parent", parent, "cos", round(float(cos), 2))
```

```output
c1 parent P1 cos 1.0
c2 parent P1 cos 0.96
c3 parent P2 cos 0.8
```

## Experiment: how much recall does each word of context buy?

The toy above is too small to say anything about retrieval quality. The experiment below builds a synthetic document and compares four chunkers, all on the same retrieval code.

The corpus has 12 sections, each with 4 paragraphs of 3 sentences, about 152 words per section. Each paragraph contains one fact sentence, so there are 48 facts per corpus. A query is the section's topic word plus two content words from the fact. We repeat the whole experiment on 5 random corpora.

Two design choices matter. First, the **embedding is a TF-IDF stand-in** (term counts weighted by inverse document frequency, then L2-normalised), not a learned embedding model, so the absolute numbers are not those of a real system. Second, **the topic word is shared by six sections**. An earlier draft gave every section a unique topic word, and parent recall was then 1.000 for a trivial reason: the topic identified the section. A result that perfect is a bug hypothesis, and the fix was to make the sections compete.

The code runs in the browser as it is, using only the standard library and NumPy.

```python
import math
from collections import Counter
import numpy as np

FILLER = "the a of and is set after during check report under when each unit then must be for with on at by from this that all new local".split()
CONTENT = "pressure voltage load temperature reading threshold cycle alarm limit sensor baseline reset interval supply phase current frequency".split()
POOL = FILLER + CONTENT
TOPICS = ["pump", "valve"]  # two topics shared by 12 sections, so the topic alone cannot find a section

def make_corpus(seed, n_sec=12, n_par=4, n_sent=3):
    rng = np.random.default_rng(seed)
    words, sents, secs, facts = [], [], [], []
    for s in range(n_sec):
        topic = TOPICS[s % 2]
        sec_start = len(words)
        for p in range(n_par):
            for k in range(n_sent):
                st = len(words)
                body = [POOL[i] for i in rng.integers(0, len(POOL), size=int(rng.integers(10, 15)))]
                body.insert(int(rng.integers(0, len(body))), topic)
                if k == 1:  # one fact sentence per paragraph (the gold answer for one query)
                    body = [topic, "unit", f"ref{s:02d}{p}", "reading"] + body[:8]
                    facts.append({"topic": topic, "span": (st, st + len(body)), "code": f"ref{s:02d}{p}"})
                words += body
                sents.append((st, len(words)))
        secs.append((sec_start, len(words), s))
    return words, sents, secs, facts

def pack(sents, max_words, bounds):
    """Greedy sentence packing: never split a sentence, never cross a section edge."""
    out = []
    for lo, hi, sid in bounds:
        cur = None
        for a, b in [sp for sp in sents if lo <= sp[0] and sp[1] <= hi]:
            if cur and b - cur[0] <= max_words:
                cur = (cur[0], b, sid)
            else:
                if cur: out.append(cur)
                cur = (a, b, sid)
        if cur: out.append(cur)
    return out

def build_index(units, words):
    """TF-IDF stand-in for a learned embedder: count * idf, L2-normalised."""
    texts = [words[a:b] for a, b, _ in units]
    vocab = sorted({t for tx in texts for t in tx})
    idx = {t: i for i, t in enumerate(vocab)}
    df = Counter(t for tx in texts for t in set(tx))
    idf = np.array([math.log((len(texts) + 1) / (df[t] + 1)) + 1 for t in vocab])
    M = np.zeros((len(texts), len(vocab)))
    for r, tx in enumerate(texts):
        for t, c in Counter(tx).items():
            M[r, idx[t]] = c
    M = M * idf
    M /= np.linalg.norm(M, axis=1, keepdims=True)
    def embed_query(qwords):
        v = np.zeros(len(vocab))
        for t, c in Counter(qwords).items():
            if t in idx: v[idx[t]] = c * idf[idx[t]]
        return v / np.linalg.norm(v)
    return M, embed_query

def evaluate(seed, kind):
    words, sents, secs, facts = make_corpus(seed)
    if kind.startswith("fixed"):
        size = int(kind.split()[1])
        units = [(i, min(i + size, len(words)), None) for i in range(0, len(words), size)]
    else:
        units = pack(sents, 48, secs)  # sentence-packed children, <= 48 words
    parents = {sid: (lo, hi) for lo, hi, sid in secs}
    M, embed_query = build_index(units, words)
    out = {"n_units": len(units), "inside": [], "R1": [], "R3": [], "ctx1": [], "ctx3": []}
    for f in facts:
        gs, ge = f["span"]
        out["inside"].append(any(a <= gs and ge <= b for a, b, _ in units))
        order = np.argsort(-(M @ embed_query([f["topic"]] + [w for w in words[gs:ge] if w in CONTENT][:2])))
        for k in (1, 3):
            if kind == "parent":
                seen = []
                for i in order:  # walk the ranked children, keep the first k distinct parents
                    if units[i][2] not in seen: seen.append(units[i][2])
                    if len(seen) == k: break
                ok = any(parents[p][0] <= gs and ge <= parents[p][1] for p in seen)
                ctx = sum(parents[p][1] - parents[p][0] for p in seen)
            else:
                top = order[:k]
                ok = any(units[i][0] <= gs and ge <= units[i][1] for i in top)
                ctx = sum(units[i][1] - units[i][0] for i in top)
            out[f"R{k}"].append(ok); out[f"ctx{k}"].append(ctx)
    return {k: float(np.mean(v)) for k, v in out.items() if k != "n_units"} | {"n_units": out["n_units"]}

CONFIGS = ["fixed 32", "fixed 128", "child", "parent"]
print("5 corpora x 48 queries each; 12 sections x 4 paragraphs x 3 sentences")
for kind in CONFIGS:
    rs = [evaluate(seed, kind) for seed in range(5)]
    m = {k: np.mean([r[k] for r in rs]) for k in rs[0]}
    s = {k: np.std([r[k] for r in rs]) for k in ("R1", "R3")}
    print(f"{kind:10s} units={m['n_units']:5.1f}  gold-inside={m['inside']:.3f}  "
          f"R@1={m['R1']:.3f}±{s['R1']:.3f}  R@3={m['R3']:.3f}±{s['R3']:.3f}  "
          f"words@1={m['ctx1']:6.1f}  words@3={m['ctx3']:6.1f}")

words, sents, secs, facts = make_corpus(0)
a, b, sid = pack(sents, 48, secs)[0]
record = {"chunk_id": 0, "parent_id": sid, "section_title": f"{sid + 1}. {TOPICS[sid % 2]} maintenance",
          "start": a, "end": b, "n_words": b - a, "text": " ".join(words[a:b])[:60] + "..."}
print("child record:", record)
```

```output

fixed 32   units= 57.2  gold-inside=0.662  R@1=0.113±0.034  R@3=0.271±0.042  words@1=  32.0  words@3=  95.7
fixed 128  units= 15.0  gold-inside=0.912  R@1=0.225±0.050  R@3=0.442±0.044  words@1= 128.0  words@3= 373.6
child      units= 47.6  gold-inside=1.000  R@1=0.163±0.040  R@3=0.375±0.035  words@1=  39.2  words@3= 118.0
parent     units= 47.6  gold-inside=1.000  R@1=0.287±0.076  R@3=0.733±0.040  words@1= 151.8  words@3= 455.2
child record: {'chunk_id': 0, 'parent_id': 0, 'section_title': '1. pump maintenance', 'start': 0, 'end': 38, 'n_words': 38, 'text': 'pressure this each unit a and the during limit voltage pump ...'}
```

Read the table column by column. `gold-inside` is the fraction of facts that some single chunk contains whole. Fixed 32-word windows leave 33.8% of facts without a chunk that holds them whole, and fixed 128-word windows leave 8.8%. Sentence-packed children never split a sentence, so every fact sits inside one child.

![A fixed 32-word window ends in the middle of a 12-word fact, so neither window contains the whole fact](diagrams/38.3-boundary-cut.svg "Boundaries decide whether a fact survives. The fact is drawn to scale; the rates are measured.")

The parent configuration returns the whole section. Its recall at 3 is 0.733, against 0.442 for fixed 128-word windows. But it returns about 455 words against 374, so the comparison is not at equal cost. Plotting recall against words returned shows what is being bought.

![Recall at 3 against words returned for top-3, for four configurations; the parent configuration sits highest and furthest right](diagrams/38.3-tradeoff.svg "Means over 5 corpora, 48 queries each. Standard deviation of recall at 3 is at most 0.044.")

The gain comes from two sources, and this experiment does not separate them. Sentence-packed children alone, with no parent, reach 0.375 recall at 3 on 118 words, which is below fixed 128-word windows at 0.442 on 374 words. The parent's advantage therefore comes mostly from returning the surrounding section, which is also the most words. A real corpus with a learned embedder and real questions could show a different balance.

> [!TRAP]
> A parent that is too large dilutes the context. The answer may be present but buried among unrelated paragraphs. Liu et al. (2023) report that accuracy drops when the relevant information sits in the middle of a long input, so measure where the answer sits, not only whether it is present.

> [!TRAP]
> A child that is too small has the opposite failure: the fact is in the index, but the model gets a fragment without its definition. Check whether each fact sits inside one chunk before you tune the retriever.

> [!TRAP]
> Two children of one parent should count once. Without deduplication, `k = 3` children can return one parent three times and waste the context budget. The walk in the worked example is the deduplication.

> [!TRAP]
> A metadata filter applied after retrieval can leave fewer than `k` results, because the top-ranked items may fail the filter. Apply hard filters such as date or document id before ranking, and store every field you filter on.

> [!NOTE]
> Parent-child is one pattern among several. Its value depends on whether the model can use the extra text. It is not a free improvement.

## Summary

- Index small children for matching and return their larger parent for answering; each child stores `parent_id`.
- Count distinct parents while walking the ranked children, not the number of children returned.
- Chunk boundaries decide whether a fact survives. Sentence-packed children never split a sentence; fixed 32-word windows left 33.8% of facts without a whole-fact chunk here.
- Recall rises with the words returned, and the parent configuration buys its recall with the most words. Compare configurations at equal context cost.
- Every number here comes from a synthetic corpus with a TF-IDF stand-in for the embedder. They show the mechanism, not a benchmark.

## Quiz time

### Question 1: Calculation

A query is $q = [1, 2]$. Child $a = [1, 2]$ and child $b = [2, 1]$ belong to parent $X$. Child $c = [0, 1]$ belongs to parent $Y$. Which parents does the retriever return for $k = 2$ distinct parents, and what is the cosine of $b$?

<details><summary>Solution</summary>

The cosines are $a$: $1.00$; $b$: $(2 + 2) / (\sqrt{5} \cdot \sqrt{5}) = 4 / 5 = 0.80$; $c$: $2 / (\sqrt{5} \cdot 1) \approx 0.894$. The ranking is $a$, $c$, $b$. Walking down it, $a$ gives $X$ and $c$ gives $Y$, so the two distinct parents are $X$ and $Y$. The cosine of $b$ is $0.80$.

</details>

### Question 2: Prediction

In the experiment, what would the gold-inside rate for fixed 32-word windows be if every fact were 40 words long instead of 12?

<details><summary>Solution</summary>

Zero. No 32-word window can hold a 40-word fact whole, so no fact can be contained in one. This follows from the definition of a window, so it is reasoning rather than a measurement.

</details>

### Question 3: Bug-spotting

A colleague reports a parent recall at 3 of 1.000 on a new corpus, with the same code. What is the most likely explanation, and what would you change?

<details><summary>Solution</summary>

The corpus probably gives each section a unique topic word, so the query identifies the section by itself and the parent hit tests nothing beyond the topic. Share the topic word across several sections, as in the experiment, and check that the top-3 distinct parents do not already cover every section that shares the topic.

</details>

### Question 4: Explanation

Why can a child-only index lose answer quality even when the child contains the fact?

<details><summary>Solution</summary>

The child holds the fact but not its context, such as the definition or the unit. The model then sees a fragment and may answer wrongly. Parent expansion supplies that context, at the cost of more words per answer.

</details>
