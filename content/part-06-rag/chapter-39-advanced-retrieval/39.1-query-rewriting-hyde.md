# 39.1 — Re-ranking Foundations & The Bi-Encoder vs Cross-Encoder Tradeoff

## Opening Motivation & Context

In the world of information retrieval and natural language processing, the ability to efficiently and accurately retrieve relevant documents is crucial. However, even with the best retrieval systems, the initial set of retrieved documents may contain many irrelevant or less relevant items. This is where re-ranking comes into play.

Re-ranking is the process of reordering the initially retrieved documents based on a more sophisticated and computationally intensive scoring mechanism. The goal is to improve the quality of the top-k retrieved documents, which are often the most important for downstream tasks.

Two primary approaches to re-ranking are bi-encoders and cross-encoders. Understanding the trade-offs between these two approaches is essential for designing effective retrieval-augmented generation (RAG) systems.

## Core Concepts Breakdown

### Bi-Encoders

Bi-encoders are a type of dual-encoder model that independently encodes the query and each document into dense vector representations. The relevance score is then computed as the similarity between these vectors, typically using cosine similarity.

> [!KEY-INSIGHT]
> Bi-encoders are computationally efficient because they encode queries and documents independently, allowing for batch processing and faster retrieval.

> [!BEST-PRACTICE]
> Use bi-encoders for initial retrieval when you need to process a large number of documents quickly.

### Cross-Encoders

Cross-encoders, on the other hand, encode the query and each document together, creating a joint representation. This joint representation is then passed through a neural network to compute the relevance score. Cross-encoders are generally more accurate but computationally more expensive.

> [!KEY-INSIGHT]
> Cross-encoders provide higher accuracy because they consider the interaction between the query and each document, capturing more nuanced relationships.

> [!WARNING]
> Cross-encoders are slower and more resource-intensive, making them less suitable for initial retrieval over large document collections.

## Code Demonstration & Runtime Output

Let's demonstrate the difference between bi-encoders and cross-encoders using a simple example with the `sentence-transformers` library.

```python
from sentence_transformers import SentenceTransformer, util
from typing import List, Tuple

def bi_encoder_retrieval(query: str, documents: List[str], top_k: int = 3) -> List[Tuple[str, float]]:
    """
    Perform retrieval using a bi-encoder model.

    Args:
        query: The query string.
        documents: List of document strings.
        top_k: Number of top documents to retrieve.

    Returns:
        List of tuples containing the document and its similarity score.
    """
    model = SentenceTransformer('all-MiniLM-L6-v2')

    # Encode the query and documents
    query_embedding = model.encode(query, convert_to_tensor=True)
    doc_embeddings = model.encode(documents, convert_to_tensor=True)

    # Compute cosine similarities
    similarities = util.pytorch_cos_sim(query_embedding, doc_embeddings)[0]

    # Get the top-k documents
    top_k_indices = similarities.topk(k=top_k).indices.tolist()
    top_k_docs = [(documents[i], similarities[i].item()) for i in top_k_indices]

    return top_k_docs

def cross_encoder_retrieval(query: str, documents: List[str], top_k: int = 3) -> List[Tuple[str, float]]:
    """
    Perform retrieval using a cross-encoder model.

    Args:
        query: The query string.
        documents: List of document strings.
        top_k: Number of top documents to retrieve.

    Returns:
        List of tuples containing the document and its relevance score.
    """
    model = SentenceTransformer('cross-encoder/ms-marco-MiniLM-L-6-v2')

    # Create query-document pairs
    pairs = [[query, doc] for doc in documents]

    # Compute relevance scores
    scores = model.predict(pairs)

    # Get the top-k documents
    top_k_indices = scores.argsort()[-top_k:][::-1]
    top_k_docs = [(documents[i], scores[i].item()) for i in top_k_indices]

    return top_k_docs

if __name__ == "__main__":
    query = "What is the capital of France?"
    documents = [
        "The capital of France is Paris.",
        "France is known for its cuisine and wine.",
        "The Eiffel Tower is located in Paris.",
        "Paris is the largest city in France.",
        "The capital of Germany is Berlin."
    ]

    print("Bi-Encoder Retrieval:")
    bi_results = bi_encoder_retrieval(query, documents)
    for doc, score in bi_results:
        print(f"Document: {doc}, Score: {score:.4f}")

    print("\nCross-Encoder Retrieval:")
    cross_results = cross_encoder_retrieval(query, documents)
    for doc, score in cross_results:
        print(f"Document: {doc}, Score: {score:.4f}")
```

> [!ADVANCED]
> The bi-encoder model uses a dual-encoder architecture, where the query and documents are encoded independently. This allows for efficient batch processing and faster retrieval. The cross-encoder model, on the other hand, uses a joint representation of the query and each document, capturing more nuanced relationships but at a higher computational cost.

## Summary & Key Takeaways

- Bi-encoders are computationally efficient and suitable for initial retrieval over large document collections.
- Cross-encoders provide higher accuracy by considering the interaction between the query and each document.
- The choice between bi-encoders and cross-encoders depends on the trade-off between computational efficiency and accuracy.
