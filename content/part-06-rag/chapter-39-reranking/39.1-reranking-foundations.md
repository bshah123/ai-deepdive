A search system must order thousands or millions of documents for every query. In this lesson you will see why production systems use two kinds of model for that job: a **bi-encoder**, which is cheap because it encodes queries and documents separately, and a **cross-encoder**, which is accurate because it reads them together. You will be able to say what each one can see, count what each one costs, and build a two-stage re-ranker.

**You need:** cosine similarity (Lesson 37.1) and the idea that a token is a vector (Lesson 24.1).

## The problem: ordering a large candidate set

In retrieval-augmented generation (RAG), a retriever returns candidate passages, and a **re-ranker** reorders them so the most relevant come first. Suppose the corpus has one million documents. A large, accurate model that scores every document costs one million model passes per query. A search system receives many queries per second, so that cost is far too high. The task is to score cheaply over the whole corpus and accurately over a short list.

## Two architectures

![A bi-encoder encodes the query and each document separately and compares two vectors with a dot product; a cross-encoder reads the query and document as one input and outputs one score](diagrams/39.1-two-architectures.svg "Encode apart, or read together. The score comes from different places.")

A **bi-encoder** runs an encoder (a transformer that maps text to a fixed-size vector) on the query, and separately on each document. The score is the dot product $q \cdot d$. The document vector $d$ does not depend on the query, so all document vectors can be computed once, stored in an index, and reused for every query.

A **cross-encoder** joins the query and the document into one input, separated by a special separator token (SEP), and runs one encoder pass over the pair. Its output is one relevance score. Every layer lets query tokens attend to document tokens, so the score can depend on how specific query words line up with specific document words. Reimers and Gurevych (2019) describe this setting in the Sentence-BERT paper: BERT (Bidirectional Encoder Representations from Transformers) takes both sentences through the network together. Nogueira and Cho (2019) apply a BERT re-implementation to query-based passage re-ranking.

The names are shorthand. Lin, Nogueira and Yates (2020) survey the same split as re-ranking transformers in multi-stage architectures and dense retrieval, which ranks directly from vectors. Their abstract does not define "bi-encoder" or "cross-encoder," so the mapping between the two vocabularies is my own reading.

> [!KEY-INSIGHT]
> The bi-encoder's only interaction with the query is one dot product between two fixed vectors. Everything it knows about a document must be packed into $d$ before the query arrives. The cross-encoder builds a different document representation for each query. This is reasoning from first principles, not a theorem: a high-dimensional vector can hold a lot, so the gap concerns what the architecture lets the model compare.

## Cost: where the time goes

Khattab and Zaharia (2020) state the same problem: earlier BERT rankers "must feed each query-document pair through a massive neural network to compute a single relevance score." Reimers and Gurevych (2019) quantify it. Finding the most similar pair among 10,000 sentences needs about 50 million inference computations with BERT. Sentence-BERT reduces the work to comparing precomputed embeddings. Their paper reports the time as well (about 65 hours down to about 5 seconds), but that depends on hardware, so the counts are the part to reuse.

The counts are simple. A cross-encoder scores every pair: $\binom{10{,}000}{2} = 49{,}995{,}000$. A bi-encoder encodes each sentence once: 10,000 encodings, then cheap comparisons.

For retrieval, take $N = 10^6$ documents and $k = 100$ candidates kept after stage 1. Assume (reasoning from first principles, not measured) that one pass costs about $2PT$ floating-point operations (FLOPs), where $P = 110$ million parameters and $T = 288$ tokens (a 256-token document plus a 32-token query). The approximation ignores the attention term. Per pass that is $6.3 \times 10^{10}$ FLOPs.

![Bar lengths on a log scale: cross-encoder on all documents 1,000,000 passes, two-stage with k = 100 at 100 passes, bi-encoder 1 query pass plus a million cheap dot products](diagrams/39.1-cost-per-query.svg "Model passes per query. The corpus size drives the first bar, and k drives the second.")

Scoring the corpus with a cross-encoder costs about $6.3 \times 10^{16}$ FLOPs per query. Re-ranking $k = 100$ candidates costs $6.3 \times 10^{12}$. The bi-encoder side costs one pass plus $10^6 \times 768 \approx 7.7 \times 10^8$ multiply-adds. Stage 1 makes the corpus size affordable, and stage 2 is paid only on the short list.

## Worked example: mean pooling cannot see word order

Real bi-encoders are transformers, and their outputs depend on order. For the hand calculation, use the simplest fixed-vector encoder: average the word vectors. Take three hand-picked 2-d vectors, $\text{dog} = [1, 0]$, $\text{man} = [0, 1]$, $\text{bites} = [1, 1]$.

- "dog bites man": mean $= [1+1+0,\ 0+1+1]/3 = [2/3,\ 2/3]$, which normalises to $[0.707,\ 0.707]$.
- "man bites dog": mean $= [0+1+1,\ 1+1+0]/3 = [2/3,\ 2/3]$. Identical.
- Query "dog bites": mean $= [1,\ 0.5]$, normalised to $[0.894,\ 0.447]$.
- Cosine with either document: $0.894 \times 0.707 + 0.447 \times 0.707 \approx 0.949$.

The cross-encoder stand-in below is a hand-written scorer that sees both texts. It adds 2 when the query bigram (two adjacent words) occurs in order, and adds 1 per query word present.

```python
import numpy as np

# Hand-picked 2-d word vectors (not learned).
vec = {"dog": np.array([1.0, 0.0]), "man": np.array([0.0, 1.0]), "bites": np.array([1.0, 1.0])}

def bi_encode(words):
    v = np.mean([vec[w] for w in words], axis=0)   # mean pooling: word order is lost
    return v / np.linalg.norm(v)

def interaction_score(query, doc):
    bigram = any(doc[i:i + 2] == query for i in range(len(doc) - 1))   # query bigram in order?
    return 2 * bigram + sum(w in doc for w in query)                   # bigram bonus + word overlap

query = ["dog", "bites"]
docs = {"dog bites man": ["dog", "bites", "man"], "man bites dog": ["man", "bites", "dog"]}

print("query vector  :", np.round(bi_encode(query), 3))
for name, words in docs.items():
    d = bi_encode(words)
    print(f"{name:15s} vector: {np.round(d, 3)}  cosine = {bi_encode(query) @ d:.3f}  interaction = {interaction_score(query, words)}")
```

```output
query vector  : [0.894 0.447]
dog bites man   vector: [0.707 0.707]  cosine = 0.949  interaction = 4
man bites dog   vector: [0.707 0.707]  cosine = 0.949  interaction = 2
```

![Two sentences with the same words both average to the vector 0.707, 0.707 and the same cosine; the interaction scorer gives 4 to the in-order match and 2 to the other](diagrams/39.1-order-blind.svg "Same words, same vector. Only a score that reads the pair separates them.")

A single fixed vector cannot separate the two sentences, because the average is the same. The score that reads the pair can.

## Experiment: how often does order decide the ranking?

For each of 200 random queries, build 47 candidates. One is relevant: the query's entity and attribute appear adjacent, in order. Three have the same two words reversed, three contain both words never adjacent, ten contain only the entity, ten contain only the attribute, and twenty contain neither. Every candidate with both words has the same bag of filler words. P@1 means precision at rank 1: the fraction of queries whose top result is the relevant document. Recall@20 is the fraction whose relevant document appears in the top 20. The code uses numpy only, so it runs in the browser.

```python
import numpy as np

# Toy bi-encoder vs interaction scorer. Token vectors are random stand-ins, not learned.
rng = np.random.default_rng(39)
DIM = 32
ENT = list(range(0, 10))      # entity tokens
ATT = list(range(10, 20))     # attribute tokens
FILL = list(range(20, 30))    # filler tokens
table = rng.normal(size=(30, DIM))
table /= np.linalg.norm(table, axis=1, keepdims=True)

def bi_encode(tokens):
    """Bi-encoder stand-in: mean-pool the token vectors, then L2-normalise. Order is ignored."""
    v = table[tokens].mean(axis=0)
    return v / np.linalg.norm(v)

def interaction_score(query, doc):
    """Cross-encoder stand-in: sees query and document together. +2 if the query bigram occurs in order."""
    bigram = any(doc[i] == query[0] and doc[i + 1] == query[1] for i in range(len(doc) - 1))
    overlap = sum(t in doc for t in query)
    return 2 * bigram + overlap

def make_query_and_candidates():
    e, a = rng.choice(ENT), rng.choice(ATT)
    query = [int(e), int(a)]
    fill = list(rng.permutation(FILL).astype(int))           # same filler bag in every document
    def place(tokens):                                      # insert tokens at random positions among fillers
        seq = list(fill)
        for t in tokens:
            seq.insert(int(rng.integers(0, len(seq) + 1)), t)
        return seq
    def bigram_doc(first, second):                          # e and a adjacent, in the given order
        seq = list(fill)
        pos = int(rng.integers(0, len(seq) + 1))
        return seq[:pos] + [first, second] + seq[pos:]
    def split_doc():                                        # e and a both present, at least one token apart
        L = len(fill) + 2
        p = int(rng.integers(0, L - 2))
        q = int(rng.integers(p + 2, L))
        out, it = [], iter(fill)
        for k in range(L):
            out.append(int(e) if k == p else int(a) if k == q else next(it))
        return out
    cands = {"positive": bigram_doc(e, a)}
    cands.update({f"swap{k}": bigram_doc(a, e) for k in range(3)})
    cands.update({f"split{k}": split_doc() for k in range(3)})
    cands.update({f"e_only{k}": place([e]) for k in range(10)})
    cands.update({f"a_only{k}": place([a]) for k in range(10)})
    cands.update({f"none{k}": place([]) for k in range(20)})
    return query, cands

queries, pos_at1_bi, recall20_bi, pos_at1_two, pos_at1_cross = 0, 0, 0, 0, 0
tie_sizes, pass_bi_docs, pair_cross, pair_two = [], 0, 0, 0
max_gap = 0.0
N_QUERIES = 200
for _ in range(N_QUERIES):
    query, cands = make_query_and_candidates()
    names = list(cands)
    order = rng.permutation(len(names))                     # random tie-breaking
    names = [names[i] for i in order]
    doc_vecs = {n: bi_encode(cands[n]) for n in names}
    qv = bi_encode(query)
    bi = {n: float(qv @ doc_vecs[n]) for n in names}
    max_gap = max(max_gap, float(np.abs(doc_vecs["positive"] - doc_vecs["swap0"]).max()))
    ranked = sorted(names, key=lambda n: -bi[n])
    top = max(bi.values())
    tie_sizes.append(sum(abs(bi[n] - top) < 1e-9 for n in names))
    pos_at1_bi += ranked[0] == "positive"
    stage1 = ranked[:20]
    recall20_bi += "positive" in stage1
    pass_bi_docs += len(names)
    # Stage 2: score only the top-20 with the interaction scorer.
    rescored = sorted(stage1, key=lambda n: -interaction_score(query, cands[n]))
    pos_at1_two += rescored[0] == "positive"
    pair_two += len(stage1)
    # One-stage: score every candidate with the interaction scorer.
    crossed = sorted(names, key=lambda n: -interaction_score(query, cands[n]))
    pos_at1_cross += crossed[0] == "positive"
    pair_cross += len(names)

print(f"queries: {N_QUERIES}, candidates per query: {len(names)}")
print(f"max |positive - swapped| bi-encoder vector difference: {max_gap:.1e}")
print(f"bi-encoder exact-tie group at top, mean size: {np.mean(tie_sizes):.1f}")
print(f"bi-encoder P@1 (random tie-break): {pos_at1_bi / N_QUERIES:.3f}")
print(f"bi-encoder recall@20: {recall20_bi / N_QUERIES:.3f}")
print(f"two-stage P@1 (bi top-20, then interaction): {pos_at1_two / N_QUERIES:.3f}")
print(f"interaction scorer on all candidates P@1: {pos_at1_cross / N_QUERIES:.3f}")
print(f"interaction-scorer pair passes per query: all={pair_cross / N_QUERIES:.0f}, two-stage={pair_two / N_QUERIES:.0f}")
print(f"bi-encoder document encodings per query (offline in practice): {pass_bi_docs / N_QUERIES:.0f}")

# Cost arithmetic (assumptions stated in the lesson)
n = 10_000
print(f"all-pairs cross-encoder passes for n={n}: {n * (n - 1) // 2:,}; bi-encoder encodings: {n:,}")
N, K = 1_000_000, 100
tokens_pair, params = 256 + 32, 110e6
flops_pass = 2 * params * tokens_pair
print(f"FLOPs per encoder pass (2 x params x tokens, assumed 110M params, 288 tokens): {flops_pass:.2e}")
print(f"cross-encoder over corpus per query: {N:,} passes = {N * flops_pass:.2e} FLOPs")
print(f"two-stage, k={K}: {K} passes = {K * flops_pass:.2e} FLOPs; ratio {N / K:,.0f}x fewer passes")
print(f"bi-encoder query: 1 pass + {N:,} dot products of dim 768 = {N * 768:.2e} multiply-adds")
```

```output
queries: 200, candidates per query: 47
max |positive - swapped| bi-encoder vector difference: 1.7e-16
bi-encoder exact-tie group at top, mean size: 7.0
bi-encoder P@1 (random tie-break): 0.135
bi-encoder recall@20: 1.000
two-stage P@1 (bi top-20, then interaction): 1.000
interaction scorer on all candidates P@1: 1.000
interaction-scorer pair passes per query: all=47, two-stage=20
bi-encoder document encodings per query (offline in practice): 47
all-pairs cross-encoder passes for n=10000: 49,995,000; bi-encoder encodings: 10,000
FLOPs per encoder pass (2 x params x tokens, assumed 110M params, 288 tokens): 6.34e+10
cross-encoder over corpus per query: 1,000,000 passes = 6.34e+16 FLOPs
two-stage, k=100: 100 passes = 6.34e+12 FLOPs; ratio 10,000x fewer passes
bi-encoder query: 1 pass + 1,000,000 dot products of dim 768 = 7.68e+08 multiply-adds
```

The dashed line is the random-pick rate for the seven-way tie.")

![Two-stage pipeline: 47 candidates pass through a bi-encoder that keeps the top 20 with recall@20 of 1.000, then a cross-scorer that ranks the 20 with P@1 of 1.000](diagrams/39.1-two-stage.svg "The toy pipeline. Stage 1 must keep the relevant document; stage 2 must rank it first.")

Reading the output:

- The bi-encoder's top group is an exact tie, seven documents on average (the positive, three reversed, three split). Its P@1 of 0.135 is close to the random-pick rate of $1/7 \approx 0.143$.
- Recall@20 is 1.000 because the seven-way tie always fits in the top 20. Stage 1 keeps the answer; it cannot rank it.
- Two-stage scoring makes 20 pair passes per query and reaches P@1 of 1.000. One-stage scoring makes 47 and also reaches 1.000.
- In practice the bi-encoder's 47 document encodings are computed once and stored, not per query.

These numbers come from a construction, not a benchmark. The relevant document differs from the seven tied documents only by word order, and the interaction scorer is written to test exactly that. P@1 of 1.000 therefore says that a stage which reads the pair can use order, not that trained cross-encoders reach 1.000 on real data. Real bi-encoders are not order-blind, so whether they lose ground on real queries is an empirical question. Lesson 39.2 covers trained cross-encoder models.

## Two-stage re-ranking

The standard design is two stages. Stage 1 is a bi-encoder over the whole index, tuned for recall: it must keep the relevant documents. Stage 2 is a cross-encoder over the $k$ survivors, tuned for precision. The parameter $k$ is a tuning choice. A larger $k$ gives stage 2 more chances to find the answer, and costs $k$ more pair passes per query. Stage 2's cost is set by $k$, not by the corpus size.

> [!TRAP]
> **Recall caps the result.** Re-ranking cannot recover a document that stage 1 dropped. If recall@k is 0.8, final P@1 cannot exceed 0.8, however good the re-ranker is.

> [!TRAP]
> **Rebuilding the index per query.** A bi-encoder saves work only if document vectors are cached. Re-encoding the corpus for each query costs one pass per document, the same as scoring it with a cross-encoder.

> [!TRAP]
> **Comparing scores across queries.** Cross-encoder scores and cosines are comparable within one query's candidate list. A single global threshold needs calibration on held-out queries first.

> [!TRAP]
> **Silent input-format errors.** A cross-encoder is trained on one input order and separator. Swapping query and document, or dropping the separator, changes the score without any error. Check one known pair before trusting a pipeline.

> [!TRAP]
> **Dot product versus cosine.** A bi-encoder trained with cosine similarity needs normalised vectors. A raw dot product on unnormalised vectors also ranks by vector length.

## Summary

- A bi-encoder encodes query and document apart and scores with a dot product, so document vectors can be indexed offline.
- A cross-encoder reads the query and document together, one pass per pair, and can use word interactions that a fixed vector cannot hold.
- A two-stage re-ranker uses a bi-encoder to keep $k$ candidates and a cross-encoder to rank them, so its cost grows with $k$, not with the corpus.
- Mean pooling gives the same vector to sentences with the same words in a different order, so a toy bi-encoder ties them.

## Quiz time

### Question 1: Calculation

A corpus has 10,000 sentences. How many inference computations does an all-pairs cross-encoder need to find the most similar pair, and how many encodings does a bi-encoder need?

<details><summary>Solution</summary>

The cross-encoder scores each unordered pair once: $\binom{10{,}000}{2} = 49{,}995{,}000$. The bi-encoder encodes each sentence once, which is 10,000 encodings, and then compares vectors cheaply.

</details>

### Question 2: Prediction

In the toy experiment, why do the seven "both words" candidates tie exactly for the bi-encoder? What P@1 would a random pick among them give?

<details><summary>Solution</summary>

Each of them contains the query's entity and attribute once and the same filler bag. Mean pooling discards order, so the vectors are the same up to rounding (the printed difference is about $10^{-16}$). A random pick among seven tied documents succeeds with probability $1/7 \approx 0.143$.

</details>

### Question 3: Bug-spotting

A colleague writes this stage-1 search. It runs on every query. What is the cost problem?

```text
def search(query, corpus):
    scores = []
    for doc in corpus:
        d = bi_encoder.encode(doc)                  # encodes the whole corpus
        scores.append(cosine(bi_encoder.encode(query), d))
    return top_k(scores, 20)
```

<details><summary>Solution</summary>

The corpus is encoded again for every query, which is one pass per document per query. That is as expensive as a cross-encoder over the whole corpus and removes the point of a bi-encoder. The document vectors should be computed once, stored in an index, and only the query encoded at search time.

</details>

### Question 4: Explanation

Why can a cross-encoder use information about the query that a bi-encoder cannot?

<details><summary>Solution</summary>

The bi-encoder computes the document vector before it sees the query, and its only query-dependent step is one dot product. The cross-encoder runs attention between query and document tokens, so its document representation depends on the query. This is reasoning from the architecture, not a measured result.

</details>

### Question 5: Calculation

With $N = 10^6$ and $k = 100$, and the per-pass cost assumed in this lesson, how many more passes does one-stage cross-encoder scoring need per query than two-stage, and what is the ratio of passes?

<details><summary>Solution</summary>

One-stage needs $10^6$ passes and two-stage needs $100$ re-ranking passes (plus one query encoding and the cached document vectors). The difference is $999{,}900$ passes, and the ratio is $10{,}000$. Because the per-pass cost is the same, the FLOP ratio is also $10{,}000$.

</details>
