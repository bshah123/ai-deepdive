A cross-encoder reads a query and a document together and returns one relevance score. In this lesson you will see how that joint reading works, how three rerankers turn it into a number, and why the cost grows with the size of the candidate list.

**You need:** the bi-encoder versus cross-encoder distinction from Lesson 39.1, and the attention formula from Lesson 25.1 (softmax over scaled dot products).

## The problem

Retrieval-augmented generation (RAG) first pulls candidate passages with a fast first stage, then places the best ones in a prompt. The first stage is usually a bi-encoder: it compares one query vector with stored document vectors. Those document vectors were computed before the query existed, so the query cannot change how a document is represented. A reranker is a second stage that takes a short list of candidates and orders it more carefully.

Take the query "What is the capital of France?" and the candidate "The Eiffel Tower is located in Paris." They share a topic, but the candidate does not answer the question. A score that reads both texts at once can check how the query's words relate to the document's words. Two separately computed vectors cannot.

The price of reading both texts at once is that the reranker runs once per candidate. The list it sees must therefore be short, and the cost section below puts a number on this.

## Intuition: one pass over the pair

![Left: a bi-encoder encodes the query and the document separately, then compares two vectors with a dot product. Right: a cross-encoder runs one transformer over the joined pair and reads one score from the CLS token.](diagrams/39.2-architectures.svg "Two architectures. Only the right-hand one lets query tokens and document tokens interact.")

A cross-encoder joins the two texts into one sequence, `[CLS] query [SEP] document [SEP]`. The [CLS] (classification) token is a special token whose final vector serves as a summary of the pair, and [SEP] (separator) separates the two texts. In every layer, attention lets any token read any other token, so query words and document words can exchange information before the score is read out.

The BERT (Bidirectional Encoder Representations from Transformers) re-ranker of Nogueira and Cho (2019) worked this way. It fed the query as sentence A and the passage as sentence B, and passed the final [CLS] vector through a single-layer network. The query was capped at 64 tokens and the whole pair at 512.

## Worked example, by hand

Take one query token, "capital", with a two-dimensional vector $(1, 0)$, and two document tokens: "capital" with $(1, 0)$ and "paris" with $(0, 1)$. Attention scores are dot products divided by $\sqrt{d} = \sqrt{2}$:

- "capital": $(1 \cdot 1 + 0 \cdot 0)/\sqrt{2} = 0.7071$
- "paris": $(1 \cdot 0 + 0 \cdot 1)/\sqrt{2} = 0$

The division by $\sqrt{d}$ keeps the scores from growing with the vector length, as derived in Lesson 25.1.

Softmax gives $e^{0.7071} = 2.0281$ and $e^0 = 1$, so the weights are $2.0281/3.0281 = 0.6698$ and $0.3302$. The code reproduces the same numbers:

```python
import numpy as np

q = np.array([1.0, 0.0])          # query token "capital"
K = np.array([[1.0, 0.0],         # document token "capital"
              [0.0, 1.0]])        # document token "paris"

scores = K @ q / np.sqrt(q.shape[0])          # divide by sqrt(d) = sqrt(2)
weights = np.exp(scores) / np.exp(scores).sum()
print("scores :", np.round(scores, 4))
print("weights:", np.round(weights, 4))
```

```output
scores : [0.7071 0.    ]
weights: [0.6698 0.3302]
```

This is a toy with identity projections and hand-picked vectors. The figure below uses the same mechanism on a three-by-four block of random vectors. It shows that matching is by shared content, not meaning: "france" puts no weight on "paris" in this toy. A trained model learns its projections from data, and how well it matches meaning depends on those trained weights, not on the architecture.

![Heat-map style grid: three query tokens (capital, of, france) as rows and four document tokens (paris, is, the, capital) as columns, with a weight in each cell. The cell for capital against capital is the largest, at 0.34.](diagrams/39.2-joint-attention.svg "Toy attention weights. ## Three score heads

The three rerankers differ in the head that turns the joint representation into a number. The head decides what the number means, and that decides how you may compare scores later, so the heads come before the cost discussion. The code below checks the heads' arithmetic; none of the three checkpoints is run here.

**BERT re-ranker (2019).** The final [CLS] vector goes through one linear layer. The paper treats the output as a probability in its training loss.

**MonoT5 (2020).** A T5 (Text-to-Text Transfer Transformer) encoder-decoder receives the text `Query: q Document: d Relevant:` and is trained to generate "true" or "false". At inference the paper uses one decoding step and applies a softmax over only the "true" and "false" logits, then ranks by $p(\text{true})$ (Nogueira, Jiang and Lin, 2020, Section 2). Two logits give a two-way softmax, and that equals a sigmoid of their difference:

$$
p(\text{true}) = \frac{e^{l_{\text{true}}}}{e^{l_{\text{true}}} + e^{l_{\text{false}}}} = \sigma\!\left(l_{\text{true}} - l_{\text{false}}\right)
$$

```python
import numpy as np

l_true = np.array([2.0, 0.4, -1.1])          # logit of "true" for three documents
l_false = np.array([-1.0, 0.1, 0.9])         # logit of "false"
p_true = np.exp(l_true) / (np.exp(l_true) + np.exp(l_false))
print("p(true):", np.round(p_true, 4))
```

```output
p(true): [0.9526 0.5744 0.1192]
```

**BGE-reranker (BAAI).** The Hugging Face model card loads a sequence-classification checkpoint and reads `logits.view(-1, )`, one raw logit per pair. The card's snippet applies no sigmoid or softmax, and it says the score "is not bounded to a specific range". The card's snippets also name both `bge-reranker-base` and `bge-reranker-large` in different places, so use one checkpoint throughout. The card's usage line, checked against the card and not run here:

<details><summary>Run locally: needs pip install transformers torch (snippet from the model card; not executed in this lesson)</summary>

```python
inputs = tokenizer(pairs, padding=True, truncation=True, return_tensors="pt", max_length=512)
scores = model(**inputs, return_dict=True).logits.view(-1, ).float()
```

`pairs` is a list of `[query, passage]` lists that you build yourself. `max_length=512` is a call-site setting in the card, not a stated limit of the model.

</details>

Now the bug in a common shortcut. Applying softmax over the single logit of a one-logit head gives 1.0 for every pair, and indexing column 1 fails:

```python
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

logits = np.array([[3.2], [-1.0], [0.4]])   # one raw logit per (query, document) pair
print("softmax over dim=1:", softmax(logits, axis=1).ravel())
try:
    logits[:, 1]                             # column 1 does not exist
except IndexError as err:
    print("IndexError:", err)
print("sigmoid:", np.round(1 / (1 + np.exp(-logits.ravel())), 4))
```

```output
softmax over dim=1: [1. 1. 1.]
IndexError: index 1 is out of bounds for axis 1 with size 1
sigmoid: [0.9608 0.2689 0.5987]
```

## Cost: why cross-encoders rerank short lists

A bi-encoder encodes each document once, offline. A cross-encoder must run the full transformer once per query-document pair, because the document cannot be encoded without the query. The count below uses the lesson's assumptions: an 8-token query, 120-token documents, and three special tokens, so each pair is $8 + 120 + 3 = 131$ tokens. The attention term grows faster than the token count, so this count understates the real cost.

```python
PAIR = 8 + 120 + 3                           # tokens in [CLS] query [SEP] doc [SEP]
N = 1000
print("pair length:", PAIR)
print("bi-encoder, online tokens per query:", 8)
print("cross-encoder, full scan:", N * PAIR)
print("two-stage (top 100 by bi-encoder):", 8 + 100 * PAIR)
print("ratio full / two-stage:", round(N * PAIR / (8 + 100 * PAIR), 2))
```

```output
pair length: 131
bi-encoder, online tokens per query: 8
cross-encoder, full scan: 131000
two-stage (top 100 by bi-encoder): 13108
ratio full / two-stage: 9.99
```

![Three horizontal bars for 1,000 candidates: bi-encoder online part 8 tokens (a sliver), two-stage 13,108 tokens, and full cross-encoder 131,000 tokens.](diagrams/39.2-cost.svg "Tokens through the transformer per query. The bi-encoder's corpus cost of 120,000 tokens is paid once, offline.")

Each count is a multiplication you can check: 131 tokens per pair times 1,000 pairs gives 131,000 token positions for one query. The two-stage count adds the query's 8 tokens once and reruns the transformer on 100 pairs. The ratio, 9.99, is close to the tenfold cut from 1,000 candidates to 100, and it is smaller only because the first-stage query cost is added back.

The two-stage pipeline is the usual practice: the first stage passes its top 100 to the cross-encoder. Its limit is recall. A relevant document that the first stage misses never reaches the reranker.

Cohere Rerank is a hosted API rather than a checkpoint you download. The Cohere documentation (checked 2026-11-23, API v2 page) says Rerank 5 models return a calibrated score between 0 and 1, with names such as `rerank-v5.0-pro`. The docs give no architecture details, so this lesson makes no claim about its internals.

## The input budget

Lengths are counted in tokens, and the limit of 512 covers the whole pair: [CLS], the query, the two [SEP] tokens, and the document. A document that is too long is cut. The budget below assumes the document is trimmed from its end; which side gets trimmed depends on the tokenizer's truncation setting, so check it for your library version.

The budget matters most for long documents, because the reranker never sees the text it cuts, and it raises no error. One common workaround is to split the document into overlapping chunks and score each chunk. That changes the cost, since each chunk is a separate pair, and it needs a rule for combining chunk scores, such as the maximum. Neither choice is free, and the right one depends on where your answers usually sit (my own reasoning, not a benchmark result).

```python
MAX_LEN, QUERY, SPECIAL = 512, 8, 3
doc_budget = MAX_LEN - (QUERY + SPECIAL)     # [CLS] and the two [SEP] tokens
doc_tokens = list(range(700))                 # token ids 0..699 stand in for a 700-token document
kept = doc_tokens[:doc_budget]
answer = range(600, 608)
print("document budget:", doc_budget)
print("answer kept:", all(t in kept for t in answer))
```

```output
document budget: 501
answer kept: False
```

![Top bar: 512 input tokens, 10 grey tokens for CLS, query and the first SEP, then 501 document tokens and a final SEP. Bottom bar, on its own scale: a 700-token document, where the first 501 tokens are kept and the answer at tokens 600 to 607 is dropped.](diagrams/39.2-truncation.svg "A 700-token document keeps only its first 501 tokens. The answer sits beyond the cut.")

> [!TRAP]
> A softmax over a single logit is always 1.0. The code above shows it. Rank by the raw logit, or apply a sigmoid if you need values between 0 and 1, and do not index a column that does not exist.

> [!TRAP]
> Scores from different heads, or from one head on different queries, are not on a common scale. The BGE card says its score is unbounded. Compare scores only within one query and one model, and set any cutoff on your own labelled data.

> [!TRAP]
> Truncation drops evidence without any error. In the example, the answer at tokens 600 to 607 is cut and the reranker never sees it.

> [!TRAP]
> A cross-encoder over the whole corpus costs 131,000 tokens per query here, against 8 for the bi-encoder's online part. Rerank a top-k list, not the corpus.

> [!TRAP]
> A model card's snippet can name a different checkpoint from its text. The BGE card does this. Load one checkpoint name and use it everywhere.

## Summary

- A cross-encoder runs the query and document through one transformer, so their tokens attend to each other, and it returns one score per pair.
- The three heads differ: BERT-style single logit (trained as a probability), MonoT5 two-way softmax over true/false logits, and BGE single raw logit with no stated range.
- Cost scales with the number of pairs, here 131 tokens each, so rerank a top-k list from a first stage.
- A softmax over one logit gives 1.0 everywhere, and truncation can cut the evidence without any error.

### Question 1: Calculation

A query has 12 tokens, the limit is 512, and the document has 900 tokens. How many document tokens are kept, counting [CLS] and the two [SEP] tokens?

The budget is $512 - (12 + 3) = 497$ document tokens. The first 497 are kept.

### Question 2: Prediction

What does this print?

```python
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

print(softmax(np.array([[0.5], [2.0]]), axis=1).ravel())
```

<details><summary>Show Solution</summary>

It prints `[1. 1.]`. Each row has one entry, so softmax over that axis is $e^z / e^z = 1$ whatever the value of $z$. This is the bug from the lesson.

</details>

### Question 3: Explanation

Why does the two-stage pipeline cost less than scoring the whole corpus, and what does it give up?

<details><summary>Show Solution</summary>

The bi-encoder compares precomputed vectors, so it touches every document cheaply. The cross-encoder runs a full transformer pass per pair, but only on the top 100. It gives up recall: any relevant document the first stage ranks below 100 never reaches the reranker, however good its score would have been.

</details>

### Question 4: Calculation

A MonoT5-style head has $l_{\text{true}} = 1.0$ and $l_{\text{false}} = -1.0$. What is $p(\text{true})$?

<details><summary>Show Solution</summary>

$p(\text{true}) = \sigma(1.0 - (-1.0)) = \sigma(2.0) = 1/(1 + e^{-2}) \approx 0.8808$.

</details>
