# 40.3 — Context Caching (Anthropic, Gemini, OpenAI) & Cost Optimization

## Opening Motivation & Context

In the realm of Retrieval-Augmented Generation (RAG), context caching is a powerful technique that can significantly optimize both performance and cost. As we delve deeper into the intricacies of RAG, it becomes evident that managing the context window efficiently is crucial. This lesson will explore how context caching works across different providers like Anthropic, Gemini, and OpenAI, and how it can help in optimizing costs associated with API calls.

## Core Concepts Breakdown

Context caching is a mechanism that allows the reuse of previously retrieved and processed context in subsequent API calls. This is particularly useful in scenarios where the same or similar context is repeatedly used across multiple queries. By caching the context, we can reduce the number of API calls, thereby optimizing costs and improving response times.

> [!KEY-INSIGHT]
> Context caching is a form of memoization applied to the context retrieval process in RAG systems. It helps in reducing redundant computations and API calls, leading to cost optimization and performance improvement.

> [!BEST-PRACTICE]
> Always cache context that is likely to be reused across multiple queries. This can significantly reduce the number of API calls and the associated costs.

> [!WARNING]
> Over-aggressive caching can lead to stale or outdated context being used, which can degrade the quality of the generated responses. It's important to balance between caching and freshness of the context.

## Code Demonstration & Runtime Output

```python
import time
from typing import Dict, Optional, List

class ContextCache:
    def __init__(self):
        self.cache: Dict[str, Dict] = {}

    def get_context(self, query: str, retrieval_function) -> Dict:
        if query in self.cache:
            print(f"Retrieving context for '{query}' from cache.")
            return self.cache[query]
        else:
            print(f"Retrieving context for '{query}' from source.")
            context = retrieval_function(query)
            self.cache[query] = context
            return context

def mock_retrieval_function(query: str) -> Dict:
    # Simulate a time-consuming retrieval process
    time.sleep(2)
    return {"query": query, "context": f"Retrieved context for {query}"}

def main():
    cache = ContextCache()

    # First call - context not in cache
    start_time = time.time()
    context1 = cache.get_context("What is the capital of France?", mock_retrieval_function)
    end_time = time.time()
    print(f"Time taken: {end_time - start_time:.2f} seconds")
    print(context1)

    # Second call - context in cache
    start_time = time.time()
    context2 = cache.get_context("What is the capital of France?", mock_retrieval_function)
    end_time = time.time()
    print(f"Time taken: {end_time - start_time:.2f} seconds")
    print(context2)

if __name__ == "__main__":
    main()
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import the necessary modules, including `time` for measuring execution time and typing annotations for better code clarity.
2. **ContextCache Class**: This class manages the caching of context.
   - `__init__`: Initializes an empty dictionary to store cached contexts.
   - `get_context`: Retrieves context for a given query. If the query is in the cache, it returns the cached context; otherwise, it retrieves the context using the provided retrieval function, caches it, and returns it.
3. **mock_retrieval_function**: A mock function that simulates a time-consuming retrieval process. In a real-world scenario, this would be replaced with an actual retrieval function.
4. **main Function**: Demonstrates the usage of the `ContextCache` class.
   - First call: The context for the query is not in the cache, so it is retrieved from the source.
   - Second call: The context for the same query is retrieved from the cache, resulting in a significant reduction in time.
5. **Execution**: The `main` function is executed when the script is run directly.

> [!ADVANCED]
> The `ContextCache` class uses a dictionary to store cached contexts. The dictionary keys are the queries, and the values are the retrieved contexts. This allows for O(1) average time complexity for both insertion and retrieval operations, making the caching mechanism efficient.

> [!QA]
> Q: When should I prefer context caching over always retrieving fresh context?
> A: Context caching is beneficial when the same or similar context is likely to be reused across multiple queries. However, if the context is highly dynamic and changes frequently, it's better to retrieve fresh context to ensure the accuracy and relevance of the generated responses.

## Summary & Key Takeaways

- Context caching is a powerful technique to optimize performance and cost in RAG systems.
- It reduces the number of API calls by reusing previously retrieved and processed context.
- Balancing between caching and freshness of the context is crucial to maintain the quality of the generated responses.
- The `ContextCache` class provides a simple yet effective mechanism for caching contexts.
