HyDE (Hypothetical Document Embeddings) searches with a made-up answer instead of the user's question. In this lesson you will see why an answer can sit closer to the right passage than the question does, run the pipeline with a stub language model and a NumPy encoder, and judge what a small experiment can and cannot show.

**You need:** the RAG pipeline from Lesson 37.1 (retrieve, then generate) and the idea that a text becomes a vector (Lesson 24.1). LM means language model; RAG means retrieval-augmented generation.

## The problem: questions and passages look different

A user writes "how do I make a model smaller in memory". The passage that answers it says "Quantization stores weights in fewer bits, such as 8-bit integers, to cut memory use." The two share one content word, "memory". A dense retriever embeds the question and each passage separately and ranks passages by cosine similarity, so it has to bridge the gap between a question's vocabulary and a passage's vocabulary without any help. When the wording differs, the question's vector can land far from the passage's vector.

## The idea: embed a hypothetical answer

HyDE (Gao, Ma, Lin and Callan, 2022) adds one step. An instruction-following LM writes a *hypothetical document*: a fluent passage that answers the query, which may contain invented details. The hypothetical is then embedded and used as the query vector. The paper's abstract names InstructGPT as the example generator and Contriever, an unsupervised contrastively trained encoder, as the example encoder.

![Pipeline: short query, LM writes a fake answer, hypothetical document, encoder, answer vector, nearest real passages](diagrams/41.1-pipeline.svg "The generated text is only a bridge. Its vector does the searching.")

The bet is that a hypothetical answer uses the same vocabulary as the passages it resembles, so its vector lands nearer to them. Question words such as "what", "how" and "why" carry no topic, so a question's vector is spread across topic-neutral wording. An answer is written in the register of the passages: it names the mechanism, uses the domain's nouns and drops the question frame. The fake details do not have to be true. They only have to point the vector the right way.

## Worked example: one query, traced

Take query 4 of the experiment below: "what does splitting text into pieces with some repetition achieve". The relevant passage is "Chunk overlap repeats a few tokens between neighbouring chunks so facts at a boundary survive."

- **Query-only.** After removing stop words, the query has five content words, and none of them is in the corpus vocabulary. Its vector is therefore all zeros, every cosine is 0, and the passage's rank comes from the tie-breaking rule, not from any similarity. The rank shown for it below (9) carries no signal.
- **HyDE.** The stub hypothesis ("Overlapping chunks repeat some tokens at each boundary, so a sentence cut in half still appears whole in one chunk") has five in-vocabulary words: chunks, tokens, boundary, cut and chunk. Its vector points at the passage's direction, with cosine 0.967, and the passage ranks first.

The experiment prints the vocabulary trace for this query so you can check it.

## The experiment

The corpus has 12 passages on optimisation and retrieval. The encoder is fixed and deliberately simple: TF-IDF (term frequency times inverse document frequency) weights over the corpus vocabulary, followed by a truncated SVD (singular value decomposition), which is latent semantic analysis (LSA). Latent dimension $K$ is the smallest value that keeps at least 80% of the squared singular values (the "energy"). The hypothetical documents are scripted, one per query, and stand in for the LM. Their wording was fixed before any result was seen. $K$ was also fixed by its rule before any retrieval result was seen. An earlier run with $K=4$ gave many cosines of exactly 1.000 or 0.000, because a 4-dimensional projection collapses many vectors onto the same directions. The energy rule reduces that collapse but does not remove it: queries 3 and 5 still reach cosine 1.000.

```python
import re
import numpy as np

DOCS = [
    "Gradient descent updates each weight by a small step against the gradient of the loss.",
    "If the learning rate is too large, the loss oscillates or diverges instead of falling.",
    "Adam keeps running averages of the gradient and of its square to scale each step size.",
    "Dropout randomly zeroes activations during training, which reduces overfitting.",
    "Early stopping ends training when the validation loss has stopped improving for a while.",
    "An inverted index maps every term to the list of documents that contain it.",
    "BM25 scores a document by term frequency with saturation and a document length penalty.",
    "Approximate nearest neighbour indexes such as HNSW trade a little recall for much faster search.",
    "Chunk overlap repeats a few tokens between neighbouring chunks so facts at a boundary survive.",
    "A cross-encoder reads the query and the passage together, which is slower but more accurate.",
    "Reciprocal rank fusion merges ranked lists by summing 1 divided by (k plus rank).",
    "Quantization stores weights in fewer bits, such as 8-bit integers, to cut memory use.",
]

# Colloquial queries whose wording does not match the relevant passages.
QUERIES = [
    ("why does my training blow up when I raise the step size", {1}),
    ("how do I stop my network from memorising the training set", {3, 4}),
    ("why did keyword search miss documents that use different words", {5, 6}),
    ("how do I make vector search fast on millions of items", {7}),
    ("what does splitting text into pieces with some repetition achieve", {8}),
    ("how do I make a model smaller in memory", {11}),
]

# Scripted stand-ins for the LM's hypothetical answers, one per query.
HYPO = [
    "A learning rate that is set too high makes each update overshoot the minimum, so the loss oscillates and can diverge.",
    "Overfitting is reduced by regularisation such as dropout, and by early stopping once the validation loss plateaus.",
    "Keyword search uses an inverted index with BM25 scoring, so a document that expresses the same idea in different words is missed.",
    "Approximate nearest neighbour search with an HNSW graph trades a little recall for much faster lookups over millions of vectors.",
    "Overlapping chunks repeat some tokens at each boundary, so a sentence cut in half still appears whole in one chunk.",
    "Quantization stores each weight in fewer bits, such as 8-bit integers, which lowers the memory a model needs.",
]
# A fluent hallucination for query 0: plausible, and wrong about the cause.
WRONG = "Training blows up when the dataset is too small, so the fix is to collect more labelled examples."

STOP = {"a", "an", "the", "of", "to", "and", "is", "it", "by", "that", "for", "on", "in", "do", "how",
        "why", "my", "i", "what", "does", "when", "which", "with", "so", "are", "as", "be", "each",
        "from", "or", "than", "this", "at", "can", "into", "its", "some", "if", "not", "too", "just",
        "up", "will", "they", "their", "one", "many", "such", "more", "instead"}

def tokens(text):
    return [w for w in re.findall(r"[a-z]+", text.lower()) if w not in STOP]

# Fixed encoder: TF-IDF over the corpus vocabulary, then a rank-K SVD (latent semantic analysis).
vocab = sorted({w for d in DOCS for w in tokens(d)})
idx = {w: i for i, w in enumerate(vocab)}

def bow(text):
    v = np.zeros(len(vocab))
    for w in tokens(text):
        if w in idx:
            v[idx[w]] += 1
    return v

X = np.array([bow(d) for d in DOCS])
df = (X > 0).sum(axis=0)
idf = np.log((1 + len(DOCS)) / (1 + df)) + 1
_, S, Vt = np.linalg.svd(X * idf, full_matrices=False)
energy = np.cumsum(S**2) / np.sum(S**2)
K = int(np.argmax(energy >= 0.8)) + 1      # smallest K keeping at least 80% of the energy
P = Vt[:K].T
print("energy kept by K =", K, ":", round(float(energy[K - 1]), 3))

def embed(text):
    z = (bow(text) * idf) @ P
    n = np.linalg.norm(z)
    return z / n if n > 0 else z

D = np.array([embed(d) for d in DOCS])

def best_relevant(qvec, rel):
    scores = D @ qvec
    order = np.argsort(-scores, kind="stable")
    ranks = {int(d): r + 1 for r, d in enumerate(order)}
    best = min(rel, key=lambda d: ranks[d])
    return ranks[best], float(scores[best])

oov = [sum(w not in idx for w in tokens(h)) / len(tokens(h)) for h in HYPO]
print("vocab size:", len(vocab), " latent dims K:", K)
print("share of hypothesis tokens outside the corpus vocabulary:", round(float(np.mean(oov)), 3))
print("query 4 in-vocab words:", [w for w in tokens(QUERIES[4][0]) if w in idx])
print("hypothesis 4 in-vocab words:", [w for w in tokens(HYPO[4]) if w in idx])

rows = []
for (q, rel), h in zip(QUERIES, HYPO):
    r_q, s_q = best_relevant(embed(q), rel)
    r_h, s_h = best_relevant(embed(h), rel)
    rows.append((r_q, r_h, s_q, s_h))

print("query  rank(query)  rank(HyDE)  cos(query)  cos(HyDE)")
for i, (a, b, s, t) in enumerate(rows):
    print(f"q{i}     {a:>10}  {b:>10}  {s:>10.3f}  {t:>10.3f}")
print("recall@2 query:", sum(a <= 2 for a, *_ in rows), "/", len(rows),
      " HyDE:", sum(b <= 2 for _, b, *_ in rows), "/", len(rows))

rel0 = QUERIES[0][1]
r_w, s_w = best_relevant(embed(WRONG), rel0)
print(f"q0 with hallucinated hypothesis: rank {r_w}, cos {s_w:.3f}")
```

The code has three parts. The `bow` and `idf` lines turn a text into TF-IDF counts over the corpus vocabulary; words the corpus never uses are dropped, which is why half the hypothesis tokens (48.9% on average) contribute nothing. The SVD projects those counts onto $K$ latent directions, and `embed` normalises the result, so a dot product is a cosine. The same `embed` function encodes documents and queries, which keeps the two in one space.

## What the numbers show

![Bar chart of the rank of the best relevant passage for each query: query-only versus HyDE](diagrams/41.1-ranks.svg "Lower is better. Query 4's query-only bar is a tie, not a ranking.")

![Bar chart of the cosine between the best relevant passage and the query vector, versus the hypothetical vector](diagrams/41.1-cosine.svg "Cosine with the best relevant passage. Query 4's query-only cosine is 0.000 because the query has no in-vocabulary word.")

Query 3 reaches cosine 1.000 in both conditions because its only in-vocabulary words belong to a single passage, so its vector points exactly along that passage. The toy saturates on keyword matches, so easy queries cannot separate the two methods. The informative queries are the ones where the conditions disagree: queries 0 and 4 in rank, and query 2 in cosine (0.635 to 0.789) with the same rank.

Recall@2 (is a relevant passage in the top two?) rises from 4 of 6 to 6 of 6. HyDE moves query 0's relevant passage from rank 3 to rank 1 and query 4's from a tie to rank 1. No query gets worse in rank. Query 5 is the one case where the cosine drops slightly (1.000 to 0.995) with no change in rank.

What these numbers do not show:

- **Six queries.** A difference of two queries is not evidence about retrieval in general. The paper's own claims (below) rest on full benchmarks.
- **Scripted hypotheses.** They were written by hand with the passages' vocabulary in mind. A real LM may not match that vocabulary, and the gain shown here is an upper estimate for this corpus.
- **The hallucination test is weak.** The wrong hypothesis for query 0 still ranks the correct passage first, with cosine 0.994 against 0.999 for the correct hypothesis. The margin shrank, but this test did not break retrieval, and one case cannot show that it never would.
- **The encoder cannot judge truth.** Word-overlap LSA has no notion of whether a hypothesis is correct. The paper argues that a trained dense encoder such as Contriever filters out hallucinated details. I have not verified that argument from the full text, and this toy has no such encoder.

## Common traps

> [!TRAP]
> **Zero-vector queries tie.** A query with no in-vocabulary word gets all-zero scores, and the rank is decided by the sort's tie-break. Report such queries as "no signal", not as a rank.

> [!TRAP]
> **Scripted hypotheses flatter the method.** A hypothesis written with the target passage's wording will match it. Evaluate HyDE with LM output you did not write.

> [!TRAP]
> **A fluent wrong answer is not automatically harmful, and not automatically safe.** Whether the hypothesis's errors matter depends on the encoder and on how far the wrong content pulls the vector. Test with hallucinations you designed to be adversarial, not only plausible ones.

> [!TRAP]
> **HyDE adds a model call per query.** The extra LM generation adds latency and cost on every search. This lesson does not measure either; they depend on the model and the serving stack.

## Summary

- HyDE embeds an LM-written hypothetical answer instead of the query, to bridge the wording gap between questions and passages.
- The hypothetical may contain false details. The method relies on the encoder to map it near real passages, so its quality depends on the encoder.
- In this toy, a scripted hypothesis raised recall@2 from 4 of 6 to 6 of 6; with six queries this is an illustration of the mechanism, not a benchmark result.
- A zero-vector query has no signal; check the vocabulary trace before trusting a rank.

## Quiz time

### Question 1: Calculation
A query has no word in the corpus vocabulary. What is its vector in the encoder above, what are its cosines with the passages, and why does its rank of the relevant passage tell you nothing?

<details><summary>Show solution</summary>

Every word is dropped, so the TF-IDF count vector is zero, and so is its projection. The code returns the zero vector. Every dot product is 0. The stable sort then orders the passages by their index, so the relevant passage's position is set by the tie-break rule, not by any similarity.

</details>

### Question 2: Prediction
The LM writes a fluent hypothesis with a wrong cause, as in `WRONG`. Predict whether this encoder will rank the correct passage first, and say what in the code determines your answer.

<details><summary>Show solution</summary>

Probably yes here, because the wrong hypothesis still shares content words with the correct passage (for example "training") and the encoder only compares word weights. The code cannot detect the error, because nothing in the pipeline models truth. Whether a dense encoder would ignore the wrong details is an empirical question; this toy does not test it.

</details>

### Question 3: Bug spotting
This retrieval code gives wrong rankings. What is wrong?

```python
D = np.array([bow(d) @ P for d in DOCS])   # documents: raw counts, no idf
def search(q):
    return np.argsort(-(D @ embed(q)))     # query: idf-weighted and normalised
```

<details><summary>Show solution</summary>

The documents and the query are encoded differently. The documents skip the IDF weighting and the normalisation, while the query has both. The dot products then compare vectors in different weightings. Use one `embed` function for both sides, as the experiment does.

</details>

### Question 4: Explanation
Why does HyDE compare hypothetical-to-passage rather than query-to-passage, and what does the 48.9% out-of-vocabulary share imply for the method?

<details><summary>Show solution</summary>

The hypothetical is written in the register of passages, so its words are more likely to match passage words. Nearly half the hypothetical's tokens fall outside the corpus vocabulary and are ignored by this encoder, so the signal comes from the remaining in-vocabulary words. A dense encoder would not discard these words; this is a limit of the toy encoder, not of HyDE in general.

</details>
