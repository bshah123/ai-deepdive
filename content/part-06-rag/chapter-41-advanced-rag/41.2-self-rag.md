In this lesson you will trace the control loop of Self-RAG (self-reflective retrieval-augmented generation). You will see how a model decides whether to retrieve, how it scores its own candidate answers against the evidence, and where that scoring can fail. The code is NumPy only and runs in the browser, with the model replaced by hand-set probabilities.

**You need:** the basic RAG loop from Lessons 37.1 and 37.2, and the idea that a probability lies between 0 and 1.

## The problem

Standard RAG retrieves a fixed number of passages for every query. For "What is 17 times 3?" that wastes work and can put irrelevant text in front of the model. For "What temperature does the Zorvex reactor run at?" one retrieved passage may be enough, but nothing checks that the final answer actually follows from it.

Self-RAG (Asai et al., 2023) trains one language model (LM) to emit special **reflection tokens** that control retrieval and grade its own output. The decisions appear in the output stream as tokens, so the same network that writes the answer also decides when to look things up.

## Four reflection token types

The paper defines four token types (its Table 1), with these possible values:

| Token | Question it answers | Values |
|---|---|---|
| `Retrieve` | Is evidence needed before the next segment? | yes, no, continue |
| `IsRel` | Is this passage relevant to the question? | relevant, irrelevant |
| `IsSup` | Does the segment's claim follow from the passage? | fully, partially, no support |
| `IsUse` | How useful is the whole answer? | 5, 4, 3, 2, 1 |

The first token is a gate. The other three are **critique tokens**: they grade a passage or a segment after it has been produced.

![Four stages in a row: a retrieve gate, retrieving the top-K passages, generating one segment per passage, and critiquing and selecting; a no branch skips retrieval](diagrams/41.2-control-flow.svg "Self-RAG control flow. K is the number of passages retrieved.")

## Step 1: the retrieve gate

The gate fires when the probability of `Retrieve = yes` is above a threshold $t$. The paper reports $t = 0.2$ for most tasks, which is a value for its setup, not a universal constant. Here the probabilities are **hand-set stubs** that stand in for the trained head. They are chosen so the arithmetic is easy to follow, and they say nothing about how a real model behaves.

![Bar chart of the stub retrieve probability for five queries, with a dashed threshold line at 0.2; three bars rise above the line](diagrams/41.2-gate.svg "Stub P(Retrieve) for five queries. Blue bars cross the threshold.")

The threshold controls how often retrieval runs. The code below prints the count at four thresholds. Notice that 0.2 and 0.5 give the same decision here, because no query has a probability between them.

## Step 2: retrieve passages

The paper's retriever is a dense encoder. To stay NumPy only, this lesson uses TF-IDF (term frequency–inverse document frequency): each passage becomes a vector of word counts, down-weighted by how common each word is across the corpus. Relevance is the cosine similarity between query and passage vectors, which lies between 0 and 1 for these non-negative vectors. The smoothed IDF formula $\log\frac{1+N}{1+\mathrm{df}}+1$ matches scikit-learn's `TfidfVectorizer`, and the experiment script checked the matrices against it (largest difference $5.6\times10^{-17}$).

The corpus is fictional, so every answer can be checked by eye.

## Step 3: score each candidate segment

For each retrieved passage, the generator writes a candidate segment. Each candidate receives:

- a generation term `gen`, the probability of the segment (a stub here);
- three critique terms, each the probability of the most desirable value, normalised over that token's values.

The paper's default weights are $1.0$ for `IsRel`, $1.0$ for `IsSup` and $0.5$ for `IsUse`. The critique score is

$$
S = 1.0\, s_{\text{rel}} + 1.0\, s_{\text{sup}} + 0.5\, s_{\text{use}}, \qquad \text{total} = \text{gen} + S.
$$

The paper's Eq. 3 is written with a plain probability and I could not confirm from the extracted text whether the released code uses probabilities or log-probabilities. This lesson uses the form the paper describes; check the code before reusing it.

Candidate A, the segment grounded in passage 0, by hand: $s_{\text{rel}} = 0.90/(0.90+0.10) = 0.90$, $s_{\text{sup}} = 0.70$, $s_{\text{use}} = 0.60$. So $S = 0.90 + 0.70 + 0.5 \times 0.60 = 1.90$, and total $= 0.55 + 1.90 = 2.45$.

![Three horizontal bars, one per candidate, split into gen, rel, sup and 0.5 times use; A is longest and C is shortest](diagrams/41.2-candidates.svg "Score decomposition. Candidate A wins on both the generation term and the critique terms.")

## The code

This block runs in the browser. It implements the gate, retrieval, critique scoring and a failure case.

```python
import re
import numpy as np

docs = [
    "The Zorvex reactor runs at 450 kelvin during normal operation.",
    "Zorvex coolant is a sodium-free salt mixture.",
    "The Halden plant schedules maintenance every 90 days.",
    "Halden plant output peaked at 12 megawatts in 2021.",
    "Quarry basalt is dense and dark grey.",
    "Zorvex reactors were first built in the eastern delta.",
]
queries = {
    "q0": "What temperature does the Zorvex reactor run at?",
    "q1": "How often is maintenance at the Halden plant?",
    "q2": "Write a haiku about rain.",
    "q3": "What is 17 times 3?",
    "q4": "What colour is quarry basalt?",
}
# Stub for the trained Retrieve head: P(Retrieve = yes | query). Hand-set for illustration.
p_retrieve = {"q0": 0.91, "q1": 0.84, "q2": 0.07, "q3": 0.12, "q4": 0.66}
THRESHOLD = 0.2
STOP = {"the", "a", "is", "at", "what", "how", "of", "does", "in", "to", "about"}

def tokens(text):
    out = []
    for w in re.findall(r"[a-z0-9]+", text.lower()):
        if w in STOP:
            continue
        if len(w) > 3 and w.endswith("s"):   # crude plural stripping: runs -> run
            w = w[:-1]
        out.append(w)
    return out

vocab = sorted({w for d in docs for w in tokens(d)})
index = {w: i for i, w in enumerate(vocab)}
N = len(docs)
df = np.zeros(len(vocab))
for d in docs:
    for w in set(tokens(d)):
        df[index[w]] += 1
idf = np.log((1 + N) / (1 + df)) + 1          # smoothed IDF, same formula as scikit-learn

def tfidf(text):
    v = np.zeros(len(vocab))
    for w in tokens(text):
        if w in index:
            v[index[w]] += 1
    v = v * idf
    return v / np.linalg.norm(v) if v.any() else v

D = np.array([tfidf(d) for d in docs])       # each row has unit length

def retrieve(q, k=2):
    scores = D @ tfidf(q)                     # cosine similarity with every passage
    top = np.argsort(-scores, kind="stable")[:k]
    return [(int(i), round(float(scores[i]), 3)) for i in top]

for qid, q in queries.items():
    if p_retrieve[qid] > THRESHOLD:
        print(qid, "top-2 passages (index, cosine):", retrieve(q))

for t in (0.05, 0.2, 0.5, 0.9):
    fired = [q for q in queries if p_retrieve[q] > t]
    print(f"threshold {t:.2f}: retrieve for {len(fired)} of {len(queries)} queries {fired}")

W = {"rel": 1.0, "sup": 1.0, "use": 0.5}      # default critique weights reported for Self-RAG

def score(c):
    s_rel = c["rel"][0] / sum(c["rel"])       # desired value's probability, normalised over the type
    s_sup = c["sup"][0] / sum(c["sup"])
    s_use = c["use"][0] / sum(c["use"])
    S = W["rel"] * s_rel + W["sup"] * s_sup + W["use"] * s_use
    return c["gen"] + S, (s_rel, s_sup, s_use, S)

cands = {
    "A d0 correct":    {"gen": 0.55, "rel": [0.90, 0.10], "sup": [0.70, 0.20, 0.10], "use": [0.60, 0.30, 0.10, 0.00, 0.00]},
    "B d5 off-topic":  {"gen": 0.30, "rel": [0.35, 0.65], "sup": [0.10, 0.30, 0.60], "use": [0.20, 0.30, 0.30, 0.15, 0.05]},
    "C d2 ungrounded": {"gen": 0.40, "rel": [0.15, 0.85], "sup": [0.05, 0.15, 0.80], "use": [0.05, 0.10, 0.25, 0.30, 0.30]},
}
for name, c in cands.items():
    total, (r, s, u, S) = score(c)
    print(f"{name:16s} s_rel={r:.2f} s_sup={s:.2f} s_use={u:.2f} S={S:.3f} total={total:.3f}")
print("selected:", max(cands, key=lambda n: score(cands[n])[0]))

# Failure case: the critic is confidently wrong about candidate C.
wrong = dict(cands)
wrong["C d2 ungrounded"] = {"gen": 0.40, "rel": [0.99, 0.01], "sup": [0.99, 0.005, 0.005], "use": [0.90, 0.05, 0.03, 0.01, 0.01]}
for name in wrong:
    total, (r, s, u, S) = score(wrong[name])
    print(f"{name:16s} s_rel={r:.3f} s_sup={s:.3f} s_use={u:.2f} S={S:.3f} total={total:.3f}")
print("selected after critic error:", max(wrong, key=lambda n: score(wrong[n])[0]))
```

The first block shows the gate and the retrieval. The last three lines show the critique. Candidate C wins in the last block because its critic was wrong, not because the segment is grounded.

## What a wrong critic does

The selection rule trusts the critic. Here candidate C is ungrounded, since passage 2 is about maintenance schedules, not temperature. If the critic instead says C is relevant ($s_{\text{rel}} = 0.99$) and fully supported ($s_{\text{sup}} = 0.99$), its critique score rises to $2.43$ and C's total reaches $2.83$, above A's $2.45$.

![Two stacked bars for candidate C, one as measured and one with a confidently wrong critic, with a dashed line marking candidate A's total of 2.45; the wrong-critic bar crosses the line](diagrams/41.2-critic-error.svg "A confidently wrong critic moves candidate C above candidate A.")

Nothing in the rule detects this. The critic scores are themselves model outputs, so a score that looks confident is not evidence that the segment is grounded. This is the strongest objection to the method. The paper reports critic agreement with GPT-4 labels (above 90% on most categories, by the authors' account); I did not read the per-category tables, so judge the rate there.

## Common traps

> [!TRAP]
> **Prompting is not training.** Writing "[Retrieve]" into a prompt does not give the model Self-RAG behaviour. The paper trains the generator on data labelled by a critic, and the reflection tokens are part of its vocabulary.

> [!TRAP]
> **The threshold is a setting, not a constant.** A lower threshold retrieves more often. Tune it on your own data; the paper's $0.2$ is a value for its experiments.

> [!TRAP]
> **Score scale matters.** The critique terms can add up to $2.5$, while the generation term is a probability in $[0, 1]$. In this formula the critique terms dominate, so the weights are part of the method, not a detail.

> [!TRAP]
> **Critic labels inherit their source.** The paper's critic is trained on labels produced by GPT-4. Its biases and errors carry over into the selection.

## Summary

- Self-RAG has the model emit a retrieve decision and three critique tokens (`IsRel`, `IsSup`, `IsUse`) as part of its output.
- The gate fires when $P(\texttt{Retrieve}=\text{yes})$ exceeds a threshold, and the threshold sets how often retrieval runs.
- Each candidate segment's score is its generation term plus a weighted sum of normalised critique probabilities.
- The rule is only as good as the critic: a confidently wrong critic can select an ungrounded segment.

## Quiz time

### Question 1: Gate count
With the stub probabilities in the code, how many queries retrieve at threshold $t = 0.5$, and which ones?

<details><summary>Solution</summary>

Three queries: q0, q1 and q4. Their probabilities (0.91, 0.84, 0.66) exceed 0.5, and the others (0.07, 0.12) do not. The output shows the same set at $t = 0.2$.

</details>

### Question 2: Hand calculation
Candidate B has $s_{\text{rel}} = 0.35$, $s_{\text{sup}} = 0.10$, $s_{\text{use}} = 0.20$ and gen $= 0.30$. What is its total?

<details><summary>Solution</summary>

$S = 1.0 \times 0.35 + 1.0 \times 0.10 + 0.5 \times 0.20 = 0.55$, so total $= 0.30 + 0.55 = 0.85$. This matches the output.

</details>

### Question 3: Bug spotting
A colleague computes $s_{\text{use}}$ as `use[0]` without normalising by the sum of the `use` probabilities. Why could this be wrong, and when is it harmless?

<details><summary>Solution</summary>

The definition normalises over the token's values. If the probabilities sum to 1, as in the code, dividing does nothing and the result is the same. It becomes wrong when the critic's distribution is unnormalised (for example, raw logits or a partial softmax over a subset of values), because the score then depends on the scale of the output.

</details>

### Question 4: Explanation
Why does the failure case in the lesson not show a bug in the code?

<details><summary>Solution</summary>

The code computes the rule exactly as specified. The failure is in the input: the critic's probabilities are wrong. A selection rule cannot correct wrong scores, so the defence has to come from checking the critic, for example with its agreement against human labels, not from the arithmetic.

</details>
