# 41.1 — Query Transformation: HyDE (Hypothetical Document Embeddings)

## Opening Motivation & Context

In the realm of information retrieval and natural language processing, the quality of a query significantly impacts the relevance of the retrieved documents. Traditional retrieval systems rely on exact keyword matching or semantic similarity between the query and documents. However, these methods often struggle with complex or ambiguous queries. Hypothetical Document Embeddings (HyDE) is an advanced query transformation technique that addresses this challenge by generating a hypothetical document that captures the intent of the query. This hypothetical document is then used to retrieve relevant documents from the corpus.

HyDE is particularly useful in scenarios where the query is complex, ambiguous, or lacks sufficient context. By transforming the query into a hypothetical document, HyDE leverages the rich semantic information embedded in the document to improve retrieval accuracy. This technique has been shown to enhance the performance of retrieval-augmented generation (RAG) systems, making them more robust and effective.

## Core Concepts Breakdown

### [!KEY-INSIGHT]
HyDE transforms a query into a hypothetical document that captures the intent and context of the query. This hypothetical document is then used to retrieve relevant documents from the corpus, leveraging the rich semantic information embedded in the document.

### [!BEST-PRACTICE]
When implementing HyDE, ensure that the hypothetical document generation model is fine-tuned on a diverse set of queries and documents to capture a wide range of intents and contexts. Additionally, use a robust embedding model to generate embeddings for both the hypothetical document and the corpus documents to ensure high-quality retrieval.

### [!WARNING]
Be cautious when using HyDE with very short or ambiguous queries, as the generated hypothetical document may not accurately capture the intent. In such cases, consider using additional context or clarification from the user to improve the quality of the hypothetical document.

## Code Demonstration & Runtime Output

```python
import torch
from transformers import AutoTokenizer, AutoModelForSeq2SeqLM, AutoModel
from sentence_transformers import SentenceTransformer

# Load the query transformation model
query_model_name = "google/flan-t5-base"
query_tokenizer = AutoTokenizer.from_pretrained(query_model_name)
query_model = AutoModelForSeq2SeqLM.from_pretrained(query_model_name)

# Load the embedding model
embedding_model_name = "sentence-transformers/all-mpnet-base-v2"
embedding_model = SentenceTransformer(embedding_model_name)

def generate_hypothetical_document(query: str) -> str:
    """
    Generate a hypothetical document for the given query.

    Args:
        query (str): The input query.

    Returns:
        str: The generated hypothetical document.
    """
    inputs = query_tokenizer(query, return_tensors="pt", max_length=512, truncation=True)
    outputs = query_model.generate(**inputs, max_length=512, num_beams=5, early_stopping=True)
    hypothetical_document = query_tokenizer.decode(outputs[0], skip_special_tokens=True)
    return hypothetical_document

def retrieve_documents(query: str, corpus: list[str], top_k: int = 5) -> list[str]:
    """
    Retrieve the top-k most relevant documents for the given query using HyDE.

    Args:
        query (str): The input query.
        corpus (list[str]): The corpus of documents.
        top_k (int): The number of documents to retrieve.

    Returns:
        list[str]: The retrieved documents.
    """
    # Generate the hypothetical document
    hypothetical_document = generate_hypothetical_document(query)

    # Generate embeddings for the hypothetical document and corpus documents
    hypothetical_embedding = embedding_model.encode(hypothetical_document, convert_to_tensor=True)
    corpus_embeddings = embedding_model.encode(corpus, convert_to_tensor=True)

    # Compute cosine similarities between the hypothetical document and corpus documents
    similarities = torch.nn.functional.cosine_similarity(hypothetical_embedding.unsqueeze(0), corpus_embeddings)

    # Retrieve the top-k most similar documents
    top_k_indices = torch.topk(similarities, k=top_k).indices
    retrieved_documents = [corpus[i] for i in top_k_indices]

    return retrieved_documents

if __name__ == "__main__":
    # Example query and corpus
    query = "What are the benefits of using HyDE for query transformation?"
    corpus = [
        "HyDE is a query transformation technique that generates a hypothetical document for the given query.",
        "The hypothetical document captures the intent and context of the query, improving retrieval accuracy.",
        "HyDE has been shown to enhance the performance of retrieval-augmented generation systems.",
        "Query transformation techniques like HyDE are particularly useful for complex or ambiguous queries.",
        "Using HyDE can significantly improve the relevance of retrieved documents in information retrieval tasks."
    ]

    # Retrieve documents using HyDE
    retrieved_documents = retrieve_documents(query, corpus)

    # Print the retrieved documents
    print("Retrieved Documents:")
    for i, doc in enumerate(retrieved_documents, 1):
        print(f"{i}. {doc}")
```
