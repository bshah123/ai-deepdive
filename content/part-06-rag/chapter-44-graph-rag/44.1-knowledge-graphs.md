# 44.1 — LlamaIndex Core Architecture: Nodes, Indices & Retrievers

## Opening Motivation & Context

In the realm of Retrieval-Augmented Generation (RAG), LlamaIndex plays a crucial role in efficiently retrieving relevant information from large document collections. At the heart of LlamaIndex's architecture are three fundamental components: Nodes, Indices, and Retrievers. Understanding these components is essential for building effective RAG systems.

Nodes represent the smallest units of information in LlamaIndex. They are typically chunks of text extracted from documents. Indices are data structures that organize these nodes for efficient retrieval. Retrievers are the components that query these indices to fetch the most relevant nodes based on a given query.

## Core Concepts Breakdown

### Nodes

Nodes are the fundamental building blocks of information in LlamaIndex. They are created by splitting documents into smaller, manageable chunks. Each node contains a portion of text along with metadata that describes its context.

> [!KEY-INSIGHT]
> Nodes are the atomic units of information in LlamaIndex. They are created by splitting documents into smaller chunks, which are then indexed for efficient retrieval.

> [!BEST-PRACTICE]
> When creating nodes, ensure that each node contains a coherent piece of information. This helps in maintaining the context and relevance of the retrieved information.

### Indices

Indices are data structures that organize nodes for efficient retrieval. LlamaIndex supports various types of indices, including vector indices, keyword indices, and list indices. Each type of index is optimized for different types of queries.

> [!KEY-INSIGHT]
> Indices are data structures that organize nodes for efficient retrieval. Different types of indices are optimized for different types of queries, such as vector similarity, keyword matching, or sequential access.

> [!WARNING]
> Choosing the wrong type of index can significantly impact the performance and accuracy of your retrieval system. Ensure that you select the index type that best matches your query requirements.

### Retrievers

Retrievers are the components that query indices to fetch the most relevant nodes based on a given query. LlamaIndex provides various types of retrievers, including vector retrievers, keyword retrievers, and hybrid retrievers. Each type of retriever uses a different strategy to match queries with nodes.

> [!KEY-INSIGHT]
> Retrievers are the components that query indices to fetch the most relevant nodes based on a given query. Different types of retrievers use different strategies to match queries with nodes, such as vector similarity, keyword matching, or a combination of both.

> [!BEST-PRACTICE]
> When using retrievers, consider the trade-offs between precision and recall. A retriever that is too strict may miss relevant nodes, while a retriever that is too lenient may include irrelevant nodes.

## Code Demonstration & Runtime Output

```python
from typing import List, Dict, Any
from llama_index.core import Document, VectorStoreIndex, SimpleDirectoryReader
from llama_index.core.node_parser import SimpleNodeParser
from llama_index.core.retrievers import VectorIndexRetriever
from llama_index.core.query_engine import RetrieverQueryEngine

def create_nodes(documents: List[Document]) -> List[Dict[str, Any]]:
    """
    Create nodes from a list of documents.

    Args:
        documents: A list of Document objects.

    Returns:
        A list of nodes, where each node is a dictionary containing the text and metadata.
    """
    node_parser = SimpleNodeParser()
    nodes = []
    for document in documents:
        nodes.extend(node_parser.get_nodes_from_documents([document]))
    return nodes

def create_index(nodes: List[Dict[str, Any]]) -> VectorStoreIndex:
    """
    Create a vector index from a list of nodes.

    Args:
        nodes: A list of nodes, where each node is a dictionary containing the text and metadata.

    Returns:
        A VectorStoreIndex object.
    """
    index = VectorStoreIndex(nodes)
    return index

def retrieve_nodes(index: VectorStoreIndex, query: str, top_k: int = 3) -> List[Dict[str, Any]]:
    """
    Retrieve the top-k most relevant nodes based on a query.

    Args:
        index: A VectorStoreIndex object.
        query: The query string.
        top_k: The number of nodes to retrieve.

    Returns:
        A list of nodes, where each node is a dictionary containing the text and metadata.
    """
    retriever = VectorIndexRetriever(index=index, similarity_top_k=top_k)
    nodes = retriever.retrieve(query)
    return nodes

def query_engine(index: VectorStoreIndex) -> RetrieverQueryEngine:
    """
    Create a query engine from a vector index.

    Args:
        index: A VectorStoreIndex object.

    Returns:
        A RetrieverQueryEngine object.
    """
    query_engine = RetrieverQueryEngine.from_args(index)
    return query_engine

if __name__ == "__main__":
    # Load documents from a directory
    documents = SimpleDirectoryReader("data").load_data()

    # Create nodes from the documents
    nodes = create_nodes(documents)

    # Create a vector index from the nodes
    index = create_index(nodes)

    # Retrieve the top-3 most relevant nodes based on a query
    query = "What is the capital of France?"
    retrieved_nodes = retrieve_nodes(index, query, top_k=3)

    # Print the retrieved nodes
    for node in retrieved_nodes:
        print(f"Node ID: {node.id_}")
        print(f"Text: {node.text}")
        print(f"Metadata: {node.metadata}")
        print()

    # Create a query engine from the index
    query_engine = query_engine(index)

    # Query the index using the query engine
    response = query_engine.query(query)

    # Print the response
    print(response)
```

3. **create_index function**: This function takes a list of nodes and creates a `VectorStoreIndex` from them. The index is used to organize the nodes for efficient retrieval.
4. **retrieve_nodes function**: This function takes a `VectorStoreIndex` and a query string, and retrieves the top-k most relevant nodes based on the query. The retrieval is done using the `VectorIndexRetriever`, which uses vector similarity to match the query with the nodes.
