# 44.3 — SubQuestionQueryEngine & RouterQueryEngine for Complex Queries

## Opening Motivation & Context

In the realm of Retrieval-Augmented Generation (RAG), complex queries often require breaking down into simpler sub-questions. This lesson explores two powerful query engines from LlamaIndex: `SubQuestionQueryEngine` and `RouterQueryEngine`. These tools are designed to handle complex queries by decomposing them into manageable sub-questions and routing them to the most appropriate tools or data sources.

## Core Concepts Breakdown

### SubQuestionQueryEngine

The `SubQuestionQueryEngine` is designed to break down complex queries into simpler sub-questions. This approach leverages the power of decomposition to tackle intricate problems systematically.

> [!KEY-INSIGHT]
> Complex queries can be more effectively addressed by breaking them down into simpler, more manageable sub-questions. This approach enhances the accuracy and efficiency of the retrieval and generation process.

> [!BEST-PRACTICE]
> Use `SubQuestionQueryEngine` when dealing with complex queries that can be logically decomposed into simpler sub-questions. This ensures that each sub-question is addressed with the appropriate context and data.

> [!WARNING]
> Ensure that the sub-questions generated are logically consistent and contextually relevant to the original query. Inconsistent or irrelevant sub-questions can lead to inaccurate results.

### RouterQueryEngine

The `RouterQueryEngine` is designed to route queries to the most appropriate tools or data sources based on predefined rules or conditions. This approach ensures that each query is handled by the most suitable tool, enhancing the overall efficiency and accuracy of the system.

> [!KEY-INSIGHT]
> Routing queries to the most appropriate tools or data sources can significantly enhance the efficiency and accuracy of the retrieval and generation process.

> [!BEST-PRACTICE]
> Use `RouterQueryEngine` when you have multiple tools or data sources that can handle different types of queries. Define clear routing rules to ensure that each query is directed to the most suitable tool.

> [!WARNING]
> Ensure that the routing rules are well-defined and unambiguous. Ambiguous or overlapping routing rules can lead to queries being directed to the wrong tools, resulting in inaccurate or irrelevant results.

## Code Demonstration & Runtime Output

```python
from typing import List, Dict, Any
from llama_index.core.query_engine import SubQuestionQueryEngine, RouterQueryEngine
from llama_index.core.tools import QueryEngineTool, ToolMetadata
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader

def setup_query_engines() -> Dict[str, Any]:
    # Load documents
    documents = SimpleDirectoryReader("data").load_data()

    # Create vector store index
    index = VectorStoreIndex.from_documents(documents)

    # Create query engines
    query_engine = index.as_query_engine()
    sub_query_engine = SubQuestionQueryEngine.from_defaults(query_engine=query_engine)

    # Create tools
    tools = [
        QueryEngineTool(
            query_engine=query_engine,
            metadata=ToolMetadata(
                name="vector_tool",
                description="Useful for answering questions about the author's work",
            ),
        ),
        QueryEngineTool(
            query_engine=sub_query_engine,
            metadata=ToolMetadata(
                name="sub_question_tool",
                description="Useful for answering complex questions that can be broken down into simpler sub-questions",
            ),
        ),
    ]

    # Create router query engine
    router_query_engine = RouterQueryEngine.from_defaults(
        query_engine_tools=tools,
    )

    return {
        "query_engine": query_engine,
        "sub_query_engine": sub_query_engine,
        "router_query_engine": router_query_engine,
    }

def main():
    query_engines = setup_query_engines()

    # Example queries
    simple_query = "What is the main theme of the author's work?"
    complex_query = "What is the main theme of the author's work and how does it compare to other works in the same genre?"

    # Query using the basic query engine
    print("Basic Query Engine Response:")
    response = query_engines["query_engine"].query(simple_query)
    print(response)

    # Query using the sub-question query engine
    print("\nSub-Question Query Engine Response:")
    response = query_engines["sub_query_engine"].query(complex_query)
    print(response)

    # Query using the router query engine
    print("\nRouter Query Engine Response:")
    response = query_engines["router_query_engine"].query(complex_query)
    print(response)

if __name__ == "__main__":
    main()
```

## Summary & Key Takeaways

- **SubQuestionQueryEngine**: Breaks down complex queries into simpler sub-questions for more effective retrieval and generation.
- **RouterQueryEngine**: Routes queries to the most appropriate tools or data sources based on predefined rules.
- **Best Practices**: Use `SubQuestionQueryEngine` for complex queries that can be decomposed and `RouterQueryEngine` for routing queries to the most suitable tools.
- **Warnings**: Ensure that sub-questions and routing rules are logically consistent and contextually relevant to avoid inaccurate results.
