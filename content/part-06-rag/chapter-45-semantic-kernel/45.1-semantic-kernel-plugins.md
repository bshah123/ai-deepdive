# 45.1 — Microsoft Semantic Kernel: Native Function Plugins & Kernels

## Opening Motivation & Context

Microsoft Semantic Kernel is a lightweight, open-source SDK that lets you easily integrate cutting-edge Large Language Models (LLMs) like OpenAI, Azure OpenAI, or Hugging Face into your .NET applications. One of its most powerful features is the ability to create and use native function plugins and kernels, which allow you to encapsulate and orchestrate complex logic in a way that's both efficient and easy to manage.

In this lesson, we'll explore how to create native function plugins and kernels using Microsoft Semantic Kernel. We'll cover the core concepts, demonstrate how to implement them with code, and provide practical examples to help you get started.

## Core Concepts Breakdown

### Native Function Plugins

Native function plugins are .NET classes that contain methods you want to expose to your Semantic Kernel. These methods can be used to encapsulate complex logic, perform calculations, or interact with external systems. By creating native function plugins, you can extend the capabilities of your Semantic Kernel and make it more versatile.

> [!KEY-INSIGHT]
> Native function plugins allow you to encapsulate complex logic in a way that's easy to manage and reuse. They can be used to extend the capabilities of your Semantic Kernel and make it more versatile.

> [!BEST-PRACTICE]
> When creating native function plugins, make sure to follow the Single Responsibility Principle. Each plugin should have a clear, focused purpose, and its methods should be designed to perform specific tasks.

### Kernels

A kernel is the central component of Microsoft Semantic Kernel. It's responsible for managing the plugins and orchestrating their execution. By creating and configuring a kernel, you can define the behavior of your Semantic Kernel and control how it interacts with the plugins.

> [!KEY-INSIGHT]
> A kernel is the central component of Microsoft Semantic Kernel. It's responsible for managing the plugins and orchestrating their execution.

> [!WARNING]
> When working with kernels, be careful not to overload them with too many plugins. This can lead to performance issues and make it difficult to manage the overall behavior of your Semantic Kernel.

## Code Demonstration & Runtime Output

Let's start by creating a simple native function plugin and a kernel to manage it. We'll create a plugin called `MathPlugin` that contains methods for performing basic mathematical operations.

```python
from semantic_kernel import Kernel
from semantic_kernel.orchestration import SKContext
from semantic_kernel.skill_definition import sk_function

class MathPlugin:
    @sk_function(
        description="Adds two numbers together",
        name="add",
    )
    def add(self, context: SKContext) -> str:
        num1 = float(context.variables["num1"])
        num2 = float(context.variables["num2"])
        result = num1 + num2
        return str(result)

    @sk_function(
        description="Subtracts two numbers",
        name="subtract",
    )
    def subtract(self, context: SKContext) -> str:
        num1 = float(context.variables["num1"])
        num2 = float(context.variables["num2"])
        result = num1 - num2
        return str(result)

if __name__ == "__main__":
    # Create a kernel
    kernel = Kernel()

    # Import the MathPlugin
    math_plugin = kernel.import_skill(MathPlugin(), "math")

    # Set the input variables
    context = kernel.create_new_context()
    context.variables["num1"] = "5"
    context.variables["num2"] = "3"

    # Call the add method
    result = math_plugin["add"].invoke(context)
    print(f"Addition result: {result}")

    # Call the subtract method
    result = math_plugin["subtract"].invoke(context)
    print(f"Subtraction result: {result}")
```

```text
Output:
Addition result: 8.0
Subtraction result: 2.0
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We start by importing the necessary modules from the `semantic_kernel` package.
2. **MathPlugin Class**: We define a class called `MathPlugin` that contains two methods, `add` and `subtract`. These methods are decorated with the `@sk_function` decorator, which allows them to be exposed as functions in the Semantic Kernel.
3. **add Method**: The `add` method takes an `SKContext` object as input, extracts the values of `num1` and `num2` from the context variables, adds them together, and returns the result as a string.
4. **subtract Method**: The `subtract` method is similar to the `add` method, but it subtracts `num2` from `num1` instead of adding them.
5. **Main Block**: In the `if __name__ == "__main__":` block, we create a kernel, import the `MathPlugin`, set the input variables, and call the `add` and `subtract` methods.

> [!ADVANCED]
> When you call the `invoke` method on a function, the Semantic Kernel creates a new `SKContext` object and passes it to the function. The function can then access the input variables and perform its logic. The result is then returned as a string and can be used by the calling code.

The bug in the code is that it attempts to divide by zero, which is not allowed in mathematics. To fix this, you should add a check to ensure that `num2` is not zero before performing the division.

```python
from semantic_kernel import Kernel
from semantic_kernel.orchestration import SKContext
from semantic_kernel.skill_definition import sk_function

class MathPlugin:
    @sk_function(
        description="Divides two numbers",
        name="divide",
    )
    def divide(self, context: SKContext) -> str:
        num1 = float(context.variables["num1"])
        num2 = float(context.variables["num2"])
        if num2 == 0:
            return "Error: Division by zero"
        result = num1 / num2
        return str(result)

if __name__ == "__main__":
    kernel = Kernel()
    math_plugin = kernel.import_skill(MathPlugin(), "math")
    context = kernel.create_new_context()
    context.variables["num1"] = "10"
    context.variables["num2"] = "0"
    result = math_plugin["divide"].invoke(context)
    print(f"Division result: {result}")
```
