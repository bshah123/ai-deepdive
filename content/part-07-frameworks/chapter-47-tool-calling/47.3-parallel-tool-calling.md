A model can ask for several tools in one turn, and it can be constrained to write arguments that match a schema. In this lesson you will time a batch of parallel calls, return their results in the form the API expects, and build a toy constrained decoder that only writes schema-valid text. You will also see exactly what that guarantee does not cover.

**You need:** the function-calling loop (Lesson 47.2) and JSON Schema (Lesson 47.1). Softmax turns a vector of scores into probabilities that are positive and sum to 1.

## The problem: three calls, one turn

A user asks for the weather in Tokyo, flights to Paris and a hotel. The model can answer with three `tool_use` blocks in one assistant message. Your harness then decides the latency. Running the calls one after another takes the sum of their times. Running independent calls at once takes the longest one. If a call needs another call's output, it must wait, so the critical path (the longest chain of dependent calls) sets the total.

![Three schedules for the same three calls: sequential, parallel, and parallel with a dependency](diagrams/47.3-timelines.svg "Same three calls under three schedules. Latencies are simulated.")

Latencies are 0.9, 1.4 and 1.1 seconds, and the hotel search depends on the flight search.

```python
# ---------- 1. Scheduling: what parallel calls buy ----------
latency = {"get_weather": 0.9, "search_flights": 1.4, "search_hotels": 1.1}  # simulated seconds
print(f"sequential, 3 calls: {sum(latency.values()):.1f} s")
print(f"parallel, 3 independent calls: {max(latency.values()):.1f} s")

deps = {"get_weather": [], "search_flights": [], "search_hotels": ["search_flights"]}
finish = {}
def finish_time(name):
    if name not in finish:
        start = max((finish_time(d) for d in deps[name]), default=0.0)
        finish[name] = start + latency[name]
    return finish[name]
print(f"hotel search depends on flights: {max(finish_time(n) for n in deps):.1f} s")

# ---------- 2. One assistant turn, several tool_use blocks ----------
turn = [
    {"type": "tool_use", "id": "toolu_1", "name": "get_weather"},
    {"type": "tool_use", "id": "toolu_2", "name": "search_flights"},
    {"type": "tool_use", "id": "toolu_3", "name": "search_hotels"},
]
done = {}
for call in sorted(turn, key=lambda c: latency[c["name"]]):   # completion order
    done[call["id"]] = {"type": "tool_result", "tool_use_id": call["id"],
                        "content": f"{call['name']} finished"}
user_message = [done[c["id"]] for c in turn]                   # one message, request order
print("completion order:", list(done))
print("user message:", [r["tool_use_id"] for r in user_message])
```

```output
sequential, 3 calls: 3.4 s
parallel, 3 independent calls: 1.4 s
hotel search depends on flights: 2.5 s
completion order: ['toolu_1', 'toolu_3', 'toolu_2']
user message: ['toolu_1', 'toolu_2', 'toolu_3']
```

The code assumes each call has a fixed latency and that the harness can run as many calls at once as it likes. Rate limits and server-side queues break both assumptions, so measure your own latencies before you rely on these numbers.

The three schedules take 3.4 s, 1.4 s and 2.5 s. In the dependent case the hotel search starts when the flight search returns at 1.4 s and then takes 1.1 s more. Parallelism helps only for independent calls, and the model cannot tell you which calls share state. Your harness has to know that.

<details><summary>Run locally: real threads, timing varies by machine</summary>

```python
import time
from concurrent.futures import ThreadPoolExecutor

def tool(name, seconds):
    time.sleep(seconds)              # stands in for a network call
    return f"{name} finished"

calls = [("get_weather", 0.9), ("search_flights", 1.4), ("search_hotels", 1.1)]

t0 = time.perf_counter()
for name, s in calls:
    tool(name, s)
print(f"sequential: {time.perf_counter() - t0:.1f} s")

t0 = time.perf_counter()
with ThreadPoolExecutor() as ex:
    futures = [ex.submit(tool, name, s) for name, s in calls]
    outputs = [f.result() for f in futures]   # results come back in request order
print(f"threaded:   {time.perf_counter() - t0:.1f} s")
print(outputs)
```

```output
sequential: 3.4 s
threaded:   1.4 s
['get_weather finished', 'search_flights finished', 'search_hotels finished']
```

The threaded run matches the analytic schedule to within 0.1 s here. Real network calls add jitter, so treat these numbers as a model, not a benchmark.

</details>

## One turn, one reply

Anthropic's documentation says that by default a model may return several `tool_use` blocks in one response. You can run them concurrently, in order, or in any mix. But every result must come back in the **next user message**, each matched to its call by `tool_use_id` (Anthropic, parallel tool use docs). Results may finish in any order. The order of your reply is what the model sees.

The output above shows this. The calls finished in the order 1, 3, 2, but the user message keeps the request order. If you skip a call, return a result for it anyway with `is_error: true` and a short explanation (Anthropic, parallel tool use docs).

![Correct: one assistant message with three tool_use blocks and one user message with three tool_result blocks. Wrong: three separate user messages](diagrams/47.3-message-shape.svg "Where the results go decides whether the model keeps calling in parallel.")

> [!TRAP]
> Returning each result in its own user message is the most common cause of a model that stops calling tools in parallel. The API accepts it, but the docs say it teaches the model to make one call per turn (Anthropic, parallel tool use docs, troubleshooting).

## Constrained decoding: a mask at each step

A language model writes one token at a time. Nothing stops it from writing `"days": "3` or a trailing comma. Setting `strict: true` on a tool makes the `input` of each `tool_use` block follow that tool's `input_schema`. The docs describe this as grammar-constrained sampling: the decoder is limited to outputs that the schema allows (Anthropic, strict tool use). The mechanism is a mask:

1. Find the next tokens that keep the output a prefix of some valid string.
2. Set the logit (pre-softmax score) of every other token to minus infinity.
3. Apply softmax to what remains and sample.

Masked tokens get probability zero, so every finished output lies in the language. The problem is not exotic: nothing in the decoding step forces it to close a brace or a quote, so without a mask a structured call depends on the model getting every token right. Willard and Louf (2023) build this for regular expressions and context-free grammars by indexing the vocabulary against an automaton. Their abstract reports little overhead, a claim I did not measure (arXiv:2307.09702).

Worked by hand, at this step: the raw softmax gives London 0.790 and the other 28 tokens share the remaining 0.210. The legal set is {Tokyo, London, Paris, Tok, Lon, Par}, and its raw mass is 0.820. Masking sets each blocked logit to minus infinity, so its $e^{-\infty} = 0$ contribution vanishes, and renormalising divides by 0.820. London becomes $0.790 / 0.820 \approx 0.963$. The mask changes nothing about how the model ranks legal tokens; it only removes the illegal mass.

![One decoding step after the opening quote: raw probabilities and masked probabilities for eight tokens](diagrams/47.3-mask-step.svg "The mask removes every token that cannot lead to a valid string, then renormalises.")

The next block is a toy, and the stub model is mine. The language has 27 strings, the vocabulary has 29 tokens, and the stub is random logits plus a boost of 6.0 towards one intended string. It shows the mechanism only. It is not a measurement of any real model.

```python
import json
import numpy as np

# ---------- 3. Constrained decoding over a finite language ----------
CITIES = ["Tokyo", "London", "Paris"]
VALID = [f'{{"city": "{c}", "days": {d}}}' for c in CITIES for d in range(1, 10)]
VALID_SET = set(VALID)
PREFIXES = {s[:i] for s in VALID for i in range(len(s) + 1)}   # every character-level viable prefix
VOCAB = ["{", '"city"', ': "', "Tokyo", "London", "Paris", "Tok", "yo", "Lon", "don",
         "Par", "is", '", ', '"days"', ': ', *map(str, range(1, 10)), "}", '"}',
         "the", "hi", "<eos>"]
EOS = VOCAB.index("<eos>")
V = len(VOCAB)

def live_states(tokens):
    # A prefix is live if some sequence of vocabulary tokens completes it to a valid string.
    live = set(VALID_SET)
    changed = True
    while changed:
        changed = False
        for p in PREFIXES:
            if p not in live and any(p + t in live for t in tokens if t != "<eos>"):
                live.add(p)
                changed = True
    return live

LIVE = live_states(VOCAB)

def allowed(text, live=LIVE, tokens=VOCAB):
    ids = [i for i, t in enumerate(tokens) if t != "<eos>" and text + t in live]
    if text in VALID_SET:
        ids.append(EOS)
    return ids

def reachable_dead_ends(tokens, ok):
    # Count reachable states from which the mask allows no token and the string is not complete.
    seen, stack, dead = set(), [""], 0
    while stack:
        p = stack.pop()
        if p in seen:
            continue
        seen.add(p)
        if p in VALID_SET:
            continue
        nxt = [p + t for t in tokens if t != "<eos>" and ok(p + t)]
        if not nxt:
            dead += 1
        stack.extend(nxt)
    return dead

no_don = [t for t in VOCAB if t != "don"]
print(f"valid strings in the language: {len(VALID)}")
print("dead ends, prefix-only mask, full vocabulary:", reachable_dead_ends(VOCAB, lambda s: s in PREFIXES))
print("dead ends, prefix-only mask, without 'don':", reachable_dead_ends(no_don, lambda s: s in PREFIXES))
print("dead ends, live-state mask, full vocabulary:", reachable_dead_ends(VOCAB, lambda s: s in LIVE))
print("dead ends, live-state mask, without 'don':", reachable_dead_ends(no_don, lambda s: s in live_states(no_don)))

INTENDED = '{"city": "London", "days": 4}'
INTENDED_IDS = [VOCAB.index(t) for t in ["{", '"city"', ': "', "London", '", ', '"days"', ': ', "4", "}"]] + [EOS]
rng = np.random.default_rng(47)
W = rng.normal(0.0, 0.8, size=(V + 1, V))   # row V = start of sequence
BOOST = 6.0                                  # the "model" is confident and mostly on track

def model_logits(prev, gen):
    z = W[prev].copy()
    if len(gen) < len(INTENDED_IDS) and gen == INTENDED_IDS[:len(gen)]:
        z[INTENDED_IDS[len(gen)]] += BOOST
    return z

def softmax(z):
    e = np.exp(z - z.max())
    return e / e.sum()

def detok(ids):
    return "".join(VOCAB[i] for i in ids)

def sample(gen_rng, constrained, max_new):
    gen, finished = [], False
    for _ in range(max_new):
        z = model_logits(gen[-1] if gen else V, gen)
        if constrained:
            mask = np.full(V, -np.inf)
            mask[allowed(detok(gen))] = 0.0
            z = z + mask
        tok = int(gen_rng.choice(V, p=softmax(z)))
        if tok == EOS:
            finished = True
            break
        gen.append(tok)
    return detok(gen), finished

def is_valid(text):
    try:
        obj = json.loads(text)
    except json.JSONDecodeError:
        return False
    return (isinstance(obj, dict) and list(obj) == ["city", "days"]
            and obj["city"] in CITIES and type(obj["days"]) is int and 1 <= obj["days"] <= 9)

print("intended string is valid:", is_valid(INTENDED))

# Mask at one step: the model has just written '{"city": "'
prefix_ids = [VOCAB.index(t) for t in ["{", '"city"', ': "']]
raw = softmax(model_logits(prefix_ids[-1], prefix_ids))
legal = allowed('{"city": "')
mask = np.full(V, -np.inf)
mask[legal] = 0.0
masked = softmax(np.log(raw) + mask)
print('state: {"city": "')
print("  allowed tokens:", [VOCAB[i] for i in legal])
print(f"  probability the model put on legal tokens: {raw[legal].sum():.3f}")
for i in sorted(range(V), key=lambda i: -raw[i])[:8]:
    tag = "allowed" if mask[i] == 0 else "blocked"
    print(f"  {VOCAB[i]!r:<12} raw {raw[i]:.3f}  masked {masked[i]:.3f}  {tag}")

N = 2000
def run(constrained, max_new):
    gen_rng = np.random.default_rng(7)
    return [sample(gen_rng, constrained, max_new) for _ in range(N)]

def summary(name, runs):
    texts = [t for t, _ in runs]
    valid = np.mean([is_valid(t) for t in texts])
    finished = np.mean([f for _, f in runs])
    city = np.mean([is_valid(t) and json.loads(t)["city"] == "London" for t in texts])
    exact = np.mean([t == INTENDED for t in texts])
    print(f"{name:<26} valid {valid:6.1%}  finished {finished:6.1%}  "
          f"city=London {city:6.1%}  exact {exact:6.1%}")

summary("unconstrained, 14 tokens", run(False, 14))
summary("constrained, 14 tokens", run(True, 14))
summary("constrained, 5 tokens", run(True, 5))
```

```output
valid strings in the language: 27
dead ends, prefix-only mask, full vocabulary: 1
dead ends, prefix-only mask, without 'don': 2
dead ends, live-state mask, full vocabulary: 0
dead ends, live-state mask, without 'don': 0
intended string is valid: True
state: {"city": "
  allowed tokens: ['Tokyo', 'London', 'Paris', 'Tok', 'Lon', 'Par']
  probability the model put on legal tokens: 0.820
  'London'     raw 0.790  masked 0.963  allowed
  '"}'         raw 0.031  masked 0.000  blocked
  '}'          raw 0.016  masked 0.000  blocked
  ': "'        raw 0.014  masked 0.000  blocked
  'don'        raw 0.012  masked 0.000  blocked
  '8'          raw 0.010  masked 0.000  blocked
  '", '        raw 0.009  masked 0.000  blocked
  '7'          raw 0.009  masked 0.000  blocked
unconstrained, 14 tokens   valid  39.1%  finished  57.7%  city=London  39.1%  exact  39.1%
constrained, 14 tokens     valid 100.0%  finished 100.0%  city=London  97.2%  exact  96.4%
constrained, 5 tokens      valid   0.0%  finished   0.0%  city=London   0.0%  exact   0.0%
```

How the toy works, in four steps:

- `allowed()` returns the vocabulary ids whose addition keeps the text inside the live-state set `LIVE`, plus the end-of-string token when the text is complete.
- `model_logits()` gives a random row of a 30-by-29 matrix `W`, indexed by the previous token, and adds the boost to the intended next token while the output is on track.
- `sample()` applies the mask (when `constrained` is true) before the softmax, draws one token, and stops at the end-of-string token or the cap.
- `is_valid()` parses the text with `json.loads`, then checks the keys, the city, and the integer range of `days`.

Unconstrained sampling produced valid JSON for 39.1% of 2,000 samples. With the mask, every sample was valid and finished. Of the constrained outputs, 97.2% named London, and 96.4% matched the intended string exactly. In this run, every valid unconstrained output was the intended string; the other samples were invalid.

![Grouped bars: unconstrained versus constrained decoding on valid JSON, city equals London, and exact match](diagrams/47.3-validity.svg "2,000 samples per setting. The 5-token cap row is in the note.")

> [!KEY-INSIGHT]
> The mask guarantees form, not content. 2.8% of constrained outputs named a different city, and every one of them was schema-valid. The schema says the value must be one of the allowed strings; it does not say which one is right.

Length is a second limit. Every valid string here takes 9 tokens, so a 5-token cap produced no complete output at all. An output cut off early is not valid JSON. Check `stop_reason` in your SDK. The structured-outputs page I read does not document the `max_tokens` case, so test it yourself.

## The dead-end trap

My first version checked only whether the characters so far were a prefix of a valid string. That fails. After `{"city"`, the token `: ` gives `{"city": `, which is a legal prefix, but no token starts with a quote, so nothing can follow it. With every logit masked to minus infinity, softmax returned NaN, and the sampler stopped with "Probabilities contain NaN". The same happens after `Lon` if the vocabulary has no `don`.

![A legal prefix with no legal continuation, and a legal path through "don"](diagrams/47.3-dead-end.svg "Prefix checks alone allow dead ends. A live-state check does not.")

The fix is to allow a token only when the new state is live: some sequence of vocabulary tokens completes it to a valid string. This is my reconstruction; I have not checked how the Willard and Louf index handles the same mismatch. With the live-state rule, the count of reachable dead ends is 0 both with the full vocabulary and without `don`.

One more subtlety. Per-step renormalisation samples each token from the model's distribution restricted to the live tokens, given the prefix so far. It does not, in general, give the model's distribution conditioned on the whole output lying in the language. The two agree only in special cases. The strict tool use docs state the guarantee as schema conformance and do not describe the sampling distribution (Anthropic, strict tool use docs). This is my own reasoning, not a cited result.

## Parallel calls and strict mode together

Strict mode applies to each tool's input, so every call in a parallel batch can be schema-valid. Parallel calling is on by default. To turn it off, set `disable_parallel_tool_use: true` inside the `tool_choice` object; it is not a top-level field (Anthropic, parallel tool use docs).

Batching is your decision, not the model's. Read-only lookups are safe to run together; calls that write or charge a card need an order that your harness enforces.

The schema must stay inside the supported subset. The structured-outputs docs say `additionalProperties` must be `false` on objects, `minimum` and `maximum` are not supported, `oneOf` is not supported (use `anyOf`), and an unsupported feature returns a 400 error (Anthropic, structured outputs docs).

## Common traps

> [!TRAP]
> A result that fails must still get a `tool_result`. Leaving it out breaks the one-reply-per-`tool_use` rule and makes the next request fail.

> [!TRAP]
> Schema-valid is not correct. A strict `city` field can still hold the wrong city. Validate business rules after the call.

> [!TRAP]
> If call B needs the output of call A, do not batch them as independent. Run them in order, or return `is_error: true` for B when A fails.

> [!TRAP]
> A prefix-only mask can deadlock. Mask on live states, and test the mask for dead ends on your real vocabulary.

> [!TRAP]
> A cut-off output is not a valid output. Check the stop reason before you parse.

## Summary

- A batch of independent calls takes the longest call's time; dependent calls take the critical path.
- All results go back in one user message, matched by `tool_use_id`; split messages teach the model to stop calling in parallel.
- Constrained decoding masks tokens that cannot lead to a valid string, then renormalises. Every output is valid by construction.
- The mask must work on live states, or it can deadlock on a legal prefix.
- Schema validity does not mean the values are correct, and a truncated output is not valid.

## Quiz time

### Question 1: Calculation

Three independent calls take 0.6 s, 2.0 s and 0.8 s. What is the wall-clock time if all three run in parallel? If the 0.8 s call must wait for the 0.6 s call, what is it?

<details><summary>Solution</summary>

Parallel: the longest call, 2.0 s. With the dependency, the chain 0.6 + 0.8 = 1.4 s is shorter than 2.0 s, so the total is still 2.0 s.

</details>

### Question 2: Prediction

At the step in the mask figure, suppose only `'London'` (raw 0.790) and `'"}'` (raw 0.031) were legal. What is London's masked probability?

<details><summary>Solution</summary>

Renormalise over the legal mass: 0.790 / (0.790 + 0.031) = 0.790 / 0.821 ≈ 0.962. The blocked token gets 0.

</details>

### Question 3: Bug-spotting

A loop appends one user message per `tool_result`. A batch has three calls. What goes wrong, and what is the fix?

<details><summary>Solution</summary>

The API accepts the messages, but the docs say the pattern teaches the model to make one call per turn, so parallelism drops off. Fix: append one user message whose content list holds all three `tool_result` blocks, each with its `tool_use_id`.

</details>

### Question 4: Explanation

Why can strict mode return a valid `city` that is still the wrong answer for the user?

<details><summary>Solution</summary>

The mask removes only tokens that break the schema. Among the legal choices, the model's own probabilities decide the value. In the toy run, 2.8% of constrained outputs named a different city, all valid.

</details>

### Question 5: Bug-spotting

A decoder allows any token whose text is a prefix of a valid string. It sometimes stops with "Probabilities contain NaN". Why, and what fixes it?

<details><summary>Solution</summary>

It reached a legal prefix with no legal continuation, such as `{"city": `. Every logit is masked, so softmax has no mass. Fix: allow a token only if the resulting state is live, meaning some vocabulary-token sequence completes it to a valid string.

</details>
