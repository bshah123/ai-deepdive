In this lesson you will build the ReAct loop, the pattern in which a language model writes a *thought* and an *action* that calls a tool, reads the tool's *observation*, and then writes the next step. You will trace one episode by hand, run the loop in plain Python, and measure what breaks when the loop loses its observations or its formatting.

**You need:** tool schemas and the function-calling loop (Lesson 47.2). No model weights are needed: the code uses a scripted stand-in for the model.

## The problem ReAct solves

A language model answers from what it learned in training. Asked "What is the cheapest lamp that is in stock?", it can only guess, because stock levels change after training. A model that writes the whole answer in one pass has no way to look anything up.

Two earlier ideas each solve half of this. Chain-of-thought prompting (Wei et al., 2022) makes the model write its reasoning before the answer, but that reasoning uses only what the model already knows. Tool use lets the model call functions, but gives no plan for what to do with the results. ReAct (Yao et al., 2022) interleaves the two, so each tool result becomes evidence for the next thought.

The paper's abstract reports that ReAct "outperforms imitation and reinforcement learning methods by an absolute success rate of 34% and 10%" on ALFWorld and WebShop, two interactive decision-making benchmarks. The abstract does not give the baseline rates, so read the paper for the setup before you quote these numbers.

## Intuition: a loop over a growing transcript

![The loop: transcript, model, parser, tool, and observation returned to the transcript; a note shows the failure without observations](diagrams/48.1-react-loop.svg "One ReAct step. The observation goes back into the transcript before the next step.")

The model never touches the outside world. It only writes text. The loop does four things: it sends the transcript to the model, parses the model's text for an action, runs the named tool, and appends the result as an observation. Then it repeats. The transcript is the model's only memory, so anything missing from it does not exist for the model.

The loop uses three fixed line formats: a thought, an action and an observation. A thought is free text. An action is `Action: Name[argument]`, and the special action `finish[answer]` ends the episode. The loop writes each tool result as an `Observation:` line.

## Worked example, by hand

The catalogue has four items: L1 is a lamp priced 35 and in stock, L2 is a lamp priced 22 and out of stock, L3 is a lamp priced 28 and in stock, and D1 is a desk priced 90 and in stock. The question is "What is the cheapest lamp that is in stock?"

![Five steps of the episode: search, three info calls, and finish, with the prompt words at each step as bars](diagrams/48.1-worked-trace.svg "The worked episode. Bars show the words the model reads at each step.")

1. **Step 1.** The transcript holds only the question, 10 words. The model writes `Action: search[lamp]`. The tool returns `L1, L2, L3`.
2. **Step 2.** The model asks `info[L1]` and gets `price 35, in stock`.
3. **Step 3.** It asks `info[L2]` and gets `price 22, out of stock`. The price is lowest, but the item cannot be bought, so it is excluded.
4. **Step 4.** It asks `info[L3]` and gets `price 28, in stock`.
5. **Step 5.** It writes `finish[L3]`. The loop stops.

Each step adds a thought, an action and an observation, so the prompt grows at every step. Counting whitespace-separated words at each step gives 10, 24, 41, 59 and 76, which the code prints; the episode reads 210 words in total. Words are a rough proxy for tokens: a real tokenizer will give different counts.

## Runnable code

The model in this code is `scripted_model`, a fixed rule written in Python. It reads the transcript and writes the next step, as a language model would, but it has no knowledge of its own. That choice is deliberate. The loop is the thing to learn, and a fixed rule makes every number in this lesson reproducible. The rule has no real reasoning, so do not read the output as evidence about how well a language model would do.

The code has four parts: the tools, the parser, the scripted model, and the loop. The last section runs experiments and prints their results.

```python
import math
import random
import re

# A tiny catalogue that the tools can read.
CATALOG = {
    "L1": {"category": "lamp", "price": 35, "in_stock": True},
    "L2": {"category": "lamp", "price": 22, "in_stock": False},
    "L3": {"category": "lamp", "price": 28, "in_stock": True},
    "D1": {"category": "desk", "price": 90, "in_stock": True},
}
ORIGINAL = dict(CATALOG)

def search(category):
    hits = [k for k, v in CATALOG.items() if v["category"] == category]
    return ", ".join(hits) if hits else "no items found"

def info(item_id):
    if item_id not in CATALOG:
        return f"error: unknown item {item_id}"
    v = CATALOG[item_id]
    return f"price {v['price']}, " + ("in stock" if v["in_stock"] else "out of stock")

TOOLS = {"search": search, "info": info}
ACTION_RE = re.compile(r"^Action: (\w+)\[(.*)\]$")

def parse_action(line):
    m = ACTION_RE.match(line.strip())
    return (m.group(1), m.group(2)) if m else None

def scripted_model(lines):
    """Stand-in for an LLM: it reads only the transcript lines, as a model reads its context."""
    lamps, facts, pending = None, {}, None
    for line in lines:
        if line.startswith("Action: "):
            pending = parse_action(line)
        elif line.startswith("Observation: ") and pending is not None:
            name, arg = pending
            obs = line[len("Observation: "):]
            if name == "search":
                lamps = obs.split(", ")
            elif name == "info" and not obs.startswith("error"):
                facts[arg] = obs
            pending = None
    if lamps is None:
        return "Thought: I need the list of lamps first.\nAction: search[lamp]"
    todo = [x for x in lamps if x not in facts]
    if todo:
        return f"Thought: I still need the price and stock of {todo[0]}.\nAction: info[{todo[0]}]"
    best = None
    for x in lamps:
        price = int(facts[x].split()[1].rstrip(","))
        if facts[x].endswith("in stock") and (best is None or price < best[1]):
            best = (x, price)
    return f"Thought: The cheapest lamp in stock is {best[0]}.\nAction: finish[{best[0]}]"

def react(question, model, max_steps=8, observe=True, feedback=True, p_slip=0.0, rng=None):
    lines = [f"Question: {question}"]
    prompt_words = []
    for step in range(1, max_steps + 1):
        prompt_words.append(sum(len(l.split()) for l in lines))
        text = model(lines)
        if p_slip and rng.random() < p_slip:      # formatting slip: the brackets are lost
            text = text.replace("[", " ").replace("]", "")
        lines.extend(text.splitlines())
        action_line = [l for l in text.splitlines() if l.startswith("Action: ")][-1]
        parsed = parse_action(action_line)
        if parsed is None:
            if not feedback:
                return {"answer": None, "steps": step, "status": "parse failure",
                        "prompt_words": prompt_words, "lines": lines}
            lines.append("Observation: error, could not parse the action; write it as Name[argument]")
            continue
        name, arg = parsed
        if name == "finish":
            return {"answer": arg, "steps": step, "status": "finished",
                    "prompt_words": prompt_words, "lines": lines}
        obs = TOOLS[name](arg) if name in TOOLS else f"error: unknown tool {name}"
        if observe:
            lines.append(f"Observation: {obs}")
    return {"answer": None, "steps": max_steps, "status": "budget exhausted",
            "prompt_words": prompt_words, "lines": lines}

QUESTION = "What is the cheapest lamp that is in stock?"

# 1. One clean episode, traced by hand.
run = react(QUESTION, scripted_model)
print("status:", run["status"], "| answer:", run["answer"], "| steps:", run["steps"])
for line in run["lines"]:
    print(line)
print("prompt words per step:", run["prompt_words"])
print("total words read:", sum(run["prompt_words"]))

# 2. Does the loop need the observations? Turn them off and watch.
blind = react(QUESTION, scripted_model, observe=False)
print("without observations:", blind["status"], "after", blind["steps"], "steps")

# 3. How much context does the loop re-read as the catalogue grows?
def make_catalog(n):
    return {f"L{i}": {"category": "lamp", "price": 20 + (7 * i) % 30, "in_stock": i % 3 != 0}
            for i in range(1, n + 1)}

print("lamps  steps  total words read  last prompt")
for n in (2, 4, 8, 16, 32):
    CATALOG.clear(); CATALOG.update(make_catalog(n))
    r = react(QUESTION, scripted_model, max_steps=80)
    print(f"{n:5d}  {r['steps']:5d}  {sum(r['prompt_words']):16d}  {r['prompt_words'][-1]:11d}")
CATALOG.clear(); CATALOG.update(ORIGINAL)

# 4. Formatting slips: a lost bracket on a fraction p of model outputs.
def exact_success(p, feedback):
    if not feedback:                       # 5 actions, none may slip
        return (1 - p) ** 5
    # 5 clean attempts within 8 steps: at most 3 slips before the 5th clean attempt
    return sum(math.comb(4 + f, 4) * (1 - p) ** 5 * p ** f for f in range(4))

def success_rate(p, feedback, trials=2000, seed=48):
    rng = random.Random(seed)
    ok = sum(react(QUESTION, scripted_model, p_slip=p, rng=rng, feedback=feedback)["answer"] == "L3"
             for _ in range(trials))
    return ok / trials

print("p_slip  no-feedback sim  exact   with-feedback sim  exact")
for p in (0.0, 0.1, 0.2, 0.3):
    a, b = success_rate(p, False), success_rate(p, True)
    print(f"{p:6.1f}  {a:16.3f}  {exact_success(p, False):.3f}   {b:17.3f}  {exact_success(p, True):.3f}")
```

Read the first block of output as the worked example, line by line. The loop stops at `finish` after five steps, and the words read per step match the hand count.

The second line is an ablation: the same loop with observations removed from the transcript. The rule learns nothing new, so it repeats `search[lamp]` until the budget of 8 steps runs out. This is true by construction of the rule. The general point holds for any model: the loop can only use what it sees.

The third block measures context growth. Each lamp adds one `info` step, and the search and the finish add two more, so steps equal lamps plus 2. The total words read rise from 130 to 10,900 as the lamps go from 2 to 32. Each doubling of the catalogue multiplies the total by 2.4, 2.9, 3.4 and 3.6, rising toward 4, which is the signature of quadratic growth. Each step re-reads the whole transcript, so the total grows with the square of the number of steps when each step adds a roughly constant amount. Serving stacks reuse cached attention keys and values for earlier tokens (Lesson 27.2), so the real compute cost differs from a word count; the growth of the context itself is still there.

The fourth block injects formatting slips. With no feedback, one slip ends the episode, so success is $(1-p)^5$ over five actions. With feedback, the loop returns an error observation and the rule retries. Success then needs five clean attempts inside 8 steps. If the fifth clean attempt comes after $f$ slips, it is counted by $\binom{4+f}{4}$ orderings, so the exact success probability is $\sum_{f=0}^{3} \binom{4+f}{4}(1-p)^5 p^f$. At $p = 0.1$ the exact no-feedback value is 0.590 and the simulated value is 0.603. The standard error of a 2,000-episode estimate near 0.59 is about 0.011, so the gap is within sampling noise. The simulation assumes slips are independent across steps and that a retry repeats the same action, which this rule does by design. A real model may vary its retries.

## Common traps

> [!TRAP] **Observations that never reach the prompt**
> The ablation above shows the failure: the loop repeats one action until the budget ends. The usual cause is truncating the transcript from the front, which silently drops the early observations the model still needs.

> [!TRAP] **The model writing its own observation**
> If generation does not stop at the line `Observation:`, the model invents tool results and the loop trusts them. Pass the next-observation marker as a stop sequence. This is standard practice in agent frameworks, but the loop logic here is my own reasoning; check your serving API's stop option before relying on it.

> [!TRAP] **No step budget**
> The loop ends only on `finish` or on `max_steps`. A model that keeps repeating an action will consume tokens and time without limit. A production loop also needs a cost and wall-clock cap, not only a step count.

> [!TRAP] **Errors that look like empty results**
> The `info` tool returns `error: unknown item` rather than an empty string, so the model can see the failure and change course. A tool that returns nothing for a bad input invites the model to treat the item as nonexistent.

> [!TRAP] **Ignoring context growth**
> Every step re-reads the transcript. The table above shows that cost rising faster than the number of steps. Long episodes need summarisation or pruning of old observations, not just a larger context window.

## Summary

- ReAct alternates a thought, an action and an observation. Observations are the only route from the outside world back into the model.
- The loop is a parser and a dispatcher wrapped around a model. The model sees only the transcript.
- In this toy, removing observations exhausts the budget, and a parse-failure retry keeps success at 0.81 when the slip rate is 0.3, against 0.18 without it.
- Each step re-reads the whole transcript, so total reading grows faster than the number of steps.

### Question 1: Calculation

Using the worked episode, how many words does the model read at step 4, before it writes its action?

<details>
<summary>Solution</summary>

The prompt at step 4 holds the transcript after three observations. The printed list gives 59 words for step 4 (the list is 10, 24, 41, 59, 76, one entry per step). Step 4 reads 59 words and writes `info[L3]`.

### Question 2: Prediction

Suppose you run the loop with `observe=False` and a larger budget of 20 steps. What status and how many steps does it report, and why?

<details>
<summary>Solution</summary>

It reports `budget exhausted` after 20 steps. The rule learns the lamp list and prices only from observations. With none in the prompt, the rule sees no lamps and writes `search[lamp]` every time, so the episode never reaches `finish`.

</details>

### Question 3: Calculation

With a slip rate of $p = 0.2$ and no feedback, what is the probability that an episode finishes with the correct answer? Use the formula from the lesson.

<details>
<summary>Solution</summary>

The episode needs all five actions to parse, so success is $(1-0.2)^5 = 0.8^5 = 0.32768$, which prints as 0.328 in the table.

</details>

### Question 4: Bug-spotting

A colleague parses each model output with `parse_action(text)` on the whole output, where `parse_action` uses `ACTION_RE.match`. Their model always writes a `Thought:` line first. What happens, and why?

<details>
<summary>Solution</summary>

Every step fails to parse. The regular expression is anchored with `^`, and `match` checks only the start of the string. The output begins with `Thought:`, so the pattern `Action: ...` never matches at position 0. The fix is to search each line for the action, as the lesson's loop does, rather than matching the whole output.

</details>

### Question 5: Explanation

Why does the lesson's loop send the full transcript to the model at every step, rather than only the latest observation?

<details>
<summary>Solution</summary>

The rule, like a language model, has no state outside its input. If only the latest observation were sent, the model could not recall earlier results, such as the lamp list from step 1. The cost is the growing prompt measured above. Summaries or pruning can reduce that cost, but whatever is dropped is lost to the model.

</details>
