# 48.2 — Plan-and-Solve & Hierarchical Task Decomposition

## Opening Motivation & Context

Plan-and-Solve and Hierarchical Task Decomposition are fundamental cognitive architectures used in AI to break down complex problems into manageable sub-tasks. These architectures are inspired by human problem-solving processes, where we often decompose large, complex problems into smaller, more manageable parts. This approach not only simplifies the problem-solving process but also makes it more efficient and effective.

In the context of AI, Plan-and-Solve architectures involve creating a plan to solve a problem and then executing that plan. Hierarchical Task Decomposition, on the other hand, involves breaking down a complex task into a hierarchy of sub-tasks, each of which can be further decomposed if necessary. These architectures are particularly useful in domains where problems are complex and require a sequence of steps to be solved.

## Core Concepts Breakdown

### Plan-and-Solve Architecture

Plan-and-Solve is a cognitive architecture that involves two main phases: planning and execution. In the planning phase, the AI system creates a plan to solve the problem. This plan is a sequence of actions that, if executed correctly, will lead to the solution of the problem. In the execution phase, the AI system executes the plan, monitoring its progress and making adjustments as necessary.

> [!KEY-INSIGHT]
> Plan-and-Solve architectures are particularly useful for problems that require a sequence of actions to be solved. They allow the AI system to break down the problem into smaller, more manageable parts, making it easier to solve.

> [!BEST-PRACTICE]
> When using Plan-and-Solve architectures, it's important to ensure that the planning phase is thorough and accurate. A well-crafted plan can significantly improve the efficiency and effectiveness of the execution phase.

> [!WARNING]
> One common pitfall when using Plan-and-Solve architectures is creating overly complex plans. While it's important to break down the problem into smaller parts, creating too many sub-tasks can make the plan difficult to execute and monitor.

### Hierarchical Task Decomposition

Hierarchical Task Decomposition is a cognitive architecture that involves breaking down a complex task into a hierarchy of sub-tasks. Each sub-task can be further decomposed into even smaller sub-tasks, creating a tree-like structure. This approach allows the AI system to focus on one sub-task at a time, making it easier to solve the problem.

> [!KEY-INSIGHT]
> Hierarchical Task Decomposition is particularly useful for problems that can be broken down into smaller, more manageable parts. It allows the AI system to focus on one part of the problem at a time, making it easier to solve.

> [!BEST-PRACTICE]
> When using Hierarchical Task Decomposition, it's important to ensure that each sub-task is well-defined and clearly understood. A well-defined sub-task can significantly improve the efficiency and effectiveness of the problem-solving process.

> [!WARNING]
> One common pitfall when using Hierarchical Task Decomposition is creating too many levels of decomposition. While it's important to break down the problem into smaller parts, creating too many levels can make the problem-solving process more complex and difficult to manage.

## Code Demonstration & Runtime Output

```python
from typing import List, Dict, Optional

class Task:
    def __init__(self, name: str, description: str, sub_tasks: Optional[List['Task']] = None):
        self.name = name
        self.description = description
        self.sub_tasks = sub_tasks if sub_tasks is not None else []

    def add_sub_task(self, task: 'Task') -> None:
        self.sub_tasks.append(task)

    def __str__(self, level: int = 0) -> str:
        ret = "\t" * level + f"{self.name}: {self.description}\n"
        for task in self.sub_tasks:
            ret += task.__str__(level + 1)
        return ret

class PlanAndSolve:
    def __init__(self, root_task: Task):
        self.root_task = root_task

    def plan(self) -> List[Task]:
        plan = []
        self._plan_helper(self.root_task, plan)
        return plan

    def _plan_helper(self, task: Task, plan: List[Task]) -> None:
        plan.append(task)
        for sub_task in task.sub_tasks:
            self._plan_helper(sub_task, plan)

    def execute(self, plan: List[Task]) -> None:
        for task in plan:
            print(f"Executing task: {task.name}")

if __name__ == "__main__":
    # Create a hierarchical task decomposition
    root_task = Task("Build a House", "Build a house from the ground up")
    foundation_task = Task("Build Foundation", "Build the foundation of the house")
    root_task.add_sub_task(foundation_task)

    framing_task = Task("Framing", "Build the frame of the house")
    root_task.add_sub_task(framing_task)

    roofing_task = Task("Roofing", "Install the roof of the house")
    framing_task.add_sub_task(roofing_task)

    electrical_task = Task("Electrical", "Install the electrical wiring")
    framing_task.add_sub_task(electrical_task)

    plumbing_task = Task("Plumbing", "Install the plumbing")
    framing_task.add_sub_task(plumbing_task)

    finishing_task = Task("Finishing", "Finish the interior of the house")
    root_task.add_sub_task(finishing_task)

    # Create a Plan-and-Solve instance and execute the plan
    plan_and_solve = PlanAndSolve(root_task)
    plan = plan_and_solve.plan()
    print("Plan:")
    for task in plan:
        print(f"{task.name}: {task.description}")
    print("\nExecution:")
    plan_and_solve.execute(plan)
```
