An agent that checks its own answer and retries can be more accurate than one that answers once. In this lesson you will compute, by hand and in NumPy, how much a judge (an evaluator that accepts or rejects each attempt) can help, and why a judge that is too lenient caps the gain. You will also see how a reflection memory changes the picture.

**You need:** the ReAct loop of Lesson 48.1 (reason, act, observe), the meaning of $P(A \mid B)$ and independent events, and NumPy arrays.

## The problem

A language-model agent answers in one pass. When the answer is wrong, nothing in that pass tells it so. A loop fixes this only if two things hold: something can tell a right answer from a wrong one, and the next attempt can use what was learned from the rejected one. Three published patterns build this loop in different ways.

- **Evaluator-optimizer.** A generator proposes an answer and a separate evaluator judges it. Anthropic describes this as a workflow that is "particularly effective when we have clear evaluation criteria" (Anthropic, 2024).
- **Self-Refine.** One language model writes an answer, critiques it, and rewrites it, with no extra training. The abstract reports about 20% absolute average improvement over seven tasks (Madaan et al., 2023).
- **Reflexion.** After a failed trial, the agent writes a short verbal reflection into an episodic memory. Later trials read that memory. The model's weights do not change. The abstract reports 91% pass@1 on the HumanEval coding benchmark, against 80% for a GPT-4 baseline (Shinn et al., 2023). Pass@1 is the share of problems solved on the first attempt. The paper's own setup is not reproduced here.

![A generator proposes an answer, a judge accepts or rejects it; a rejection writes a reflection note into memory, which the generator reads on the next attempt](diagrams/48.3-loop.svg "The loop. Output leaves only through the accept branch.")

> [!WARNING]
> Huang et al. (2023, ICLR 2024) report that large language models "cannot self-correct reasoning yet" when no external feedback is given, and that performance can even degrade after self-correction. The judge is therefore the weak point, and the rest of this lesson measures what a weak judge costs.

## Worked example by hand

Make three assumptions. They are not measured properties of any model.

- The generator is correct on an attempt with probability $p = 0.4$.
- The judge accepts a correct answer with probability $t = 0.9$ (true accept).
- The judge accepts a wrong answer with probability $f = 0.2$ (false accept).

Per attempt, the judge accepts with probability $a = pt + (1-p)f = 0.36 + 0.12 = 0.48$. Of the accepted answers, the share that is correct (the *precision*) is $pt/a = 0.36/0.48 = 0.75$.

![One hundred attempts: 40 correct, 36 of them accepted; 60 wrong, 12 of them accepted; accepted answers are 36 correct and 12 wrong, precision 0.75](diagrams/48.3-hundred-attempts.svg "Counting 100 attempts. Hatched cells are correct answers the judge rejected by mistake.")

So a single accepted answer is right only 75% of the time. A judge that accepts 20% of wrong answers is not a safety net; it is a source of confident errors.

## From one attempt to $K$ attempts

Assume attempts are independent with the same $p$. (Real retries of one model are correlated, so this overstates the gain; see the traps below.) Let $K$ be the attempt budget. The loop stops at the first accepted attempt. If nothing is accepted, it outputs the last attempt.

- $P(\text{some attempt accepted}) = 1 - (1-a)^K$.
- $P(\text{output correct}) = \bigl[1-(1-a)^K\bigr]\dfrac{pt}{a} + (1-a)^{K-1}\,p(1-t)$.

The second term covers the case where all $K$ attempts are rejected and the last one was correct. Rearranging gives

$$
P(\text{output correct}) = \frac{pt}{a} + (1-a)^{K-1}\bigl[p(1-t) - (1-a)\tfrac{pt}{a}\bigr].
$$

At $K = 1$ this reduces to $p$. The bracket is negative exactly when $f < t$: a judge that accepts wrong answers less often than correct ones. In that case output accuracy rises towards $pt/a$ from below and never exceeds it. The accepted-error rate, $(1-p)f\,[1-(1-a)^K]/a$, rises towards $(1-p)f/a = 0.25$ for these numbers.

```python
p, t, f = 0.4, 0.9, 0.2        # generator accuracy, judge true-accept, judge false-accept

a = p * t + (1 - p) * f        # P(judge accepts one attempt)
print("accept per attempt a =", round(a, 4))
print("p*t =", round(p * t, 4), " (1-p)*f =", round((1 - p) * f, 4))
print("precision limit p*t/a =", round(p * t / a, 4))

def output_correct(K):
    acc_any = 1 - (1 - a) ** K
    return acc_any * p * t / a + (1 - a) ** (K - 1) * p * (1 - t)

def accepted_wrong(K):
    acc_any = 1 - (1 - a) ** K
    return (1 - p) * f * acc_any / a

for K in range(1, 6):
    print(f"K={K}  output correct={output_correct(K):.4f}  accepted wrong={accepted_wrong(K):.4f}")
```

The formula is only as good as its independence assumption, so check it by simulation. This block draws 200,000 simulated items for each setting and compares the result with the formula.

```python
import numpy as np

P, T, F, N, SEED = 0.4, 0.9, 0.2, 200_000, 4831

def simulate(p, t, f, K, n=N, seed=SEED):
    rng = np.random.default_rng(seed)
    done = np.zeros(n, bool); out_correct = np.zeros(n, bool); last = np.zeros(n, bool)
    for _ in range(K):
        correct = rng.random(n) < p
        accept = np.where(correct, rng.random(n) < t, rng.random(n) < f)
        new = accept & ~done
        out_correct[new] = correct[new]
        done |= accept
        last = correct
    out_correct[~done] = last[~done]
    return out_correct.mean(), (done & ~out_correct).mean()

def simulate_reflexion(p0, p1, r, t, f, K, n=N, seed=SEED):
    rng = np.random.default_rng(seed)
    done = np.zeros(n, bool); out_correct = np.zeros(n, bool); last = np.zeros(n, bool)
    useful = np.zeros(n, bool)
    for _ in range(K):
        p_cur = np.where(useful, p1, p0)
        correct = rng.random(n) < p_cur
        accept = np.where(correct, rng.random(n) < t, rng.random(n) < f)
        new = accept & ~done
        out_correct[new] = correct[new]
        rejected = ~accept & ~done
        useful |= rejected & (rng.random(n) < r)
        done |= accept
        last = correct
    out_correct[~done] = last[~done]
    return out_correct.mean(), (done & ~out_correct).mean()

print("Judge sweep, N = 200,000 items per row (seed 4831)")
for f in [0.0, 0.2, 0.4]:
    for K in range(1, 6):
        c, w = simulate(P, T, f, K)
        print(f"f={f} K={K}  correct={c:.4f}  accepted wrong={w:.4f}")
print("Reflection memory, K = 3, p1 = 0.7 after a useful note")
for r in [0.0, 0.5, 1.0]:
    c, w = simulate_reflexion(P, 0.7, r, T, F, 3)
    print(f"r={r}  correct={c:.4f}  accepted wrong={w:.4f}")
```

The simulation agrees with the formula to within about 0.001, which is the Monte Carlo noise at this sample size. The judge sets the outcome. With a perfect judge ($f = 0$), five attempts reach about 0.90 correct and accept no wrong answers. With $f = 0.2$, five attempts reach about 0.72 correct, and about 0.24 of all items end with an accepted wrong answer. Among items that end with an accepted answer, one in four is wrong at any $K$, the same 0.75 precision as with one attempt. With $f = 0.4$, the loop plateaus near 0.59 and ends with an accepted wrong answer for about 0.40 of all items at $K = 5$.

## Reflection memory

The judge's rejection carries information that a bare retry throws away. A reflection note says what went wrong, and a later attempt can read it. This is the mechanism of Reflexion. The simulation models it crudely: after each rejection, the note is useful with probability $r$, and a useful note raises the per-attempt success probability from $p_0 = 0.4$ to $p_1 = 0.7$ for the rest of the item. Both $r$ and $p_1$ are assumptions I chose; the size of the gain depends on them directly.

![Three pairs of bars at K = 3: with no useful notes, correct 0.656 and accepted wrong 0.214; with r = 0.5, 0.748 and 0.184; with r = 1, 0.800 and 0.161](diagrams/48.3-reflexion.svg "Reflection memory at K = 3. r = 0 reduces to plain retry, which matches the formula's 0.655 to within noise.")

Read the chart this way. At $r = 0$ the memory is never useful, so the loop is a plain retry, and the 0.656 matches the formula (0.6554) — a check that the simulation is wired correctly. As $r$ grows, accuracy rises and accepted errors fall. Both effects depend on $p_1$ being much larger than $p_0$. That is a property of the assumed model, not a measured result about any language model.

> [!TIP]
> When you read a paper that reports a reflection gain, ask three things: what the judge's false-accept rate was, how many attempts were allowed, and whether the baseline received the same budget. Each one can move the result as much as the reflection step.

## Common traps

> [!TRAP]
> **A single accept is not a verified answer.** With $f = 0.2$ and $p = 0.4$, the precision of one accepted answer is $0.75$. Stopping on the first accept leaves a quarter of answers wrong.

> [!TRAP]
> **A judge that shares the generator's blind spots adds no information.** If the judge makes the same mistake as the generator, the loop accepts the same error with more confidence. Huang et al. (2023) find that intrinsic self-correction, without external feedback, is not reliably helpful (the abstract does not name the benchmarks, and I did not read the full paper).

> [!TRAP]
> **Independent retries are an assumption.** The formulas assume each attempt is a fresh draw with the same $p$. Retries from one model on one prompt are often correlated, which lowers the real gain. Measure it on your own task.

> [!TRAP]
> **Decide the fallback before you measure.** The formula outputs the last attempt when nothing is accepted. A system that returns "no answer" instead gets a different accuracy and a different accepted-error rate.

> [!TRAP]
> **Do not compare a loop with a single attempt at equal cost without saying so.** $K = 5$ uses five times the calls. Compare at equal budget, or report the cost next to the gain.

## Summary

- The loop has three parts: a generator, a judge that accepts or rejects, and a memory that carries rejection feedback to the next attempt.
- With judge accept rates $t$ (correct answers) and $f$ (wrong answers), one attempt is accepted with probability $a = pt + (1-p)f$, and the precision of accepted answers is $pt/a$.
- For $f < t$, more attempts raise output accuracy towards $pt/a$ from below, while the accepted-error rate also rises. For $f > t$, output accuracy falls below $p$ as attempts grow.
- A reflection memory helps only through the probability that a note is useful. Both that probability and the gain it brings are assumptions unless measured.

## Quiz time

### Question 1: Calculation

A generator is correct with $p = 0.5$. The judge accepts correct answers with $t = 0.8$ and wrong answers with $f = 0.3$. With $K = 1$, what is the precision of an accepted answer?

<details><summary>Show solution</summary>

$a = pt + (1-p)f = 0.5 \times 0.8 + 0.5 \times 0.3 = 0.40 + 0.15 = 0.55$. Precision $= pt/a = 0.40/0.55 \approx 0.727$.

</details>

### Question 2: Prediction

Using the same $p = 0.5$ and $t = 0.8$, the judge's false-accept rate is raised to $f = 0.9$. Does the loop's output accuracy, as $K$ grows, end above or below $p = 0.5$?

<details><summary>Show solution</summary>

Below. $f \ge t$ here, so the bracket in the rearranged formula is non-negative and output accuracy falls towards $pt/a$. Here $a = 0.4 + 0.45 = 0.85$ and $pt/a = 0.40/0.85 \approx 0.471$. The output accuracy starts at $p = 0.5$ at $K = 1$ and decreases towards $0.471$ as $K$ grows.

</details>

### Question 3: Bug-spotting

A student writes this loop body for the simulation:

```python
for _ in range(K):
    correct = rng.random(n) < p
    accept = np.where(correct, rng.random(n) < t, rng.random(n) < f)
    out_correct[accept] = correct[accept]
    done |= accept
```

What is wrong, and what does it change?

<details><summary>Show solution</summary>

It drops `new = accept & ~done`. Every later accept overwrites the output of an earlier accept. The output then becomes the last accepted attempt, not the first. For the items where the first accept was wrong and a later attempt is correct, the output is wrongly scored as correct, so the error rate is understated. The fix is to write only the newly accepted items, as the lesson's code does.

</details>

### Question 4: Explanation

Reflexion reports gains without changing any weights. Where does the improvement come from in the model above?

<details><summary>Show solution</summary>

From the reflection note, which is kept in memory and read on later attempts, so the success probability of those attempts changes. In the model this is $p_1 > p_0$ for items with a useful note. The model does not change the generator's weights. Whether a real agent gets the same effect depends on the task and on whether the note is informative; the Reflexion abstract describes the mechanism, but the size of the gain depends on its benchmarks and setup.

</details>

### Question 5: Calculation

At $K = 3$, $f = 0.2$, what fraction of all items ends with an accepted wrong answer, according to the formula?

<details><summary>Show solution</summary>

$(1-p)f\,[1-(1-a)^3]/a = 0.6 \times 0.2 \times (1 - 0.52^3)/0.48 = 0.12 \times 0.8594/0.48 \approx 0.2148$. The simulation gives 0.2146.

</details>
