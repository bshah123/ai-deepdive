# 50.1 — Multi-Agent Topology: Supervisor, Hierarchical & Peer-to-Peer

## Opening Motivation & Context

Multi-agent systems are a fundamental concept in artificial intelligence and distributed computing. They involve multiple autonomous agents interacting with each other to achieve a common goal. The topology of these systems refers to the way agents are organized and communicate with each other. Understanding different topologies is crucial for designing efficient and effective multi-agent systems.

In this lesson, we will explore three common multi-agent topologies: Supervisor, Hierarchical, and Peer-to-Peer. Each topology has its own strengths and is suited for different types of problems. By the end of this lesson, you will be able to identify the appropriate topology for your multi-agent system and implement it in Python.

## Core Concepts Breakdown

### Supervisor Topology

In a supervisor topology, there is a central supervisor agent that controls and coordinates the activities of other worker agents. The supervisor agent makes decisions and assigns tasks to the worker agents based on the system's goals and the current state of the environment.

> [!KEY-INSIGHT]
> The supervisor topology is ideal for systems where a central authority is needed to make decisions and coordinate activities.

> [!BEST-PRACTICE]
> Use the supervisor topology when you need a central point of control and decision-making in your multi-agent system.

> [!WARNING]
> Centralized control can be a bottleneck and a single point of failure. Ensure your supervisor agent is robust and can handle failures gracefully.

### Hierarchical Topology

In a hierarchical topology, agents are organized in a tree-like structure with a clear chain of command. Each agent has a supervisor and can have multiple subordinates. This structure allows for decentralized decision-making while maintaining some level of coordination.

> [!KEY-INSIGHT]
> The hierarchical topology balances centralization and decentralization, making it suitable for complex systems with multiple levels of decision-making.

> [!BEST-PRACTICE]
> Use the hierarchical topology when your system requires multiple levels of decision-making and coordination.

> [!WARNING]
> Managing a hierarchical structure can be complex. Ensure that each level of the hierarchy has clear roles and responsibilities.

### Peer-to-Peer Topology

In a peer-to-peer topology, all agents are equal and can communicate directly with each other. There is no central authority or hierarchy. This topology is decentralized and allows for flexible and dynamic interactions.

> [!KEY-INSIGHT]
> The peer-to-peer topology is ideal for systems where agents need to interact dynamically and there is no central authority.

> [!BEST-PRACTICE]
> Use the peer-to-peer topology when your system requires flexible and dynamic interactions among agents.

> [!WARNING]
> Peer-to-peer systems can be challenging to manage and coordinate. Ensure that agents can communicate effectively and handle conflicts gracefully.

## Code Demonstration & Runtime Output

Let's implement a simple multi-agent system with each of the three topologies in Python.

```python
from abc import ABC, abstractmethod
from typing import List, Dict, Optional

class Agent(ABC):
    def __init__(self, name: str):
        self.name = name

    @abstractmethod
    def perform_task(self, task: str) -> str:
        pass

class WorkerAgent(Agent):
    def perform_task(self, task: str) -> str:
        return f"{self.name} is performing task: {task}"

class SupervisorAgent(Agent):
    def __init__(self, name: str, workers: List[WorkerAgent]):
        super().__init__(name)
        self.workers = workers

    def perform_task(self, task: str) -> str:
        results = []
        for worker in self.workers:
            results.append(worker.perform_task(task))
        return f"{self.name} supervised the following tasks:\n" + "\n".join(results)

class HierarchicalAgent(Agent):
    def __init__(self, name: str, subordinates: List[Agent]):
        super().__init__(name)
        self.subordinates = subordinates

    def perform_task(self, task: str) -> str:
        results = []
        for subordinate in self.subordinates:
            results.append(subordinate.perform_task(task))
        return f"{self.name} managed the following tasks:\n" + "\n".join(results)

class PeerAgent(Agent):
    def __init__(self, name: str, peers: List[Agent]):
        super().__init__(name)
        self.peers = peers

    def perform_task(self, task: str) -> str:
        results = []
        for peer in self.peers:
            results.append(peer.perform_task(task))
        return f"{self.name} collaborated on the following tasks:\n" + "\n".join(results)

def main():
    # Supervisor Topology
    worker1 = WorkerAgent("Worker 1")
    worker2 = WorkerAgent("Worker 2")
    supervisor = SupervisorAgent("Supervisor", [worker1, worker2])
    print(supervisor.perform_task("Task 1"))

    # Hierarchical Topology
    worker3 = WorkerAgent("Worker 3")
    worker4 = WorkerAgent("Worker 4")
    manager = HierarchicalAgent("Manager", [worker3, worker4])
    director = HierarchicalAgent("Director", [manager])
    print(director.perform_task("Task 2"))

    # Peer-to-Peer Topology
    peer1 = PeerAgent("Peer 1", [])
    peer2 = PeerAgent("Peer 2", [])
    peer1.peers = [peer2]
    peer2.peers = [peer1]
    print(peer1.perform_task("Task 3"))

if __name__ == "__main__":
    main()
```

```text
Worker 2 is performing task: Task 1
Director managed the following tasks:
Manager managed the following tasks:
Worker 3 is performing task: Task 2
Worker 4 is performing task: Task 2
Peer 1 collaborated on the following tasks:
Peer 2 is performing task: Task 3
```

### How this works (Line-by-Line Breakdown)

1. **Imports and Abstract Base Class**: We import necessary modules and define an abstract base class `Agent` with an abstract method `perform_task`.
2. **WorkerAgent**: A concrete implementation of `Agent` that performs tasks.
3. **SupervisorAgent**: A supervisor agent that manages a list of worker agents and coordinates their tasks.
4. **HierarchicalAgent**: An agent that manages a list of subordinates, creating a hierarchical structure.
5. **PeerAgent**: An agent that collaborates with a list of peers, creating a peer-to-peer structure.
6. **Main Function**: We create instances of each topology and demonstrate their functionality by performing tasks.

> [!ADVANCED]
> The `Agent` abstract base class ensures that all agents implement the `perform_task` method. The use of type hints (`List`, `Dict`, `Optional`) improves code readability and helps catch type-related errors early. The `__main__` block ensures that the code runs only when the script is executed directly.

> [!QA]
> Q: When should I prefer the supervisor topology over the hierarchical or peer-to-peer topology?
> A: The supervisor topology is ideal when you need a central authority to make decisions and coordinate activities. It is suitable for systems where a single point of control is necessary, such as in military command structures or centralized management systems.

## Summary & Key Takeaways

- **Supervisor Topology**: Use when a central authority is needed for decision-making and coordination.
- **Hierarchical Topology**: Use when your system requires multiple levels of decision-making and coordination.
- **Peer-to-Peer Topology**: Use when agents need to interact dynamically and there is no central authority.
- **Centralized Control**: Can be a bottleneck and a single point of failure.
- **Hierarchical Management**: Complex to manage, ensure clear roles and responsibilities.
- **Peer-to-Peer Systems**: Challenging to manage and coordinate, ensure effective communication and conflict resolution.
