Agents that cooperate must do two things: send messages whose *type* the receiver can act on, and, when a group must settle on one value, reach agreement even when some members lie or crash. In this lesson you will implement a contract-net exchange, count its messages and compare the count with all-to-all broadcast. You will compute how many faulty agents a quorum rule tolerates, and how much majority voting over language-model agents gains, and when it stops gaining.

**You need:** Python classes and dataclasses, basic probability (independence and binomial coefficients), and the topologies from Lesson 50.1.

## The problem

Two agents that exchange free text ("I can take it, roughly") cannot tell whether a reply is a bid, a refusal or a question. Each message needs a type that says what the sender is doing, and a rule for what may follow what. A second problem appears when a group must act on one value, such as a plan or a lock holder. A faulty member may tell different peers different things. Protocols solve the first problem; consensus algorithms solve the second.

## Messages carry a speech act

The contract net protocol (Smith, 1980) gives each message a type. A *manager* announces a task. *Contractors* return bids. The manager awards the task to the best bidder and rejects the rest.

![Three phases of the contract net for four contractors: announce, bid and award, each with four messages](diagrams/50.2-contract-net.svg "One task, four contractors: the contract net uses 3N messages.")

Smith calls the messages task announcements and bids, and his announcements can go to all nodes (general broadcast), to a subset, or to one node (point-to-point). The code's performative names (cfp, propose) are my labels, not checked against a specification. It uses point-to-point addressing, so each announcement is a separate message.

## Worked example by hand

Four contractors quote costs A = 7, B = 4, C = 9 and D = 5. The manager sends four cfp (call for proposals) messages and receives four propose messages. It then sends one accept-proposal to B, the cheapest bid, and three reject-proposal messages. The total is 4 + 4 + 4 = 12.

Run the protocol. The code uses only the standard library:

```python
from dataclasses import dataclass

ALLOWED = {"cfp", "propose", "refuse", "accept-proposal", "reject-proposal"}

class ProtocolError(Exception):
    pass

@dataclass(frozen=True)
class Message:
    performative: str   # the speech act: what the sender is doing
    sender: str
    receiver: str
    content: object = None

class Contractor:
    def __init__(self, name, cost):
        self.name, self.cost, self.state = name, cost, "idle"

    def handle(self, msg):
        if msg.performative not in ALLOWED:
            raise ProtocolError(f"unknown performative {msg.performative!r}")
        if msg.performative == "cfp":
            self.state = "bid"
            return Message("propose", self.name, msg.sender, self.cost)
        if msg.performative == "accept-proposal":
            if self.state != "bid":
                raise ProtocolError(f"{self.name}: accept-proposal without a pending proposal")
            self.state = "working"
            return None
        if msg.performative == "reject-proposal":
            self.state = "idle"
            return None
        raise ProtocolError(f"{self.name}: {msg.performative} is not a valid request here")

def contract_net(contractors, task):
    by_name = {c.name: c for c in contractors}
    log = []

    def send(msg):
        log.append(msg)
        reply = by_name[msg.receiver].handle(msg)
        if reply is not None:
            log.append(reply)
        return reply

    bids = [send(Message("cfp", "manager", c.name, task)) for c in contractors]
    winner = min(bids, key=lambda m: m.content)          # lowest cost wins
    for bid in bids:
        kind = "accept-proposal" if bid is winner else "reject-proposal"
        send(Message(kind, "manager", bid.sender, task))
    return winner.sender, len(log)

agents = [Contractor("A", 7), Contractor("B", 4), Contractor("C", 9), Contractor("D", 5)]
winner, n_msgs = contract_net(agents, "task-1")
print("winner:", winner, "| messages:", n_msgs)

try:   # A already rejected, so it is idle; an accept now is out of order
    agents[0].handle(Message("accept-proposal", "manager", "A", "task-1"))
except ProtocolError as err:
    print("rejected:", err)

for n in (4, 8, 16):
    print(f"n={n:2d}  contract net={3 * n:3d}  all-to-all round={n * (n - 1):3d}")
```

```output
winner: B | messages: 12
rejected: A: accept-proposal without a pending proposal
n= 4  contract net= 12  all-to-all round= 12
n= 8  contract net= 24  all-to-all round= 56
n=16  contract net= 48  all-to-all round=240
```

> [!KEY-INSIGHT]
> `Contractor.handle` checks its state before it accepts an award. The same message (accept-proposal) is legal after a bid and a protocol violation otherwise. Encoding legal message orders as a state check is what makes a protocol testable.

## How the count scales

With point-to-point messages, each contractor costs one announcement, one reply and (at most) one award, so a round costs $3N$ messages for $N$ contractors. An all-to-all exchange, in which every agent sends its value to every other agent, costs $N(N-1)$. The two costs are equal only at $N = 4$.

![Bar chart of messages per round: contract net grows linearly to 48 at N = 16; all-to-all grows quadratically to 240](diagrams/50.2-message-growth.svg "Messages per round. The quadratic curve overtakes the linear one at N = 5.")

With a broadcast channel the $N$ announcements become one message. The count falls to $2N + 1$ (my own arithmetic from the message types above).

## Consensus: agreeing when some agents lie

Negotiation needs each agent to act on the award it receives. Consensus needs all honest agents to agree on one value, even when $f$ members are faulty. Two fault models matter.

- **Crash faults.** A node stops responding. Majority quorums suffice: $n \ge 2f + 1$ nodes tolerate $f$ crashes, and any two majorities overlap (reasoning from first principles). Raft (Ongaro and Ousterhout, 2014) was designed for understandability. Its crash-fault, majority-quorum design is my understanding; I read only the abstract.
- **Byzantine faults.** A node may send conflicting values to different peers. Lamport, Shostak and Pease (1982) show that with unsigned (oral) messages the problem is solvable if and only if more than two-thirds of the generals are loyal, that is $n \ge 3f + 1$.

The overlap argument gives the quorum size. Two quorums of size $q$ out of $n$ nodes share at least $2q - n$ nodes. For Byzantine tolerance that overlap must contain at least $f + 1$ nodes, so at least one honest node is in both quorums. Hence $2q - n \ge f + 1$, so $q \ge \lceil (n + f + 1)/2 \rceil$.

```python
import math

print(" n  crash f  crash quorum  byzantine f  byzantine quorum")
for n in range(3, 10):
    f_crash = (n - 1) // 2                       # tolerate f crashes if n >= 2f + 1
    q_crash = n // 2 + 1                         # majority quorum
    f_byz = (n - 1) // 3                         # tolerate f Byzantine nodes if n >= 3f + 1
    q_byz = math.ceil((n + f_byz + 1) / 2)       # two quorums overlap in at least f + 1 nodes
    print(f"{n:2d}  {f_crash:7d}  {q_crash:13d}  {f_byz:11d}  {q_byz:16d}")
```

## Voting over language-model agents

Multi-agent language-model systems often aggregate several samples by vote. Self-consistency (Wang et al., 2022) samples several reasoning paths and keeps the most consistent answer. Multi-agent debate (Du et al., 2023) has several model instances critique each other's answers over rounds. Neither abstract gives a panel size, so I quote no numbers from them.

Take a binary answer, $k$ voters (odd), each correct with probability $p$, and votes that are independent. Here $p$ is the accuracy of one voter. Lesson 50.1 used $p$ for the error rate, so its $p = 0.3$ is an accuracy of $0.7$ here. The majority is correct with probability $\sum_{i > k/2} \binom{k}{i} p^i (1-p)^{k-i}$ (reasoning from first principles). Independence is the assumption that carries the result. The code below checks the formula by simulation and adds a correlated-error model: with probability $\rho$ the whole panel shares one error draw, otherwise votes are independent. In that model the accuracy is $\rho p + (1 - \rho)\,\mathrm{maj}(k, p)$, which tends to $\rho p + 1 - \rho$ as $k$ grows. This is my own model, not a published result.

```python
import numpy as np
from math import comb

def majority_correct(k, p):
    """Exact P(majority of k independent binary votes is correct), k odd."""
    return sum(comb(k, i) * p**i * (1 - p)**(k - i) for i in range(k // 2 + 1, k + 1))

def correlated_panel(k, p, rho, trials, rng):
    """With probability rho the whole panel shares one error draw; otherwise votes are independent."""
    shared = rng.random(trials) < rho
    common = rng.random(trials) < p
    indep = rng.random((trials, k)) < p
    votes = np.where(shared[:, None], common[:, None], indep)
    return (votes.sum(axis=1) > k / 2).mean()

p, trials = 0.7, 50_000
rng = np.random.default_rng(0)
print("k   exact    monte-carlo")
for k in (1, 3, 5, 9, 15, 31):
    mc = (rng.random((trials, k)) < p).sum(axis=1)
    print(f"{k:2d}  {majority_correct(k, p):.4f}   {(mc > k / 2).mean():.4f}")

print("\nk    rho=0.0  rho=0.3  rho=0.3 exact")
for k in (1, 3, 9, 31, 101):
    mc0 = correlated_panel(k, p, 0.0, trials, rng)
    mc3 = correlated_panel(k, p, 0.3, trials, rng)
    exact3 = 0.3 * p + 0.7 * majority_correct(k, p)
    print(f"{k:3d}  {mc0:.4f}   {mc3:.4f}   {exact3:.4f}")
```

The first table matches the binomial formula within sampling error for $k$ from 1 to 31. The second table shows the effect of correlation. With $\rho = 0.3$, 31 agents reach about 0.90, while 31 independent agents reach 0.99. The ceiling $0.3 \times 0.7 + 0.7 = 0.91$ holds however many agents join.

![Paired bars for k = 1, 3, 9 and 31: independent votes rise to 0.99, while votes with 30 percent shared error stop near 0.90; a dashed line marks the 0.91 ceiling](diagrams/50.2-vote-accuracy.svg "Majority-vote accuracy at p = 0.7. Correlated errors cap the gain from more voters.")

> [!TRAP]
> Majority voting over copies of one model is not independent voting. Shared training data and shared prompts make errors correlate, and the gain from extra voters then stops at the ceiling above. Measure the error correlation on held-out questions before you trust a vote count.

> [!TRAP]
> A broadcast announcement is one message on a broadcast channel but $N$ messages point-to-point. A message budget quoted without its addressing mode is not comparable.

> [!TRAP]
> Accepting a message in the wrong state is a bug even when the message type is valid. Test each state transition, including the illegal ones.

> [!TRAP]
> Quorum arithmetic is easy to misapply. Five nodes tolerate only $f = 1$ Byzantine fault, the same as four nodes, and a crash-fault majority protocol gives no guarantee once a node can lie.

## Summary

- A protocol gives each message a type and a legal order; the code's contract net uses cfp, propose, accept-proposal and reject-proposal.
- Point-to-point contract-net rounds cost $3N$ messages, against $N(N-1)$ for all-to-all exchange.
- Crash-fault agreement needs $n \ge 2f+1$ with majority quorums; Byzantine agreement needs $n \ge 3f+1$ with quorums of size $\lceil (n+f+1)/2 \rceil$.
- Majority voting over independent agents helps quickly, but correlated errors cap the gain.

## Quiz time

### Question 1: Calculation

A contract net has 6 contractors, all of which bid, and point-to-point messages. How many messages does one round use? How many does one all-to-all round use among 6 agents?

<details><summary>Show solution</summary>

One round uses $3 \times 6 = 18$ messages. An all-to-all round uses $6 \times 5 = 30$ messages.

</details>

### Question 2: Prediction

After a round in which B wins, B is in state working. What does `agents[1].handle(Message("accept-proposal", "manager", "B", "task-2"))` do?

<details><summary>Show solution</summary>

It raises `ProtocolError` with the message "B: accept-proposal without a pending proposal". The state check requires state bid, and B is working.

</details>

### Question 3: Bug-spotting

A team says: "Nine independent agents, each 70 percent accurate, give a 95 percent majority." Find the error.

<details><summary>Show solution</summary>

For $k = 9$ and $p = 0.7$ the exact majority accuracy is 0.9012. The value 0.95 belongs to $k = 15$. The claim mixes up the panel size. The independence assumption is also not checked.

</details>

### Question 4: Explanation

Why does a group of 3 nodes with 1 Byzantine fault fail to agree when the quorum is 2?

<details><summary>Show solution</summary>

Two quorums of size 2 out of 3 nodes overlap in $2 + 2 - 3 = 1$ node. That node may be the faulty one, so the honest nodes cannot rely on it. The overlap must contain $f + 1 = 2$ nodes. A quorum of 3 gives an overlap of 3 and works.

</details>
