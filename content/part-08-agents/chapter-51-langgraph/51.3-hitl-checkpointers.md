# 51.3 — Human-in-the-Loop (HITL), Checkpointers & Time Travel Debugging

## Opening Motivation & Context

In the realm of autonomous agents and AI systems, there comes a point where human intervention is necessary. This is where Human-in-the-Loop (HITL) comes into play. HITL involves integrating human judgment into the decision-making process of AI systems, ensuring that critical decisions are made by humans when necessary. This is particularly important in scenarios where AI systems might lack the necessary context or where human oversight is required for ethical or legal reasons.

Checkpointers are another crucial component in this context. They allow you to save the state of your AI system at various points, enabling you to resume from those points later. This is particularly useful for debugging and testing, as it allows you to "time travel" back to specific states and see how the system behaved at those points.

## Core Concepts Breakdown

### Human-in-the-Loop (HITL)

HITL is a methodology that integrates human judgment into the decision-making process of AI systems. This is particularly important in scenarios where AI systems might lack the necessary context or where human oversight is required for ethical or legal reasons.

> [!KEY-INSIGHT]
> HITL is about balancing the strengths of AI (speed, consistency, and scalability) with the strengths of humans (context, judgment, and adaptability).

> [!BEST-PRACTICE]
> Always design your AI systems with HITL in mind. This means ensuring that your system can be paused, inspected, and resumed by a human when necessary.

### Checkpointers

Checkpointers are a mechanism that allows you to save the state of your AI system at various points. This is particularly useful for debugging and testing, as it allows you to "time travel" back to specific states and see how the system behaved at those points.

> [!KEY-INSIGHT]
> Checkpointers are like save points in a video game. They allow you to save your progress and resume later.

> [!BEST-PRACTICE]
> Use checkpointers to save the state of your AI system at critical points. This will make debugging and testing much easier.

> [!WARNING]
> Be careful not to save too much data. This can lead to performance issues and unnecessary storage usage.

## Code Demonstration & Runtime Output

```python
from typing import TypedDict, Annotated, Literal
from langgraph.graph import StateGraph, END
from langgraph.graph.message import add_messages
from langgraph.checkpoint.memory import MemorySaver

class State(TypedDict):
    messages: Annotated[list, add_messages]

def human_node(state: State) -> Literal["human", END]:
    print("Human-in-the-Loop: Please provide input.")
    user_input = input("> ")
    state["messages"].append({"role": "human", "content": user_input})
    return "human"

def ai_node(state: State) -> Literal["ai", END]:
    print("AI: Processing...")
    state["messages"].append({"role": "ai", "content": "AI response"})
    return "ai"

def should_continue(state: State) -> Literal["human", END]:
    if len(state["messages"]) > 5:
        return END
    return "human"

if __name__ == "__main__":
    memory = MemorySaver()
    graph_builder = StateGraph(State)
    graph_builder.add_node("human", human_node)
    graph_builder.add_node("ai", ai_node)
    graph_builder.add_edge("human", "ai")
    graph_builder.add_conditional_edges("ai", should_continue)
    graph_builder.set_entry_point("human")
    graph = graph_builder.compile(checkpointer=memory)

    config = {"configurable": {"thread_id": "1"}}
    for s in graph.stream(None, config, stream_mode="values"):
        print(s)
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: We import necessary modules and classes from the `langgraph` library.
2. **State Class**: We define a `State` class that inherits from `TypedDict`. This class will hold the state of our graph.
3. **human_node Function**: This function represents the human-in-the-loop node. It prompts the user for input and adds it to the state.
4. **ai_node Function**: This function represents the AI node. It processes the input and adds a response to the state.
5. **should_continue Function**: This function determines whether the graph should continue or end based on the number of messages in the state.
6. **Main Block**: In the main block, we create a `MemorySaver` instance to save the state of our graph. We then build the graph using the `StateGraph` class, add our nodes and edges, and compile the graph with the checkpointer.
7. **Streaming**: Finally, we stream the graph and print the state at each step.

> [!ADVANCED]
> The `MemorySaver` class uses Python's `pickle` module to serialize and deserialize the state of the graph. This allows the state to be saved to memory and retrieved later.

> A: You should prefer using a checkpointer when you need to save the state of your AI system at various points. This is particularly useful for debugging and testing, as it allows you to "time travel" back to specific states and see how the system behaved at those points.

```python
from typing import TypedDict, Annotated, Literal
from langgraph.graph import StateGraph, END
from langgraph.graph.message import add_messages

class State(TypedDict):
    messages: Annotated[list, add_messages]

def node(state: State) -> Literal[END]:
    print("Node executed")
    return END

if __name__ == "__main__":
    graph_builder = StateGraph(State)
    graph_builder.add_node("node", node)
    graph_builder.set_entry_point("node")
    graph = graph_builder.compile()
    for s in graph.stream(None, stream_mode="values"):
        print(s)
```
