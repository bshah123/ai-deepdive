# 53.2 — Continuous Batching & In-Flight Request Scheduling

## Opening Motivation & Context

In the realm of AI and machine learning, the performance and efficiency of serving models are critical factors that determine user satisfaction and system scalability. One of the key techniques to optimize model serving is continuous batching, which involves grouping multiple incoming requests into a single batch for processing. This approach leverages the parallel processing capabilities of modern hardware, such as GPUs, to maximize throughput and minimize latency.

In-flight request scheduling is another crucial aspect of efficient model serving. It involves managing the queue of incoming requests and determining the optimal order in which to process them. Effective scheduling can significantly improve the overall performance of the system by reducing idle time and maximizing resource utilization.

## Core Concepts Breakdown

### Continuous Batching

Continuous batching is a technique that groups multiple incoming requests into a single batch for processing. This approach is particularly useful in scenarios where the model's inference time is significantly higher than the time it takes to receive a request. By batching requests, we can reduce the overhead associated with individual requests and improve the overall throughput of the system.

> [!KEY-INSIGHT]
> Continuous batching is a trade-off between latency and throughput. While batching can improve throughput, it may also increase the latency for individual requests, as they must wait for the batch to be filled before processing.

> [!BEST-PRACTICE]
> To maximize the benefits of continuous batching, it is essential to choose an appropriate batch size. A batch size that is too small may not fully utilize the available resources, while a batch size that is too large may increase the latency for individual requests.

### In-Flight Request Scheduling

In-flight request scheduling involves managing the queue of incoming requests and determining the optimal order in which to process them. Effective scheduling can significantly improve the overall performance of the system by reducing idle time and maximizing resource utilization.

> [!KEY-INSIGHT]
> In-flight request scheduling is a dynamic process that requires continuous monitoring and adjustment. The optimal scheduling strategy may vary depending on the current workload and system conditions.

> [!WARNING]
> Poor scheduling decisions can lead to suboptimal performance and increased latency. It is crucial to monitor the system's performance and adjust the scheduling strategy as needed.

## Code Demonstration & Runtime Output

```python
import time
import random
from typing import List, Tuple, Optional
from dataclasses import dataclass

@dataclass
class Request:
    id: int
    arrival_time: float
    processing_time: float

class ModelServer:
    def __init__(self, batch_size: int, max_in_flight: int):
        self.batch_size = batch_size
        self.max_in_flight = max_in_flight
        self.in_flight: List[Request] = []
        self.batch: List[Request] = []
        self.request_id = 0

    def generate_request(self) -> Request:
        self.request_id += 1
        arrival_time = time.time()
        processing_time = random.uniform(0.1, 0.5)
        return Request(self.request_id, arrival_time, processing_time)

    def add_to_batch(self, request: Request) -> None:
        self.batch.append(request)
        if len(self.batch) >= self.batch_size:
            self.process_batch()

    def process_batch(self) -> None:
        if not self.batch:
            return

        print(f"Processing batch of {len(self.batch)} requests")
        for request in self.batch:
            print(f"Processing request {request.id} (arrival time: {request.arrival_time:.2f}, processing time: {request.processing_time:.2f})")
            time.sleep(request.processing_time)
            self.in_flight.remove(request)

        self.batch.clear()

    def schedule_request(self, request: Request) -> None:
        if len(self.in_flight) < self.max_in_flight:
            self.in_flight.append(request)
            self.add_to_batch(request)
        else:
            print(f"Request {request.id} rejected due to too many in-flight requests")

def simulate_server(server: ModelServer, duration: float) -> None:
    start_time = time.time()
    while time.time() - start_time < duration:
        request = server.generate_request()
        print(f"Generated request {request.id} at time {request.arrival_time:.2f}")
        server.schedule_request(request)
        time.sleep(random.uniform(0.05, 0.2))

if __name__ == "__main__":
    server = ModelServer(batch_size=3, max_in_flight=5)
    simulate_server(server, duration=5.0)
```

### How this works (Line-by-Line Breakdown)

1. **Imports**: The code imports necessary modules, including `time`, `random`, and typing modules for type hints.
2. **Request Class**: The `Request` class is defined using the `@dataclass` decorator, which automatically generates special methods like `__init__`, `__repr__`, etc. It has three attributes: `id`, `arrival_time`, and `processing_time`.
3. **ModelServer Class**: The `ModelServer` class is initialized with `batch_size` and `max_in_flight` parameters. It also initializes empty lists for `in_flight` and `batch` requests, and sets `request_id` to 0.
4. **generate_request Method**: This method generates a new request with a unique ID, current arrival time, and a random processing time between 0.1 and 0.5 seconds.
5. **add_to_batch Method**: This method adds a request to the batch. If the batch size reaches the specified `batch_size`, it calls the `process_batch` method.
6. **process_batch Method**: This method processes the current batch of requests. It prints the batch size and processes each request in the batch, printing the request details and sleeping for the request's processing time. It then removes the request from the `in_flight` list and clears the batch.
7. **schedule_request Method**: This method schedules a request by adding it to the `in_flight` list if there are fewer than `max_in_flight` requests in flight. Otherwise, it rejects the request.
8. **simulate_server Function**: This function simulates the server by generating requests at random intervals and scheduling them using the `ModelServer` instance.
9. **Main Block**: The main block creates a `ModelServer` instance with a batch size of 3 and a maximum of 5 in-flight requests. It then simulates the server for 5 seconds.

The `process_batch` method processes the batch in a sequential manner, which can be optimized further by using parallel processing techniques. The `schedule_request` method uses a simple threshold-based approach to reject requests when the maximum number of in-flight requests is reached. ### Question #3: Find and fix the bug

```python
import time
from typing import List

class BuggyServer:
    def __init__(self, batch_size: int):
        self.batch_size = batch_size
        self.batch: List[int] = []

    def add_to_batch(self, request_id: int) -> None:
        self.batch.append(request_id)
        if len(self.batch) == self.batch_size:

    def process_batch(self) -> None:
        print(f"Processing batch: {self.batch}")
```

<details><summary>Show Solution</summary>
The bug in the code is that the `process_batch` method uses `self.batch = []` to clear the batch, which creates a new list and does not modify the existing list in place. This can lead to unexpected behavior if there are references to the batch list elsewhere in the code. The fixed code should use `self.batch.clear()` to clear the batch in place.

```python
import time
from typing import List

class FixedServer:
    def __init__(self, batch_size: int):
        self.batch_size = batch_size
        self.batch: List[int] = []

    def add_to_batch(self, request_id: int) -> None:
        self.batch.append(request_id)
        if len(self.batch) == self.batch_size:
            self.process_batch()

    def process_batch(self) -> None:
        print(f"Processing batch: {self.batch}")
        self.batch.clear()

def simulate_fixed_server(server: FixedServer, num_requests: int) -> None:
    for i in range(num_requests):
        server.add_to_batch(i)
        time.sleep(0.1)

if __name__ == "__main__":
    server = FixedServer(batch_size=3)
    simulate_fixed_server(server, num_requests=5)
```
