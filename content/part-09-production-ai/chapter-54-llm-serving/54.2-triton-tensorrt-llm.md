# 54.2 — Triton Inference Server & TensorRT-LLM Engine Compilation

## Opening Motivation & Context

In the realm of AI and machine learning, the need for high-throughput model serving is paramount. As models grow in complexity and size, the demand for efficient inference becomes increasingly critical. This lesson focuses on two key technologies: the Triton Inference Server and the TensorRT-LLM Engine. These tools are designed to optimize the serving of large language models (LLMs) and other AI models, ensuring high throughput and low latency.

The Triton Inference Server is an open-source inference serving software developed by NVIDIA. It provides a unified interface for deploying models from different frameworks, such as TensorFlow, PyTorch, and ONNX, on a variety of hardware platforms. The TensorRT-LLM Engine, on the other hand, is a high-performance inference engine for LLMs that leverages NVIDIA's TensorRT framework to optimize model execution on NVIDIA GPUs.

By combining these two technologies, we can achieve high-throughput model serving that meets the demands of modern AI applications. This lesson will guide you through the process of setting up and using the Triton Inference Server with the TensorRT-LLM Engine for compiling and serving LLMs.

## Core Concepts Breakdown

### Triton Inference Server

The Triton Inference Server is a flexible and high-performance inference server that supports a wide range of deep learning and machine learning frameworks. It provides a unified interface for deploying models, making it easier to manage and scale AI applications. The server can be configured to handle multiple models simultaneously, and it supports both synchronous and asynchronous inference requests.

> [!KEY-INSIGHT]
> The Triton Inference Server acts as a bridge between different AI frameworks and hardware platforms, providing a unified interface for model deployment and inference.

> [!BEST-PRACTICE]
> Always use the latest version of the Triton Inference Server to ensure compatibility with the latest AI frameworks and hardware platforms.

### TensorRT-LLM Engine

The TensorRT-LLM Engine is a high-performance inference engine for LLMs that leverages NVIDIA's TensorRT framework to optimize model execution on NVIDIA GPUs. It supports a variety of LLMs, including BERT, GPT, and T5, and it provides features such as dynamic batching, model parallelism, and quantization to further optimize performance.

> [!KEY-INSIGHT]
> The TensorRT-LLM Engine is designed to maximize the performance of LLMs on NVIDIA GPUs, making it an ideal choice for high-throughput model serving.

> [!WARNING]
> Ensure that your NVIDIA GPU drivers are up to date to avoid compatibility issues with the TensorRT-LLM Engine.

## Code Demonstration & Runtime Output

Let's start by setting up the Triton Inference Server and compiling the TensorRT-LLM Engine for a sample LLM. We'll use the Hugging Face Transformers library to load the model and the TensorRT-LLM Engine to compile it for inference.

```python
import os
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer
from tensorrt_llm import Builder, LLM

# Define the model and tokenizer paths
model_path = "gpt2"
tokenizer_path = "gpt2"

# Load the model and tokenizer
model = AutoModelForCausalLM.from_pretrained(model_path)
tokenizer = AutoTokenizer.from_pretrained(tokenizer_path)

# Define the engine configuration
engine_config = {
    "max_batch_size": 8,
    "max_input_len": 1024,
    "max_output_len": 1024,
    "dtype": "float16",
    "use_gemm_plugin": True,
    "use_fp8": False,
}

# Build the TensorRT-LLM Engine
builder = Builder()
engine = builder.build(model, engine_config)

# Save the engine
engine.save("gpt2.engine")

# Define the Triton Inference Server configuration
triton_config = {
    "model_repository": "model_repository",
    "model_name": "gpt2",
    "model_version": "1",
    "input_names": ["input_ids", "attention_mask"],
    "output_names": ["output_ids"],
    "input_shapes": {"input_ids": (1, 1024), "attention_mask": (1, 1024)},
    "output_shapes": {"output_ids": (1, 1024)},
    "dtype": "FP16",
}

# Create the model repository directory
os.makedirs(triton_config["model_repository"], exist_ok=True)

# Save the engine to the model repository
engine.save(os.path.join(triton_config["model_repository"], triton_config["model_name"], triton_config["model_version"], "model.plan"))

# Save the configuration file
with open(os.path.join(triton_config["model_repository"], triton_config["model_name"], "config.pbtxt"), "w") as f:
    f.write(f"""
name: "{triton_config["model_name"]}"
platform: "tensorrt_plan"
max_batch_size: {triton_config["input_shapes"]["input_ids"][0]}
input [
  {{
    name: "input_ids"
    data_type: TYPE_INT32
    dims: {triton_config["input_shapes"]["input_ids"]}
  }},
  {{
    name: "attention_mask"
    data_type: TYPE_INT32
    dims: {triton_config["input_shapes"]["attention_mask"]}
  }}
]
output [
  {{
    name: "output_ids"
    data_type: TYPE_INT32
    dims: {triton_config["output_shapes"]["output_ids"]}
  }}
]
""")

print("Triton Inference Server and TensorRT-LLM Engine setup complete.")
```

3. **Load Model and Tokenizer**: We use the `AutoModelForCausalLM` and `AutoTokenizer` classes from the Hugging Face Transformers library to load the model and tokenizer.
4. **Define Engine Configuration**: We define the configuration for the TensorRT-LLM Engine, including parameters such as `max_batch_size`, `max_input_len`, `max_output_len`, `dtype`, `use_gemm_plugin`, and `use_fp8`.
