### 3. **Sampling Strategies**
- **Head-Based Sampling**: Decide at trace start (e.g., sample 1% of requests).
- **Tail-Based Sampling**: Decide after trace completion (e.g., sample traces with `latency > 1s`).
- **LLM-Specific Rules**:
  ```yaml
  # OTel Collector sampling config
  processors:
    probabilistic_sampler:
      sampling_percentage: 10
    filter:
      spans:
        include:
          match_type: strict
          attributes:
            - key: llm.model.id
              value: "gpt-4-*"
  ```

### 4. **Context Propagation in LLM Systems**
- **HTTP Headers**: `traceparent` (W3C standard) and `tracestate` (vendor-specific).
- **gRPC Metadata**: Propagate context in RPC calls.
- **Async Frameworks**: Ensure context flows across async tasks (e.g., Python `asyncio`, Go `goroutines`).

class LLMTracer:
    """
    A class to handle distributed tracing for LLM applications using OpenTelemetry.
    """

    def __init__(self, service_name: str, otlp_endpoint: str):
        """
        Initialize the LLMTracer with the given service name and OTLP endpoint.

        Args:
            service_name (str): The name of the service.
            otlp_endpoint (str): The endpoint for the OTLP exporter.
        """
        self.service_name = service_name
        self.otlp_endpoint = otlp_endpoint
        self.tracer_provider = TracerProvider()
        self.tracer = self.tracer_provider.get_tracer(__name__)
        self.exporter = OTLPSpanExporter(endpoint=self.otlp_endpoint, insecure=True)
        self.span_processor = BatchSpanProcessor(self.exporter)
        self.tracer_provider.add_span_processor(self.span_processor)

    def instrument(self):
        """
        Instrument various libraries and frameworks for distributed tracing.
        """
        # Instrument common libraries
        RequestsInstrumentor().instrument()
        GrpcInstrumentorClient().instrument()
        PymongoInstrumentor().instrument()
        Psycopg2Instrumentor().instrument()
        RedisInstrumentor().instrument()
        SQLAlchemyInstrumentor().instrument()
        URLLib3Instrumentor().instrument()
        URLLibInstrumentor().instrument()
        HTTPXClientInstrumentor().instrument()
        AioHttpClientInstrumentor().instrument()
        Jinja2Instrumentor().instrument()
        LoggingInstrumentor().instrument()

        # Instrument web frameworks
        FastAPIInstrumentor().instrument()
        GrpcInstrumentorServer().instrument()
        GrpcAioInstrumentorClient().instrument()
        GrpcAioInstrumentorServer().instrument()

    def trace_llm_call(self, prompt: str, model: str) -> Tuple[str, float]:
        """
        Trace an LLM call with the given prompt and model.

        Args:
            prompt (str): The prompt for the LLM.
            model (str): The model to use for the LLM.

        Returns:
            Tuple[str, float]: The response from the LLM and the time taken.
        """
        with self.tracer.start_as_current_span("llm_call") as span:
            span.set_attribute("prompt", prompt)
            span.set_attribute("model", model)
            start_time = time.time()
            # Simulate LLM call
            time.sleep(1)
            response = f"Response to prompt: {prompt} using model: {model}"
            end_time = time.time()
            span.set_attribute("response", response)
            span.set_attribute("time_taken", end_time - start_time)
            return response, end_time - start_time

    def shutdown(self):
        """
        Shutdown the tracer and exporter.
        """
        self.span_processor.shutdown()
        self.exporter.shutdown()

if __name__ == "__main__":

# Step-by-Step Execution Trace

1. **User Request**:
   ```bash
   curl -X POST http://localhost:8000/chat \
     -H "x-user-id: user123" \
     -H "x-request-id: req456" \
     -d '{"prompt": "Explain LLM tracing"}'
   ```

2. **API Gateway**:
   - Creates span `chat_request` with `trace_id=abc123`, `span_id=def456`.
   - Injects `traceparent: 00-abc123-def456-01` into headers.
   - Forwards request to `prompt-preprocessor`.

3. **Prompt Preprocessor**:
   - Extracts `traceparent` from headers.
   - Creates child span `preprocess` with `parent_id=def456`.
   - Adds attributes: `llm.prompt.text`, `llm.prompt.tokens`.
   - Forwards to `model-inference`.

4. **Model Inference (vLLM)**:
   - Extracts `traceparent`.
   - Creates span `inference` with `parent_id=preprocess`.
   - For each token generation step:
     ```python
     with tracer.start_as_current_span("inference_step") as step_span:
         step_span.set_attribute("llm.token.id", token_id)
         step_span.set_attribute("llm.token.text", token_text)
     ```
   - Forwards to `safety-filter`.

5. **Safety Filter**:
   - Extracts `traceparent`.
   - Creates span `safety_check` with `parent_id=inference`.
   - Adds attributes: `llm.safety.score`, `llm.safety.flagged`.
   - Returns response to `api-gateway`.

6. **OTel Collector**:
   - Receives spans via OTLP.
   - Applies sampling (10% of traces).
   - Exports to Jaeger and logs.

7. **Jaeger UI**:
   - Visualizes trace `abc123` with 4 spans:
     ```
     chat_request (api-gateway)
     ├── preprocess (prompt-preprocessor)
     ├── inference (model-inference)
     │   ├── inference_step (token 1)
     │   ├── inference_step (token 2)
     │   └── ...
     └── safety_check (safety-filter)
     ```

# Hard-Won Production Traps & Antipatterns

> [!TRAP] **High-Cardinality Explosion**
> **Problem**: Adding `llm.prompt.text` as a span attribute causes storage/performance issues.
> **Solution**:
> - Hash prompts: `llm.prompt.id = md5(prompt_text)`.
> - Use exemplars (sampled traces) for debugging.
> - Apply attribute limits in the OTel Collector:
>   ```yaml
>   processors:
>     attributes:
>       actions:
>         - key: llm.prompt.text
>           action: delete
>   ```

> [!TRAP] **Broken Context Propagation**
> **Problem**: Async tasks (e.g., Celery, asyncio) lose trace context.
> **Solution**:
> - Use framework-specific instrumentation (e.g., `opentelemetry.instrumentation.celery`).
> - Manually propagate context:
>   ```python
>   from opentelemetry.context import attach, detach
>   token = attach(extract(request.headers))
>   try:
>       # async task
>   finally:
>       detach(token)
>   ```

# Systems Benchmarking & Performance Profile

| **Component**               | **Time Complexity**       | **Space Complexity**      | **Production Impact**                     |
|-----------------------------|---------------------------|---------------------------|-------------------------------------------|
| Span Creation               | O(1)                      | O(1)                      | Minimal overhead per request.             |
| Context Propagation         | O(1)                      | O(1)                      | Negligible (header parsing).              |
| OTel Collector (Batching)   | O(n) (n = batch size)     | O(n)                      | Reduces export overhead.                  |
| Sampling                    | O(1)                      | O(1)                      | Critical for cost control.                |
| Jaeger Storage              | O(log n) (query)          | O(n) (traces)             | Index high-cardinality attributes.        |

### **Latency Overhead**:
- **Span Creation**: ~50-100µs per span.
- **Context Propagation**: ~10-20µs per hop.
- **OTel Collector**: ~1-5ms per batch (configurable).

### **Storage Costs**:
- **Raw Span**: ~1KB (with attributes).
- **1M requests/day**: ~1GB/day (before sampling).
- **With 10% sampling**: ~100MB/day.

### **Optimizations**:
1. **Sampling**: Use tail-based sampling for LLM-specific rules.
2. **Batching**: Configure `BatchSpanProcessor` with `max_queue_size=2048`, `schedule_delay=5s`.
3. **Attribute Filtering**: Drop low-value attributes (e.g., `http.route`).
