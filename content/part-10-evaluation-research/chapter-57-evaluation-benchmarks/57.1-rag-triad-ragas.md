Retrieval-augmented generation (RAG) answers a question by retrieving passages from a document store and asking a language model (LLM) to answer from them. In this lesson you will score five test answers with the three RAG triad checks, see which failure each check catches, and read the definitions used by the RAGAS evaluation framework.

**You need:** TF-IDF and cosine similarity (Lesson 22.1) and the RAG pipeline (Lesson 37.2).

## The problem: a fluent answer can be partly invented

A user asks "When did Ferncliff Lab open?" Ferncliff Lab is an invented lab, so no answer can come from outside knowledge. The retriever returns three chunks of text, and the model replies: "Ferncliff Lab opened in 2014. The state funded it in 2016." The first sentence is in the retrieved text. The second is not. A single overall rating would hide where the fault lies: in the retriever, in the generator, or in the answer's focus. The triad separates these.

## Three checks, one per edge

A RAG pipeline has three texts: the query, the retrieved context and the answer. Each pair of texts forms an edge, and the RAG triad (a set of three checks named in the TruLens evaluation documentation) puts one check on each edge.

![Triangle with the query, retrieved context and answer as corners; context relevance on the query-context edge, groundedness on the context-answer edge, answer relevance on the query-answer edge](diagrams/57.1-rag-triad.svg "Three texts, three edges. Each edge gets one score.")

- **Context relevance** (query to context) asks whether the retrieved text bears on the question. A low score points at the retriever.
- **Groundedness** (context to answer) asks whether each claim in the answer is supported by the context. RAGAS calls this **faithfulness**. A low score points at the generator.
- **Answer relevance** (query to answer) asks whether the answer addresses the question. A low score catches answers that are off target, even if they are true.

RAGAS (Es et al., 2023) defines the same three ideas. Its stated goal is to evaluate RAG pipelines without human-written reference answers.

## Worked example: groundedness, claim by claim

Groundedness is scored per claim. Treat each sentence of the answer as one claim. A claim is supported when one chunk contains enough of its content terms. Content terms are the words that remain after removing stopwords (words such as "the", "of", "in") and stripping plural and past-tense endings, so "opened" becomes "open".

![Two claims from case B, each with its best matching chunk. Claim one covers 1.00 of its terms and is supported; claim two covers 0.00 and is not. F equals 1 divided by 2, which is 0.50](diagrams/57.1-claim-check.svg "Claim by claim. One supported claim out of two gives F = 0.50.")

Case B's first claim, "Ferncliff Lab opened in 2014.", has the content terms {ferncliff, lab, open, 2014}. Chunk 0 contains all four, so the claim's support is 1.00. The second claim, "The state funded it in 2016.", has the terms {state, fund, 2016}. No chunk contains any of them, so its support is 0.00. Using a support threshold θ = 0.8 (a claim counts as supported when its support is at least θ), the faithfulness is F = supported claims / all claims = 1/2 = 0.50.

The judge in this lesson is a stub. Term overlap stands in for the language model or natural language inference (NLI) model that RAGAS and most production systems use to decide whether a claim follows from the context. The aggregation is the part that carries over.

## Code: five test cases, three scores

The code uses only the standard library, so it runs in the browser. It builds a six-chunk corpus, retrieves with TF-IDF, and scores five answers.

```python
import math
import re

# Toy corpus. The facts are invented so that no answer can come from outside knowledge.
CHUNKS = [
    "Ferncliff Lab opened in 2014 in the town of Brindle.",
    "The lab has 42 staff members, of whom 11 hold doctorates.",
    "Its main instrument is a cryo-microscope bought in 2019.",
    "Brindle is a market town known for its river mill.",
    "The river mill closed to visitors in 2011 for repairs.",
    "Staff at the lab publish on protein structure every year.",
]

STOP = {"a", "an", "the", "of", "in", "on", "at", "to", "for", "by", "with", "as", "is", "was",
        "be", "its", "it", "this", "that", "has", "have", "did", "when", "what", "who", "how",
        "where", "whom", "and", "or", "every", "their", "from", "year", "years", "each", "not",
        "are", "which", "does", "do"}


def stem(tok):
    # Crude suffix stripping: "opened" -> "open", "members" -> "member".
    for suf in ("ed", "s"):
        if tok.endswith(suf) and len(tok) - len(suf) >= 4:
            return tok[: -len(suf)]
    return tok


def terms(text):
    words = re.findall(r"[a-z0-9]+", text.lower().replace("-", " "))
    return [stem(w) for w in words if w not in STOP]


def idf_table(docs):
    n = len(docs)
    df = {}
    for d in docs:
        for t in set(terms(d)):
            df[t] = df.get(t, 0) + 1
    return {t: math.log((1 + n) / (1 + c)) + 1 for t, c in df.items()}


def tfidf(text, idf):
    v = {}
    for t in terms(text):
        v[t] = v.get(t, 0.0) + idf.get(t, math.log(1 + len(CHUNKS)) + 1)
    return v


def cosine(a, b):
    dot = sum(w * b.get(t, 0.0) for t, w in a.items())
    na = math.sqrt(sum(w * w for w in a.values()))
    nb = math.sqrt(sum(w * w for w in b.values()))
    return dot / (na * nb) if na and nb else 0.0


IDF = idf_table(CHUNKS)


def retrieve(query, k):
    qv = tfidf(query, IDF)
    ranked = sorted(range(len(CHUNKS)), key=lambda i: (-cosine(qv, tfidf(CHUNKS[i], IDF)), i))
    return ranked[:k]


def split_claims(answer):
    return [s.strip() for s in re.split(r"(?<=\.)\s+", answer.strip()) if s.strip()]


def support(claim, context):
    """Stub for the LLM/NLI check: the fraction of the claim's terms found in the best chunk."""
    ct = set(terms(claim))
    return max(len(ct & set(terms(CHUNKS[i]))) / len(ct) for i in context)


def faithfulness(answer, context, theta=0.8):
    cl = split_claims(answer)
    supported = [support(c, context) >= theta for c in cl]
    return sum(supported) / len(cl)


def context_relevance(question, context, min_shared=2):
    qt = set(terms(question))
    relevant = [len(qt & set(terms(CHUNKS[i]))) >= min_shared for i in context]
    return sum(relevant) / len(context)


def answer_relevance(question, answer):
    """Stub: cosine between the question and the answer as bags of terms.
    RAGAS instead generates questions from the answer and averages their similarity."""
    def bag(t):
        d = {}
        for w in terms(t):
            d[w] = d.get(w, 0.0) + 1.0
        return d
    return cosine(bag(question), bag(answer))


QUESTION = "When did Ferncliff Lab open?"
ctx_lab = retrieve(QUESTION, 3)
ctx_mill = retrieve("What does the river mill do?", 2)

CASES = [
    ("A grounded and on topic", "Ferncliff Lab opened in 2014.", ctx_lab, QUESTION),
    ("B one invented date", "Ferncliff Lab opened in 2014. The state funded it in 2016.", ctx_lab, QUESTION),
    ("C grounded, off topic", "The lab has 42 staff members.", ctx_lab, QUESTION),
    ("D right answer, wrong context", "Ferncliff Lab opened in 2014.", ctx_mill, QUESTION),
    ("E near miss paraphrase", "The lab was opened in 2014 by a team of 42 people.", ctx_lab, QUESTION),
]

results = {}
print("retrieved for question:", ctx_lab)
print("retrieved for mill query:", ctx_mill)
print()
print(f"{'case':32s} {'F':>5s} {'CR':>5s} {'AR':>5s}")
for name, answer, ctx, q in CASES:
    f = faithfulness(answer, ctx)
    cr = context_relevance(q, ctx)
    ar = answer_relevance(q, answer)
    results[name] = {"F": f, "CR": cr, "AR": ar}
    print(f"{name:32s} {f:5.2f} {cr:5.2f} {ar:5.2f}")

print()
print("claim supports for case B:")
for c in split_claims(CASES[1][1]):
    print(f"  {support(c, ctx_lab):.2f}  {c}")

print()
print("case E faithfulness vs theta:")
sweep = {}
for theta in (0.5, 0.8, 1.0):
    sweep[theta] = faithfulness(CASES[4][1], ctx_lab, theta)
    print(f"  theta={theta:.1f}  F={sweep[theta]:.2f}")
print("case E claim support:", round(support(split_claims(CASES[4][1])[0], ctx_lab), 3))
```

C grounded, off topic             1.00  0.33  0.29

Read the table row by row. Case A passes every check. Case B has one invented claim, so F falls to 0.50 while context relevance is unchanged. Case C is grounded but off topic, and its answer relevance is 0.29. Case D is the most instructive. The retriever fetched the mill chunks, so the answer "Ferncliff Lab opened in 2014" must come from the model's memory. Its answer relevance (0.87) is as high as case A's, but its groundedness is 0.00. Only the triad catches this. Case E is discussed below.

## Under the hood: the RAGAS formulas

Es et al. (2023, Section 3) define three ratios. Let $S$ be the set of statements in the answer and $V \subseteq S$ the statements the judge finds supported by the context:

$$F = \frac{|V|}{|S|}$$

Answer relevance generates $n$ questions $q_i$ from the answer and averages their cosine similarity with the original question $q$:

$$AR = \frac{1}{n}\sum_{i=1}^{n} \mathrm{sim}(q, q_i)$$

Context relevance is the fraction of context sentences that the judge extracts as needed to answer the question. Let $C$ be the context sentences and $E \subseteq C$ those extracted:

$$CR = \frac{|E|}{|C|}$$

The stub changes three things. First, $V$ is decided by term recall against threshold θ, not by an LLM. Second, AR is the cosine between the question and the answer's term counts, with no question generation. Third, $E$ is the set of context sentences that share at least two content terms with the question.

Three consequences follow from the formulas.

1. F is a mean of 0/1 indicators, so its resolution is $1/|S|$. An answer with two claims can only score 0, 0.50 or 1.00.
2. AR can be high whenever the answer repeats the question's words. It does not check where the facts came from (case D).
3. CR depends only on the retrieved set and the question. Cases A, B, C and E share one retrieved set, so all four have CR = 0.33.

## Threshold sensitivity

![A number line from 0 to 1 with a marker at 0.50 for case E's claim, and dashed thresholds at 0.5 and 0.8 and 1.0; the claim is supported at 0.5 and not at 0.8 or 1.0](diagrams/57.1-threshold.svg "Case E's claim has support 0.50. Whether the answer is grounded depends on θ.")

Case E says "The lab was opened in 2014 by a team of 42 people." Its best chunk covers half of its terms (lab, open and 2014 out of six). The context never mentions a team, so the claim is only partly supported. F is 1.00 at θ = 0.5 and 0.00 at θ = 0.8. The threshold decided the verdict, not the evidence. Any groundedness number should state its judge and threshold, and be checked against human labels before two systems are compared.

## Common traps

> [!TRAP] Term overlap is not entailment. The stub treats "not" as a stopword, so "The lab did not open in 2014." gets support 1.00. A real judge has to check meaning, and negation is exactly what term overlap loses.

> [!TRAP] A high answer-relevance score is not evidence of groundedness. Case D has AR 0.87 and F 0.00.

> [!TRAP] Context relevance does not depend on the answer. Four different answers share CR 0.33 because they share one retrieved set.

> [!TRAP] Threshold comparisons must be exact. If the code uses `support > theta` where the definition says "at least θ", case E's claim (support exactly 0.50) fails at θ = 0.5 and F drops from 1.00 to 0.00.

> [!TRAP] Short answers give coarse scores. With two claims, F can only be 0, 0.50 or 1.00, so a one-point change in the judge moves the score a lot.

## Summary

- The RAG triad puts one check on each edge: context relevance (query to context), groundedness (context to answer) and answer relevance (query to answer).
- Groundedness is scored claim by claim: F = supported claims / all claims, at a stated threshold θ.
- A high answer-relevance score can coexist with zero groundedness, so the three scores must be read together to locate a failure.
- Each score is a ratio whose value depends on the judge and the threshold. Report both.

### Question 1: Calculation

An answer has four claims, and the judge marks three as supported by the context. What is F, and which edge of the triad does it measure?

<details>
<summary>Solution</summary>

F = 3/4 = 0.75. It measures the context-to-answer edge, which is groundedness.

</details>

### Question 2: Prediction

The retriever returns the river-mill chunks for a lab question, and the model answers "Ferncliff Lab opened in 2014" from memory. Predict whether each score is high or low.

<details>
<summary>Solution</summary>

Context relevance is low, because the retrieved text does not bear on the question. Groundedness is low, because the claim is not in the context. Answer relevance is high, because the answer repeats the question's terms. Case D in the experiment gives 0.00, 0.00 and 0.87.

</details>

### Question 3: Bug-spotting

A colleague writes `supported = support > theta` and sets θ = 0.5. Case E's claim has support 0.50. What is F with this code, and what should it be under the definition in this lesson?

<details>
<summary>Solution</summary>

With `>`, the claim fails and F = 0.00. The lesson defines "supported" as support at least θ, so the check must be `>=`, which gives F = 1.00. A boundary value flips the verdict, so thresholds must be specified exactly.

</details>

### Question 4: Explanation

RAGAS generates questions from the answer instead of comparing the original question directly with the answer text. Give one plausible reason. Then say what in the source you would need to confirm it.

<details>
<summary>Solution</summary>

One plausible reason is that a generated question has the same form as the original question, so the comparison is question to question and is less sensitive to the answer's style. This is my own reasoning, not a result from the paper. To confirm the authors' motivation, read the discussion of answer relevance in Es et al. (2023, Section 3).

</details>
