A judge model is a large language model (LLM) that reads an output and returns a rating. In this lesson you will turn a judge's token probabilities into a continuous score, detect position bias with a swap test, and measure how well a judge agrees with human raters.

**You need:** the dot product (Lesson 20.1), and softmax as a probability distribution over a finite set of options.

> [!NOTE]
> Every number in this lesson comes from a simulated judge written in NumPy, with fixed random seeds. The simulation illustrates the mechanisms; it is not a measurement of any real language model. The published results that are quoted come from the cited papers, and each is labelled as such.

## The problem

Open-ended outputs such as summaries, dialogue replies and answers have many acceptable forms. A metric that counts word overlap with one reference misses good answers. Liu et al. (2023) report that reference-based metrics such as BLEU (Bilingual Evaluation Understudy) and ROUGE (Recall-Oriented Understudy for Gisting Evaluation) correlate weakly with human judgments, especially on creative tasks.

Human raters are the reference, but they are slow and expensive. A judge model can score thousands of outputs, provided its ratings agree with humans. That raises two questions: how to get a score that is more than a single integer, and how to tell whether the judge's verdicts are reliable.

## Intuition: a judge is a classifier over score tokens

![Five boxes in a row: task and criteria, model writes evaluation steps, model fills score form, probability of each score, sum of p(s) times s. The last two boxes are highlighted.](diagrams/57.2-judge-pipeline.svg "G-Eval-style scoring. The model writes the rubric and fills the form; the score comes from the probabilities of the score tokens.")

G-Eval (Liu et al., 2023) has two ingredients. First, the judge writes its own evaluation steps from the task description and the criteria, using chain-of-thought (step-by-step reasoning). Second, the judge fills in a form that ends with a score token. The final score is not the printed integer. It is the expected value under the judge's probabilities for the score tokens:

$$
\text{score} = \sum_{i} p(s_i)\, s_i
$$

Here $s_i$ are the allowed scores (the paper's examples use 1 to 5) and $p(s_i)$ is the probability the model assigns to token $s_i$ (Liu et al., 2023, Section 2). The probabilities come from the model's output distribution. A judge reached through an application programming interface (API) that returns only text cannot supply them, so the weighted score is unavailable there.

## Worked example by hand

Take five scores and a judge that assigns these probabilities: $p = [0.05,\ 0.10,\ 0.20,\ 0.40,\ 0.25]$. They sum to 1.00.

The hard score, the most likely token, is 4. The expected score is:

$$
0.05 \cdot 1 + 0.10 \cdot 2 + 0.20 \cdot 3 + 0.40 \cdot 4 + 0.25 \cdot 5 = 0.05 + 0.20 + 0.60 + 1.60 + 1.25 = 3.70
$$

The 0.25 on score 5 pulls the result up, and the mass on 1 and 2 pulls it down. The 3.70 keeps the judge's doubt that the hard score 4 throws away.

![Bars for the probabilities of score tokens 1 to 5, with a dashed line at the expected score 3.70 between 3 and 4.](diagrams/57.2-weighted-score.svg "The judge's probabilities over score tokens. The dashed line marks the expected score.")

Check the arithmetic with this code, which uses only NumPy:

```python
import numpy as np

scores = np.array([1, 2, 3, 4, 5])
p = np.array([0.05, 0.10, 0.20, 0.40, 0.25])   # judge's probability for each score token
expected = float(np.dot(p, scores))             # sum_i p(s_i) * s_i
argmax_score = int(scores[np.argmax(p)])        # hard score: the most likely token
print("expected score:", round(expected, 3), " argmax score:", argmax_score)
```

```output
expected score: 3.7  argmax score: 4
```

> [!KEY-INSIGHT]
> The weighted score is only as good as the probabilities behind it. A judge that is confidently wrong gives a confidently wrong score. Calibration, meaning whether stated probabilities match how often the judge is right, is a separate property that you must measure.

## Why the weighted score resolves ties

A hard score takes one of five values, so many responses tie. Ties weaken rank-based agreement measures. Spearman's rank correlation $\rho$ is the Pearson correlation of the ranks, and tied values receive their average rank.

The next simulation has 300 responses. Each has a latent quality $z$ drawn from $N(0,1)$, the normal distribution with mean 0 and variance 1. The human rating is a noisy linear function of $z$. The judge's latent opinion has its own noise, and its probabilities over the five scores form a soft bump centred on that opinion. Run seed 1, then 20 seeds to see whether the difference is stable.

```python
import numpy as np

def rank(x):
    x = np.asarray(x, float)
    order = np.argsort(x, kind="stable")
    r = np.empty(len(x))
    r[order] = np.arange(1, len(x) + 1)
    for v in np.unique(x):                             # average ranks over ties
        m = x == v
        r[m] = r[m].mean()
    return r

def spearman(a, b):
    return float(np.corrcoef(rank(a), rank(b))[0, 1])

def resolution_run(seed, n=300):
    rng = np.random.default_rng(seed)
    z = rng.standard_normal(n)                                  # latent quality of each response
    human = 3 + 1.1 * z + 0.5 * rng.standard_normal(n)          # human rating (continuous)
    mu = 3 + 1.1 * z + 0.8 * rng.standard_normal(n)             # judge's latent opinion
    s = np.arange(1, 6)
    logits = -(s[None, :] - mu[:, None]) ** 2 / (2 * 0.6 ** 2)  # judge's distribution over 1..5
    pj = np.exp(logits - logits.max(1, keepdims=True))
    pj /= pj.sum(1, keepdims=True)
    hard = s[np.argmax(pj, 1)]
    weighted = pj @ s
    return {"distinct_hard": int(len(np.unique(hard))),
            "distinct_weighted": int(len(np.unique(np.round(weighted, 9)))),
            "rho_hard": spearman(hard, human),
            "rho_weighted": spearman(weighted, human)}

resolution = resolution_run(seed=1)
print("distinct values  hard:", resolution["distinct_hard"], " weighted:", resolution["distinct_weighted"])
print("spearman vs human  hard:", round(resolution["rho_hard"], 3), " weighted:", round(resolution["rho_weighted"], 3))
gaps = [resolution_run(seed=s) for s in range(20)]
diff = np.array([g["rho_weighted"] - g["rho_hard"] for g in gaps])
print("20 seeds: weighted minus hard rho, mean", round(diff.mean(), 3), " min", round(diff.min(), 3),
      " max", round(diff.max(), 3))
```

```output
distinct values  hard: 5  weighted: 300
spearman vs human  hard: 0.609  weighted: 0.63
20 seeds: weighted minus hard rho, mean 0.017  min -0.005  max 0.047
```

The resolution gain is real: 300 distinct values instead of 5. The agreement gain is small and not guaranteed. Across 20 seeds the weighted score is ahead on average by 0.017, and on two of the 20 seeds it is behind. Do not expect a large accuracy gain from probability weighting alone.

## Position bias and the swap test

Position bias means the verdict depends on which slot a response occupies, not only on its quality. Wang et al. (2023) show that changing the order of candidate responses in the context can change which model the judge ranks higher. Zheng et al. (2023) measured this on the MT-Bench benchmark. Given two similar answers to the same question, judged in both orders, GPT-4 (a model from OpenAI) gave the same verdict 65.0% of the time, and GPT-3.5 gave the same verdict 46.2% of the time (their Table 2).

The swap test is the standard check. Call the judge twice, once with the responses in order A then B, and once with B then A. Declare a winner only if the same response wins both calls. An inconsistent pair counts as a tie. Zheng et al. (2023, Section 3.4) use this conservative rule.

![A table with two rows. Row one: call 1 picks slot 1 (A), call 2 picks slot 2 (A), verdict A wins. Row two: call 1 picks slot 1 (A), call 2 picks slot 1 (B), verdict tie.](diagrams/57.2-swap-test.svg "Swap test. A verdict survives only if the same response wins in both orders.")

To see the rule's effect, simulate a pairwise judge. Its logit for "prefer the response in slot 1" is $\kappa (q_{\text{first}} - q_{\text{second}}) + \beta + \varepsilon$, with $\kappa = 2$, Gaussian noise $\varepsilon \sim N(0,1)$, and $\beta$ as a slot-1 bias. Latent qualities are $N(0,1)$, and the ground truth is whether A is better than B.

```python
import numpy as np

def judge_prefers_first(q_first, q_second, rng, beta, kappa=2.0, sigma=1.0):
    """Simulated judge. Logit = kappa*(quality gap) + beta (slot-1 bias) + Gaussian noise.
    Returns True when the judge picks the response in the first slot."""
    logit = kappa * (q_first - q_second) + beta + sigma * rng.standard_normal(q_first.shape)
    return logit > 0

def position_bias_report(beta, n=2000, seed=0):
    rng = np.random.default_rng(seed)
    qA = rng.standard_normal(n)                        # latent quality of response A
    qB = rng.standard_normal(n)                        # latent quality of response B
    truth_A = qA > qB                                  # ground truth: is A better?
    first_1 = judge_prefers_first(qA, qB, rng, beta)   # call 1: A in slot 1
    first_2 = judge_prefers_first(qB, qA, rng, beta)   # call 2: B in slot 1 (swapped)
    A_wins_1 = first_1                                 # call 1 picks slot 1 = A
    A_wins_2 = ~first_2                                # call 2 picks slot 1 = B, so A wins iff slot 1 is not picked
    consistent = A_wins_1 == A_wins_2                  # same winner in both orders
    naive_correct = A_wins_1 == truth_A                # single order, no tie option
    return {
        "beta": beta,
        "slot1_pref_rate": float(np.mean(first_1)),                 # 0.5 means no slot preference
        "naive_acc": float(np.mean(naive_correct)),                 # single order, all pairs
        "naive_acc_on_consistent": float(np.mean(naive_correct[consistent])),
        "consistency": float(np.mean(consistent)),
        "tie_rate": float(1 - np.mean(consistent)),                 # inconsistent pairs become ties
        "swap_acc_decided": float(np.mean(naive_correct[consistent])),
        "swap_acc_ties_wrong": float(np.mean(naive_correct & consistent)),
    }

print("beta  slot1  naive  naive|cons  consist  tie    acc|decided  acc(ties wrong)")
for beta in [0.0, 0.5, 1.0]:
    r = position_bias_report(beta)
    print(f"{r['beta']:.1f}   {r['slot1_pref_rate']:.3f}  {r['naive_acc']:.3f}  "
          f"{r['naive_acc_on_consistent']:.3f}       {r['consistency']:.3f}    {r['tie_rate']:.3f}  "
          f"{r['swap_acc_decided']:.3f}        {r['swap_acc_ties_wrong']:.3f}")
```

```output
beta  slot1  naive  naive|cons  consist  tie    acc|decided  acc(ties wrong)
0.0   0.503  0.882  0.959       0.839    0.161  0.959        0.804
0.5   0.556  0.877  0.965       0.807    0.193  0.965        0.779
1.0   0.624  0.841  0.974       0.725    0.275  0.974        0.706
```

Read the columns from left to right. At $\beta = 0$ the judge has no slot preference (slot1 = 0.503), yet it is inconsistent on 16.1% of pairs. Random noise alone flips verdicts, so inconsistency is not proof of position bias. At $\beta = 1.0$ the slot-1 rate rises to 0.624, consistency falls to 72.5%, and naive single-order accuracy drops from 0.882 to 0.841.

![Grouped bars at three beta values for slot-1 pick, consistency, naive accuracy and accuracy on decided pairs.](diagrams/57.2-position-bias.svg "Simulated judge at three slot-1 weights. Every bar comes from the code above.")

The swap rule's gain needs care. On the pairs it keeps, accuracy is 0.959 to 0.974. But the naive|cons column shows that single-order verdicts on the same pairs are exactly as accurate. The swap rule improves precision by abstaining on the pairs it cannot resolve. It does not make the judge better. With ties counted as wrong, the swap rule scores below single-order accuracy at every $\beta$ (0.804 against 0.882 at $\beta = 0$). Whether abstention pays depends on how often the judge is right on the pairs it drops, and this simulation sets that by construction.

> [!TRAP]
> The swap test cannot detect a bias that is the same in both orders. A judge that prefers longer responses in either slot returns consistent verdicts, so the swap test passes it. Zheng et al. (2023) name verbosity bias and self-enhancement bias as separate problems, and the swap test does not address them.

## Alignment: agreement with human judgments

Alignment here means agreement with human judgments on your own task, measured on a labelled set that the judge did not see during design. Two kinds of measure are common.

- **Score correlation.** Spearman $\rho$ and Kendall $\tau$ compare judge scores with human scores. Liu et al. (2023) report, for G-Eval with GPT-4 on the summarization task (the SummEval dataset, averaged over four dimensions), $\rho = 0.514$ and $\tau = 0.418$ (their Table 1). The paper's abstract also says that LLM evaluators may favour LLM-generated text.
- **Pairwise agreement.** Zheng et al. (2023) report that GPT-4 agreed with human votes on MT-Bench first-turn pairs in 66% of cases when ties count (random baseline 33%), and in 85% of cases when ties are excluded (random baseline 50%). Human-to-human agreement on the first-turn pairs was 63% and 81% (their Table 5a).

Those published figures come from the papers, not from the simulation above. They describe one benchmark and one judge, so they do not transfer to your criteria without a new check.

> [!TRAP]
> Do not treat a judge as validated because another benchmark reports high agreement. Measure agreement on your own labelled sample, with the same criteria and the same output distribution you will score in production.

> [!TRAP]
> Spearman with ties needs average ranks. Ranking with `argsort` alone assigns tied values different ranks and biases the correlation. The `rank` function above shows the fix.

## Summary

- A judge's score can be the probability-weighted average of score tokens, which has far finer resolution than the hard score. It needs token probabilities, which some APIs do not expose.
- Position bias shows up as a slot preference and as verdicts that flip when the order is swapped. Noise also causes flips, so measure both.
- The swap test keeps only consistent verdicts. In simulation it buys precision by abstaining, not by making the judge more accurate.
- Alignment is measured on your own labelled data with rank correlation and pairwise agreement. Published agreement figures do not transfer.

## Quiz time

### Question 1: Calculation

A judge returns probabilities $p = [0.1,\ 0.2,\ 0.3,\ 0.3,\ 0.1]$ over scores 1 to 5. Compute the probability-weighted score. What does `np.argmax` return as the hard score, and why?

<details><summary>Show solution</summary>

The weighted score is $0.1 \cdot 1 + 0.2 \cdot 2 + 0.3 \cdot 3 + 0.3 \cdot 4 + 0.1 \cdot 5 = 0.1 + 0.4 + 0.9 + 1.2 + 0.5 = 3.1$. Scores 3 and 4 tie at probability 0.3. `np.argmax` returns the index of the first maximum, which is the position for score 3. The hard score is therefore 3, although the expected score sits between 3 and 4.

</details>

### Question 2: Prediction

Suppose the judge's noise is zero and $\beta = 0$. What happens to the consistency rate in the swap test, and what is the tie rate?

<details><summary>Show solution</summary>

With zero noise and no slot bias, the logit is $\kappa(q_{\text{first}} - q_{\text{second}})$, so the judge always picks the higher-quality response. Both orders name the same response, so consistency is 100% and the tie rate is 0. The only exception is a pair with exactly equal quality, which has probability zero for continuous draws.

</details>

### Question 3: Bug-spotting

This swap function has a bug. Find it and fix it.

```python
def swap_verdict(judge, a, b):
    v1 = judge(a, b)        # True if the judge picks the first slot
    v2 = judge(b, a)
    return "A" if v1 else "B"
```

<details><summary>Show solution</summary>

The function never uses `v2`, so it is a single-order judge with a different name. A second call that is ignored cannot detect position bias. The fix requires both calls to agree, and returns a tie otherwise:

```python
def swap_verdict(judge, a, b):
    v1 = judge(a, b)        # True if the judge picks the first slot (A)
    v2 = judge(b, a)        # True if the judge picks the first slot (B)
    a_wins_2 = not v2       # in the swapped call, A wins iff slot 1 is not picked
    if v1 and a_wins_2:
        return "A"
    if not v1 and not a_wins_2:
        return "B"
    return "tie"
```

</details>

### Question 4: Explanation

In the simulation, naive accuracy falls as $\beta$ rises, but $\beta$ is a property of the slot, not of the responses. Why does it still change which verdicts are correct?

<details><summary>Show solution</summary>

The bias enters the logit as an additive constant. A pair with quality gap $\Delta$ is judged on the sign of $\kappa \Delta + \beta + \varepsilon$. When $|\kappa \Delta|$ is small relative to $\beta$, the bias decides the verdict and can overrule the quality difference. The effect is probabilistic because of the noise $\varepsilon$, but on average it moves near-tied pairs toward slot 1. This is reasoning from the model we wrote, not an empirical claim about any real judge.

</details>
