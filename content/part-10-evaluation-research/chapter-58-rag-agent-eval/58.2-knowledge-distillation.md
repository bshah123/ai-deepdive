# 58.2 — Knowledge Distillation: Training Compact SLMs from Frontier Models

## Opening Motivation & Context

Knowledge distillation is a powerful technique in the field of machine learning that allows us to transfer the knowledge from a large, complex model (often referred to as the "teacher" model) to a smaller, more efficient model (the "student" model). This process is particularly relevant in the context of frontier models, which are state-of-the-art models that push the boundaries of what's possible in terms of performance and accuracy.

The primary motivation behind knowledge distillation is to create compact, efficient models that can be deployed in resource-constrained environments, such as mobile devices or edge devices, without sacrificing too much performance. By distilling the knowledge from a large model into a smaller one, we can achieve a balance between model size, computational efficiency, and accuracy.

## Core Concepts Breakdown

### Knowledge Distillation Overview

Knowledge distillation involves training a smaller model (the student) to mimic the behavior of a larger, more complex model (the teacher). The student model is trained using a combination of the ground truth labels and the soft targets (probability distributions) produced by the teacher model. This approach allows the student model to learn not only from the correct labels but also from the rich information contained in the teacher's predictions.

> [!KEY-INSIGHT]
> Knowledge distillation enables the creation of compact, efficient models that can achieve performance close to that of larger, more complex models, making them suitable for deployment in resource-constrained environments.

> [!BEST-PRACTICE]
> When performing knowledge distillation, it's important to carefully tune the temperature parameter, which controls the softness of the teacher's predictions. A higher temperature can help the student model learn more from the teacher's predictions, but it may also introduce more noise.

> [!WARNING]
> One common pitfall in knowledge distillation is the mismatch between the teacher and student architectures. If the student model is significantly different from the teacher model, it may struggle to learn the teacher's predictions effectively. It's important to ensure that the student model has a similar capacity to the teacher model to facilitate effective knowledge transfer.

## Code Demonstration & Runtime Output

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.utils.data import DataLoader, TensorDataset
from typing import Tuple, List

# Define a simple teacher model
class TeacherModel(nn.Module):
    def __init__(self, input_size: int, hidden_size: int, output_size: int) -> None:
        super(TeacherModel, self).__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_size, output_size)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        out = self.fc1(x)
        out = self.relu(out)
        out = self.fc2(out)
        return out

# Define a simple student model
class StudentModel(nn.Module):
    def __init__(self, input_size: int, hidden_size: int, output_size: int) -> None:
        super(StudentModel, self).__init__()
        self.fc1 = nn.Linear(input_size, hidden_size)
        self.relu = nn.ReLU()
        self.fc2 = nn.Linear(hidden_size, output_size)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        out = self.fc1(x)
        out = self.relu(out)
        out = self.fc2(out)
        return out

# Define a function to perform knowledge distillation
def knowledge_distillation(teacher: nn.Module, student: nn.Module, dataloader: DataLoader, epochs: int, temperature: float) -> None:
    criterion = nn.KLDivLoss(reduction='batchmean')
    optimizer = optim.Adam(student.parameters())

    for epoch in range(epochs):
        for inputs, targets in dataloader:
            # Get the teacher's predictions
            with torch.no_grad():
                teacher_logits = teacher(inputs)

            # Get the student's predictions
            student_logits = student(inputs)

            # Calculate the distillation loss
            distillation_loss = criterion(
                nn.functional.log_softmax(student_logits / temperature, dim=1),
                nn.functional.softmax(teacher_logits / temperature, dim=1)
            )

            # Calculate the classification loss
            classification_loss = nn.functional.cross_entropy(student_logits, targets)

            # Combine the losses
            total_loss = distillation_loss + classification_loss

            # Backpropagate and update the student's parameters
            optimizer.zero_grad()
            total_loss.backward()
            optimizer.step()

        print(f'Epoch {epoch + 1}, Loss: {total_loss.item()}')

# Generate synthetic data
def generate_data(num_samples: int, input_size: int, output_size: int) -> Tuple[torch.Tensor, torch.Tensor]:
    inputs = torch.randn(num_samples, input_size)
    targets = torch.randint(0, output_size, (num_samples,))
    return inputs, targets

if __name__ == '__main__':
    # Set the random seed for reproducibility
    torch.manual_seed(42)

    # Define the model parameters
    input_size = 10
    hidden_size = 20
    output_size = 5
    num_samples = 1000
    batch_size = 32
    epochs = 10
    temperature = 2.0

    # Generate synthetic data
    inputs, targets = generate_data(num_samples, input_size, output_size)

    # Create a DataLoader for the synthetic data
    dataset = TensorDataset(inputs, targets)
    dataloader = DataLoader(dataset, batch_size=batch_size, shuffle=True)

    # Initialize the teacher and student models
    teacher = TeacherModel(input_size, hidden_size, output_size)
    student = StudentModel(input_size, hidden_size // 2, output_size)

    # Perform knowledge distillation
    knowledge_distillation(teacher, student, dataloader, epochs, temperature)
```

<details><summary>Show Solution</summary>

The bug in the code is that the output tensor from the model is not passed through a softmax function before being used in the cross-entropy loss. To fix this, we can add a softmax function to the model's forward method:

```python
import torch
import torch.nn as nn

# Define a simple model
class SimpleModel(nn.Module):
    def __init__(self, input_size: int, output_size: int) -> None:
        super(SimpleModel, self).__init__()
        self.fc = nn.Linear(input_size, output_size)
        self.softmax = nn.Softmax(dim=1)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        out = self.fc(x)
        out = self.softmax(out)
        return out

# Initialize the model
model = SimpleModel(10, 5)

# Generate a random input tensor
input_tensor = torch.randn(1, 10)

# Get the model's predictions
output_tensor = model(input_tensor)

# Calculate the loss
loss = nn.functional.cross_entropy(output_tensor, torch.tensor([0]))

print(loss.item())
```
