By the end you will be able to build a Self-Instruct-style generation loop and an Evol-Instruct-style evolution loop, and say which filter stops which failure. The teacher here is a stub, not a language model, so every number shows a mechanism. None of them predicts what a real model would produce.

**You need:** Python 3.12, standard library only. The code runs in the in-browser Python on this page.

## The problem

Instruction tuning needs many pairs of an instruction and a response. Writing them by hand is slow. Self-Instruct (Wang et al., 2022) started from 175 human-written seed tasks and let a language model propose more. A naive loop fails in two ways. The model copies its own demonstrations, so the pool fills with near-duplicates. It also writes items the target task cannot use, such as requests that need an image. Each failure needs its own check.

![Loop: the seed pool and machine pool supply demonstrations; the teacher writes a candidate; filters decide whether it joins the pool](diagrams/58.1-selfinstruct-loop.svg "The Self-Instruct loop. Only accepted items feed back into the next prompt.")

## Self-Instruct: sample, write, filter

Each prompt shows the model 8 instructions: 6 from the human seeds and 2 from the machine-generated pool. The model writes one new instruction. It is kept only if its ROUGE-L similarity to every existing instruction is below 0.7. It must also pass heuristic filters: no banned keywords such as image, picture or graph, a sensible length, and no duplicate instances. The paper reports 52,445 instructions and 82,439 instances after filtering (its Table 1).

ROUGE-L is an F1 score built on the longest common subsequence (LCS) of two word sequences. For a candidate $c$ and reference $r$ with LCS length $\ell$, precision is $P = \ell/|c|$, recall is $R = \ell/|r|$, and the score is $F = 2PR/(P+R)$.

Worked example by hand. Take the candidate "Summarize a news article about rent prices." and the reference "Summarize a news article about volcanoes." The candidate has 7 words, the reference has 6, and the LCS is "summarize a news article about", so $\ell = 5$. Then $P = 5/7$, $R = 5/6$, and $F = 10/13 \approx 0.769$. That is above 0.7, so the second instruction is rejected even though its topic differs. The filter measures shared word order, not meaning.

The stub teacher copies a demonstration with probability 0.35 and changes its first word. Otherwise it composes a fresh instruction from templates. The 0.35 is my assumption, not measured from any model. It produces the near-duplicates the ROUGE filter exists to catch. The code below runs the whole loop and then sweeps the threshold. Outputs are deterministic because every random choice comes from a seeded `random.Random`.

```python
import random, re
from collections import Counter

def pick(rng, seq):
    return seq[int(rng.random() * len(seq))]

def tokens(s):
    return re.findall(r"[a-z0-9]+", s.lower())

def lcs_len(a, b):
    prev = [0] * (len(b) + 1)
    for x in a:
        cur = [0]
        for j, y in enumerate(b, 1):
            cur.append(prev[j - 1] + 1 if x == y else max(prev[j], cur[j - 1]))
        prev = cur
    return prev[-1]

def rouge_l(cand, ref):
    """ROUGE-L F1 on lower-cased word tokens. Our tokenizer, not the paper's."""
    c, r = tokens(cand), tokens(ref)
    if not c or not r:
        return 0.0
    l = lcs_len(c, r)
    if l == 0:
        return 0.0
    p, q = l / len(c), l / len(r)
    return 2 * p * q / (p + q)

VERBS = ["summarize", "classify", "translate", "explain", "list", "rewrite", "compare", "extract"]
OBJECTS = ["a news article", "a product review", "a short story", "a math word problem",
           "an email", "a recipe", "a picture caption", "a poem"]
CONSTRAINTS = ["in exactly three bullet points", "in under fifty words", "for a ten-year-old reader",
               "in the present tense", "as valid JSON", "without any adjectives"]
TOPICS = ["volcanoes", "rent prices", "solar panels", "the French Revolution", "sleep cycles",
          "bicycle repair", "coral reefs", "tax forms", "chess openings", "monsoon rain",
          "vaccine trials", "public libraries", "electric cars", "river deltas", "job interviews",
          "wind turbines", "medieval castles", "bread baking", "lunar eclipses", "water filters"]
BANNED = {"picture", "image", "graph"}   # keyword filter; the paper names image, picture, graph

def fresh(rng):
    text = f"{pick(rng, VERBS).capitalize()} {pick(rng, OBJECTS)} about {pick(rng, TOPICS)}"
    if rng.random() < 0.5:
        text += " " + pick(rng, CONSTRAINTS)
    return text + "."

class StubTeacher:
    """Stand-in for an LLM. It is not a language model: it writes templated text.
    With probability copy_prob it imitates a demonstration (copy it, swap the first word).
    Otherwise it composes a fresh instruction."""
    def __init__(self, copy_prob=0.35):
        self.copy_prob = copy_prob

    def write(self, rng, demos):
        if rng.random() < self.copy_prob:
            words = pick(rng, demos).split()
            words[0] = pick(rng, VERBS).capitalize()
            return " ".join(words)
        return fresh(rng)

SEED_TASKS, DEMOS, FROM_HUMAN, THRESHOLD = 175, 8, 6, 0.7

def self_instruct(rng, seeds, teacher, proposals=1000, threshold=THRESHOLD):
    pool, machine = list(seeds), []
    funnel = Counter(proposed=0, rejected_keyword=0, rejected_length=0, rejected_rouge=0, accepted=0)
    for _ in range(proposals):
        demos = [pick(rng, seeds) for _ in range(FROM_HUMAN)]
        demos += [pick(rng, machine or seeds) for _ in range(DEMOS - FROM_HUMAN)]
        cand = teacher.write(rng, demos)
        funnel["proposed"] += 1
        toks = tokens(cand)
        if BANNED & set(toks):
            funnel["rejected_keyword"] += 1
        elif not 3 <= len(toks) <= 20:              # our length cutoffs, not the paper's
            funnel["rejected_length"] += 1
        elif max(rouge_l(cand, p) for p in pool) >= threshold:
            funnel["rejected_rouge"] += 1
        else:
            funnel["accepted"] += 1
            pool.append(cand)
            machine.append(cand)
    return machine, funnel

seed_rng = random.Random(1)
seeds = [fresh(seed_rng) for _ in range(SEED_TASKS)]

machine, funnel = self_instruct(random.Random(2), seeds, StubTeacher())
print("funnel:", dict(funnel))
print("first accepted:", machine[:3])
print("ROUGE-L, near-twins:", round(rouge_l("Summarize a news article about rent prices.", "Summarize a news article about volcanoes."), 3))

sweep_rows = []
for t in [0.5, 0.6, 0.7, 0.8, 0.9]:
    m, f = self_instruct(random.Random(2), seeds, StubTeacher(), 1000, t)
    words = {w for s in m for w in tokens(s)}
    sweep_rows.append((t, f["accepted"], len(words)))
    print(f"threshold {t:.1f}: accepted {f['accepted']:4d}  distinct words {len(words)}")

OPS = {
    "add constraint": ["in under fifty words", "without any bullet points", "as valid JSON", "in the present tense"],
    "deepen": ["focusing on edge cases", "for a specialist audience", "with the main assumptions stated"],
    "concretize": ["using a concrete everyday example", "with three specific numbers", "naming a real city"],
    "more reasoning steps": ["showing each reasoning step", "checking the answer before stating it"],
    "complicate input": ["given a table with missing values", "where two of the inputs conflict"],
}

def evolve(rng, starts, rounds=4):
    by_depth = {0: list(starts)}
    killed = []
    for d in range(1, rounds + 1):
        nxt, dead = [], 0
        for text in by_depth[d - 1]:
            op = pick(rng, list(OPS))
            clause = pick(rng, OPS[op])
            if clause in text:                  # no information gain: the clause is already there
                dead += 1
            else:
                nxt.append(text.rstrip(".") + ", " + clause + ".")
        by_depth[d] = nxt
        killed.append(dead)
    return by_depth, killed

by_depth, killed = evolve(random.Random(3), seeds[:40])
for d in range(5):
    n = len(by_depth[d])
    mean = sum(len(tokens(s)) for s in by_depth[d]) / n if n else 0.0
    print(f"depth {d}: survivors {n:2d}  mean words {mean:5.1f}")
print("eliminated per round:", killed)
print("example at depth 4:", by_depth[4][0])
```

Of the 1000 proposals, 99 fail the keyword rule and 861 fail the ROUGE rule, leaving 40. The stub is harsh because its outputs share template words. The funnel therefore says more about the stub's template space than about any model. What should transfer is the shape: most proposals die at the similarity filter, and the pool grows slowly (my reasoning).

Changing the threshold shows the trade-off. At 0.5 and 0.6 almost nothing passes. At 0.8 and 0.9 the accepted count rises to 200 and 596, but the distinct-word count stays at 84. The extra items add no new vocabulary, so by this measure they are near-copies of earlier ones. That is my inference: the sweep did not measure pairwise similarity within the pool.

## Evol-Instruct: make the instructions harder

Evol-Instruct (Xu et al., 2023, WizardLM) rewrites seed instructions step by step into harder ones. Its five in-depth operations are: add constraints, deepening, concretizing, increased reasoning steps, and complicating the input. An in-breadth mutation creates new instructions on different topics. An eliminator drops failed evolutions. Its four failure cases include no information gain over the original (judged by a ChatGPT model in the paper) and a short apology-style response.

The stub implements the five in-depth operations as added clauses. It leaves out the in-breadth step. Its one elimination rule matches the first failure case: if the clause is already in the instruction, the evolution adds nothing and the lineage is dropped. Four rounds run on 40 seeds. Every survivor at depth $d$ has exactly $d$ added clauses.

![Survivors by depth: 40, 40, 36, 34, 26; mean words 9.0, 13.8, 18.5, 23.4, 27.9; eliminations between depths 0, 4, 2, 8](diagrams/58.1-evol-depth.svg "Evol-Instruct in the stub: survivors per depth, with the eliminated lineages between columns.")

The last round loses 8 of the 34 lineages alive at its start, which is about 24%. Early rounds lose fewer. Length grows from 9.0 to 27.9 words. Length is not quality, though. In the stub, longer instructions only carry more clauses. Whether a real model learns more from them is an empirical question this stub cannot answer.

## Why self-generated pools can collapse

A model trained on its own output loses the tails of the original distribution. Shumailov et al. (arXiv:2305.17493) call this model collapse. They report irreversible defects in variational autoencoders, Gaussian mixtures and language models. Our toy is a 50-category Zipf distribution. Each generation draws 200 samples from the current model and refits by frequency, which is the maximum-likelihood estimate for a categorical distribution. A category that gets zero samples can never return. The numbers are averages over 20 runs.

```python
import bisect, math, random

K, N, GENS, RUNS = 50, 200, 30, 20
zipf = [1.0 / (k + 1) for k in range(K)]          # Zipf-like: category k has weight 1/k
Z = sum(zipf)
p_real = [w / Z for w in zipf]

def draw_counts(rng, probs, n):
    cum, s = [], 0.0
    for p in probs:
        s += p
        cum.append(s)
    counts = [0] * len(probs)
    for _ in range(n):
        u = rng.random() * s
        counts[min(bisect.bisect_right(cum, u), len(probs) - 1)] += 1
    return counts

def entropy_bits(p):
    return -sum(x * math.log2(x) for x in p if x > 0)

def run(seed, anchor):
    """Each generation: sample from the current model, refit by empirical frequency (maximum likelihood)."""
    rng = random.Random(seed)
    p = list(p_real)
    support, entropy = [], []
    for g in range(GENS + 1):
        support.append(sum(1 for x in p if x > 0))
        entropy.append(entropy_bits(p))
        if g == GENS:
            break
        if anchor:   # half the training sample is always fresh real data
            counts = [a + b for a, b in zip(draw_counts(rng, p, N // 2), draw_counts(rng, p_real, N // 2))]
        else:        # pure self-training: all of it is generated by the previous model
            counts = draw_counts(rng, p, N)
        total = sum(counts)
        p = [x / total for x in counts]
    return support, entropy

print(f"real distribution: entropy {entropy_bits(p_real):.2f} bits over {K} categories")
series = {}
for anchor in (False, True):
    sup = [0.0] * (GENS + 1)
    ent = [0.0] * (GENS + 1)
    for seed in range(RUNS):
        s, e = run(seed, anchor)
        for g in range(GENS + 1):
            sup[g] += s[g] / RUNS
            ent[g] += e[g] / RUNS
    label = "anchored (half real)" if anchor else "pure self-training"
    series[label] = (sup, ent)
    print(label)
    for g in (0, 1, 5, 10, 20, 30):
        print(f"  gen {g:2d}: support {sup[g]:5.1f} of {K}  entropy {ent[g]:5.2f} bits")
```

## Common traps

> [!TRAP]
> ROUGE-L is lexical. Two instructions about different topics scored 0.769 above, and the filter rejected them. It catches copies and misses paraphrases of the same task.

> [!TRAP]
> Do not tune the threshold for pool size alone. A looser threshold gives more items, but the distinct-word count saturated at 84 in the sweep. Measure diversity, not count.

> [!TRAP]
> Do not let the teacher judge its own output with no independent check. The paper's eliminator uses a ChatGPT model, and a judge from the same family can share the teacher's blind spots (my reasoning; not measured here).

> [!TRAP]
> More evolution rounds give longer instructions, not automatically better training data. Depth is a count of clauses, and the stub's quality is not measured at all.

> [!TRAP]
> Feeding a model only its own output for many generations removes the tail. Our pure run loses 41 of 50 categories by generation 30 (a toy result; see above).

## Summary

- Self-Instruct grows an instruction pool by prompting a model with demonstrations and filtering its outputs with a ROUGE-L threshold of 0.7 and keyword and length rules.
- ROUGE-L measures shared word order. It catches copies but misses paraphrases and can reject different topics that share a template.
- Evol-Instruct makes instructions harder by adding constraints and steps, and drops evolutions that add no information.
- Count and length are not quality. Measure diversity, and check judge independence.
- Self-generated data without real data loses its tail; keeping a real-data share holds the distribution in the toy.

## Quiz time

### Question 1: Calculation

Compute ROUGE-L F1 for the candidate "Explain an email." against the reference "Explain an email about volcanoes." The candidate has 3 words, the reference has 5, and the LCS is 3. Would the stub's threshold of 0.7 accept the candidate?

<details><summary>Show solution</summary>

$P = 3/3 = 1$ and $R = 3/5 = 0.6$, so $F = 2 \cdot 1 \cdot 0.6 / (1 + 0.6) = 0.75$. Since $0.75 \ge 0.7$, the candidate is rejected.

</details>

### Question 2: Prediction

If the threshold were set to 1.0, which proposals would the ROUGE filter reject? Would the accepted count go up or down compared with 0.9?

<details><summary>Show solution</summary>

Only a score of exactly 1.0 is rejected, which means the token sequences are identical to an existing item. Fewer proposals are rejected, so the accepted count should go up relative to 0.9 (596). We did not run 1.0, so the size of the increase is not measured.

</details>

### Question 3: Bug-spotting

```python
def evolve_step(rng, text):
    op = pick(rng, OPS.keys())
    clause = pick(rng, OPS[op])
    return text.rstrip(".") + ", " + clause + "."
```

Find two problems.

<details><summary>Show solution</summary>

First, `pick` indexes with `len(seq)` and `seq[i]`, and `dict_keys` objects cannot be indexed, so the call raises `TypeError`. The fix is `pick(rng, list(OPS))`. Second, the function never checks whether the clause is already present, so it can add a duplicate, which the elimination rule is supposed to drop.

</details>

### Question 4: Explanation

Why does an anchored training sample keep categories that pure self-training loses?

<details><summary>Show solution</summary>

A category with zero count gets zero probability in the next model, so it is never sampled again and cannot recover. Fresh draws from the real distribution give the tail positive mass in every generation, so it survives.

</details>
