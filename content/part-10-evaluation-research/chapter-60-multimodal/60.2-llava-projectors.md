A vision-language model needs one step that is easy to skip: turning image features into input that a language model can read. In this lesson you will count the visual tokens that three connectors produce (linear, two-layer MLP and Q-Former), compute their parameter and memory costs, and run a small NumPy test of linear against MLP connectors.

**You need:** matrix multiplication and softmax (Lesson 25.1), and the idea that a vision encoder outputs one feature vector per image patch (Lesson 60.1).

## The problem: two spaces of different widths

A decoder-only language model (LLM) reads a sequence of vectors of fixed width $D_L$. For a 7B-class model with a LLaMA-style architecture I assume $D_L = 4096$ and 32 layers; I did not open a configuration file to confirm this. A vision encoder, here CLIP ViT-L/14 from Lesson 60.1, outputs one vector per patch with width $D_V = 1024$. The two widths differ, and the encoder was trained for a different objective, so its features cannot be fed to the LLM unchanged. A connector maps the $D_V$-wide patch features into $D_L$-wide visual tokens.

The number of patches follows from the resolution. A 14-pixel patch on a 336-pixel image gives a $24 \times 24$ grid, so $(336/14)^2 = 576$ patches. At 224 pixels the grid is $16 \times 16 = 256$.

![Four boxes in a row showing the shape at each stage: image 336 px, ViT 576 by 1024, connector 1024 to 4096, and LLM input 640 by 4096](diagrams/60.2-bridge-shapes.svg "Shapes for a 336-pixel image with a 64-token prompt. Only the connector changes the width.")

Every row of the connector output becomes one token in the prompt. Each visual token costs LLM context, prefill compute and KV-cache memory (the stored keys and values that let the model avoid recomputing earlier tokens). A connector is therefore judged on two things: how much of the image it carries, and how many tokens it hands over.

## Three connectors

**Linear projection.** One matrix $W \in \mathbb{R}^{D_V \times D_L}$ and a bias $b$ are applied to each patch: $H_v = Z_v W + b$. Here $Z_v$ is the $576 \times 1024$ patch matrix and $H_v$ is $576 \times 4096$. LLaVA (Liu et al., 2023, arXiv:2304.08485, Section 4.1) used a single linear layer to map CLIP features into the word-embedding space of Vicuna. The parameter count is $1024 \cdot 4096 + 4096 = 4{,}198{,}400$.

**Two-layer MLP.** $H_v = \mathrm{GELU}(Z_v W_1 + b_1)\,W_2 + b_2$. LLaVA-1.5 (Liu et al., 2023, arXiv:2310.03744) describes its connector as an MLP ("fully-connected vision-language cross-modal connector") in place of the linear layer. The abstract does not give the hidden width. I assume it equals $D_L$, which gives $20{,}979{,}712$ parameters. The output is still one token per patch, so 576 tokens.

**Q-Former.** BLIP-2 (Li et al., 2023, arXiv:2301.12597) calls its module a "lightweight Querying Transformer". It uses 32 learned query vectors, each of width 768 (its Section 3.1). The queries are constants learned in advance; the image enters through cross-attention, where the queries ask and the patch features answer. The 32 outputs are then projected to the LLM width and placed in front of the text embeddings (Section 3.3). The LLM reads 32 visual tokens at any resolution. The Q-Former is trained in a first stage against the frozen image encoder, before it meets the LLM, so it is more than a projection. The real module also has self-attention among the queries; the code below keeps only the cross-attention step.

![Three columns: the linear connector is one box, the MLP is three stacked layers, the Q-Former is a set of queries feeding one cross-attention block; each column shows its output token count](diagrams/60.2-three-connectors.svg "Structure and output count per image. Parameter counts are computed for the linear and MLP cases only.")

These are 2023 designs. Later systems use other connectors, and I have not checked them, so this lesson makes no claim about the current state of the art.

## Worked example by hand: the token budget

Take a 336-pixel image and a 64-token text prompt. With a linear or MLP connector the LLM reads $576 + 64 = 640$ tokens. The KV cache stores one key and one value per token, per layer. In fp16 (2 bytes per number) that is

$$
2 \times 32 \times 4096 \times 2\ \text{bytes} = 524{,}288\ \text{bytes} = 0.5\ \text{MiB per token}.
$$

For 640 tokens that is $640 \times 0.5 = 320$ MiB for one sequence, with no grouped-query attention. A Q-Former gives $32 + 64 = 96$ tokens and $96 \times 0.5 = 48$ MiB, a ratio of $640 / 96 \approx 6.7$.

Check every number with NumPy. This block runs in the browser on its own:

```python
import numpy as np

def softmax(z, axis=-1):
    z = z - z.max(axis=axis, keepdims=True)     # subtract the max for stability
    e = np.exp(z)
    return e / e.sum(axis=axis, keepdims=True)

def gelu(x):                                     # tanh approximation of GELU
    return 0.5 * x * (1 + np.tanh(np.sqrt(2 / np.pi) * (x + 0.044715 * x ** 3)))

rng = np.random.default_rng(0)
D_V, D_L = 1024, 4096                            # ViT-L width, 7B-class LLM width

def n_patches(resolution, patch=14):
    return (resolution // patch) ** 2

print("patches at 224 px:", n_patches(224), " at 336 px:", n_patches(336))

Z = rng.standard_normal((576, D_V)) * 0.02       # patch features of one 336-px image

# Linear connector: one matrix, applied to every patch
W = rng.standard_normal((D_V, D_L)) * 0.02
b = np.zeros(D_L)
H_lin = Z @ W + b
print("linear:", H_lin.shape, "params:", W.size + b.size)

# Two-layer MLP connector (hidden width = D_L is my assumption)
W1 = rng.standard_normal((D_V, D_L)) * 0.02
b1 = np.zeros(D_L)
W2 = rng.standard_normal((D_L, D_L)) * 0.02
b2 = np.zeros(D_L)
H_mlp = gelu(Z @ W1 + b1) @ W2 + b2
print("MLP:   ", H_mlp.shape, "params:", W1.size + b1.size + W2.size + b2.size)

# Q-Former-style resampler: 32 learned queries (width 768) cross-attend to the patches
Dq, Nq = 768, 32
queries = rng.standard_normal((Nq, Dq)) * 0.02
Wq = rng.standard_normal((Dq, Dq)) * 0.02
Wk = rng.standard_normal((D_V, Dq)) * 0.02
Wv = rng.standard_normal((D_V, Dq)) * 0.02
att = softmax((queries @ Wq) @ (Z @ Wk).T / np.sqrt(Dq))   # (32, 576): softmax over patches
out = att @ (Z @ Wv)                                          # (32, 768)
Wo = rng.standard_normal((Dq, D_L)) * 0.02
print("Q-Former attention:", att.shape, "rows sum to 1:", bool(np.allclose(att.sum(axis=1), 1)))
print("Q-Former tokens to LLM:", (out @ Wo).shape)

# Token budget for one prompt with 64 text tokens, fp16 KV cache, 32 layers
TEXT, LAYERS, BYTES = 64, 32, 2
kv_per_token = 2 * LAYERS * D_L * BYTES          # keys and values, every layer
print("KV bytes per token:", kv_per_token)
for name, n_vis in [("linear, 224 px", 256), ("linear, 336 px", 576), ("Q-Former", 32)]:
    T = n_vis + TEXT
    print(f"{name}: {T} prompt tokens, KV cache {T * kv_per_token / 2**20:.0f} MiB")
```

```output
patches at 224 px: 256  at 336 px: 576
linear: (576, 4096) params: 4198400
MLP:    (576, 4096) params: 20979712
Q-Former attention: (32, 576) rows sum to 1: True
Q-Former tokens to LLM: (32, 4096)
KV bytes per token: 524288
linear, 224 px: 320 prompt tokens, KV cache 160 MiB
linear, 336 px: 640 prompt tokens, KV cache 320 MiB
Q-Former: 96 prompt tokens, KV cache 48 MiB
```

The per-token cost is the memory cost. The attention term grows as $T^2$, but at these lengths it is small next to the projection and feed-forward work. Per layer, attention needs about $4T^2 D_L$ FLOPs (the score and value products). The projections and feed-forward need about $2 \cdot 12 D_L^2 \cdot T$ FLOPs, using roughly $12 D_L^2$ weights per layer, which is close to the LLaMA-7B layer size. The ratio is $T / (6 D_L)$. For $T = 640$ it is $0.026$, so attention adds about 2.6% on top of the projection work. This is my own first-principles estimate, not a measurement. The cost of a visual token is therefore almost entirely linear in the token count.

## Toy test: linear against MLP

A toy cannot settle whether LLaVA-1.5's MLP helps in practice, since that result depends on a real LLM and real data. It can show when extra capacity pays off. The setup: 16-dimensional synthetic "vision features" $V$, and a target $Y = \tanh(V C_1) C_2$, a nonlinear function of $V$. The strength of the nonlinearity is set by the scale of $C_1$. A linear connector is fitted by least squares. An MLP (16 to 64 with tanh, then to 4) is trained by full-batch gradient descent for 4000 steps with manual backpropagation. Both are tested on 2000 unseen samples, with 400 or 4000 training samples.

<details><summary>Toy code (NumPy only; about 17 s on a laptop, too slow for the in-browser runner)</summary>

```python
import numpy as np

def run_toy(scale, n_train, seed_teacher=7, H=64, lr=0.05, steps=4000):
    T = np.random.default_rng(seed_teacher)            # one fixed teacher per setting
    C1 = T.standard_normal((16, 32)) * scale / 4.0
    C2 = T.standard_normal((32, 4)) / np.sqrt(32)

    def make(n, rng):
        V = rng.standard_normal((n, 16))               # stand-in for vision features
        return V, np.tanh(V @ C1) @ C2                 # target is nonlinear in V

    Vtr, Ytr = make(n_train, np.random.default_rng(1))
    Vte, Yte = make(2000, np.random.default_rng(2))

    # linear connector: least squares with a bias column (closed form)
    Atr = np.hstack([Vtr, np.ones((n_train, 1))])
    Ate = np.hstack([Vte, np.ones((len(Vte), 1))])
    Wl, *_ = np.linalg.lstsq(Atr, Ytr, rcond=None)
    lin_te = float(((Ate @ Wl - Yte) ** 2).mean())

    # MLP connector: 16 -> H (tanh) -> 4, full-batch gradient descent, manual backprop
    r = np.random.default_rng(3)
    W1 = r.standard_normal((16, H)) * 0.3; b1 = np.zeros(H)
    W2 = r.standard_normal((H, 4)) * 0.3;  b2 = np.zeros(4)
    for _ in range(steps):
        h = np.tanh(Vtr @ W1 + b1)
        pred = h @ W2 + b2
        d = 2 * (pred - Ytr) / Ytr.size                # gradient of mean squared error
        gW2, gb2 = h.T @ d, d.sum(0)
        dz = (d @ W2.T) * (1 - h ** 2)                 # back through tanh
        gW1, gb1 = Vtr.T @ dz, dz.sum(0)
        W1 -= lr * gW1; b1 -= lr * gb1
        W2 -= lr * gW2; b2 -= lr * gb2
    mlp_te = float(((np.tanh(Vte @ W1 + b1) @ W2 + b2 - Yte) ** 2).mean())
    return Yte.var(axis=0).mean(), lin_te, mlp_te, Wl.size, W1.size + b1.size + W2.size + b2.size

for scale, label in [(0.25, "mild"), (1.0, "strong")]:
    for n in (400, 4000):
        var, lin, mlp, p_lin, p_mlp = run_toy(scale, n)
        print(f"{label:6s} n={n:5d}  var={var:.4f}  linear={lin:.3g} ({p_lin} params)  MLP={mlp:.3g} ({p_mlp} params)")
```

```output
mild   n=  400  var=0.0314  linear=9.11e-05 (68 params)  MLP=0.012 (1348 params)
mild   n= 4000  var=0.0314  linear=8.43e-05 (68 params)  MLP=0.00289 (1348 params)
strong n=  400  var=0.2327  linear=0.0197 (68 params)  MLP=0.0363 (1348 params)
strong n= 4000  var=0.2327  linear=0.0187 (68 params)  MLP=0.0195 (1348 params)
```

</details>

![Grouped bars of held-out error for linear and MLP connectors in four toy settings, with the mild teacher giving tiny linear error and the strong teacher giving MLP error close to linear at 4000 samples](diagrams/60.2-toy-sweep.svg "Held-out mean squared error (lower is better). Toy data, one seed per setting.")

Read the table in two regimes. With the mild teacher the target is almost linear over the range of the inputs (the tanh is nearly the identity at this scale), so the linear connector is nearly exact. The MLP has about 20 times as many parameters and is worse at both sizes. With the strong teacher the linear fit still explains most of the variance (test error 0.0187 against a variance of 0.2327), and the MLP is worse at 400 samples and only roughly ties at 4000. The MLP's extra capacity needs data and optimisation to pay off.

These results come with caveats. The MLP was trained for a fixed 4000 steps with one learning rate; it may not be converged, and I did not tune it. The teacher is a single tanh layer, not a vision-language mapping. The toy shows a mechanism, not the size of the LLaVA-1.5 gain.

## Common traps

> [!TRAP]
> Resolution changes the token count quadratically. Going from 224 px to 336 px gives $(336/224)^2 = 2.25$ times as many patches (576 against 256), not 1.5 times.

> [!TRAP]
> Fewer tokens is cheaper, but not free. A Q-Former's 32 outputs must carry everything the answer needs. Whether they do is an empirical question for each task, and this lesson does not measure it.

> [!TRAP]
> More parameters in the connector is not better by itself. The full-size MLP here has about 5 times the parameters of the full-size linear layer ($20{,}979{,}712 / 4{,}198{,}400 \approx 5.0$). In the toy, the MLP had about 20 times the linear fit's parameters and lost at 400 samples.

> [!TRAP]
> The memory numbers assume fp16, no grouped-query attention, and a 32-layer, width-4096 model. A model with a different shape changes all of them. Recompute with the formula, not the table.

> [!TRAP]
> The Q-Former is not a drop-in projection. BLIP-2 trains it in a first stage against the frozen image encoder. Swapping in a random Q-Former, as the code above does, tests shapes and memory only.

## Summary

- A connector maps vision-encoder patch features (width 1024 here) into the LLM's input width (4096) and sets the number of visual tokens.
- Linear and MLP connectors emit one token per patch: 576 at 336 px. The MLP has about 5 times the parameters of the linear layer.
- A Q-Former uses 32 learned queries that cross-attend to the patches, so the LLM sees 32 visual tokens at any resolution.
- For a 7B-class model in fp16, each token costs about 0.5 MiB of KV cache, so 576 visual tokens cost about 288 MiB per sequence.
- In the toy, the MLP helps only when the target is strongly nonlinear and there is enough data.

## Quiz time

### Question 1: How many visual tokens and how much KV cache?

A ViT with 14-pixel patches sees a 448-pixel image, and a linear connector passes every patch to the LLM. The prompt has 100 text tokens. Using the 7B-class configuration in this lesson, how many visual tokens are there, and what is the fp16 KV cache for the whole prompt?

<details><summary>Show solution</summary>

$448 / 14 = 32$, so there are $32^2 = 1024$ visual tokens. The prompt has $1024 + 100 = 1124$ tokens. Each token costs $524{,}288$ bytes $= 0.5$ MiB, so the cache is $1124 \times 0.5 = 562$ MiB.

</details>

### Question 2: Which connector has more parameters?

A linear connector maps $D_V = 1024$ to $D_L = 4096$. A two-layer MLP uses the same widths with a hidden layer of width 4096. Which has more trainable parameters, and by how much?

<details><summary>Show solution</summary>

The MLP. The linear layer has $1024 \cdot 4096 + 4096 = 4{,}198{,}400$ parameters. The MLP has $20{,}979{,}712$, about 5 times as many, because its second matrix is $4096 \times 4096$. The hidden width is an assumption here, so the figure changes if the real hidden width differs.

</details>

### Question 3: Find the bug

A student implements the Q-Former's attention weights as follows. `scores` has shape `(32, 576)`.

```python
att = softmax(scores, axis=0)
```

What is wrong, and what should the axis be?

<details><summary>Show solution</summary>

`axis=0` normalises over the 32 queries, so each patch's weights sum over queries and each query's row does not sum to 1. The softmax must run over the 576 patches, which is the last axis: `axis=-1`. A check is that each row of `att` sums to 1, as the lesson's code confirms.

</details>

### Question 4: Why is the Q-Former's count fixed?

Explain why the Q-Former keeps the number of visual tokens at 32 when the resolution goes up, while a linear connector's count grows with resolution. Which part of the Q-Former makes this possible?

<details><summary>Show solution</summary>

The output size equals the number of learned queries, not the number of patches. Each query produces one output vector by attending to all patches. Adding patches changes the size of the attention weights (32 by $N$) but not the output shape (32 by 768). A linear connector maps each patch to one output, so its output size equals the patch count.

</details>
