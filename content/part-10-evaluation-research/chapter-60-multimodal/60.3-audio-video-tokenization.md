A large language model (LLM) reads sequences of vectors, so audio and video must first be turned into a few thousand vectors per minute. In this lesson you will compute the audio front end's frame counts and token rates by hand, see how a residual codec turns audio into discrete ids, and check that a 3D convolution whose stride equals its kernel is the same as cutting video into tubelets and applying one matrix multiply.

**You need:** matrix multiplication, what a convolution does (a small filter slid along a signal), and the idea that a model consumes embeddings (Lesson 25.1 on attention, Lesson 60.2 on projectors).

## The problem: raw signals are too long

A 30-second speech clip at 16 kHz (16,000 samples per second) is 480,000 numbers. A one-minute video at 24 frames per second, each frame 224 × 224 pixels with three colour channels, is 216,760,320 numbers (computed below). Self-attention cost grows with the square of the sequence length (Lesson 25.1), so the front end has to shrink each signal to a few thousand vectors per minute before the transformer sees it. Audio is one-dimensional and dense in time. Video adds two spatial axes and a time axis, so the design choices differ.

## Audio: a log-Mel spectrogram first

Whisper (Radford et al., 2022) works on 30-second chunks of 16 kHz audio. Its front end, in the openai/whisper code, does four things:

1. Split the signal into windows of 400 samples (25 milliseconds), one window every 160 samples (10 ms). That is 100 windows per second.
2. Take a fast Fourier transform (FFT) of each window. The short-time Fourier transform (STFT) gives 201 frequency bins, 40 Hz apart.
3. Group the bins into 80 bands with triangular mel filters. The mel scale is roughly linear below 1 kHz and logarithmic above it, so low frequencies get finer bands. Whisper uses the Slaney mel scale from the librosa library. Under that scale, 1000 Hz maps to 15.0 mel and 2000 Hz to 25.08 mel.
4. Take log10 of each band energy, floor values at 8 decades below the loudest value, and rescale with (x + 4) / 4.

![Five boxes from a 30-second waveform to 1500 encoder positions, with the shape under each box](diagrams/60.3-audio-frontend.svg "The Whisper front end, with the array shape after each stage")

> [!KEY-INSIGHT]
> The shape is the whole story: a waveform of 480,000 numbers becomes an 80 × 3,000 image, and the encoder then keeps 1,500 positions. Every later number follows from these shapes.

**Worked check, by hand.** One second is 16,000 samples. Whisper pads 200 samples on each side so that frames are centred, giving 16,400 samples. The number of windows is 1 + (16,400 − 400) / 160 = 101. The code then drops the last window, leaving 100. For 30 seconds the same arithmetic gives 3,000. The block below rebuilds this in NumPy, a Python numerical library, and prints the shapes.

```python
import numpy as np

SR, NFFT, HOP, NMELS = 16000, 400, 160, 80
F_SP, MIN_LOG_HZ = 200.0 / 3, 1000.0          # Slaney mel scale, as in librosa's default
MIN_LOG_MEL = MIN_LOG_HZ / F_SP
LOGSTEP = np.log(6.4) / 27.0

def hz_to_mel(f):
    f = np.asarray(f, dtype=float)
    log_part = MIN_LOG_MEL + np.log(np.maximum(f, 1e-10) / MIN_LOG_HZ) / LOGSTEP
    return np.where(f >= MIN_LOG_HZ, log_part, f / F_SP)

def mel_to_hz(m):
    m = np.asarray(m, dtype=float)
    log_part = MIN_LOG_HZ * np.exp(LOGSTEP * (m - MIN_LOG_MEL))
    return np.where(m >= MIN_LOG_MEL, log_part, F_SP * m)

def hann(n):
    return 0.5 - 0.5 * np.cos(2 * np.pi * np.arange(n) / n)

def stft_power(x):
    xp = np.pad(x, NFFT // 2, mode="reflect")      # centre the frames, as torch.stft does
    n_frames = 1 + (len(xp) - NFFT) // HOP
    idx = np.arange(NFFT)[None, :] + HOP * np.arange(n_frames)[:, None]
    spec = np.fft.rfft(xp[idx] * hann(NFFT), axis=1)
    return (np.abs(spec) ** 2).T                  # (201 bins, frames)

def mel_filters(n_mels=NMELS):
    fft_f = np.linspace(0, SR / 2, NFFT // 2 + 1)
    hz = mel_to_hz(np.linspace(hz_to_mel(0.0), hz_to_mel(SR / 2), n_mels + 2))
    fd = np.diff(hz)
    ramps = hz[:, None] - fft_f[None, :]
    w = np.maximum(0, np.minimum(-ramps[:-2] / fd[:-1, None], ramps[2:] / fd[1:, None]))
    return w * (2.0 / (hz[2:] - hz[:-2]))[:, None]

def log_mel(x):
    lg = np.log10(np.maximum(mel_filters() @ stft_power(x)[:, :-1], 1e-10))  # drop last frame
    lg = np.maximum(lg, lg.max() - 8.0)           # keep 8 decades below the peak
    return (lg + 4.0) / 4.0

print("mel(1000 Hz) =", round(float(hz_to_mel(1000.0)), 2), " mel(2000 Hz) =", round(float(hz_to_mel(2000.0)), 2))
t = np.arange(30 * SR) / SR
x = 0.5 * np.sin(2 * np.pi * 440 * t) + 0.2 * np.sin(2 * np.pi * (300 + 150 * t) * t)
print("1 s  ->", log_mel(x[:SR]).shape, "frames")
m = log_mel(x)
print("30 s ->", m.shape)
print("value range:", round(float(m.min()), 4), "to", round(float(m.max()), 4))
centres = mel_to_hz(np.linspace(hz_to_mel(0.0), hz_to_mel(SR / 2), NMELS + 2))[1:-1]
print("loudest band at frame 40:", round(float(centres[np.argmax(m[:, 40])]), 1), "Hz")
```

```output
mel(1000 Hz) = 15.0  mel(2000 Hz) = 25.08
1 s  -> (80, 100) frames
30 s -> (80, 3000)
value range: -0.4988 to 1.5012
loudest band at frame 40: 446.9 Hz
```

The loudest band in frame 40 is centred at 446.9 Hz, the band nearest the 440 Hz tone. The chirp in the test signal has amplitude 0.2 against the tone's 0.5, so the tone wins in this frame.

## Conv stem: 100 frames per second becomes 50

Whisper's encoder begins with two one-dimensional convolutions. The first has kernel size 3 and stride 1. The second has kernel size 3 and stride 2, so it keeps every other frame. Each is followed by GELU, a smooth ReLU-like activation, and then a fixed sinusoidal position code is added (openai/whisper, `model.py`). The output length of a convolution with kernel $k$, stride $s$ and padding $p$ is

$$
L_{\text{out}} = \left\lfloor \frac{L + 2p - k}{s} \right\rfloor + 1.
$$

For 3,000 frames, the first conv gives 3,000 and the second gives $\lfloor 2999 / 2 \rfloor + 1 = 1500$. That is 50 positions per second. The block runs a random-weight version to check the shape.

```python
import numpy as np
rng = np.random.default_rng(0)

def conv_len(L, k, s, p):                      # output length of a 1-D convolution
    return (L + 2 * p - k) // s + 1

def conv1d(x, w, stride=1, pad=1):             # x: (C_in, L), w: (C_out, C_in, k)
    xp = np.pad(x, ((0, 0), (pad, pad)))
    k = w.shape[2]
    out = np.empty((w.shape[0], (xp.shape[1] - k) // stride + 1))
    for i in range(out.shape[1]):
        out[:, i] = np.tensordot(w, xp[:, i * stride:i * stride + k], axes=([1, 2], [0, 1]))
    return out

mel = rng.normal(size=(80, 3000))              # 30 s of log-Mel frames (random values here)
h = np.maximum(conv1d(mel, rng.normal(size=(16, 80, 3)) * 0.05, stride=1), 0)
h = np.maximum(conv1d(h, rng.normal(size=(16, 16, 3)) * 0.05, stride=2), 0)
print("stem output:", h.shape, "| formula gives", conv_len(conv_len(3000, 3, 1, 1), 3, 2, 1))
```

```output
stem output: (16, 1500) | formula gives 1500
```

These 50 vectors per second are continuous floats. Nothing in the encoder quantizes them. A speech LLM, a language model that takes audio input, passes them through a connector into the language model's embedding space, the pattern from Lesson 60.2. Whisper's decoder then emits text tokens, which are a different thing.

## Discrete audio tokens: residual vector quantization

A model that predicts audio the way a GPT (generative pre-trained transformer) predicts text needs discrete ids. Vector quantization (VQ) finds the nearest entry in a codebook of $K$ vectors, and the index of that entry is the token. Residual VQ (RVQ) applies this in stages: codebook 1 picks $c_1$, the residual $r_1 = x - c_1$ is quantized by codebook 2, and so on. Each stage adds one id per frame, and the decoder sums the chosen entries to rebuild $x$.

EnCodec (Défossez et al., 2022) works at 24 kHz with 75 latent steps per second, 1,024 entries per codebook (10 bits), and up to 32 codebooks. Its paper states bandwidths of 1.5 to 24 kbps. Bits per second (bps) equal frame rate × codebooks × 10, so 75 × 10 × 2 = 1,500 bps and 75 × 10 × 32 = 24,000 bps. The rate therefore depends on how many codebooks you keep, not on the length of the codebooks alone.

![Three residual stages applied to one vector, with the residual norm after each stage](diagrams/60.3-rvq-stages.svg "Residual vector quantization on one vector from the toy data")

The block below builds a toy RVQ in NumPy. The data are synthetic 8-dimensional vectors, and each codebook is fitted with k-means on the residuals of the previous stage. It is not a codec and its numbers do not measure audio quality.

```python
import numpy as np
rng = np.random.default_rng(7)
centres = rng.normal(0, 3, size=(20, 8))
X = centres[rng.integers(0, 20, 2000)] + rng.normal(0, 1.0, size=(2000, 8))

def kmeans(Z, K, seed, iters=25):               # plain Lloyd iterations
    r = np.random.default_rng(seed)
    C = Z[r.choice(len(Z), K, replace=False)].copy()
    for _ in range(iters):
        a = ((Z[:, None, :] - C[None]) ** 2).sum(-1).argmin(1)
        for k in range(K):
            if np.any(a == k):
                C[k] = Z[a == k].mean(0)
    return C, ((Z[:, None, :] - C[None]) ** 2).sum(-1).argmin(1)

K, books, codes, R = 16, [], [], X.copy()
for stage in range(8):                          # each stage quantizes what the last one missed
    C, a = kmeans(R, K, seed=stage + 1)
    books.append(C); codes.append(a)
    R = R - C[a]

print("n_q  bits/vector  MSE")
recon = np.zeros_like(X)
print(f"{0:3d}  {0:11d}  {np.mean(X ** 2):.4f}")
for n in range(8):
    recon = recon + books[n][codes[n]]
    print(f"{n + 1:3d}  {4 * (n + 1):11d}  {np.mean((X - recon) ** 2):.4f}")
```

```output
n_q  bits/vector  MSE
  0            0  8.3759
  1            4  1.4498
  2            8  0.7303
  3           12  0.4255
  4           16  0.2478
  5           20  0.1445
  6           24  0.0853
  7           28  0.0501
  8           32  0.0298
```

![Bars of mean squared error for zero to eight codebooks, with bits per vector under each bar](diagrams/60.3-rvq-error.svg "Reconstruction error in the toy RVQ: the first codebook removes most of the error")

After the first codebook, each added stage cut the error by a factor of about 1.7 to 2. That holds for this toy only. In a real codec the encoder, decoder and codebooks are trained together, and the quality trade-off is measured with listening tests.

AudioLM (Borsos et al., 2022) combines two token streams. Its abstract describes discretized activations of an audio-pretrained masked language model, used for long-term structure, and the discrete codes of a neural codec, used for high-quality synthesis. Calling the first "semantic" and the second "acoustic" tokens is common usage, and my label, not the paper's wording.

## Video: tubelets are 3D patches

A video clip is a tensor of shape $T \times H \times W \times C$. ViViT (Arnab et al., 2021), Section 3.2, describes two ways to make tokens. In tubelet embedding, the clip is cut into non-overlapping tubes of size $t \times h \times w$. Each tube is flattened and linearly projected. The paper notes that this "corresponds to a 3D convolution", and the number of tokens along each axis is $\lfloor T/t \rfloor$, $\lfloor H/h \rfloor$, $\lfloor W/w \rfloor$. Smaller tubelets give more tokens and more computation.

For a 16-frame clip at 224 × 224, the counts are:

- 2D patches of 16 × 16 taken from every frame: 16 × 196 = 3,136 tokens.
- Tubelets of 2 × 16 × 16: 8 × 196 = 1,568 tokens, each holding 1,536 numbers.
- Tubelets of 4 × 16 × 16: 4 × 196 = 784 tokens.

![A clip cut into tubelets with a bar for each token count](diagrams/60.3-tubelet.svg "Tubelets fuse time and space into one token")

Why is a convolution with stride equal to kernel the same as a matrix multiply? Each output position sees exactly one non-overlapping patch, and the filter is a weight vector over that patch. The block checks this numerically with a naive loop-based 3D convolution against reshape and matmul.

```python
import numpy as np
rng = np.random.default_rng(0)

def conv3d_naive(x, w, stride):                # x: (C, T, H, W), w: (O, C, kt, kh, kw), no padding
    C, T, H, W = x.shape
    O, _, kt, kh, kw = w.shape
    st, sh, sw = stride
    To, Ho, Wo = (T - kt) // st + 1, (H - kh) // sh + 1, (W - kw) // sw + 1
    y = np.zeros((O, To, Ho, Wo))
    for a in range(To):
        for b in range(Ho):
            for c in range(Wo):
                patch = x[:, a*st:a*st+kt, b*sh:b*sh+kh, c*sw:c*sw+kw]
                y[:, a, b, c] = np.tensordot(w, patch, axes=([1, 2, 3, 4], [0, 1, 2, 3]))
    return y

def tubelet_linear(x, Wl, t, p):               # cut non-overlapping tubelets, then one matmul
    C, T, H, W = x.shape
    nt, nh, nw = T // t, H // p, W // p
    tub = x[:, :nt*t, :nh*p, :nw*p].reshape(C, nt, t, nh, p, nw, p)
    tub = tub.transpose(1, 3, 5, 0, 2, 4, 6).reshape(nt, nh, nw, C * t * p * p)
    return (tub @ Wl.T).transpose(3, 0, 1, 2)

x = rng.normal(size=(3, 4, 32, 32))
w = rng.normal(size=(5, 3, 2, 8, 8))
a = conv3d_naive(x, w, stride=(2, 8, 8))
b = tubelet_linear(x, w.reshape(5, -1), t=2, p=8)
print("conv3d shape:", a.shape, "| same as tubelet matmul:", bool(np.abs(a - b).max() < 1e-10))

T, H, W, C = 16, 224, 224, 3
def tokens(t, p):
    return (T // t) * ((H // p) * (W // p))
print("2D patches 16x16, per frame:", tokens(1, 16))
print("tubelet 2x16x16:", tokens(2, 16))
print("tubelet 4x16x16:", tokens(4, 16))
print("raw numbers in 1 min at 24 fps:", 60 * 24 * H * W * C)
print("values per 2x16x16x3 tubelet:", 2 * 16 * 16 * C)
print("MACs, 3x3x3 conv to 64 ch, full resolution:", T * H * W * 64 * C * 27)
print("MACs, tubelet linear to 768 dims:", tokens(2, 16) * (2 * 16 * 16 * C) * 768)
```

```output
conv3d shape: (5, 2, 4, 4) | same as tubelet matmul: True
2D patches 16x16, per frame: 3136
tubelet 2x16x16: 1568
tubelet 4x16x16: 784
raw numbers in 1 min at 24 fps: 216760320
values per 2x16x16x3 tubelet: 1536
MACs, 3x3x3 conv to 64 ch, full resolution: 4161798144
MACs, tubelet linear to 768 dims: 1849688064
```

The arithmetic also shows the cost of a conventional 3D convolution. A 3 × 3 × 3 convolution from 3 colour channels to 64 channels, at full resolution, performs about $4.16 \times 10^9$ multiply-accumulate operations (MACs), and it leaves 16 × 224 × 224 = 802,816 positions for the transformer. A tubelet projection to 768 dimensions performs about $1.85 \times 10^9$ MACs and leaves 1,568 tokens.

## Common traps

> [!TRAP]
> The encoder runs at 100 frames per second before the stride-2 conv and at 50 positions per second after it. Quote the rate that matches the layer you mean.

> [!TRAP]
> Whisper's encoder output is continuous. Its generated tokens are text. Do not read the decoder output as audio tokens.

> [!TRAP]
> A codec's rate is frame rate × codebooks × bits per code, not codebooks alone. 8 codebooks at 75 Hz is 6 kbps, not 8 kbps.

> [!TRAP]
> In RVQ, the toy's error numbers describe k-means on synthetic data. Do not compare them with codec quality.

> [!TRAP]
> A tubelet with stride smaller than its kernel makes overlapping windows, so more tokens share the same pixels and the count rises above the non-overlapping count.

## Summary

- Whisper's front end maps 30 s of 16 kHz audio to an 80 × 3,000 log-Mel array, then the conv stem gives 1,500 positions, or 50 per second.
- Whisper's encoder vectors are continuous. Discrete audio tokens come from codecs such as EnCodec, which uses residual codebooks.
- EnCodec's bitrate is frame rate × codebooks × 10 bits: 75 × 10 × 8 = 6,000 bps for 8 codebooks.
- A 3D convolution with stride equal to kernel is a linear projection of non-overlapping tubelets (ViViT, Section 3.2).
- Tubelets trade token count against per-token detail: 2 × 16 × 16 gives 1,568 tokens for a 16-frame clip, versus 3,136 for per-frame patches.

## Quiz time

### Question 1: Calculation

A 10-second clip at 16 kHz goes through Whisper's front end. How many log-Mel frames and how many encoder positions does it produce?

<details><summary>Solution</summary>

The clip has 160,000 samples. Centre padding gives 1 + 160,000 / 160 = 1,001 windows, and dropping the last leaves 1,000 frames. The first conv keeps 1,000 frames. The stride-2 conv gives $\lfloor 999/2 \rfloor + 1 = 500$ positions, which is 50 per second over 10 seconds.

</details>

### Question 2: Prediction

EnCodec at 24 kHz with 8 codebooks of 1,024 entries runs for one minute. What is the bitrate, and how many codes are produced?

<details><summary>Solution</summary>

Bitrate: 75 × 8 × 10 = 6,000 bps, or 6 kbps. Codes: 75 × 8 × 60 = 36,000 per minute, which matches the 6 kbps bar (36,000) in the tokens-per-minute figure above.

</details>

### Question 3: Find the bug

```python
def n_tubelet_tokens(T, H, W, t=2, p=16):
    return (T * (H // p) * (W // p)) // t

print(n_tubelet_tokens(15, 224, 224))   # frames: 15, expected tokens: 7 * 196
```

<details><summary>Solution</summary>

The function gives 15 × 196 // 2 = 1,470, but the tubelet count uses $\lfloor T / t \rfloor = \lfloor 15 / 2 \rfloor = 7$ temporal positions, which gives 7 × 196 = 1,372. The bug is applying the division to the product, which keeps the half-tubelet of the last frame. The fix is `(T // t) * (H // p) * (W // p)`.

</details>

### Question 4: Explanation

Why does RVQ use several small codebooks instead of one codebook with $1024^n$ entries for $n$ stages?

<details><summary>Solution</summary>

This follows from counting (reasoning, not a cited result). One codebook with $1024^n$ entries has as many distinct codes as $n$ stages of size 1,024, but storing it and finding the nearest entry would cost on the order of $1024^n$ distance computations per frame. RVQ needs $n$ tables of 1,024 entries and $n \times 1024$ distances per frame, and each stage works on the residual that the previous stages left.

</details>

### Question 5: Explanation

A tubelet embedding uses kernel $(2, 16, 16)$ and stride $(1, 16, 16)$. What changes compared with stride $(2, 16, 16)$?

<details><summary>Solution</summary>

Adjacent windows now overlap in time, so each frame appears in two tubelets. The temporal count becomes $T - 2 + 1 = 15$ for a 16-frame clip instead of 8. The spatial count is unchanged at 196. That gives 15 × 196 = 2,940 tokens instead of 1,568, and the cost of the embedding grows with the number of windows. This is the trap noted above: stride smaller than kernel means overlap.

</details>
